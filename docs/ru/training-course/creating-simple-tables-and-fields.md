### <a name="creating-tables-sections-and-folders-ai"></a> Дополнительные вопросы

#### <a name="creating-tables-sections-and-folders-ai1"></a> Где находятся разделы и папки в Totum?

Разделы и папки в Totum находятся в одной и той же таблице. Разделы отображаются в верхней панели, а папки расположены в левой колонке дерева навигации, которую можно скрывать и открывать.

#### <a name="creating-tables-sections-and-folders-ai2"></a> Как добавить новую ветку в Totum?

**Как добавить новую ветку в Totum:**

1. Перейдите в верхнюю панель, где находятся разделы.
2. Нажмите на значок плюса.
3. Введите название и параметры для Нового раздела/секции.
4. Раздел появится в списке разделов в соответсвии со порядком своей сортировки.

#### <a name="creating-tables-sections-and-folders-ai3"></a> Как добавить новую папку в Totum?

Чтобы добавить новую папку в Totum:

1. Нажмите на кнопку "Плюс Папка" в левой колонке (где расположены папки и таблицы).
2. Введите название новой папки (например, "Новая папка").
3. Нажмите "Сохранить".

После этого новая папка появится в левой колонке.

#### <a name="creating-tables-sections-and-folders-ai4"></a> Можно ли создавать вложенные папки в Totum? Если да, то как это сделать?

**Можно ли создавать вложенные папки в Totum?**

Да, в Totum можно создавать вложенные папки.

**Как это сделать:**

1. **Нажмите на плюс** в левой колонке, чтобы добавить новую папку.

2. **Введите название новой папки** и сохраните её.

3. **Раскройте созданную папку**, нажав на стрелку рядом с её названием.

4. **Нажмите на плюс** внутри раскрытой папки, чтобы добавить вложенную папку.

5. **Введите название вложенной папки** и сохраните её.

Теперь у вас есть вложенная папка внутри основной папки.

#### <a name="creating-tables-sections-and-folders-ai5"></a> Как добавить новую таблицу в папку?

**Добавление новой таблицы в папку**

1. Перейдите в нужную папку в дереве таблиц.

2. Нажмите на кнопку с плюсом в правом верхнем углу: `+`.

3. Выберите опцию 'Таблица' из выпадающего меню.

4. В появившемся окне заполните необходимые поля:
   - **Название таблицы**: Укажите название новой таблицы.
   - **Тип таблицы**: Выберите тип таблицы (например, 'Простая таблица').

5. Нажмите кнопку 'Сохранить'.

После этого новая таблица будет добавлена в выбранную папку.

#### <a name="creating-tables-sections-and-folders-ai6"></a> Какие параметры необходимо указать при создании новой таблицы?

При создании новой таблицы необходимо указать следующие параметры:

1. **name**: Имя таблицы (обязательный параметр).
2. **type**: Тип таблицы (обязательный параметр). Возможные значения: Простая, Циклов, Временная и Расчетная.
3. **title**: Заголовок таблицы (обязательный параметр).

Остальные параметры являются необязательными и могут быть указаны/отредактированы после создания.

#### <a name="creating-tables-sections-and-folders-ai7"></a> Можно ли редактировать настройки уже созданной таблицы? Если да, то как это сделать?

**Да, можно редактировать настройки уже созданной таблицы.**

Для этого нужно:

1. Перейти в таблицу, которую вы хотите редактировать.

2. Нажать на кнопку параметров таблицы, которая находится рядом с названием таблицы.

3. В открывшемся окне вы можете изменить настройки таблицы.

4. Сохраните изменения.

**Важно:**

Имя таблицы задается только при ее создании и изменить его нельзя. Если вы допустили ошибку в имени, то вам нужно будет удалить таблицу и создать новую. При этом, если в таблице есть уже заполненные поля, то такую таблицу с данными можно сдублировать и в дублируемой таблице указать корректное имя, а таблицу с некорректным именем удалить.

#### <a name="creating-tables-sections-and-folders-ai8"></a> Где в Totum находятся настройки таблицы?

Настройки таблицы в Totum находятся в панели параметров таблицы, которая доступна через кнопку рядом с названием таблицы.

#### <a name="creating-tables-sections-and-folders-ai9"></a> Можно ли изменить Name таблицы после её создания? Если нет, то что делать в случае ошибки?

Нет, Name таблицы в Totum задается только при создании и изменить его нельзя. Если вы допустили ошибку в имени таблицы, вам нужно удалить таблицу и создать новую с правильным именем. При этом, если в таблице есть уже заполненные поля, то такую таблицу с данными можно сдублировать и в дублируемой таблице указать корректное имя, а таблицу с некорректным именем удалить. Для удаления папки необходимо зайти в системную таблицу, где хранятся все папки, и скрыть её там. Папки не удаляются окончательно из таблицы, они скрываются и могут быть затем восстановлены.

#### <a name="creating-tables-sections-and-folders-ai13"></a> Как удалить ненужную папку из системы?

Для удаления ненужной папки в системе Totum, выполните следующие шаги:

1. Перейдите в системную таблицу, где хранятся все папки. Она находится по пути: **Системные таблицы** > **Основные** > **Таблицы и поля**.

2. Найдите таблицу, которая называется **Дерево**.

3. Откройте таблицу **Дерево**.

4. Найдите строку с вашей папкой, которую хотите удалить.

5. В выпадающем меню в колонке с **id** нажмите **Скрыть**.

6. Папка будет скрыта и не будет отображаться в интерфейсе, но её можно будет восстановить при необходимости.

Вы можете потренироваться в своей базе данных на демонстрационном сервере и перейти к следующему уроку.

### <a name="adding-fields-ai"></a> Дополнительные вопросы

#### <a name="adding-fields-ai1"></a> Что такое плейсменты?

Плейсменты в Totum — это области в таблице, где могут находиться поля. Основные плейсменты включают:

1. **Хедер**: Находится в верхней части таблицы и содержит поля, которые не зависят от строк.

2. **Префильтр**: Находится выше строчной части и позволяет фильтровать данные перед их отображением.

3. **Строчная часть**: Основная часть таблицы, где находятся строки данных.

4. **Футер**: Находится в нижней части таблицы и может содержать поля, привязанные к столбцам строчной части.

Не все таблицы имеют все эти плейсменты. Например, простая таблица не имеет футера, а временная таблица не имеет префильтра.

Все виды плейсментов присутствуют, например, есть у Расчетной таблицы в дереве.

#### <a name="adding-fields-ai2"></a> Как организованы плейсменты в расчетной таблице?

**Организация плейсментов в расчетной таблице:**

1. **Хэдер**: Плейсмент, который находится сразу после названия таблицы. Поля в хэдере обозначаются префиксом `h_`.

2. **Префильтр**: Плейсмент, который находится выше строчной части таблицы. Поля в префильтре обозначаются префиксом `fl_`.

3. **Строчная часть**: Основная часть таблицы, где располагаются поля без префиксов.

4. **Футер**: Плейсмент, который находится внизу таблицы. Поля в футере обозначаются префиксом `f_`.

4. **Футер колонок**: Плейсмент, который находится внизу таблицы, но привязан к конкретному полю. Поля в футере колонок также обозначаются префиксом `f_`.

#### <a name="adding-fields-ai3"></a> Какие плейсменты существуют в расчетной таблице?

В расчетной таблице существует несколько плейсментов:

1. **Хэдер**: Находится сразу после названия таблицы.

2. **Префильтр**: Относится к части строк и находится выше строчной части.

3. **Строчная часть**: Основная часть таблицы, где располагаются строки данных.

4. **Футер**: Общий футер, который находится внизу таблицы.

5. **Футер колонки**: Поле в футере, привязанное к конкретной колонке строчной части.

#### <a name="adding-fields-ai4"></a> Что такое хэдер и где он находится?

Хэдер — это верхняя часть таблицы, которая находится сразу после названия таблицы. В хэдере можно размещать поля, которые будут отображаться в верхней части таблицы.

#### <a name="adding-fields-ai5"></a> Что такое префильтр и каково его расположение в таблице?

**Префильтр**: находится выше строчной части и позволяет фильтровать данные строчной части таблицы перед их отображением.

#### <a name="adding-fields-ai6"></a> Как организованы поля в строчной части?

Поля в строчной части таблицы Totum организованы по горизонтальной линии и имеют последовательность, называемую Sort. Каждое поле при добавлении получает определенное значение Sort, которое определяет его позицию относительно других полей. Например, первое добавленное поле может получить Sort 10, следующее — Sort 20 и так далее. Если новое поле вставляется между существующими полями, оно получает Sort, равное sort предыдущего поля плюс 10, и при сохранении все последующие поля сдвигаются вправо на 10 пунктов.

#### <a name="adding-fields-ai7"></a> Какие плейсменты могут отсутствовать в таблицах?

В таблицах могут отсутствовать следующие плейсменты:

1. **Футер**: Простая таблица не имеет футера, что означает отсутствие футера и футеров столбцов.

2. **Префильтр**: Временная таблица не имеет префильтра.

#### <a name="adding-fields-ai8"></a> Какие плейсменты отсутствуют в простой и временной таблицах?

В простой таблице отсутствует футер, что означает отсутствие футера и футеров столбцов. В временной таблице отсутствует префильтр.

#### <a name="adding-fields-ai9"></a> Как добавить поле в таблицу?

**Как добавить поле в таблицу?**

**Способ 1**

1. **Откройте таблицу в режиме редактирования**: Перейдите в таблицу, в которой вы хотите добавить поле.

2. **Нажмите на кнопку 'Добавить поле'**: В верхней части интерфейса таблицы найдите кнопку 'Добавить поле' и нажмите на нее.

3. **Выберите плейсмент для нового поля**: По умолчанию поле будет добавлено в строчную часть таблицы. Если вы хотите добавить поле в другой плейсмент (например, в хедер или футер), выберите соответствующий вариант в выпадающем меню.

4. **Введите название поля**: В появившемся окне введите название нового поля. 'name' поля будет сгенерирован автоматически, но вы можете его изменить.

5. **Сохраните изменения**: Нажмите кнопку 'Сохранить', чтобы добавить новое поле в таблицу.

6. **Проверьте добавление поля**: Новое поле будет добавлено в указанное место в таблице. Вы можете проверить его наличие и настройки в интерфейсе таблицы.

**Способ 2**

Нажмите на выпадающее меню поля и выберите "Вставить после". В этом случае поле сразу добавляется в то размещение, из которого мы выбрали его для вставки.

#### <a name="adding-fields-ai10"></a> Какое Name присваивается полю по умолчанию при добавлении?

При создании полю автоматически присваивается Name, соответствующий названию поля и плейсменту. Его можно изменить при создании поля.

В строчной части Name по умолчанию не имеет префикса.

Если поле при создании перемещается из строчной части в другой плейсмент, к его Name добавляется префикс, соответствующий этому плейсменту (например, 'h_' для хедера, 'f_' для футера и 'fl_' для фильтра).

**Важно**

Если поле перемещается в другой плейсмент не при создании, а позже при редактировании, то префикс автоматически не присваевается. В этом случае рекомендуется изменить name поля на name содержащий префикс.

#### <a name="adding-fields-ai11"></a> Что происходит с именем поля, если его переместить в другой плейсмент?

Если поле перемещается в другой плейсмент при создании, к его Name автоматически добавляется префикс, соответствующий новому плейсменту.

Например, если поле перемещается в хедер, к Name добавляется префикс 'h_'. Если в футер, то 'h_'. Для фильтра добавляется 'fl_'.

Однако, если поле создается в строчной части и затем перемещается в другой плейсмент, его Name остается прежним (без префикса).

#### <a name="adding-fields-ai12"></a> Какие префиксы добавляются к Name поля в зависимости от его плейсмента?

Префиксы, которые добавляются к Name поля в зависимости от его плейсмента:

1. Хэдер: `h_`

2. Футер: `f_`

3. Префильтр: `fl_`

Эти префиксы добавляются автоматически при перемещении поля в соответствующий плейсмент.

В строчной части Name по умолчанию не имеет префикса.

#### <a name="adding-fields-ai13"></a> Как можно изменить Name поля после его создания?

Для изменения Name есть специальный инструмент, вызываемый из контекстного меню в заголовке поля.

#### <a name="adding-fields-ai14"></a> Какой тип данных присваивается полю по умолчанию?

По умолчанию полю присваивается тип данных 'Строка'.

#### <a name="adding-fields-ai15"></a> Какие есть способы добавления поля в таблицу?

**Способы добавления поля в таблицу:**

1. **Добавление через кнопку "Добавить поле"**:
   - Нажмите на кнопку "Добавить поле" в интерфейсе таблицы.
   - Поле по умолчанию будет добавлено в строчную часть таблицы, но вы можете изменить целевой плейсмент в процессе добавления или позже.
   - Введите название поля.
   - Полю автоматически присваивается Name, соответствующий названию поля и плейсменту. Name при создании можно изменить вручную.

2. **Добавление через выпадающее меню "Вставить после"**:
   - Нажмите левой кнопкой мыши на выпадающее меню в заголовке поля и выберите "Вставить после" из выпадающего меню.
   - Введите название нового поля.
   - Полю автоматически присваивается Name, соответствующий названию поля и плейсменту. Name при создании можно изменить вручную.
   - Поле будет добавлено после выбранного поля.

#### <a name="adding-fields-ai16"></a> Что такое Sort в контексте таблицы?

Sort — это последовательность полей в таблице, определяющая их порядок отображения. Поля с меньшим значением Sort отображаются левее, а с большим — правее. При добавлении нового поля ему автоматически присваивается значение Sort, чтобы определить его позицию относительно других полей.

#### <a name="adding-fields-ai17"></a> Как изменяется Sort при добавлении нового поля?

При добавлении нового поля в таблицу Totum, оно автоматически получает значение Sort, которое на 10 больше, чем у последнего существующего поля в том же плейсменте. Если поле вставляется между существующими полями, оно получает Sort, равный Sort предыдущего поля плюс 10, и все последующие поля сдвигаются вправо на 10 пунктов. При добавлении поля можно задать нужный Sort поля вручную.

#### <a name="adding-fields-ai18"></a> Что происходит с последовательностью Sort, когда новое поле вставляется между существующими?

Если поле вставляется между существующими полями, оно получает Sort, равный Sort предыдущего поля плюс 10, и все последующие поля сдвигаются вправо на 10 пунктов. При добавлении поля можно задать нужный Sort поля вручную.

#### <a name="adding-fields-ai19"></a> Что происходит с Sort при вставке поля в другой плейсмент?

При вставке поля в другой плейсмент, Sort этого поля изменяется в соответствии с последовательностью полей в новом плейсменте. Например, если поле было в строчной части с Sort 100 и перемещено в хедер, оно получит новое место в хедере в соответствии со своим sort. При изменении плейсмента поля можно задать нужный Sort поля в этом плейсменте вручную.

Как открыть настройки поля

#### <a name="the-order-of-the-fields-in-the-table-ai1"></a> Как влияет параметр Sort на порядок вычисления кодов в таблице?

Параметр Sort в таблице Totum определяет порядок, в котором рассчитываются коды и коды действий в таблице. Он влияет не только на последовательность отображения полей, но и на порядок их вычисления.

Например, если поле с кодом, который вычисляет значение на основе других полей, имеет более высокий Sort, чем эти поля, то на момент расчета этого поля значения из других полей могут быть еще не вычислены. Это может привести к некорректным результатам.

Порядок расчета определяется не только расположением по сортировке, но и среди различных мест размещения. Сначала рассчитывается хедер, затем префильтр, затем строчная часть и, наконец, футер. Строки рассчитываются в порядке возрастания номеров строк сверху вниз, а поля подвала рассчитываются в соответствии с их сортировкой.

Таким образом, параметр Sort играет ключевую роль в определении порядка вычисления кодов в таблице Totum и может значительно повлиять на конечный результат.

#### <a name="the-order-of-the-fields-in-the-table-ai5"></a> Какие существуют режимы расчета Строчной части и Футера?

Существует два режима расчета Строчной части и Футера:

1. **Стандартный режим**: По умолчанию, строки рассчитываются в порядке возрастания номеров строк сверху вниз. Сначала полностью рассчитывается первая строка слева направо, затем вторая строка — также слева направо. После этого рассчитываются поля Футеров колонок в соответствии с их сортировкой и потом оставшиеся поля в Футере, тоже в соответствии с их sort.

2. **Альтернативный (поколоночный) режим**: В этом режиме расчет Футера колонки происходит одновременно с расчетом строк в колонке. Колонки рассчитываются сверху вних в порядке своих sort. Это позволяет использовать в расчетах Футера данные из строк, которые еще не были полностью рассчитаны в стандартном режиме. Этот режим доступен только в расчетных и временных таблицах. Он может быть включен, если это необходимо для корректного расчета таблицы.

#### <a name="how-to-change-the-name-of-the-field-change-the-placement-ai17"></a> Что делать, если поле добавлено не в то расположение?

#### <a name="how-to-change-the-name-of-the-field-change-the-placement-ai18"></a> Сохраняется ли значение поля при его перемещении?

#### <a name="how-to-change-the-name-of-the-field-change-the-placement-ai21"></a> Что происходит с префиксом Name поля при его перемещении?

Префикс Name поля при его перемещении из одного расположения в другое не меняется. Это сделано для того, чтобы продолжали функционировать коды, которые ссылаются на это поле.

Хорошей практикой при этом является наличие правильных префиксов у полей, что бы при использовании полей в кодах было понятно, где находится поле. Например, если поле с Name 'field_20' перемещается из Хедера в Строчную часть или наоборот, префикс не изменится, и поле будет продолжать иметь тот же Name, но хорошей практикой будет изменить name после перемещения. Префиксы служат помощниками для понимания расположения полей, но не являются гарантией текущего расположения.

#### <a name="how-to-change-the-name-of-the-field-change-the-placement-ai22"></a> Для чего нужны префиксы Name поля?

Префиксы Name поля в системе Totum используются для удобства и ясности при работе с кодами. Они помогают быстро определить, в каком разделе таблицы находится поле. Например, если поле имеет префикс 'h_', то это указывает на то, что поле находится в хедере таблицы. Это облегчает чтение и понимание кода, особенно в сложных таблицах с большим количеством полей. Однако, важно помнить, что префиксы — это лишь помощник, а не гарантия, что поле действительно находится в указанном разделе, так как префикс не меняется при перемещении поля из одного расположения в другое автоматически.

#### <a name="how-to-change-the-name-of-the-field-change-the-placement-ai23"></a> Какие префиксы получают поля при перемещении?

При перемещении поля из одного расположения в другое префикс не меняется. Префиксы присваиваются автоматически при создании полей в нужном расположении. Например, если поле создается в хедере, ему присваивается префикс 'h_'. Если поле создается в футере, ему присваивается префикс 'f_'. Если поле создается в перифильтре, ему присваивается префикс 'fl_'. Эти префиксы служат для удобства использования в кодах, чтобы сразу было видно, в каком разделе находится поле.

#### <a name="how-to-change-the-name-of-the-field-change-the-placement-ai24"></a> Как понять, в каком расположении находится поле по его Name?

Поле в Totum может находиться в разных частях таблицы: в Хедере, в Строчной части, в Фктере или в Префильтре. Чтобы определить расположение поля по его Name, можно использовать префиксы, которые автоматически присваиваются при создании полей в определенных частях таблицы.

1. **Префикс 'h_'**: Поле находится в Хедеое.
2. **Префикс 'f_'**: Поле находится в Футере.
3. **Префикс 'fl_'**: Поле находится в Префильтре.
4. **Отсутствие префикса**: Поле находится в Строчной части.

Пример:

- Поле с Name 'h_field_11' находится в хедере.
- Поле с Name 'f_field_11' находится в футуре.
- Поле с Name 'fl_field_11' находится в перифильтре.
- Поле с Name 'field_11' находится в строчной части.

Обратите внимание, что при изменении плейсмента поля после его создания префиксы не добавляются и не изменяются. Поэтому, если не изменить Name поля вручную, то префикс или отсутсвие префикса будет соответствовать первоначальному плейсменту. Поэтому наличие префикса является помощником при определении расположения поля, но не гарантирует точное соответствие расположению.

#### <a name="how-to-change-the-name-of-the-field-change-the-placement-ai25"></a> Что такое Name поля и что такое заголовок поля. Чем они отличаются?

Name поля — это уникальный идентификатор поля, который используется в кодах для обращения к этому полю. Он задается при создании поля и не изменяется автоматически. Например, Name поля может быть 'field_11'.

Заголовок поля — это текст, который отображается пользователю в интерфейсе таблицы. Он может быть изменен в любое время и используется для удобства отображения. Например, заголовок поля может быть 'Цена'.

Отличие между ними заключается в том, что Name поля используется для программной работы с полем, а заголовок поля — для отображения пользователю.

### <a name="some-field-settings-using-the-numeric-field-as-an-example-text"></a> Текст урока (по видео)

Некоторые параметры полей на примере числового поля.
Разные типы полей имеют разные настройки. Здесь мы рассматриваем числовое поле, так как чаще всего настраиваются именно числовые поля.
Не все поля в этой таблице являются числовыми. Например, по умолчанию поле создается как строковое. Тип поля отображается в параметрах поля, это самый левый символ.
Самая базовая настройка числового поля — количество знаков после запятой.
Параметр включен, если рядом установлена галочка и в нем введено значение. Если галочка не стоит, а значение введено, то этот параметр неактивен. То есть, недостаточно просто ввести значение, нужно еще поставить галочку для его включения.
Здесь доступны 15 значений после запятой, и действительно можно ввести 15 цифр. Но Totum обрабатывает только 10 из них в своих вычислениях. Последние 5 обнуляются.
Следующий параметр, связанный с этим, — это округление. Обратите внимание, что округление всегда активно: существует 3 направления округления числа — вверх, вниз или математическое округление, но его нельзя включить или выключить, потому что оно всегда работает. С ним связан параметр шага округления — его можно включить или выключить, но само округление всегда активно.
Округление работает, если введенное или закодированное значение не соответствует количеству знаков после запятой, или если у вас нет знаков после запятой, но задан целочисленный шаг. В этом случае округление будет работать. Сохраняем. Здесь во втором поле указано, что обрабатывается 10 знаков после запятой, остальные обнуляются.
Следующий наиболее часто используемый параметр — это параметр отображения денежной суммы. Он выглядит следующим образом. Мы можем поставить галочку для «денежного формата», и в зависимости от языковой схемы будет отображаться денежное значение. Для русской схемы не денежное значение отображается без пробелов между тысячами и с точкой в качестве разделителя дробной части. Денежное значение отображается с пробелом между тысячами и запятой в качестве разделителя дробной части. Денежный формат часто используется с двумя знаками после запятой и единицей измерения. Здесь, например, доллар, и есть еще один параметр, который позволяет разместить единицу измерения перед значением, а не после всего этого блока, включая префиксы и эти параметры. Он влияет только на отображение. Внутри значение, как было, например, 10, так и остается 10. При открытии для редактирования оно выглядит так, но отображается с дополнительными условиями (например, префикс, разделение тысячных, разделение десятитысячных).
Следующий важный момент — можно ли использовать строку как число? Да, но только если вы вводите в это поле значение, состоящее из цифр. А если есть разделители дробной части, то это должна быть обязательно точка. Если, например, используется запятая и мы складываем по коду числовое значение и строку. То есть: деньги плюс строка как число. И здесь мы видим ошибку. Она говорит о том, что один из параметров не является числом, потому что числа, запятая и числа — это не число, а строка. Невозможно выполнять операции сложения числа и строки. Поэтому здесь возникает ошибка.
Можно ли ввести строковое значение в числовое поле? Нет, нельзя. Это сразу блокируется. Если мы попытаемся сохранить число с буквами или только буквы, система сообщит, что это не число, и не позволит сохранить его.
Довольно часто используется не стандартный денежный формат, а переопределенный. Как это выглядит? Мы устанавливаем денежный формат, и затем каждый элемент — префикс, разделитель тысяч, десятичный разделитель и постфикс, то есть значение после, — можно переопределить, включив соответствующий параметр. Если параметр отключен, то этот параметр не переопределяется.

Обратите внимание, что при использовании единицы измерения она появляется в заголовке поля после запятой. При использовании постфикса это не отображается. Числовые поля обрабатывают и отрицательные значения. Для ввода отрицательного значения необходимо поставить минус и 100.
В Totum есть возможность ввода относительного значения. Если мы хотим, например, вычесть 10 из этого значения, то нужно ввести: плюс минус 10. Получим минус 110. Если мы хотим добавить 10, то вводим плюс 10, и это будет прибавление. Если вводим минус 10, это будет ввод конечного отрицательного числа.
Можно задать форматирование отрицательного значения в другом формате. Это можно указать в префиксе, разделителе тысяч, десятичном разделителе и постфиксе. Если поставить двойную звездочку, то это будет шаблон для положительных значений и 0. После этого будет форматирование для отрицательных значений. Например, здесь у нас значение минус 10 — вот оно, минус 10, и префикс для отрицательного — скобка, постфикс для отрицательного — скобка, пробел, шт., вот так. Еще раз напомню: это только отображение. В кодах, при получении значения этого числа, оно будет минус 10.

Мы отключаем «Показать в Web» и включаем его снова — все флажки внутри будут сняты. То есть, при отключении родительского параметра, все дочерние значения отключаются. Например, если у вас есть поле с большим количеством настроек, и вы хотите сбросить, допустим, раздел «показать в интернете», вы просто выключаете его, включаете снова, и все параметры сбрасываются. Вы можете установить только те, которые вам нужны.

#### <a name="some-field-settings-using-the-numeric-field-as-an-example-ai6"></a> Что произойдет, если введенное значение не соответствует количеству знаков после запятой?

Если введенное значение не соответствует количеству знаков после запятой, то будет применено округление в соответствии с заданными параметрами. Округление всегда активно и может быть направлено вверх, вниз или математически. Также можно задать шаг округления, который можно включить или выключить. Например, если у вас нет знаков после запятой, но задан целочисленный шаг, округление все равно будет работать.

#### <a name="some-field-settings-using-the-numeric-field-as-an-example-ai7"></a> Какой параметр используется для отображения денежного формата?

#### <a name="some-field-settings-using-the-numeric-field-as-an-example-ai13"></a> Что такое относительное значение и как его вводить?

**Относительное значение в Totum**

Относительное значение в Totum — это возможность изменять числовое значение в поле относительно его текущего значения. Это позволяет добавлять или вычитать значения без необходимости вручную вводить новое значение.

**Пример использования**

1. **Вычитание значения**: Если вы хотите вычесть 10 из текущего значения, введите:
   ```
   +-10
   ```
   Результат будет: текущее значение минус 10.

2. **Добавление значения**: Если вы хотите добавить 10 к текущему значению, введите:
   ```
   +10
   ```
   Результат будет: текущее значение плюс 10.

3. **Ввод конечного отрицательного значения**: Если вы хотите установить конкретное отрицательное значение, введите:
   ```
   -10
   ```
   Результат будет: -10.

На выходе мы получаем значение, отформатированное в соответствии с заданными параметрами, с возможностью ввода относительных значений.

Например, если в параметре префикса указана двойная звездочка, то после нее идет форматирование для положительных значений и 0, а затем форматирование для отрицательных значений. Это позволяет задать разные форматы отображения для положительных и отрицательных чисел.

#### <a name="duplicate-and-paste-fields-duplicate-to-another-table-ai4"></a> Почему в одной таблице нельзя иметь два поля с одинаковым Name?

В одной таблице нельзя иметь два поля с одинаковым Name, потому что Name используется для идентификации поля в коде и при обработке данных. Если два поля будут иметь одинаковый Name, это приведет к конфликтам и ошибкам при выполнении операций, так как система не сможет однозначно определить, к какому полю обращаться. Поэтому Name каждого поля должен быть уникальным в пределах одной таблицы.

Первое глобальное требование, чтобы пользователь мог редактировать любое поле в таблице, — это наличие доступа к изменениям в этой таблице. Например, мы заходим в настройки таблицы, к настройке раздела 'роли на изменение' и 'роли на чтение'. Здесь вы можете назначить роли, для которых будет доступно совершать изменения в данной таблице, а также роли, которые смогут только просматривать информацию в таблицах. Чтение и изменение — это разные действия. Когда вы назначаете роль для изменения, чтение автоматически включается. То есть вам не нужно назначать роль для чтения и роль для изменения отдельно. Роль для изменения всегда имеет приоритет над ролью для чтения. Если же вы назначаете только роль на чтение, то изменение будет недоступно.

Что это значит для пользователя? Пользователь с ролью на изменение может изменять поля. Если же пользовател имеет доступ только для чтения в этой таблице, и любое поле, которое он попытается изменить, будет для него заблокировано.

Настройки редактирования в настройках поля
Вернемся в панель настроек поля. Следующая настройка, отвечающая за редактирование поля, позволяет открывать уже созданную строку для редактирования. Она относится к настройкам полей. Мы заходим в настройки полей. И здесь должна быть установлена галочка «Редактируемое в WEB». Если нет других настроек, например, ограничений на редактирование по ролям, то все роли в этой таблице, имеющие доступ к изменениям, смогут изменять это поле в уже созданной строке. Если опция «Редактируемое в WEB» отключена, и поле не может быть отредактировано.

Но кроме уже созданных строк есть и новые добавляемые строки. Если вы хотите, чтобы кнопка «Добавить» была доступна, то в настройках таблицы должна быть установлена галочка «Добавление строк». Можно поставить ограничение, что только создатель может добавлять строки. Если же мы хотим, чтобы все могли добавлять строки, нам нужно убрать конкретные роли и тогда в разделе "Ролевой доступ на добавление" будет указано Все роли. Тогда будет указано, что все роли могут добавлять. Если в разделе "Ролевой доступ на добавление" указан создатель, это означает, что если мы переключимся на пользователя, то у него есть разрешение на редактирование таблицы, но нет разрешения на добавление новых строк. То же самое касается и удаления строк. Например, если в разделе "Ролевой доступ на удаление" указано удаление строк и дублирование. Для этого в настройках таблицы есть два соответствующих параметра — «удаление» и «роли для удаления и дублирования». И также роли для дублирования.

У создателя есть возможность добавлять строки. И что мы можем здесь увидеть? Мы видим, что это поле заблокировано, но его можно редактировать, так как за изменения в добавляемой строке отвечает настройка поля. Вот настройка — «Редактирование при добавлении в WEB». И если здесь выбрана роль, то только эта может редактировать поле в добавляемой строке. Если мы отключим эту опцию, то изменение этого поля при добавлении будет доступно для всех остальных ролей.

Это довольно популярная комбинация, когда добавление разрешено, но редактирование разрешено только для конкретных ролей или вообще запрещено. Например, это используется в таблицах с финансовыми операциями, где записываются денежные транзакции. В этом случае, чтобы не допустить тихих изменений задним числом, разрешено добавление и редактирование при добавлении, но затем редактирование запрещено.

Настройки видимости в настройках поля
Если в может быть установлено, что роль не может видеть это поле. У нас есть индикатор глаза, который показывает, что только создатель и определенные роли могут видеть это поле. Если мы переключимся на пользователя, у которого есть нет роли с видимостью этого поля, то мы не видим это поле. И он не может его увидеть, так как оно не передается в его браузер, он не знает о его существовании. Как это делается? В настройках поля есть параметр «Видимость для ролей». Если он включен и здесь выбраны роли, то это поле будет передаваться в браузер только для указанных ролей.

Это основные настройки доступа к таблицам и полям. Также есть возможность блокировки жесткого и мягкого редактирования с помощью кодов, но об этом мы поговорим в следующих частях этого руководства.

### <a name="adding-rows-and-accesses-to-add-and-change-ai"></a> Дополнительные вопросы

#### <a name="adding-rows-and-accesses-to-add-and-change-ai1"></a> Каким образом пользователь может редактировать поле, если оно доступно для редактирования?

Пользователь может редактировать поле, если оно доступно для редактирования, следующим образом:

1. Дважды щелкните на поле, чтобы открыть его для редактирования.
2. Щелкните правой кнопкой мыши на поле и выберите опцию 'Редактировать' из контекстного меню.

Если поле заблокировано, пользователь увидит сообщение 'Заблокировано', и кнопка редактирования в контекстном меню не появится.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai2"></a> Что произойдет, если пользователь попытается отредактировать заблокированное поле?

Если пользователь попытается отредактировать заблокированное поле, то он увидит сообщение: «Заблокировано». Это произойдет независимо от способа блокировки поля.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai3"></a> Какие действия необходимо предпринять, чтобы пользователь мог редактировать любое поле в таблице?

Для того чтобы пользователь мог редактировать любое поле в таблице, необходимо выполнить следующие действия:

1. **Настройки таблицы:**
   - Перейдите в настройки таблицы.
   - В разделе 'роли на изменение' назначьте роль пользователя, которая будет иметь доступ к изменениям в таблице.

2. **Настройки поля:**
   - Перейдите в настройки каждого поля, которое должно быть редактируемым.
   - Установите галочку 'Редактируемое в WEB' для каждого поля (это настройка по умолчанию при создании поля).

После выполнения этих действий пользователь с назначенной ролью сможет редактировать любое соответствующее поле в таблице.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai4"></a> Как назначить роли, которые смогут изменять или только просматривать информацию в таблице?

**Назначение ролей для изменения и просмотра информации в таблице**

1. Откройте настройки таблицы.

2. Перейдите к разделу 'роли на изменение' и 'роли на чтение'.

3. В поле 'роли на изменение' укажите роли, которые будут иметь доступ к изменениям в таблице. Например, роль 'admin'.

4. В поле 'роли на чтение' укажите роли, которые будут иметь доступ только к просмотру информации в таблице. Например, роль 'user'.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai5"></a> Почему при назначении роли на изменение автоматически включается доступ к чтению?

Это сделано для упрощения управления доступами. Когда вы назначаете роль для изменения, чтение автоматически включается, чтобы избежать необходимости отдельно назначать роль для чтения. Это упрощает процесс настройки доступа и предотвращает возможные ошибки, связанные с забыванием назначить роль для чтения. Таким образом, роль для изменения всегда имеет приоритет над ролью для чтения, что обеспечивает более гибкое и удобное управление доступами.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai6"></a> Какое действие будет недоступно, если роль пользователя имеет доступ только на чтение?

Если роль пользователя имеет доступ только на чтение, то ему будет недоступно редактирование полей в таблице. Также он не сможет нажимать на кнопки, если в настройках полей кнопок не установлено специальное разрешение на активацию в режиме просмотра таблицы.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai7"></a> Как включить возможность редактирования уже созданных строк?

**Включение возможности редактирования уже созданных строк:**

1. Перейдите в настройки таблицы.

2. Убедитесь, что у пользователя есть доступ на изменение в таблице через параметр 'Роли на изменение'.

3. Перейдите в настройки поля, которое нужно сделать редактируемым.

4. Установите галочку в параметре 'Редактируемое в WEB'.

Теперь поле будет доступно для редактирования в уже созданных строках.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai8"></a> Какая настройка отвечает за возможность ограничения редактирования поля в уже созданной строке по ролям?

Настройка поля, отвечающая за возможность редактирования поля в уже созданной строке, находится в настройках поля в блоке «Редактируемое в WEB» и называется 'Редактирование доступно ролям'. Если не включать эту настройку, то редактирование будет доступно всем ролям, которые имеют доступ на редактирования в этой таблице. Если включить - то редактировать поле смогут только те роли, которые будут выбраны.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai9"></a> Что произойдет, если отключить опцию «Редактируемое в WEB»?

Если отключить опцию «Редактируемое в WEB», то поле станет недоступным для редактирования через веб-интерфейс. Это означает, что пользователи смогут увидеть его, но не смогут изменять значение этого поля в уже созданных строках, даже если у них есть соответствующие права на редактирование таблицы.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai10"></a> Какие действия может выполнять пользователь, если установлена галочка «Добавление строк»?

Если в настройках таблицы установлена галочка «Добавление строк», это означает, что пользователи могут добавлять новые строки в таблицу. Однако, возможность добавления строк может быть ограничена определенными ролями или условиями. Например, можно настроить, чтобы только определенные роли могли добавлять строки, или чтобы добавление было доступно только создателю таблицы. Если в разделе 'Ролевой доступ на добавление' указано 'Все роли', то все пользователи с доступом к таблице могут добавлять строки. Если указано 'Создатель', то только пользователь с ролью Создатель может добавлять новые строки.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai11"></a> Что означает, если в разделе «Ролевой доступ на добавление» указано «Все роли»?

Если в разделе «Ролевой доступ на добавление» указано «Все роли», это означает, что все роли могут добавлять строки в таблицу.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai12"></a> Какие параметры необходимо установить, чтобы разрешить удаление и восстановление строк?

Для разрешения удаления и восстановления строк в таблице необходимо установить следующие параметры:

1. В настройках таблицы, в разделе 'Ролевой доступ на удаление', выбрать роли, которым разрешено удаление строк. Если выбрать 'Все роли', то удаление будет доступно всем.

2. В настройках таблицы, в разделе 'Ролевой доступ на восстановление', выбрать роли, которым разрешено восстанавливать строки. Если выбрать 'Аналогично ролям на удаление', то восстановления будет доступно тем же ролям, что и удаление.

Эти настройки позволят пользователям с указанными ролями удалять и восстанавливать строки в таблице.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai13"></a> Какую роль играет настройка «Редактирование при добавлении в WEB»?

Настройка «Роли при добавлении в WEB» определяет, какие роли могут редактировать поле в добавляемой строке. Если для этой настройки выбрана определенная роль, то только пользователи с этой ролью смогут редактировать поле при добавлении новой строки. Если опция отключена, то редактирование этого поля при добавлении будет доступно для всех ролей. Это позволяет контролировать, кто может изменять данные в момент добавления новых строк, что особенно важно в таблицах с финансовыми операциями или другими критичными данными.

для того, что бы эта настройка действовала, необходимо, что бы было разрешено редактирование поля при добавлении настройкой поля Редактирование при добавлении (insertable).

#### <a name="adding-rows-and-accesses-to-add-and-change-ai14"></a> Какая роль может редактировать поле в добавляемой строке, если указана конкретная роль для редактирования?

Если в настройке поля 'Роли при добавлении в WEB' указана конкретная роль, то только эта роль может редактировать поле в добавляемой строке.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai15"></a> Как можно скрыть поле от определенных ролей?

**Как скрыть поле от определенных ролей**

Для того чтобы скрыть поле от определенных ролей в таблице Totum, необходимо использовать настройку 'Видимость для ролей' в параметрах поля.

1. **Откройте настройки поля**: Перейдите в настройки поля, которое вы хотите скрыть.

2. **Найдите параметр 'Видимость для ролей'**: В настройках поля найдите параметр 'Видимость для ролей'.

3. **Установите роли**: В этом параметре выберите роли, для которых поле будет видимо. Если параметр активен, а роль не выбрана, то поле не будет передаваться в браузер для этой роли.

Если параметр 'Видимость для ролей' отключен, то это поле будет видно всем ролям, у которым есть доступ к данной таблицы, если оно не скрыто в настройках глаза и доступно для отображения в WEB.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai16"></a> Какая настройка позволяет регулировать видимость полей для разных ролей?

Настройка, которая позволяет регулировать видимость полей для разных ролей, находится в параметре поля 'Видимость для ролей'. Если этот параметр включен и выбраны определенные роли, то поле будет передаваться в браузер только для указанных ролей.

#### <a name="adding-rows-and-accesses-to-add-and-change-ai17"></a> Что произойдет, если у пользователя нет роли с видимостью поля?

Если у пользователя нет роли с видимостью поля, то он не увидит это поле. Поле не будет передано в его браузер, и он не будет знать о его существовании.
