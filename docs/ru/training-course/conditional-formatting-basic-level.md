Форматирование – это действия, направленные на редактирование отображения данных, выдаваемых пользователю. Например, выделение цветом, блокировка изменений, блокировка добавления строки, курсив или жирный шрифт. Форматирование применимо к полю, строке или всей таблицы, и в зависимости от этого параметры форматирования немного отличаются.

`setFormat`
Доступна в секциях: Форматирование ячейки.
```totum
=: setFormat(condition: ; block: ; color: ; bold: ; background: ; decoration: ; italic: ; progress: ; progresscolor: ; icon: ; text: ; hide: ; showhand: ; placeholder: )
```
Изменяет внешний вид ячейки без условий, либо по условиям condition:.
Результаты работы функции применяются к ячейке последовательно, в соответствии с индексами f1=:, f2=:, f3=: и так далее.
`setFormat`имеет преимущество над `setRowFormat` при пересечении условий форматирования.

В коде форматирования можно использовать не только функции форматирования. Единственное, что должно быть возвращено в начальную секцию f, - это результат работы функции форматирования. Но мы можем использовать в коде и другие функции.
Например, сделаем так, чтобы значение $#nfv было больше или равно не равно 10, а данным, которые мы рассчитаем кодом. В качестве примера возьмем и посчитаем количество строк в этой таблице и умножим их на 10. И если значения поля больше полученного результата, то пусть будет выделение жирным.

```totum

calc: listCount(list: $list) * 10
list: selectList(table: $#ntn; field: 'id')
```

```totum
f1=: setFormat(bold: true; background: 'OldLace')
```

### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai"></a> Дополнительные вопросы

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai1"></a> Какая функция должна быть вызвана в коде форматирования?

В коде форматирования должна быть вызвана функция `setFormat` для форматирования ячеек. Эта функция позволяет изменять внешний вид ячейки, например, задавать цвет текста, цвет фона, делать текст жирным или курсивом и т.д.

Пример использования функции `setFormat` в коде форматирования:

```totum
f1=: setFormat(condition: $calc > 10; background: "tomato"; color: "white")

calc: listCount(list: $list)
    list: selectList(table: $#ntn; field: 'id')
```

В этом примере, если количество строк в таблице больше 10, то фон ячейки станет красным, а текст белым.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai2"></a> Можно ли использовать другие функции кодов в коде-форматирования?

Да, в коде форматирования можно использовать другие функции, но важно, чтобы в начальную строку кода возвращалась именно функция форматирования. Это означает, что вы можете использовать различные функции для вычислений или условий, но результат их работы должен быть передан в функцию форматирования, такую как `setFormat` или `setFloatFormat`.

Пример использования других функций в коде форматирования:

```totum
f1=: setFormat(condition: $calc > 10; background: "tomato"; color: "white")

calc: listCount(list: $list)
        list: selectList(table: $#ntn; field: 'id')
```

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai3"></a> В какой момент вычисляется форматирование?

Форматирование в системе Totum вычисляется после всех остальных кодов и перед отдачей таблицы пользователю в браузер. Это означает, что сначала выполняются все расчеты и действия, связанные с данными в таблице, а затем применяется форматирование, чтобы отобразить данные в нужном виде для пользователя.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai4"></a> Какие параметры setFormat задают жирный, цвет текста и цвет фона?

В функции `setFormat` для задания жирного шрифта, цвета текста и цвета фона используются следующие параметры:

1. **Жирный шрифт**:
   - Параметр: `bold`
   - Значение: `true` для включения жирного шрифта.

   Пример:

```totum
f1=: setFormat(bold: true)
```

2. **Цвет текста**:
   - Параметр: `color`
   - Значение: строка, представляющая цвет в формате HEX (например, `#FF6347`) или текстовое определение цвета HTML (например, `tomato`).

   Пример:

```totum
f1=: setFormat(color: "tomato")
```

3. **Цвет фона**:
   - Параметр: `background`
   - Значение: строка, представляющая цвет в формате HEX (например, `#FFD700`) или текстовое определение цвета HTML (например, `OldLace`).

   Пример:

```totum
f1=: setFormat(background: "oldLace")
```

Пример кода, который задает все три параметра одновременно:

```totum
f1=: setFormat(bold: true; color: "#FF6347"; background: "#FFD700")
```

В этом примере текст будет жирным, цвет текста будет `#FF6347` (например, томатный), а цвет фона будет `#FFD700` (например, золотистый).

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai5"></a> Как сделать значения в поле жирным с помощью setFormat?

Чтобы сделать значения в поле жирным с помощью функции `setFormat`, необходимо использовать параметр `bold` и установить его значение в `true`. Вот пример кода форматирования, который делает значения в поле жирным:

```totum
f1=: setFormat(bold: true)
```

Этот код применяется в секции форматирования поля и делает все значения в этом поле жирными.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai7"></a> Как попасть в форматирование полей?

Чтобы попасть в форматирование полей в системе Totum, вы можете воспользоваться одним из следующих способов:

1. **Через заголовок поля**:
   - Щелкните по заголовку поля, которое вы хотите отформатировать.
   - В появившемся меню выберите раздел «Формат».
   - В этом разделе вы увидите код, который начинается с `f1=:`. Это обозначает начало блока форматирования.

2. **Через настройки поля**:
   - Откройте настройки поля, которое вы хотите отформатировать.
   - Прокрутите окно настроек вниз до раздела "Условное форматирование ячейки".
   - Убедитесь, что форматирование включено, чтобы оно применялось.

В обоих случаях вы будете работать с кодом, который начинается с `f1=:`. Это обозначает, что вы находитесь в секции форматирования. В этой секции вы можете использовать функции форматирования, такие как `setFormat`, для изменения внешнего вида ячейки в зависимости от заданных условий.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai8"></a> Чем отличается код, начинающийся с f1=:, от кода с префиксом =:?

Код, начинающийся с `f1=:` (например, в секции форматирования поля), предназначен для выполнения действий по форматированию ячеек или таблицы в Totum. Он обрабатывается после всех остальных кодов и перед отдачей таблицы пользователю в браузер. В этом коде используются функции форматирования, такие как `setFormat` или `setFloatFormat`.

Код с префиксом `=:` (например, в секции кода) выполняет основные вычисления и действия в таблице. Он обрабатывается перед форматированием и может содержать любые функции и операции, доступные в Totum.

Таким образом, основное отличие заключается в том, что код с префиксом `f1=:` предназначен для форматирования и используется в секциях форматирования ячейки, строки, либо таблицы. А код с префиксом `=:` предназначен для основных вычислений и действий и применяется в секциях кода и кода действий.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai9"></a> Какие функции доступны в секции форматирования ячейки?

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai10"></a> Как применяется setFormat по условиям?

Функция `setFormat` в Totum используется для изменения внешнего вида ячейки в таблице на основе заданных условий. Она позволяет задавать различные параметры форматирования, такие как цвет текста, цвет фона, жирность шрифта и другие, в зависимости от выполнения определенных условий.

**Пример использования setFormat с условием**

Рассмотрим пример, где мы хотим выделить ячейки жирным шрифтом и изменить цвет фона, если значение в ячейке больше 10.

```totum
f1=: setFormat(condition: $#nfv > 10; bold: true; background: "oldLace")
```

В этом примере:

- `condition: $#nfv > 10` — условие, при котором будет применяться форматирование. Здесь используется быстрая переменная `$#nfv`, которая возвращает текущее значение поля. Условие проверяет, больше ли это значение 10.
- `bold: true` — делает текст в ячейке жирным.
- `background: "oldLace"` — задает цвет фона ячейки. В данном случае используется цвет с названием `oldLace`.

**Множественные условия**

Функция `setFormat` поддерживает множественные условия, которые можно задавать последовательно. Если одно из условий выполняется, то применяются соответствующие параметры форматирования.

```totum
f1=: setFormat(condition: $#nfv > 10; bold: true; background: "oldLace")
f2=: setFormat(condition: $#nfv <= 10; color: "red")
```

В этом примере:

- Если значение в ячейке больше 10, то текст будет жирным и фон будет цвета `oldLace`.
- Если значение в ячейке меньше или равно 10, то цвет текста будет красным.

**Порядок выполнения**

Форматирование выполняется после всех остальных кодов и перед отдачей таблицы пользователю в браузер. Это означает, что любые изменения, сделанные в данных, будут учтены перед применением форматирования.

**Пример с использованием других функций**

В коде форматирования можно использовать и другие функции для вычисления условий. Например, можно посчитать количество строк в таблице и использовать это значение в условии:

```totum
f1=: setFormat(condition: $#nfv > $calc; bold: true)
	calc: listCount(list: $list) * 10
		list: selectList(table: $#ntn; field: 'id')
```

Здесь `calc` вычисляет количество строк в таблице и умножает его на 10. Если значение в ячейке больше этого результата, то текст будет выделен жирным.

Таким образом, `setFormat` позволяет гибко настраивать внешний вид ячеек в зависимости от различных условий, что делает интерфейс более информативным и удобным для пользователя.

В параметре `condition` функции `setFormat` в Totum можно использовать все стандартные операторы сравнения. Вот список доступных операторов:

Эти операторы позволяют задавать условия, при выполнении которых будет применяться форматирование. Например, вы можете использовать условие, чтобы выделить ячейку цветом, если её значение больше определенного числа, или сделать текст жирным, если значение равно определенному значению.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai12"></a> Что делает параметр block в функции setFormat?

Параметр `block` в функции `setFormat` используется для блокировки или разблокировки ячейки в таблице. Если `block` установлен в `false`, ячейка остаётся разблокированной, и пользователь может вносить изменения.

Пример использования параметра `block` в функции `setFormat`:

```totum
f1=: setFormat(condition: $#nfv > 10; block: true)
```

В этом примере ячейка будет заблокирована, если значение текущего поля (`$#nfv`) больше 10.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai13"></a> Как передать цвет текста ячейки в параметре color?

Пример кода, который устанавливает цвет текста ячейки в HEX формате:

Пример кода, который устанавливает цвет текста ячейки с использованием текстового определения цвета HTML:


- `"form" = true` — скрывает поле в формах.

Таким образом, параметр `hide` позволяет гибко управлять видимостью поля в различных частях пользовательского интерфейса Totum.

```totum
	children: selectTreeChildren(table: $#ntn; id: $#nvf; parent: 'tree')
```

В этом примере:

1. Мы используем функцию `selectTreeChildren` для получения списка дочерних элементов для текущей строки, где родительское поле имеет name `tree`.
2. Если полученный список дочерних элементов равен пустому списку, то устанавливаем `expand: false`, чтобы отключить возможность разворачивания.

Таким образом, папка не будет разворачиваться, если в ней нет дочерних элементов.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai27"></a> Что делает параметр textasvalue и какие значения он принимает?

Параметр `textasvalue` используется в функции `setFormat` в Totum. Он позволяет копировать значение из параметра `text` в контекстную панель и отображать его как значение поля. Это может быть полезно, когда нужно, чтобы текст, отображаемый в ячейке, считался её значением.

**Пример использования**

```totum
f1=: setFormat(textasvalue: true)
```

В этом примере значение из параметра `text` будет скопировано и отображено в контекстной панели как значение поля.

**Возможные значения**

Параметр `textasvalue` может принимать следующие значения:

- `"num"` — указывает, что значение в `text` следует интерпретировать как числовое.
- `"str"` — указывает, что значение в `text` следует интерпретировать как строковое.
- `"num|."` или `"num|,"` — уточняет тип значений и символ разделителя десятичных для чисел.

Таким образом, `textasvalue` позволяет более гибко управлять тем, как текст в ячейке воспринимается и обрабатывается в контексте таблицы.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai28"></a> Можно ли в коде форматирования использовать другие функции помимо форматирования?

Да, в коде форматирования можно использовать другие функции, помимо функций форматирования. Однако результат работы должен быть возвращен в начальную секцию `f` через функцию форматирования. Это позволяет использовать различные вычисления и условия для определения, какое форматирование применять.

Например, можно использовать функции для вычисления условий, при которых будет применяться форматирование:

```totum
f1=: setFormat(condition: $calc > 10; background: "tomato"; color: "white")

calc: listCount(list: $list)
    list: selectList(table: $#ntn; field: 'id')
```

В этом примере используется функция `listCount` для подсчета количества строк в таблице, и если это количество больше 10, то применяется форматирование с фоном "tomato" и текстом "white".

Таким образом, в коде форматирования можно использовать любые функции, которые помогут определить условия для применения форматирования, но итоговый результат должен быть передан через функцию форматирования, такую как `setFormat`.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai29"></a> Как сделать условное выделение жирным для значений, если поле status равно 1?

Для того чтобы сделать условное выделение жирным для значений, если поле `status` равно 1, необходимо использовать функцию `setFormat` в коде форматирования. В данном случае мы будем использовать параметр `bold` для выделения текста жирным шрифтом и параметр `condition` для проверки условия.

Вот пример кода форматирования, который решает эту задачу:

```totum
f1=: setFormat(condition: #status = 1; bold: true)
```

В этом коде:

- `condition: #status = 1` — условие, при котором форматирование будет применено. Если значение в поле `status` равно 1, то условие выполняется.
- `bold: true` — параметр, который делает текст в ячейке жирным.

Таким образом, если значение в поле `status` равно 1, текст в соответствующей ячейке будет выделен жирным шрифтом.

#### <a name="highlighting-the-field-in-bold-text-color-and-background-color-ai30"></a> Как одновременно задать несколько свойств форматирования в одной функции?

В Totum вы можете задать несколько свойств форматирования в одной функции `setFormat` через указание параметров, разделенных точкой с запятой. Это позволяет одновременно изменять различные аспекты отображения ячейки, такие как цвет текста, цвет фона, жирность текста и другие.

Вот пример, как это можно сделать:

```totum
f1=: setFormat(bold: true; color: "#FF5733"; background: "#C70039")
```

В этом примере:

- `bold: true` делает текст в ячейке жирным.
- `color: "#FF5733"` устанавливает цвет текста на оранжево-красный.
- `background: "#C70039"` задает цвет фона ячейки на темно-красный.

Вы можете добавлять другие параметры, такие как `italic`, `decoration`, `progress`, и так далее, в зависимости от ваших потребностей. Все параметры должны быть указаны через точку с запятой.

### <a name="several-formatting-conditions-qa"></a> Вопросы и ответы

#### <a name="several-formatting-conditions-q1"></a> Можно ли использовать несколько condition?

Да, в `setFormat`, как и в остальных функциях умеющих `condition` — они множественне. Форматирование будет выполнено только если все `condition` выполнятся в `true`.

Если один выполнился в `false` — то последующие даже не будут рассчитываться. Поэтому ставьте легкие условия вперед, а тяжелые по рассчету назад.

#### <a name="several-formatting-conditions-q2"></a> Что будет если написать несколько последовательных условий?

Форматирование может иметь несколько последовательных блоков:

```totum

f1=: setFormat(bold: true)

f2=: setFormat(condition: $#nfv < 0; color: "tomato")

// Все делаем жирным, а те, которые меньше ноля красными

```

Блоки сортируются как строки, те `11` меньше чем `2` — этим можно пользоваться, что бы вставлять условия между имеющихся правил:

```

f0=:

f1=:

f11=:

f2=:

```

Хорошей практикой является расположение строк в том порядке в котором они будут выполнятся.

Рекомендуем первое условия начинать с `f1=:`, что бы у вас всегда оставалась возможность вставить стартовое условия `f0=:`.

#### <a name="several-formatting-conditions-q3"></a> Как отменить все предыдущие установленные значения?

В тех параметрах, в которых используется `true/false` — нужно передать противоположное значение по условиям.

Там где передаются значения надо передать пустое значение в параметр — `""`.

Например все блокируем, а нужный разблокируем:

```totum
f1=: setFormat(block: true)

f2=: setFormat(condition: #status = true; block: false)

```

Например все подсвечиваем по одному условию и снимаем подсветку по другому:

```totum
f1=: setFormat(condition: #price >= 10000; color: "tomato")

f2=: setFormat(condition: #price >= 20000; color: "")

// Выделяем красным, там где price попадает в интервал 10000 (включая) — 20000 (исключая)

```

### <a name="several-formatting-conditions-text"></a> Текст урока (по видео)

В этом видео рассказывается о нескольких условиях форматирования одновременно.
Их может быть несколько, не зависящих друг от друга. Давайте вернемся к нашему примеру кода, здесь может быть более одного условия. Например, у нас есть условие, что значение $#nfv больше, чем calc.
Можно задать еще одно условие, поскольку условие – это множественный параметр. Здесь вы можете ссылаться на другие поля, независимо от их сортировки. Неважно, вычисляется ли поле, на значение которого мы ссылаемся, раньше или позже, потому что форматирование вычисляется в самый последний момент перед отправкой на сервер, когда все поля уже вычислены. Мы можем обращаться к любому полю в таблице и к любому полю в другой таблице.
Напишем условие, что поле 2 равно B. Напомню, что в условиях сравнения, если вы сравниваете со строками, нужно ставить двойные кавычки. И если оба сравнения истинны, то только тогда выделение полужирным шрифтом – true.
В результате, первому условию у нас, к примерно удовлетворяют 30,40,50, но есть только одна строка, в которой поле 2 равно B. И только эта ячейка выделена фоном и жирным шрифтом.
```totum
f1=: setFormat(condition: $#nfv > $calc; condition: #field_2 = "B"; bold: true; background: "oldlace")
calc: listCount(list: $list) * 5
list: selectList(table: $#ntn; field: 'id')
f2=: setFormat(condition: #field_2 = "C"; background: "tomato"; color: "white")
```
Итак, мы можем использовать несколько условий в одной секции кода форматирования. Для этого необходимо задать несколько параметров condition. Это работает следующим образом: сначала вычисляется 1-е условие, если оно истинно, то вычисляется 2-е условие и так далее. В данном случае нам желательно поменять условия местами. Потому что второе условие – это просто сравнение. Оно не требует расчета. Здесь нет никаких вычислений. Если в поле 2 = B, окажется true, то будет проверено это условие, и только после этого машина перейдет к вычислениям. Упорядочивание условий в правильном порядке - хороший способ оптимизировать работу кода с нагрузкой. Помните об этом.
Хорошо, давайте сохраним это. Результат тот же самый, но он использует меньше мощности сервера. Это часто требуется, потому что форматирование выполняется в заданном поле в каждой строке. А не только в той ячейке, в которой мы видим результат выполненного форматирования.
Если первое условие выполняется в false, то дальше условия не проверяются, но если мы поставим вычисляемые условия вначале, то calc будет выполняться для каждого из этих полей. Это уже немного больше времени.
```totum
f1=: setFormat(condition: #field_2 = "B"; condition: $#nfv > $calc; bold: true; background: "oldlace")
calc: listCount(list: $list) * 5
list: selectList(table: $#ntn; field: 'id')
f2=: setFormat(condition: #field_2 = "C"; background: "tomato"; color: "white")
```

Мы можем использовать несколько условий форматирования в одном коде форматирования. Каждое из них задается отдельной секцией, начинающейся с `f1=:`. Мы также можем поставить еще одну строку и написать здесь `setFormat` с одним условием, которое устанавливает фон и цвет. Условие такое: если поле2 равно C, то фон будет tomato. Обратите внимание, что мы не ставим красный цвет, он выглядит слишком резко. Не делайте именно красный - он не очень хорошо вписывается в общую цветовую гамму – лучше поставить tomato. И если вы окрашиваете фон в темные цвета, измените цвет текста на светлый в той же функции форматирования. Мы поставим белый.
Сохраняем. Давайте посмотрим, что у нас получилось. Условие поле 2 равно C дает нам фон tomato и инвертированный цвет текста в этой ячейке. Обратите внимание, что это условие перекрывает первое. То есть, если в двух строках форматирования будет задан одинаковый параметр, например `background`, условие `background` из первой `f1=:`не выполняется, а из `f2=:`выполняется, так как секции упорядочиваются по номеру после f. 1,2,3,4,5 и так далее. Обратите внимание, что сортировка осуществляется по правилам сортировки строк. Так что если мы поставим `f11=:`, то он будет вычислен после единицы, но перед двойкой, потому что это строковое сравнение. Если вам нужно вставить что-то между уже написанными условиями форматирования, вы можете вставить это вот так. Место, где находится строка, не имеет значения - порядок задается только номером после f. Строка может стоять так: f1, f2, f11, но f11 все равно будет выполняться после f1.
Давайте попробуем так. Вставим сюда `f11=: setFormat(background = “orange”)`, то есть, установим оранжевый фон без всяких условий. Давайте посмотрим, как это выглядит. Все окрасилось в оранжевый цвет, а условие, описанное в `f2=:`– в красный. Фон ячейки, выделенной жирным шрифтом, тоже стал не “oldlace”, а “orange”. Почему? Потому что в первой секции применены жирный и фон. В следующей секции по порядку применяется только фон, который отменяет предыдущие форматирования. Но здесь в секции `f2=:` используются и цвет текста, и фон. И цвет, и фон накладываются друг на друга.
Если мы скажем, что здесь будет false, то есть уберем полужирный шрифт, то и полужирного здесь не будет. То есть у нас были строки, выделенные по условиям жирным, а теперь он стал обычным.
Как быть, если мы хотим залить не красным, а просто отменить предыдущее форматирование. Здесь фон залит оранжевым, а здесь нам не нужен фон томатного цвета. Мы просто хотим восстановить фон по умолчанию. В этом случае мы должны задать пустое значение, поставив “”. Чтобы отменить, нам нужно передать пустую строку.
По умолчанию первым блоком является f1. Это сделано для того, чтобы вы всегда могли вставить f0. Итак, `f0=:`. Часто бывает так, что вы написали все условия, а потом оказывается, что нужно вставить в начало несколько основных параметров, которые должны применяться ко всем строкам. Для этого можно использовать `f2=:`. Например, `f2=:  setFormat(background = “ whitesmoke”)`, и мы устанавливаем по умолчанию фон white-smoke, а дальше уже все идет по плану.
То есть сначала он окрашивается в бело-дымчатый, а потом в соответствии с условиями применяются другие форматы. Мы смотрим, и в итоге в бело-дымчатый не окрасилось ничего, потому что единственная ячейка, которая могла бы попасть в этот цвет, у нас по другому условию возвращается к базовому цвету условием `background = “whitesmoke”`. При этом, когда мы делаем whitesmoke секцией f0  – это не основной цвет, возврат идет не к нему. Это цвет, который задан в коде и будет применяться, если не перекрывается никакими другими условиями в последующих секциях.
Однако есть другая опция. Мы можем вообще задать базовый цвет колонки, изменить его следующим образом: в настройках поля есть такой параметр «Цвет панели». Если мы укажем whitesmoke там, то базовым цветом этого поля будет именно whitesmoke. Тогда параметр `background = “ ”`, указанный в коде форматирования этого поля, будет возвращать именно к этому цвету, заданному «Цвет панели». Также важно, что когда мы задаем цвет фона в годе, это влияет на нагрузку на сервер. А когда через параметр «Цвет панели», это на нагрузку сервера не влияет, потому что этот цвет применяется к полю на стороне клиента.
Например, в следующем поле мы устанавливаем в параметре «Цвет панели» цвет oldlace, он такой желтенький. Этот цвет будет применен базово, но имеет очень низкий приоритет и будет перекрыт всеми остальными условиями форматирования.
Следующий момент. Можно сделать форматированием блокировку поля. Например, здесь мы сделаем все поля заблокированными, а четверку - разблокированной.
```totum
f1=: setFormat(block: true)
f2=: setFormat(condition: $#nfv = "B"; block: false)
```
Есть такая особенность: когда вы набираете заглавные буквы, то при автозаполнении с  \ буквы автоматически преобразуются в строчные. При этом регистр букв имеет значение. Проверьте этот момент, потому что B заглавная, B строчная - разница есть.
Так вот, здесь у нас все заблокировано. B разблокирована, мы можем внести изменения. Если мы изменим ее на D, это поле снова станет заблокированным. Так что эта блокировка – не является жесткой. Она выполняется на стороне клиента. Это блокировка от ошибок пальцев. Если человек хочет обойти ее и знает javascript, он может это сделать. Да, в логе будет записано, что он изменил, но изменения в критических местах связаны с блокировкой на стороне сервера - об этом мы поговорим в кодах действий.

Можно ли использовать несколько condition?
Да, в setFormat, как и в остальных функциях умеющих condition — они множественне. Форматирование будет выполнено только если все condition выполнятся в true.
Если один выполнился в false — то последующие даже не будут рассчитываться. Поэтому ставьте легкие условия вперед, а тяжелые по расчету назад.

Что будет если написать несколько последовательных условий?
Форматирование может иметь несколько последовательных блоков (секций):
```totum
f1=: setFormat(bold: true)
f2=: setFormat(condition: $#nfv < 0; color: "tomato")

// Все делаем жирным, а те, которые меньше ноля красными
```
Блоки сортируются как строки, те 11 меньше чем 2 — этим можно пользоваться, что бы вставлять условия между имеющихся правил:
``` totum
f0=:
f1=:
f11=:
f2=:
```

Хорошей практикой является расположение строк в том порядке, в котором они будут выполняться.
Рекомендуем первое условия начинать с `f1=:`, что бы у вас всегда оставалась возможность вставить стартовое условия `f0=:`.

Там, где передаются значения, надо передать пустое значение в параметр — "".
Например, все блокируем, а нужный разблокируем:


### <a name="several-formatting-conditions-ai"></a> Дополнительные вопросы

#### <a name="several-formatting-conditions-ai1"></a> Какое количество условий может быть в коде форматирования?

В коде форматирования в системе Totum может быть любое количество условий. Каждое условие задается отдельной секцией, начинающейся с `f1=:`, `f2=:` и так далее. Условия выполняются последовательно, и каждое из них может содержать несколько параметров `condition`. Форматирование будет выполнено только если все `condition` в одной секции выполнятся в `true`. Если одно из условий в секции выполнится в `false`, то последующие условия в этой секции даже не будут рассчитываться.

Пример кода форматирования с несколькими условиями:

```totum
f1=: setFormat(condition: #field_1 > 10; condition: #field_2 = "A"; bold: true; background: "lightblue")

f2=: setFormat(condition: #field_3 < 5; color: "red")

f3=: setFormat(condition: #field_4 = "active"; decoration: "underline")
```

В этом примере:

- В секции `f1=:` форматирование будет применено, если `#field_1` больше 10 и `#field_2` равно "A".
- В секции `f2=:` цвет текста будет красным, если `#field_3` меньше 5.
- В секции `f3=:` текст будет подчеркнут, если `#field_4` равно "active".

Таким образом, количество условий в коде форматирования не ограничено, и вы можете использовать столько условий, сколько необходимо для достижения нужного результата.

#### <a name="several-formatting-conditions-ai2"></a> Как происходит вычисление условий в формате?

В Totum вычисление условий в формате происходит следующим образом:

1. **Вычисление условий внутри `setFormat`**:
   - Условия `condition` внутри функции `setFormat` вычисляются слева направо. Это означает, что сначала проверяется первое условие, затем второе и так далее.
   - Если одно из условий выполняется в `false`, то последующие условия не будут рассчитываться. Поэтому рекомендуется ставить легкие условия вперед, а тяжелые по расчету назад.

2. **Применение условий блоков кода `f`**:
   - Условия блоков кода `f` применяются в порядке их индекса. Индексы сравниваются как строки, что означает, что, например, `f11` будет применен раньше, чем `f2`, потому что строка `"11"` меньше, чем строка `"2"` в строковом сравнении.
   - Это позволяет вставлять условия между уже существующими правилами, если необходимо.

Пример кода форматирования:

```totum
f1=: setFormat(condition: #field_2 = "B"; condition: $#nfv > $calc; bold: true; background: "oldlace")
	calc: listCount(list: $list) * 5
		list: selectList(table: $#ntn; field: 'id')

f2=: setFormat(condition: #field_2 = "C"; background: "tomato"; color: "white")
```

В этом примере:
- В `f1=:` сначала проверяется, равно ли `#field_2` значению `"B"`, и только если это условие истинно, проверяется второе условие.
- `f2=:` будет применено после `f1=:`, так как его индекс больше.

Таким образом, порядок вычисления условий и применение блоков кода в Totum позволяет гибко управлять форматированием данных в таблице.

#### <a name="several-formatting-conditions-ai3"></a> Можно ли ссылаться на другие поля в условиях в коде форматирования, и как это влияет на вычисление?

Да, в условиях форматирования в системе Totum можно ссылаться на другие поля. Это позволяет задавать сложные условия для применения форматирования. Например, можно задать условие, что значение в текущем поле должно быть больше определенного значения, вычисленного на основе данных из другого поля.

**Пример кода форматирования:**

```totum
f1=: setFormat(condition: $#nfv > $calc; condition: #field_2 = "B"; bold: true; background: "oldlace")
	calc: listCount(list: $list) * 5
		list: selectList(table: $#ntn; field: 'id')
f2=: setFormat(condition: #field_2 = "C"; background: "tomato"; color: "white")
```

**Пояснение:**

1. **Условие 1**: Если значение вычисленное в строке `calc` больше чем значение в текущем поле, и значение в `field_2` равно `"B"` то ячейка будет выделена жирным шрифтом и окрашена в цвет "oldlace".

2. **Условие 2**: Если значение в поле `#field_2` равно "C", то ячейка будет окрашена в цвет "tomato" и текст будет белым.

**Влияние на вычисление:**

- Условия форматирования вычисляются в самый последний момент перед отправкой данных в браузер, когда все поля уже вычислены.
- Это означает, что можно ссылаться на любое поле в таблице, независимо от их сортировки, и быть уверенным, что значение будет корректно вычислено.
- Если первое условие выполняется в `false`, то дальше условия не проверяются, но если мы поставим вычисляемые условия вначале, то `calc` будет выполняться для каждого из этих полей. Это уже немного больше времени.

**Оптимизация:**

- Для оптимизации работы кода с нагрузкой рекомендуется упорядочивать условия в правильном порядке. Например, сначала проверять простые условия, которые не требуют вычислений, а затем более сложные условия.

Пример оптимизированного кода:

```totum
f1=: setFormat(condition: #field_2 = "B"; condition: $#nfv > $calc; bold: true; background: "oldlace")
	calc: listCount(list: $list) * 5
		list: selectList(table: $#ntn; field: 'id')
f2=: setFormat(condition: #field_2 = "C"; background: "tomato"; color: "white")
```

**Результат:**

- В результате, если значение в поле `#field_2` равно "B" и значение в текущем поле больше, чем значение, вычисленное в строке `calc`, то ячейка будет выделена жирным шрифтом и окрашена в цвет "oldlace".
- Если значение в поле `#field_2` равно "C", то ячейка будет окрашена в цвет "tomato" и текст будет белым.

Таким образом, использование ссылок на другие поля в условиях форматирования позволяет создавать более гибкие и сложные правила для отображения данных в таблице.

#### <a name="several-formatting-conditions-ai4"></a> Почему важно порядок условий в коде форматирования?

В системе Totum порядок условий в коде форматирования важен по нескольким причинам:

1. **Оптимизация производительности**: Условия в коде форматирования выполняются последовательно. Если первое условие выполняется в `false`, то последующие условия не проверяются. Это означает, что если вы поставите вычисляемые условия вначале, то они будут выполняться для каждого из этих полей, что может увеличить нагрузку на сервер. Поэтому рекомендуется ставить легкие условия вперед, а тяжелые по расчету назад, чтобы оптимизировать работу кода.

2. **Приоритет выполнения**: Порядок выполнения условий влияет на то, какие форматирования будут применены. Если несколько условий (например f1 и f2) могут быть истинными для одного и того же поля, то будет применено форматирование из последнего, которое выполнится в `true`.

3. **Логическая последовательность**: Порядок условий внутри функции setformat может отражать логическую последовательность проверки. Например, сначала можно проверить простые условия, такие как равенство или неравенство, а затем более сложные условия, которые требуют дополнительных вычислений.

4. **Управление видимостью и доступом**: Порядок условий по вертикали (f1, f2 итд) может быть использован для управления видимостью и доступом к данным. Например, сначала можно проверить условия, которые блокируют доступ к данным, а затем условия, которые изменяют их видимость или форматирование.

Пример кода форматирования с учетом порядка условий:

```totum
f0=: setFormat(block: true)

f1=: setFormat(condition: #field = true; condition: $#nfv > 10; block: false; bold: true)
```

Этот код в системе Totum задает форматирование ячейки, делая ее заблокированной по умолчанию и разблокируя ее, если выполняются два условия: значение в поле #field равно true и значение в текущей ячейке больше 10. Также при выполнении этих условий текст в ячейке становится жирным.

#### <a name="several-formatting-conditions-ai5"></a> Что происходит, если первое условие в condition выполняется в false?

Если первое условие в `condition` выполняется в `false`, то последующие условия в этой же функции `setFormat` или другой функции, поддерживающей множественные условия, не проверяются и не рассчитываются. Это означает, что если первое условие не выполняется, то функция завершает свою работу без выполнения дальнейших условий и действий, которые могли бы быть связаны с ними.

**Пример**

Рассмотрим пример кода форматирования в Totum:

```totum
f1=: setFormat(condition: #field_1 > 10; condition: #field_2 = "A"; bold: true; background: "lightblue")
```

В этом примере:

- Первое условие: `#field_1 > 10`
- Второе условие: `#field_2 = "A"`

Если первое условие `#field_1 > 10` выполняется в `false`, то второе условие `#field_2 = "A"` даже не будет проверяться. В результате, форматирование (жирный шрифт и светло-голубой фон) не будет применено, так как первое условие не выполнено.

**Оптимизация**

Это поведение позволяет оптимизировать выполнение кода, так как не требуется выполнять лишние вычисления, если уже известно, что итоговое действие не будет выполнено. Поэтому рекомендуется ставить более простые и легкие условия впереди, чтобы минимизировать нагрузку на сервер и ускорить выполнение кода.

#### <a name="several-formatting-conditions-ai6"></a> Как отменить предыдущее форматирование в последовательности условий в кодах форматирования?

В системе Totum, чтобы отменить предыдущее форматирование в последовательности условий в кодах форматирования, необходимо передать пустое значение в параметр, который вы хотите сбросить, или противоположное значение для параметров, использующих `true/false`.

**Пример отмены форматирования**

Допустим, у вас есть несколько условий форматирования, и вы хотите отменить предыдущее форматирование для определенных ячеек. Рассмотрим пример, где мы сначала выделяем ячейки красным цветом, если значение больше или равно 10000, а затем отменяем это выделение, если значение больше или равно 20000.

```totum
f1=: setFormat(condition: #price >= 10000; color: "tomato")

f2=: setFormat(condition: #price >= 20000; color: "")
```

**Объяснение**

1. **Первое условие (`f1=:`)**: Если значение в поле `#price` больше или равно 10000, ячейка будет выделена красным цветом (`color: "tomato"`).

2. **Второе условие (`f2=:`)**: Если значение в поле `#price` больше или равно 20000, цвет ячейки будет сброшен к значению по умолчанию, так как мы передаем пустую строку в параметр `color` (`color: ""`).

**Пример отмены других параметров**

Если вы хотите отменить, например, жирное выделение, вы можете сделать это, передав `bold: false`:

```totum
f1=: setFormat(bold: true)

f2=: setFormat(condition: #status = true; bold: false)
```

**Заключение**

Таким образом, для отмены предыдущего форматирования в Totum вы можете использовать пустые значения для параметров, которые принимают строки, и противоположные значения для параметров, которые принимают `true/false`. Это позволяет гибко управлять форматированием и изменять его в зависимости от условий.

#### <a name="several-formatting-conditions-ai7"></a> Как задать базовый цвет для колонки?

В системе Totum вы можете задать базовый цвет для колонки, используя параметр "Цвет панели" в настройках поля. Этот параметр позволяет установить цвет, который будет использоваться по умолчанию для фона ячеек в данной колонке. Вот как это можно сделать:

**Шаги для установки базового цвета колонки:**

1. **Откройте настройки таблицы**: Перейдите в нужную таблицу.

2. **Выберите нужное поле**: Найдите поле, для которого вы хотите установить базовый цвет. Откройте его настройки.

3. **Установите цвет панели**: В настройках поля найдите параметр "Цвет панели". Укажите желаемый цвет, например, `oldlace`, `whitesmoke` или любой другой цвет, поддерживаемый CSS.

4. **Сохраните изменения**: После установки цвета панели сохраните изменения в настройках поля.

**Пример использования:**

Если вы хотите установить цвет `oldlace` для колонки, вы можете указать это значение в параметре "Цвет панели". Это сделает фон ячеек в этой колонке `oldlace` по умолчанию.

**Важные моменты:**

- **Приоритет цвета**: Базовый цвет, установленный через параметр "Цвет панели", имеет самый низкий приоритет и может быть перекрыт настройками цвета фона, передаваемыми через коды форматирования.
- **Нагрузка на сервер**: Установка базового цвета через "Цвет панели" не нагружает сервер, так как этот цвет применяется на стороне клиента.

Таким образом, использование параметра "Цвет панели" позволяет легко и эффективно управлять базовым цветом колонок в системе Totum.

#### <a name="several-formatting-conditions-ai8"></a> Какое влияние на нагрузку сервера имеет форматирование фона?

Форматирование фона в системе Totum может оказывать влияние на нагрузку сервера, особенно если оно выполняется через код. Давайте рассмотрим, как это происходит и какие есть способы оптимизации.

**Влияние на нагрузку сервера**

1. **Форматирование через код**: Когда фон ячеек таблицы задается через код форматирования, это требует дополнительных вычислений на стороне сервера. Каждое условие форматирования должно быть проверено, и в зависимости от его выполнения, сервер должен определить, какой цвет фона применить к каждой ячейке. Это может увеличить нагрузку на сервер, особенно если таблица содержит большое количество строк и столбцов, и если условия форматирования сложные или многочисленные.

2. **Частота пересчета**: Форматирование выполняется каждый раз при пересчете таблицы, когда она открыта у пользователя в активной вкладке. Если таблица пересчитывается часто, это может дополнительно увеличить нагрузку на сервер.

**Способы оптимизации**

1. **Использование параметра "Цвет панели"**: Если возможно, задавайте цвет фона через параметр "Цвет панели" в настройках поля. Это позволяет применять цвет на стороне клиента, что не увеличивает нагрузку на сервер. Цвет панели применяется непосредственно в браузере пользователя и не требует дополнительных вычислений на сервере.

2. **Оптимизация условий форматирования**: Старайтесь упрощать условия форматирования. Например, используйте более простые условия или объединяйте их, чтобы уменьшить количество проверок, которые должен выполнить сервер.

3. **Порядок условий**: Расположите условия в порядке их вычислительной сложности. Легкие условия, которые требуют меньше вычислений, должны быть проверены первыми. Это позволит избежать выполнения более сложных условий, если легкие условия уже вернули `false`.

4. **Ограничение количества форматируемых ячеек**: Если возможно, ограничьте количество ячеек, к которым применяется форматирование. Например, применяйте форматирование только к поля, которые действительно в этом нуждаются.

**Заключение**

Форматирование фона через код может увеличить нагрузку на сервер, но с помощью оптимизации условий и использования параметра "Цвет панели" можно минимизировать это влияние. Важно учитывать эти аспекты при разработке таблиц в Totum, чтобы обеспечить эффективную работу системы.

#### <a name="several-formatting-conditions-ai9"></a> Можно ли заблокировать и разблокировать поле через условия форматирования?

Да, в системе Totum можно заблокировать и разблокировать поле через условия форматирования, используя функцию `setFormat` с параметром `block`. Это позволяет управлять доступностью поля для редактирования в зависимости от заданных условий.

**Пример кода форматирования для блокировки и разблокировки поля:**

```totum
f1=: setFormat(block: true)

f2=: setFormat(condition: #status = "active"; block: false)
```

**Объяснение:**

1. **Блокировка всех полей**:
   - В первой строке `f1=:` используется функция `setFormat` с параметром `block: true`, что блокирует поле во всех строках, делая его недоступным для редактирования.

2. **Разблокировка по условию**:
   - Во второй строке `f2=:` используется функция `setFormat` с параметром `condition: #status = "active"; block: false`. Это условие проверяет, равно ли значение поля `status` строке `"active"`. Если условие выполняется, поле будет разблокировано и доступно для редактирования.

**Важные моменты:**

- **Порядок выполнения**: Условия форматирования выполняются в порядке их определения. Если первое условие блокирует поле, а второе разблокирует его при выполнении определенного условия, то поле будет разблокировано только в случае выполнения этого условия.

- **Слабая блокировка**: Блокировка через форматирование является слабой, так как она осуществляется на стороне клиента (в браузере). Это означает, что опытный пользователь может обойти такую блокировку, если захочет. Для более надежной блокировки следует использовать коды действий с функцией `errorException`.

Таким образом, с помощью условий форматирования в Totum можно гибко управлять доступностью полей для редактирования, задавая условия для их блокировки и разблокировки.

#### <a name="several-formatting-conditions-ai10"></a> Как работает блокировка поля на стороне клиента?

Блокировка поля на стороне клиента в системе Totum осуществляется с помощью функции `setFormat` в секции форматирования ячейки. Это позволяет заблокировать поле от редактирования, но не от чтения. Блокировка выполняется на стороне клиента и предназначена для защиты от случайных изменений. Если пользователь захочет, он сможет снять эту блокировку через инструменты разработчика браузера. Для жесткой блокировки используются коды действия.

**Пример использования `setFormat` для блокировки поля:**

```totum
f1=: setFormat(block: true)
```

В этом примере поле будет заблокировано для редактирования во всех строках. Если необходимо разблокировать определенные поля при выполнении определенного условия, можно использовать параметр `condition`:

```totum
f1=: setFormat(block: true)

f2=: setFormat(condition: #status = true; block: false)
```

В этом примере поле будет заблокировано во всех строках, кроме тех, где поле `status` равно `true`.

**Особенности блокировки на стороне клиента:**

1. **Слабая блокировка**: Блокировка на стороне клиента является слабой, так как она выполняется в браузере пользователя. Это означает, что опытный пользователь может обойти эту блокировку, используя инструменты разработчика.

2. **Защита от случайных изменений**: Основная цель блокировки на стороне клиента — защита от случайных изменений, которые могут произойти по ошибке.

3. **Жесткая блокировка**: Для более надежной защиты от изменений используются коды действия, которые выполняются на стороне сервера и могут предотвратить изменения данных независимо от действий пользователя в браузере.

Таким образом, блокировка поля на стороне клиента в Totum предоставляет базовую защиту от случайных изменений, но для критически важных данных рекомендуется использовать более надежные механизмы блокировки на стороне сервера.

#### <a name="several-formatting-conditions-ai11"></a> Можно ли использовать несколько condition в одном коде форматирования?

Да, в Totum можно использовать несколько `condition` в одном коде форматирования. Форматирование будет выполнено только если все `condition` выполнятся в `true`. Если хотя бы одно из условий выполнится в `false`, то последующие даже не будут рассчитываться. Это позволяет оптимизировать работу кода, ставя легкие условия вперед, а более тяжелые по расчету назад.

**Пример использования нескольких `condition` в коде форматирования:**

```totum
f1=: setFormat(condition: $#nfv > $calc; condition: #field_2 = "B"; bold: true; background: "oldlace")

calc: listCount(list: $list) * 5
list: selectList(table: $#ntn; field: 'id')
```

В этом примере форматирование будет применено только если оба условия выполнятся: значение текущего поля (`$#nfv`) больше, чем результат вычисления `$calc`, и значение в поле `#field_2` равно "B". Если оба условия истинны, то текст будет выделен жирным шрифтом и фон будет установлен в цвет "oldlace".

**Оптимизация порядка условий**

Важно помнить, что условия проверяются последовательно, и если первое условие выполнится в `false`, то последующие не будут проверяться. Поэтому рекомендуется ставить легкие условия, которые не требуют сложных вычислений, впереди, а более сложные условия — позади.

**Пример оптимизации порядка условий:**

```totum
f1=: setFormat(condition: #field_2 = "B"; condition: $#nfv > $calc; bold: true; background: "oldlace")

calc: listCount(list: $list) * 5
list: selectList(table: $#ntn; field: 'id')
```

В этом примере сначала проверяется простое условие `#field_2 = "B"`, и только если оно истинно, выполняется более сложное вычисление `$calc`.

Таким образом, использование нескольких `condition` в одном коде форматирования позволяет гибко управлять условиями применения форматирования и оптимизировать производительность кода.

#### <a name="several-formatting-conditions-ai12"></a> Что будет, если написать несколько последовательных блоков в форматировании?

В системе Totum, если вы напишете несколько последовательных блоков в форматировании, каждый из них будет выполняться в порядке их нумерации. Блоки форматирования в Totum начинаются с префикса `f` и нумеруются, например, `f1=:`, `f2=:`, и так далее. Порядок выполнения блоков определяется строчной сортировкой, то есть `f11` будет выполнен после `f1`, но перед `f2`, так как это строковое сравнение.

**Пример использования нескольких блоков форматирования:**

```totum
f1=: setFormat(bold: true)

f2=: setFormat(condition: $#nfv < 0; color: "tomato")

f11=: setFormat(background: "whitesmoke")

f3=: setFormat(condition: #status = "active"; color: "green")
```

**Как это работает:**

1. **Порядок выполнения**:
   - `f1` будет выполнен первым, и поле во всех строках будет сделано жирным.
   - `f11` будет выполнен вторым, и поле во всех строках будет иметь фон "whitesmoke".
   - `f2` будет выполнен третьим, и поле, в строках значение в которых которых меньше 0, будет окрашено в "tomato".
   - `f3` будет выполнен последним, и поле в строках со статусом "active" будет окрашено в "green".

2. **Перекрытие параметров**:
   - Если в нескольких блоках указаны одинаковые параметры, например, `color`, то будет применено значение из последнего по порядку блока. Например, если `f2` и `f3` оба изменяют цвет текста, то цвет из `f3` будет применен, если условие в `f3` выполнено.

3. **Отмена форматирования**:
   - Чтобы отменить форматирование, установленное в предыдущих блоках, можно передать пустое значение. Например, чтобы отменить цвет, можно использовать `color: ""`.

**Практическое применение:**

Использование нескольких блоков форматирования позволяет гибко настраивать внешний вид таблицы в зависимости от различных условий. Это может быть полезно для визуального выделения важных данных или для улучшения читаемости таблицы.

Таким образом, последовательные блоки форматирования в Totum позволяют создавать сложные правила отображения данных, которые применяются в зависимости от условий и порядка выполнения блоков.

В системе Totum сортировка блоков условий в кодах форматирования происходит по строчной сортировке. Это означает, что блоки форматирования, начинающиеся с префикса `f` и нумерующиеся, например, `f1=:`, `f2=:`, и так далее, выполняются в порядке их нумерации. **Пример использования нескольких блоков форматирования:**

```totum

f2=: setFormat(condition: $#nfv < 0; color: "tomato")
```

   - `f11` будет выполнен вторым, и поле во всех строках будет иметь фон "whitesmoke".

3. **Отмена форматирования**:
   - Чтобы отменить форматирование, установленное в предыдущих блоках, можно передать пустое значение. Например, чтобы отменить цвет, можно использовать `color: ""`.

**Практическое применение:**

Использование нескольких блоков форматирования позволяет гибко настраивать внешний вид таблицы в зависимости от различных условий. Это может быть полезно для визуального выделения важных данных или для улучшения читаемости таблицы.

Таким образом, последовательные блоки форматирования в Totum позволяют создавать сложные правила отображения данных, которые применяются в зависимости от условий и порядка выполнения блоков.

#### <a name="several-formatting-conditions-ai14"></a> Как отменить ранее установленные значения в условиях форматирования?

В системе Totum, чтобы отменить ранее установленные значения в условиях форматирования, необходимо передать пустое значение в параметр, который вы хотите сбросить, или противоположное значение для параметров, использующих `true/false`.

**Пример отмены форматирования**

Допустим, у вас есть несколько условий форматирования, и вы хотите отменить предыдущее форматирование для определенных ячеек. Рассмотрим пример, где мы сначала выделяем ячейки красным цветом, если значение больше или равно 10000, а затем отменяем это выделение, если значение больше или равно 20000.

```totum
f1=: setFormat(condition: #price >= 10000; color: "tomato")

f2=: setFormat(condition: #price >= 20000; color: "")
```

**Объяснение**

1. **Первое условие (`f1=:`)**: Если значение в поле `#price` больше или равно 10000, ячейка будет выделена красным цветом (`color: "tomato"`).

2. **Второе условие (`f2=:`)**: Если значение в поле `#price` больше или равно 20000, цвет ячейки будет сброшен к значению по умолчанию, так как мы передаем пустую строку в параметр `color` (`color: ""`).

**Пример отмены других параметров**

Если вы хотите отменить, например, жирное выделение, вы можете сделать это, передав `bold: false`:

```totum
f1=: setFormat(bold: true)

f2=: setFormat(condition: #status = true; bold: false)
```

**Заключение**

Таким образом, для отмены предыдущего форматирования в Totum вы можете использовать пустые значения для параметров, которые принимают строки, и противоположные значения для параметров, которые принимают `true/false`. Это позволяет гибко управлять форматированием и изменять его в зависимости от условий.

#### <a name="several-formatting-conditions-ai15"></a> Можно ли вставлять блоки условий между существующими правилами форматирования?

Да, в системе Totum можно вставлять блоки условий между существующими правилами форматирования. Это достигается за счет использования нумерации секций форматирования, которая сортируется как строки. Таким образом, вы можете вставить новое условие между уже существующими, используя соответствующую нумерацию.

**Пример**

Предположим, у вас есть два правила форматирования:

```totum
f1=: setFormat(bold: true)

f2=: setFormat(condition: $#nfv < 0; color: "tomato")
```

Если вы хотите вставить новое условие между `f1` и `f2`, вы можете использовать нумерацию, например, `f11`:

```totum
f1=: setFormat(bold: true)

f11=: setFormat(condition: #status = "active"; background: "lightgreen")

f2=: setFormat(condition: $#nfv < 0; color: "tomato")
```

**Объяснение**

- **Нумерация блоков**: Блоки (правила) форматирования нумеруются как строки, поэтому `f11` будет выполнено после `f1` и перед `f2`.
- **Гибкость**: Это позволяет вам добавлять новые условия в любое место в последовательности выполнения, не нарушая существующую логику.
- **Порядок выполнения**: Убедитесь, что порядок выполнения соответствует вашим требованиям, так как более поздние условия могут переопределять параметры, установленные в более ранних условиях.

**Рекомендации**

- **Начинайте с `f1`**: Рекомендуется начинать первое условие с `f1=:`. Это оставляет возможность вставить стартовое условие `f0=:` в будущем, если потребуется.
- **Пустые значения**: Для отмены предыдущих установленных значений используйте пустые строки, например, `color: ""`.

Таким образом, система Totum предоставляет гибкость в управлении условиями форматирования, позволяя легко добавлять и изменять правила в зависимости от ваших потребностей.

#### <a name="locking-and-highlighting-the-whole-string-by-conditions-ai4"></a> Что такое параметр condition в функции setRowFormat?

Параметр **condition** в функции **setRowFormat** в Totum используется для задания условий, при которых будет применяться форматирование к строкам таблицы. Этот параметр является множественным, что означает, что его можно использовать несколько раз в одной функции для создания сложных условий.

**Особенности параметра condition:**

- **Условие срабатывания**: Параметр condition задает условие в формате "значение 1" = "значение 2". Это условие определяет, когда будет применяться заданное форматирование к строке.

- **Множественный параметр**: Параметр condition может быть использован несколько раз в одной функции, что позволяет создавать сложные условия. Все условия проверяются последовательно.

- **Последовательное выполнение**: Если одно из условий condition выполняется в false, то последующие условия не будут рассчитаны, и параметры форматирования не будут применены.

- **Типы данных**: Обе части условия могут быть числом, строкой, датой или булевым значением. Это позволяет гибко настраивать условия форматирования.

- **Сравнение списков**: Обе части условия могут быть как одним значением, так и списком. В зависимости от этого могут получаться различные комбинации сравнений: один к одному, один ко многим, многие ко многим.

- **Операторы сравнения**: Возможны все операторы сравнения, такие как =, !=, >, < и другие.

**Пример использования:**

```totum

```

#### <a name="locking-and-highlighting-the-whole-string-by-conditions-ai5"></a> Для чего используется параметр block в setRowFormat?

**Пример использования:**


**Особенности:**

#### <a name="locking-and-highlighting-the-whole-string-by-conditions-ai10"></a> Какие отличия между setRowFormat и setFormat?

В системе Totum функции `setRowFormat` и `setFormat` используются для форматирования, но они применяются к разным элементам таблицы и имеют свои особенности. Давайте рассмотрим их отличия:

**setRowFormat**

- **Применение**: Используется для форматирования строк в таблице.
- **Параметры**:
  - **condition**: Условие, при котором применяется форматирование.
  - **block**: Блокировка изменений в строке, включая удаление, перемещение и дублирование.
  - **blockdelete**: Запрещает удалять строку.
  - **blockorder**: Запрещает сортировать строку по `n`.
  - **blockduplicate**: Запрещает дублировать строку.
  - **color, bold, background, decoration, italic**: Параметры для изменения внешнего вида строки (цвет текста, жирность, цвет фона, подчеркивание, курсив).
  - **rowcomment**: Комментарий в кнопках управления строкой, поддерживает HTML.
- **Особенности**: Форматирование строки может перекрывать форматирование таблицы, если они применяются одновременно.

**setFormat**

- **Применение**: Используется для форматирования отдельных полей в таблице.
- **Параметры**:
  - **condition**: Условие, при котором применяется форматирование.
  - **block**: Блокировка изменений в поле.
  - **color, bold, background, decoration, italic**: Параметры для изменения внешнего вида поля (цвет текста, жирность, цвет фона, подчеркивание, курсив).
  - **text**: Изменение текста, отображаемого в поле.
  - **comment**: Комментарий, отображаемый при наведении на поле.
- **Особенности**: Форматирование поля имеет наивысший приоритет и может перекрывать форматирование строки.

**Основные отличия**

1. **Область применения**: `setRowFormat` применяется к строкам и в коде форматирования строк, а `setFormat` — к отдельным полям в кодах форматирования полей.
2. **Блокировка действий**: `setRowFormat` имеет дополнительные параметры для блокировки действий над строкой (удаление, дублирование, сортировка), которые отсутствуют в `setFormat`.
3. **Приоритет**: Форматирование поля (`setFormat`) имеет более высокий приоритет и может перекрывать форматирование строки (`setRowFormat`).

Таким образом, `setRowFormat` и `setFormat` используются для различных целей и имеют свои уникальные параметры и особенности, которые позволяют гибко настраивать внешний вид и поведение таблиц в Totum.

#### <a name="locking-and-highlighting-the-whole-string-by-conditions-ai11"></a> Какие ограничения существуют у блокировок, установленных через setRowFormat?

Блокировки, установленные через `setRowFormat` в системе Totum, имеют ряд ограничений, которые важно учитывать при их использовании. Вот основные из них:

1. **Слабая блокировка**: Блокировки, установленные через `setRowFormat`, являются слабыми, так как они осуществляются на стороне клиента (браузера). Это означает, что они могут быть обойдены пользователем с достаточными техническими навыками, например, через инструменты разработчика в браузере.

2. **Не защищают от взлома**: Поскольку блокировки выполняются на стороне клиента, они не обеспечивают защиту от взлома. Их основная цель — предотвратить случайные ошибки пользователей, такие как случайное удаление или изменение данных.

3. **Не влияют на серверные операции**: Блокировки, установленные через `setRowFormat`, не влияют на серверные операции и не могут предотвратить выполнение действий, инициированных через серверные скрипты или API.

4. **Не заменяют серверные проверки**: Для критически важных операций, таких как управление финансами или движением товаров, рекомендуется использовать серверные проверки и коды действий, которые выполняются на стороне сервера и обеспечивают более надежную защиту.

5. **Зависимость от условий**: Блокировки через `setRowFormat` зависят от условий, заданных в коде. Если условия изменяются или не выполняются, блокировки могут не сработать.

Для более надежной защиты данных и предотвращения несанкционированных действий рекомендуется использовать коды действий и серверные проверки, которые выполняются на стороне сервера и обеспечивают более высокий уровень безопасности.

#### <a name="locking-and-highlighting-the-whole-string-by-conditions-ai12"></a> Что будет, если задать blockdelete = true для всех строк и blockdelete = false для конкретной строки?

Если в системе Totum задать `blockdelete = true` для всех строк и `blockdelete = false` для конкретной строки, то результат будет следующим:

1. **Общая блокировка удаления**: Все строки в таблице будут заблокированы для удаления из-за условия `blockdelete: true`, которое применяется ко всем строкам.

2. **Исключение для конкретной строки**: Для конкретной строки, для которой задано `blockdelete: false`, блокировка удаления будет снята. Это означает, что эту строку можно будет удалить, несмотря на общую блокировку для всех остальных строк.

Таким образом, в результате выполнения этих условий, все строки будут заблокированы для удаления, за исключением той конкретной строки, для которой блокировка удаления была отключена. Это позволяет гибко управлять доступом к удалению строк в таблице, устанавливая общие правила и исключения для отдельных строк.

Пример кода форматирования строк с использованием `setRowFormat`:

```totum
f0=: setRowFormat(blockdelete: true)

f1=: setRowFormat(condition: #id = 3; blockdelete: false)
```

### <a name="blocking-values-in-the-field-by-conditions-ai"></a> Дополнительные вопросы

#### <a name="blocking-values-in-the-field-by-conditions-ai1"></a> Что означает параметр block в коде форматирования?

Параметр `block` в коде форматирования в системе Totum используется для блокировки изменения значения в поле. Если значение параметра `block` установлено в `true`, то поле будет заблокировано для редактирования. Это означает, что пользователь не сможет изменить значение в этом поле через интерфейс. Если значение параметра `block` установлено в `false`, то поле будет разблокировано и доступно для редактирования.

**Пример использования параметра `block` в коде форматирования поля:**

```totum
f1=: setFormat(condition: #status = 3; block: true)
```

В этом примере поле будет заблокировано для редактирования, если значение в поле `status` равно 3.

**Особенности:**

- **Блокировка на клиенте**: Блокировка через параметр `block` осуществляется на стороне клиента. Это означает, что если пользователь знает JavaScript, он может обойти эту блокировку и изменить значение поля. Поэтому такие блокировки считаются нежесткими и используются в основном для предотвращения случайных изменений.

- **Разблокировка поля**: Если строка заблокирована через код форматирования строки, то можно разблокировать конкретное поле, указав в его коде форматирования `block: false`.

- **Блокировка при добавлении**: Поле можно заблокировать только при добавлении, используя условие, что `id` строки равно пустой строке:

```totum
f1=: setFormat(condition: #id = ""; block: true)
```

- **Блокировка для роли или пользователя**: Можно заблокировать поле для определенной роли или пользователя, используя быстрые переменные `$#nr` (список ролей пользователя) и `$#nu` (id пользователя):

```totum
f1=: setFormat(condition: $#nr = 2; block: true)
```

В этом примере поле будет заблокировано для всех пользователей, у которых активна роль с id 2.

Таким образом, параметр `block` в коде форматирования позволяет гибко управлять доступностью полей для редактирования в зависимости от различных условий.

#### <a name="blocking-values-in-the-field-by-conditions-ai2"></a> Где выполняется блокировка при использовании параметра block кода форматирования?

Блокировка при использовании параметра `block` кода форматирования выполняется на стороне клиента. Это означает, что блокировка осуществляется в браузере пользователя, и если человек знает JavaScript, он может обойти эту блокировку. Таким образом, блокировки через форматирование являются нежесткими и служат в основном для защиты от ошибок пользователя, а не от преднамеренного взлома. Для более жесткой блокировки, которая выполняется на стороне сервера, необходимо использовать другие механизмы, такие как коды действий с функцией `errorException`.

#### <a name="blocking-values-in-the-field-by-conditions-ai3"></a> Можно ли обойти блокировку форматирования на стороне клиента?

Да, блокировка форматирования на стороне клиента в системе Totum может быть обойдена, если пользователь обладает знаниями в области JavaScript. Блокировки, реализованные через форматирование, являются нежесткими, поскольку они выполняются на стороне клиента (в браузере). Это означает, что если пользователь знает, как работать с JavaScript, он может изменить или отправить данные в обход этих блокировок.

Блокировки форматированием в Totum предназначены в первую очередь для предотвращения случайных ошибок пользователей, таких как случайное изменение данных. Они не обеспечивают защиту от преднамеренного взлома или обхода. Для более надежной защиты данных рекомендуется использовать жесткие блокировки на стороне сервера, которые будут рассмотрены позже.

Пример кода, который блокирует изменение поля через форматирование:

```totum
f1=: setFormat(block: true)
```

Этот код блокирует изменение поля, но, как упоминалось ранее, это блокировка на стороне клиента и может быть обойдена.

Для более надежной защиты данных следует использовать серверные механизмы, такие как коды действий с функцией `errorException`, которые могут предотвратить нежелательные изменения данных на уровне сервера.

#### <a name="blocking-values-in-the-field-by-conditions-ai4"></a> Для каких случаев подходит блокировка через форматирование?

Блокировка через форматирование в системе Totum подходит для защиты от случайных изменений данных в полях таблицы. Она используется для предотвращения ошибок при вводе данных, но не является жесткой защитой от преднамеренного взлома. Рассмотрим подробнее, в каких случаях такая блокировка может быть полезна:

1. **Защита от ошибок пользователей**: Блокировка через форматирование помогает предотвратить случайные изменения данных пользователями, которые могут быть вызваны ошибками при вводе или неосторожными действиями.

2. **Управление доступом на уровне интерфейса**: Форматирование позволяет управлять доступом к полям на уровне пользовательского интерфейса, делая их недоступными для редактирования в определенных условиях, например, в зависимости от роли пользователя или статуса записи.

3. **Упрощение интерфейса**: Блокировка полей через форматирование может использоваться для упрощения интерфейса, скрывая или делая недоступными для редактирования поля, которые не должны изменяться в текущем контексте.

4. **Контроль за процессами**: В некоторых случаях блокировка через форматирование может использоваться для контроля за процессами, например, блокируя поля после достижения определенного этапа в рабочем процессе.

5. **Временная блокировка**: Форматирование может быть использовано для временной блокировки полей, например, до выполнения определенных условий или действий.

#### <a name="blocking-values-in-the-field-by-conditions-ai5"></a> Как заблокировать изменение значения в поле только в строке добавления?

Чтобы заблокировать изменение значения в поле только в строке добавления в системе Totum, необходимо использовать код форматирования с условием, которое проверяет, является ли строка строкой добавления. В строке добавления поле `id` пустое, поэтому условие будет проверять, что `id` равно пустой строке. Вот пример кода форматирования, который блокирует изменение значения в поле только в строке добавления:

```totum
f1=: setFormat(condition: #id = ""; block: true)
```

В этом коде:

- `setFormat` — функция, которая используется для установки форматирования поля.
- `condition: #id = ""` — условие, которое проверяет, что `id` строки равно пустой строке, что соответствует строке добавления.
- `block: true` — параметр, который блокирует изменение значения в поле, если условие выполняется.

Таким образом, поле будет заблокировано для изменения только в строке добавления, а в остальных строках таблицы оно останется доступным для редактирования.

#### <a name="blocking-values-in-the-field-by-conditions-ai6"></a> Как разблокировать поле в конкретной строке при общей блокировке поля?

В системе Totum, если у вас заблокировано поле в конкретной строке через код форматирования строки, вы можете разблокировать это поле, используя код форматирования поля. Форматирование полей имеет приоритет над форматированием строк, поэтому, если в коде форматирования поля указано `block: false`, то поле будет разблокировано, даже если строка заблокирована.

**Пример кода**

Предположим, у вас есть таблица, в которой все поля в строках заблокированы через код форматирования строки. Вы хотите разблокировать конкретное поле в определенной строке. Для этого вы можете использовать следующий код:

1. **Код форматирования строки**: Блокирует все поля в строке.

```totum
f1=: setRowFormat(condition: #id = 2; block: true)
```

В этом примере строка с `id = 2` будет заблокирована.

2. **Код форматирования поля**: Разблокирует конкретное поле в строке.

```totum
f2=: setFormat(condition: #id = 2; block: false)
```

В этом примере поле будет разблокировано в строке с `id = 2`, несмотря на общую блокировку строки.

**Объяснение**

- **setRowFormat**: Используется для блокировки всех полей в строке. В данном случае, строка с `id = 2` будет заблокирована.
- **setFormat**: Используется для разблокировки конкретного поля. Указание `block: false` для поля в строке с `id = 2` разблокирует это поле, несмотря на общую блокировку строки.

Таким образом, вы можете управлять доступностью полей в строках, используя коды форматирования строк и полей в системе Totum.

#### <a name="blocking-values-in-the-field-by-conditions-ai7"></a> Что такое переменная $#nr и как она используется в коде?

Переменная `$#nr` в системе Totum — это быстрая переменная, которая возвращает список из номеров ролей пользователя, текущая роль активна у пользователя, осуществляющего изменения. Она используется для определения ролей пользователя в условиях форматирования, кодах действий и других местах, где необходимо учитывать роль пользователя.

**Пример использования переменной `$#nr` в коде форматирования**

Предположим, у вас есть поле, которое должно быть заблокировано для редактирования для всех пользователей, кроме тех, у кого есть роль с номером 1. Вы можете использовать переменную `$#nr` для проверки наличия этой роли у пользователя и разблокировки поля для редактирования:

```totum
f1=: setFormat(condition: $#nr = 1; block: false)
```

В этом примере, если у пользователя есть роль с номером 1, то поле будет разблокировано для редактирования, несмотря на другие условия блокировки.

**Пример использования переменной `$#nr` в коде действия**

Вы можете использовать переменную `$#nr` в коде действия, чтобы выполнять определенные действия только для пользователей с определенными ролями. Например, если вы хотите, чтобы определенное действие выполнялось только для пользователей с ролью 2, вы можете использовать следующий код:

```totum
a1=: if(condition: $#nr = 2; then: $do_action)

do_action: set(table: 'some_table'; field: 'some_field' = "new_value")
```

В этом примере действие `do_action` будет выполнено только для пользователей, у которых есть роль с номером 2.

**Заключение**

Переменная `$#nr` позволяет гибко управлять доступом и поведением системы в зависимости от ролей пользователя, что делает её важным инструментом для настройки прав доступа и логики в Totum.

#### <a name="blocking-values-in-the-field-by-conditions-ai8"></a> Как использовать переменную $#nu для настройки блокировки?

Переменная `$#nu` в системе Totum возвращает идентификатор (ID) текущего пользователя, который выполняет действие. Это позволяет использовать её для настройки блокировок и других условий, зависящих от конкретного пользователя. Давайте рассмотрим, как можно использовать эту переменную для настройки блокировки поля.

**Пример использования переменной `$#nu` для блокировки поля**

Предположим, у вас есть таблица, в которой вы хотите заблокировать редактирование определенного поля для всех пользователей, кроме одного конкретного пользователя с ID 10. Вы можете использовать переменную `$#nu` в коде форматирования поля, чтобы настроить это условие.

**Шаги для настройки блокировки:**

1. **Откройте настройки поля**: Перейдите в настройки таблицы и найдите поле, для которого вы хотите настроить блокировку.

2. **Добавьте код форматирования**: В секции форматирования поля добавьте код, который будет использовать переменную `$#nu` для проверки ID текущего пользователя.

3. **Настройте условие блокировки**: Используйте функцию `setFormat` для блокировки поля, если ID текущего пользователя не равен 10.

Вот пример кода форматирования, который реализует это условие:

```totum
f1=: setFormat(condition: $#nu != 10; block: true)
```

**Объяснение кода:**

- **`condition: $#nu != 10`**: Это условие проверяет, что ID текущего пользователя не равен 10. Если условие истинно (то есть пользователь не является пользователем с ID 10), то выполняется действие, указанное в `setFormat`.

- **`block: true`**: Это действие блокирует редактирование поля, если условие истинно.

Таким образом, поле будет заблокировано для всех пользователей, кроме пользователя с ID 10. Этот подход позволяет гибко управлять доступом к полям на основе идентификатора пользователя, что может быть полезно для настройки прав доступа и обеспечения безопасности данных.

#### <a name="blocking-values-in-the-field-by-conditions-ai9"></a> В чем отличие переменных $#nr и $#nu?

В системе Totum переменные `$#nr` и `$#nu` используются для получения информации о текущем пользователе и его ролях. Давайте рассмотрим их подробнее:

1. **$#nr**:
   - Это переменная, которая возвращает список из номеров ролей текущего пользователя.
   - Она позволяет определить, какие роли назначены пользователю в данный момент.
   - Например, если у пользователя есть роли с идентификаторами 1 и 3, то `$#nr` вернет список `[1, 3]`.

2. **$#nu**:
   - Это переменная, которая возвращает номер текущего пользователя из таблицы пользователей.
   - Она позволяет идентифицировать пользователя, который в данный момент работает с системой.
   - Например, если у пользователя идентификатор 5, то `$#nu` вернет значение `5`.

**Пример использования**

Переменные `$#nr` и `$#nu` могут быть использованы в кодах для условного форматирования, ограничения доступа или выполнения действий в зависимости от роли или идентификатора пользователя. Например:

```totum
f1=: setFormat(condition: $#nr = 1; block: true)
```

В этом примере поле будет заблокировано для всех пользователей, у которых есть роль с идентификатором 1.

```totum
f2=: setFormat(condition: $#nu = 10; block: false)
```

В этом примере поле будет разблокировано для пользователя с идентификатором 10.

Таким образом, `$#nr` и `$#nu` предоставляют гибкие возможности для управления доступом и поведением системы в зависимости от текущего пользователя и его ролей.

#### <a name="blocking-values-in-the-field-by-conditions-ai10"></a> Как заблокировать строку по id с помощью setRowFormat?

Чтобы заблокировать строку по `id` с помощью функции `setRowFormat` в системе Totum, необходимо использовать код форматирования строк. Функция `setRowFormat` позволяет задать условия, при которых строка будет заблокирована для редактирования, удаления или дублирования.

Вот пример кода форматирования строк, который блокирует строку с определенным `id`:

```totum
f1=: setRowFormat(condition: #id = 5; block: true)
```

**Объяснение:**

- **`f1=:`** — это префикс, обозначающий начало кода форматирования строк. Нумерация `f1`, `f2`, и так далее, определяет порядок выполнения, если у вас несколько условий.

- **`setRowFormat`** — функция, которая используется для форматирования строк. Она позволяет задать различные параметры, такие как блокировка строки.

- **`condition: #id = 5`** — условие, при котором будет применено форматирование. В данном случае, строка будет заблокирована, если ее `id` равно 5.

- **`block: true`** — параметр, который указывает, что строка должна быть заблокирована. Это означает, что строка не может быть изменена, удалена или продублирована.

Этот код блокирует строку с `id` равным 5, предотвращая любые изменения в этой строке. Если вам нужно заблокировать несколько строк, вы можете использовать условие с множественным выбором, например:

```totum
f1=: setRowFormat(condition: #id = json`[5, 10, 15]`; block: true)
```

В этом примере строки с `id` 5, 10 и 15 будут заблокированы.

#### <a name="blocking-values-in-the-field-by-conditions-ai11"></a> Какое форматирование имеет приоритет — форматирование строки или форматирование поля?

В системе Totum форматирование поля имеет приоритет перед форматированием строки. Это означает, что если у вас есть условия форматирования как для строки, так и для отдельного поля, то форматирование, заданное для поля, будет применено в первую очередь, даже если оно противоречит форматированию строки.

**Пример**

Если строка заблокирована через код форматирования строки, но в поле указано `block: false`, то это поле будет разблокировано, несмотря на блокировку строки. Это позволяет более гибко управлять доступом и отображением данных в таблице, обеспечивая возможность переопределения общих настроек строки для отдельных полей.

**Пример кода**

Форматирование строки:

```totum
f1=: setRowFormat(condition: #status = 3; block: true)
```

Форматирование поля:

```totum
f1=: setFormat(condition: #status = 3; block: false)
```

В этом примере, если статус строки равен 3, то строка будет заблокирована, но конкретное поле будет разблокировано благодаря форматированию поля.

#### <a name="blocking-values-in-the-field-by-conditions-ai12"></a> Можно ли заблокировать поле как на изменение, так и на добавление через форматирование поля?

Да, в системе Totum можно заблокировать поле как на изменение, так и на добавление через форматирование поля. Для этого используется параметр `block: true` в функции `setFormat`. Когда этот параметр установлен, поле блокируется как на изменение, так и в процессе добавления.

Пример кода форматирования поля для блокировки поля:

```totum
f1=: setFormat(block: true)
```

Этот код заблокирует поле для всех пользователей, предотвращая его изменение и добавление значений. Если необходимо разблокировать поле для определенных условий, можно использовать дополнительные условия в функции `setFormat`.

Пример разблокировки поля для определенного пользователя:

```totum
f1=: setFormat(block: true)

f2=: setFormat(condition: $#nu = 10; block: false)
```

В этом примере поле будет заблокировано для всех, кроме пользователя с ID 10.

#### <a name="blocking-values-in-the-field-by-conditions-ai13"></a> Какие ограничения существуют у блокировки через форматирование?

Блокировка через форматирование в системе Totum имеет несколько ограничений, которые важно учитывать при использовании этой функции:

1. **Клиентская сторона**: Блокировка через форматирование осуществляется на стороне клиента. Это означает, что если пользователь обладает знаниями в области JavaScript, он может обойти эту блокировку, изменив данные напрямую через консоль браузера. Таким образом, блокировка через форматирование не является жесткой и не может гарантировать полную защиту от преднамеренного изменения данных.

2. **Нежесткая блокировка**: Поскольку блокировка через форматирование не защищает данные на уровне сервера, она считается нежесткой. Это делает её подходящей для предотвращения случайных ошибок пользователей (например, "ошибок пальцев"), но не для защиты от злонамеренных действий.

3. **Форматирование полей и строк**: Форматирование полей имеет преимущество перед форматированием строк. Это означает, что если строка заблокирована через код форматирования строки, но в поле указано `block: false`, то поле будет разблокировано.

4. **Блокировка на изменение и добавление**: При передаче параметра `block: true` поле блокируется как на изменение, так и в процессе добавления. Это может ограничивать гибкость в ситуациях, когда требуется блокировать поле только в одном из этих случаев.

5. **Условия блокировки**: Блокировка может быть настроена на основе различных условий, таких как роль пользователя, статус строки и другие параметры. Однако, если условия не настроены правильно, это может привести к нежелательным результатам, например, к блокировке полей для всех пользователей.

6. **Отсутствие защиты от серверных изменений**: Блокировка через форматирование не защищает данные от изменений, которые могут быть выполнены через серверные скрипты или API. Для защиты данных на уровне сервера необходимо использовать другие механизмы, такие как коды действий с функцией `errorException`.

В целом, блокировка через форматирование в Totum является полезным инструментом для предотвращения случайных ошибок пользователей, но не должна рассматриваться как средство защиты от преднамеренных изменений данных. Для более надежной защиты рекомендуется использовать серверные механизмы блокировки.

#### <a name="blocking-values-in-the-field-by-conditions-ai14"></a> Что произойдет, если указать condition: #id = ""; block: true для строки добавления?

Если в системе Totum указать условие `condition: #id = ""; block: true` для строки добавления, это приведет к блокировке поля только в строке добавления.

**Объяснение:**

- **#id = ""**: В Totum строка добавления не имеет `id`, поэтому условие `#id = ""` будет истинным только для строки добавления. Это условие используется для идентификации строки добавления.

- **block: true**: Этот параметр указывает, что поле должно быть заблокировано для редактирования.

Таким образом, при указании `condition: #id = ""; block: true`, поле будет заблокировано только в строке добавления, и пользователи не смогут его редактировать при добавлении новой строки. Однако, после того как строка будет добавлена и получит свой `id`, это условие больше не будет выполняться, и поле станет доступным для редактирования в обычных строках таблицы.

#### <a name="blocking-values-in-the-field-by-conditions-ai15"></a> Какие быстрые переменные используются для определения роли и пользователя?

В системе Totum для определения роли и пользователя используются две быстрые переменные:

1. **`$#nr`** — (от now roles) возвращает список из номеров ролей пользователя. Эта переменная позволяет определить, какие роли назначены текущему пользователю.

2. **`$#nu`** — (от now user) возвращает номер пользователя в таблице пользователей. Эта переменная позволяет определить, какой пользователь в данный момент выполняет действия в системе.

Эти переменные часто используются в кодах действий, форматирования или селектах для обработки текущей роли пользователя и его идентификатора. Например, они могут быть использованы для настройки доступа к определенным функциям или данным в зависимости от роли или идентификатора пользователя.

#### <a name="blocking-values-in-the-field-by-conditions-ai16"></a> Как сделать блокировку для поля в зависимости от статуса записи?

Для блокировки поля в зависимости от статуса записи в системе Totum, вы можете использовать код форматирования поля с функцией `setFormat`. Эта функция позволяет задать условия, при которых поле будет заблокировано для редактирования.

Вот пример, как это можно сделать:

**Пример кода форматирования**

Предположим, у вас есть поле `status`, и вы хотите заблокировать другое поле, например, `amount`, если статус равен `"completed"`.

Пример кода форматирования:

```totum
f1=: setFormat(condition: #status = "completed"; block: true)
```

**Объяснение**

- **`condition: #status = "completed"`**: Условие, при котором будет применено форматирование. В данном случае, если значение поля `status` равно `"completed"`.
- **`block: true`**: Параметр, который указывает, что поле будет заблокировано для редактирования, если условие выполняется.

**Разблокировка для определенных пользователей**

Если вы хотите разблокировать поле для определенных пользователей, например, для пользователя с ID 10, вы можете добавить дополнительное условие:

**Объяснение**

- **`block: false`**: Параметр, который указывает, что поле будет разблокировано для редактирования, если условие выполняется.

**Итог**

Таким образом, вы можете гибко управлять блокировкой полей в зависимости от статуса записи и других условий, используя код форматирования в Totum.

### <a name="what-are-text-and-coment-in-field-formatting-text"></a> Текст урока (по видео)

Что такое `text` и `comment` в форматировании поля

Начнем с `comment`.  И сразу же рассмотрим сложное поле: select. Как вы помните, select - это база (значение) в поле и отображение, которое видит пользователь. Когда написано potato, значение селекта восвсе не potato. Внутри хранится значение, например, 5. Потому что это select из другой таблицы, и 5 – это id строки другой таблицы, на которую ссылается это поле.

В форматировании пишем следующее условие: f3 равно двоеточию. В заданном формате мы пишем условие: условие now-field-value равно 5, что является картофелем. Начинаем с комментария и пишем «very good». Заполните его открывающей или закрывающей скобкой. Исправьте строчные буквы. Посмотрим, что у нас получилось.

``` totum
F3=: setFormat(condition: $#nfv= 5; comment: «very good»)
```

Теперь в ячейке с отображением «картофель» будет в правом верхнем углу буква «i». Если навести на нее курсор и удерживать его, то появится подсказка «very good». А если мы откроем контекстную панель правой кнопки мыши, то увидим здесь иконку и то же сообщение. Эта надпись может быть не только написана текстом, но и вычислена с помощью кода. Комментарии используются для информирования пользователей. Например, когда вы понимаете, что все ошибаются в одном и том же месте, такая подсказка может быть очень полезной.

``` totum
F3=: setFormat(condition: $#nfv= «C»; text: «COLD»)
```

```totum
f1=: setFormat(align: "center")
```

В этом примере текст или значение в ячейке будет выровнено по центру. Выравнивание может быть полезно для улучшения визуального восприятия данных в таблице, особенно когда необходимо обеспечить единообразие в отображении данных.

#### <a name="what-are-text-and-coment-in-field-formatting-ai12"></a> Какие варианты выравнивания доступны для `align`?

В Totum для параметра `align` доступны следующие варианты выравнивания:

1. `"center"` — для выравнивания текста по центру.
2. `"right"` — для выравнивания текста по правому краю.

По умолчанию текст выравнивается по левому краю, если не указано иное. Вы можете использовать параметр `align` в функции `setFormat` для изменения выравнивания текста в поле. Например:

```totum
f1=: setFormat(align: "center")
```

Этот код выравнивает текст в поле по центру.

#### <a name="what-are-text-and-coment-in-field-formatting-ai13"></a> Если задан text и мы из этого поля возмем select, то что мы получим?

Если в поле задан параметр `text` для форматирования, то это влияет только на отображение значения пользователю. При обращении к этому полю из кода, например, с использованием функции `select`, будет возвращено фактическое значение поля, а не то, что отображается пользователю через `text`.

Таким образом, если вы используете `select` для получения значения из поля, в котором задан `text`, вы получите исходное значение, хранящееся в базе данных, а не текст, отображаемый пользователю.

Пример:

Предположим, у вас есть таблица с полем `status`, в котором задано форматирование с `text`:

```totum
f1=: setFormat(condition: $#nfv = 1; text: "Active")
```

Если вы выполните следующий код в поле в другой таблице:

```totum
=: select(table: 'your_table'; field: 'status'; where: 'id' = 1)
```

Вы получите фактическое значение поля `status`, например, `1`, а не "Active", даже если пользователю отображается "Active".

#### <a name="what-are-text-and-coment-in-field-formatting-ai14"></a> Может ли поле быть пустым, но отображать `text`?

Да, поле может быть пустым, но отображать `text` пользователю. Это достигается с помощью форматирования поля, где вы можете задать отображаемый текст, который будет виден пользователю, даже если само значение поля пустое.

Пример использования форматирования для отображения текста в пустом поле:

```totum
f1=: setFormat(text: $format)

format: numFormat(num: $available; thousandssep: " "; unittype: " pcs")

available: select(table: 'warenhouse'; field: 'available'; where: 'id' = #product)
```

В этом примере, даже если поле пустое, пользователю будет отображаться форматированный текст, который показывает текущее количество доступных товаров на складе. Это полезно для информационных полей, которые должны показывать динамически изменяющиеся данные.

#### <a name="what-are-text-and-coment-in-field-formatting-ai15"></a> Как использовать пустое поле для отображения информации?

В Totum можно использовать пустое поле для отображения информации, которая будет динамически обновляться. Это достигается с помощью форматирования поля, где в параметре `text` можно задать текст или вычисляемое значение, которое будет отображаться пользователю. При этом само поле остается пустым, и его значение не сохраняется в базу данных.

Вот пример, как это можно сделать:

```totum
f1=: setFormat(text: $format)

format: numFormat(num: $available; thousandssep: " "; unittype: " pcs")

available: select(table: 'warehouse'; field: 'available'; where: 'id' = #product)
```

В этом примере:

1. Мы используем функцию `setFormat` для форматирования поля.
2. В параметре `text` передаем вычисляемое значение `$format`.
3. `$format` вычисляется с помощью функции `numFormat`, которая форматирует число с разделителем тысяч и единицей измерения.
4. Значение для форматирования берется из строки кода `$available`, которая получает данные из таблицы `warehouse` с помощью функции `select`.
5. `select` выбирает поле `available` из таблицы `warehouse`, где `id` соответствует значению в поле `#product` из текущей таблицы.

Таким образом, даже если поле пустое, пользователь будет видеть актуальную информацию, например, количество доступных товаров на складе. Это полезно для отображения динамически изменяющихся данных, которые не нужно сохранять в таблице.

#### <a name="what-are-text-and-coment-in-field-formatting-ai16"></a> Закрывает ли `comment` основное значение поля?

Нет, `comment` не закрывает основное значение поля. Он используется для отображения дополнительной информации в виде иконки `i` рядом с полем. При наведении на эту иконку появляется всплывающая подсказка с текстом, указанным в `comment`. Основное значение поля при этом остается доступным для использования в кодах и других операциях.

Пример использования `comment` в Totum:

```totum
f1=: setFormat(condition: math`$round / $calc` != 1; comment: "Похоже, что коробка неполная")

~calc: #quantity / #capacity_pcs

round: round(num: $calc; type: "down"; step: 1; dectimal: 0)
```

В этом примере, если условие выполняется, рядом с полем будет отображаться иконка `i`, при наведении на которую появится подсказка "Похоже, что коробка неполная". Однако основное значение поля остается неизменным и доступным для использования.

#### <a name="what-are-text-and-coment-in-field-formatting-ai17"></a> В этом коде форматирования f1=: setFormat(text: $discounted_price) discounted_price: $#nfv * $discount discount: 100 - #discount / 100 В контекстной панели и фильтрах отображается в том числе неизмененное значение, мне нужно, что бы text было единственно видимым значением для пользователя.

В Totum, чтобы сделать так, чтобы `text` было единственным видимым значением для пользователя, и оно отображалось везде, включая контекстную панель и фильтры, можно использовать параметр `textasvalue: true` в функции `setFormat`. Это позволит отображать текстовое значение вместо фактического значения поля во всех интерфейсах.

Вот как можно изменить ваш код:

```totum
f1=: setFormat(text: $discounted_price; textasvalue: true)
	discounted_price: $#nfv * $discount
		discount: 100 - #discount / 100
```

С помощью `textasvalue: true`, значение, указанное в `text`, будет использоваться как основное значение поля для отображения, фильтрации и других операций, связанных с пользовательским интерфейсом.

#### <a name="formatting-the-whole-table-q4"></a> Какие параметры отвечают за блокировку добавления, удаления и дублирования?

Когда вы имеете дело со всевозможными настройками блокировки полей, цвета текста, цвета заливки, помните, что форматирование таблицы - самое слабое из трех форматирований. То есть, сначала идет форматирование таблицы, затем форматирование строки, а потом самое сильное форматирование – форматирование определенного поля. Так что, если вы скажете `block: true` для всей таблицы, а для какого-то поля скажете `block: false`, поле будет разблокировано.
Это можно активно использовать. Например, блокировать всю таблицу, когда заказ достиг статуса завершенного, но само поле статуса может быть разблокировано.
Здесь будет рассказано о специфических параметрах настройки форматирования таблицы: `tabletitle`, `rowstitle`, `tabletext` и `tablecomment`. Все эти настройки позволяют отображать строку с дополнительной информаций в различных частях таблицы.

Для примера заполним данные параметры описанием, что этот параметр из себя представляет:

```totum
=: setTableFormat(tabletitle: « отображаемый заголовок таблицы»; rowstitle: « отображаемый заголовок строчной части таблицы»; tabletext: « текст, отображаемый под описанием таблицы»; tablecomment: « отображаемый под префильтром текст»)
```

Давайте посмотрим, где будет располагаться информация, передаваемая в каждый из этих параметров. Tabletitle изменяет заголовок. В дереве таблица, в настройках форматирования задан параметр ` tabletitle `, она по-прежнему называется так, как указано в настройках таблицы. Но в отображении таблицы название изменено. Здесь могут быть отображены и некоторые динамические вещи.
Далее, под названием таблицы следует информация, задаваемая параметром `tabletext`. Этот текст может быть динамическим с точки зрения условий. Поскольку коды форматирования выполняются после исполнения всех кодов и кодов действия всех полей таблицы, и вы можете ссылаться на префильтры, когда вычисляете `tabletext`. Например, в скрытом префильтре у вас есть какой-то текст или параметры, вы можете вывести их здесь, в верхней части таблицы, чтобы проинформировать пользователей о чем-то.
Далее, `rowstitle`. Он создает заголовок для строчной части. А также он позволет свернуть строчную часть. Если кликнуть на этот заголовок, строчная часть сворачиваться.
Ниже же отображается текст, переданный через параметр `tablecomment`. В нем, например, можно объяснить, почему кнопка добавления отключена. Очень удобно, потому что этот текст будет находиться на одном уровне с кнопкой добавления. Здесь может быть большой текст. Та часть, которая влезает в строку, будет отображаться постоянно, но если пользователь кликнет на текст, то увидит все сообщение.
Теперь мы поэкспериментируем с блокировкой добавлений по условию. Например, создадим условие, и добавляем условие block: true, если count больше пяти. В count мы делаем список-countList, список - это selectList из текущей таблицы - $#ntn. Здесь мы берем id и просто считаем. То есть мы берем все строки в этой таблице и считаем их.

```totum
f2=: setTableFormat(condition: $count > 5; blockadd: true; tablecomment: «количество строк больше 5» )
count: listCount(list: $list)
list: selectList(table: $#ntn; field: 'id')
```
При выполнении этой блокировки, если строк больше пяти, то не показываем кнопку добавления строк, чтобы пользователь не смог добавить новые строки. И чтобы пользователю было понятно, через параметр  tablecomment выдается комментарий, поясняющий, почему добавление новых строк заблокировано. Как вы понимаете, можно написать любой текст в качестве пояснения.

#### <a name="formatting-the-whole-table-ai6"></a> Что делает параметр `block` в `setTableFormat`?

Параметр `block` в функции `setTableFormat` в системе Totum используется для блокировки всех изменений в таблице. Это включает в себя блокировку удаления, перемещения и дублирования строк. В этом примере, если значение поля h_status равно "completed", то все изменения в таблице будут заблокированы. Это может быть полезно, например, для предотвращения изменений в таблице, когда она находится в завершенном состоянии.

#### <a name="formatting-the-whole-table-ai20"></a> Какой приоритет у форматирования таблицы, строки и поля?

В системе Totum приоритет форматирования определяется следующим образом:

1. **Форматирование поля** — наивысший приоритет. Это означает, что если для поля задано какое-либо форматирование, оно будет применено в первую очередь, независимо от других настроек.

2. **Форматирование строки** — средний приоритет. Форматирование строки применяется ко всей строке, но может быть перекрыто форматированием поля.

3. **Форматирование таблицы** — низший приоритет. Форматирование таблицы применяется ко всей таблице, но может быть перекрыто как форматированием строки, так и форматированием поля.

Таким образом, если для одного и того же элемента (например, ячейки) заданы разные параметры форматирования на уровне таблицы, строки и поля, то в первую очередь будет применено форматирование поля, затем строки, и только потом таблицы. Это позволяет более точно настраивать внешний вид и поведение отдельных элементов таблицы.

#### <a name="formatting-the-whole-table-ai25"></a> Как скрыть кнопки управления рядом с названием таблицы?

В системе Totum для скрытия кнопок управления рядом с названием таблицы используется параметр `topbuttons` в функции форматирования таблицы `setTableFormat`. Этот параметр позволяет управлять видимостью кнопок, которые обычно располагаются рядом с заголовком таблицы.

**Пример кода для скрытия кнопок управления:**

```totum
f1=: setTableFormat(topbuttons: false)
```

**Объяснение кода:**

1. **`setTableFormat`**: Это функция, используемая для форматирования всей таблицы. Она позволяет задавать различные параметры, такие как блокировка действий, изменение заголовков и управление видимостью элементов интерфейса.

2. **`topbuttons: false`**: Параметр, который скрывает кнопки управления рядом с названием таблицы. Когда этот параметр установлен в `false`, кнопки управления не будут отображаться в интерфейсе.

Таким образом, с помощью параметра `topbuttons` в функции `setTableFormat` вы можете скрыть кнопки управления рядом с названием таблицы, если они не нужны пользователям или если вы хотите упростить интерфейс.
