#### <a name="creation-of-the-select-field-and-how-it-works-q1"></a> Что за значение хранится в поле Селект?

[Селект][36] (он же выпадающий список) состоит из `оснований` (они же значения) и `отображений` (то, что показывается пользователю).

В поле храняться `значения`. По умолчанию это `id` строк той таблицы, на которую ссылается [Селект][36].

Отображения считаются при каждом открытии страницы по формуле указанной в [коде селекта][4].

#### <a name="creation-of-the-select-field-and-how-it-works-q2"></a> Какое значение мы видим в поле Селект?

Пользователь видит `отображение`.

[Код селекта][4] считает соответсвия `значений` и `отображений`:

`1` = `яблоко`

`2` = `банан`

`3` = `дыня`

Пользователь видит `ялоко, банан, дыня`. Если он выберет `банан`, то в поле сохранится его основание — `4`, пользователь при этом будет видеть рассчитанное [кодом селекта][4] отображение `банан`.

Но в поле хранится `значение`, те `4`. И если мы возмем его кодом:

```totum

= : #select

```

То мы получим именно `4`.

#### <a name="creation-of-the-select-field-and-how-it-works-q3"></a> Если строка на которую ссылается Селект будет изменена, то в какой момент мы увидим изменение в поле?

При первом обновлении таблицы.

#### <a name="creation-of-the-select-field-and-how-it-works-q4"></a> Что изменится Значение или Отображение?

Изменится `отображение`. `Значение` остается неизменным и привязывает поле к строке в другой таблице.

#### <a name="creation-of-the-select-field-and-how-it-works-q5"></a> Зачем нужен параметр Заголовок селекта при пустом значении?

Чтобы иметь возможность выбрать пустое значение.

#### <a name="creation-of-the-select-field-and-how-it-works-ai1"></a> Что такое поле типа select и для чего оно используется?

Поле типа "Селект" в системе Totum — это поле, которое связывает таблицы и отображает значения на основе выбора из выпадающего списка. Оно используется для создания связей между таблицами, позволяя выбирать значения из определенного столбца другой таблицы. Поле "Селект" хранит строковое значение, которое является `id` строки в таблице-источнике, но отображает рассчитанное по формуле отображение, которое видит пользователь.

**Основные особенности и использование поля "Селект":**

1. **Значение и отображение**:
   - **Значение**: Это `id` строки в таблице-источнике, которое хранится в поле "Селект".
   - **Отображение**: Это визуальное представление значения, которое видит пользователь. Оно рассчитывается по формуле, заданной в параметре поля "код селекта".

2. **Код селекта**:
   - Это основной параметр, который определяет, как будет рассчитываться отображение значения в поле "Селект". Код селекта должен возвращать либо результат работы функций `selectRowListForSelect` и `selectRowListForTree`, либо сформированный другими способами список ассоциированных массивов.

   Пример кода селекта:

```totum
=: selectRowListForSelect(table: 'products'; field: 'product'; order: 'product' asc)
```

3. **Множественные значения**:
   - Поле "Селект" может быть настроено на множественные значения, что позволяет выбирать несколько значений одновременно.

4. **Редактирование источника**:
   - Поле "Селект" может быть настроено так, чтобы позволять редактирование таблицы-источника непосредственно из поля.

5. **Индивидуальный расчет селекта**:
   - Возможность пересчитывать содержимое выпадающего списка селекта заново для каждого поля при любом изменении в таблице. Это используется, если набор значений в селекте различается от строки к строке или зависит от других полей.

6. **Применение**:
   - Поле "Селект" широко используется для создания связей между таблицами, что позволяет пользователям выбирать значения из связанных таблиц и отображать их в текущей таблице.

Таким образом, поле типа "Селект" в Totum является мощным инструментом для работы с данными, позволяя создавать динамические связи между таблицами и обеспечивая удобный интерфейс для выбора значений.

#### <a name="creation-of-the-select-field-and-how-it-works-ai2"></a> Какие значения можно хранить в поле select?

В поле типа `select` в системе Totum хранятся значения, которые представляют собой `id` строк из таблицы-источника, на которую ссылается это поле. Эти значения называются "основаниями" селекта.

**Основные моменты:**

1. **Значения (Основания)**:
   - В поле `select` хранятся именно значения (основания), которые по умолчанию являются `id` строк таблицы-источника.
   - Эти значения могут быть числовыми или строковыми, в зависимости от настроек и данных в таблице.

2. **Отображения**:
   - Пользователь видит не сами значения, а их отображения, которые рассчитываются по формуле, заданной в параметре "Код селекта".
   - Отображения могут быть любыми строковыми значениями, которые вы хотите показать пользователю вместо `id`.

3. **Код селекта**:
   - Код селекта отвечает за расчет отображений и может использовать функции, такие как `selectRowListForSelect`, для получения списка значений и их отображений.

4. **Множественные значения**:
   - Если включен параметр "Множественные значения", в поле `select` может храниться список значений, а не одно значение.

**Пример кода селекта:**

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name'; order: 'product_name' asc)
```

В этом примере значения, хранящиеся в поле `select`, будут `id` строк из таблицы `products`, а отображения — это значения из поля `product_name` этой таблицы.

Таким образом, в поле `select` хранятся значения, которые ссылаются на строки в другой таблице, а пользователю показываются соответствующие отображения.

#### <a name="creation-of-the-select-field-and-how-it-works-ai3"></a> Какие параметры являются обязательными в функции selectRowListForSelect при создании поля селект?

В функции `selectRowListForSelect` при создании поля типа Селект в системе Totum обязательными параметрами являются:

1. **table**: Указывает на таблицу, из которой будут браться значения для селекта. Это параметр определяет источник данных для выпадающего списка.

2. **field**: Указывает на поле в таблице, из которого будут браться отображаемые значения для селекта. Это параметр определяет, какие данные будут отображаться пользователю в выпадающем списке.

Пример использования функции `selectRowListForSelect` с обязательными параметрами:

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name')
```

В этом примере значения для селекта будут браться из таблицы `products`, а отображаемые значения будут взяты из поля `product_name`.

#### <a name="creation-of-the-select-field-and-how-it-works-ai4"></a> Что такое 'Код селекта' и как его правильно написать?

**Что такое 'Код селекта' в системе Totum?**

'Код селекта' в системе Totum — это параметр поля типа Селект, который определяет, как будет рассчитываться отображение значения в этом поле. Он используется для динамического заполнения выпадающего списка значениями из другой таблицы. Код селекта должен возвращать либо результат работы функций `selectRowListForSelect` и `selectRowListForTree`, либо сформированный другими способами список ассоциированных массивов.

**Как правильно написать 'Код селекта'?**

Для написания 'Кода селекта' необходимо использовать функции, которые возвращают список значений и их отображений. Давайте рассмотрим пример использования функции `selectRowListForSelect`.

**Пример кода селекта**

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name'; order: 'product_name' asc)
```

**Объяснение кода**

- **`selectRowListForSelect`**: Это основная функция, которая используется для получения списка значений для поля типа Селект.
- **`table: 'products'`**: Указывает, что данные будут браться из таблицы 'products'.
- **`field: 'product_name'`**: Указывает, что отображения Селекта будут браться из поля 'product_name' таблицы 'products'.
- **`order: 'product_name' asc`**: Указывает, что отображения в выпадающем списке будут отсортированы по полю 'product_name' в порядке возрастания.

**Дополнительные параметры**

- **`where`**: Можно использовать для фильтрации значений, например, `where: 'category' = "Electronics"`.
- **`preview`**: Можно указать дополнительные поля для отображения в панели по правой кнопке мыши, например, `preview: 'price'`.

**Пример с фильтрацией и превью**

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name'; where: 'category' = "Electronics"; order: 'product_name' asc; preview: 'price'; preview: 'stock')
```

В этом примере мы получаем список продуктов из категории "Electronics", отсортированных по имени, и добавляем поля 'price' и 'stock' для отображения в панели.

**Заключение**

'Код селекта' — это мощный инструмент для динамического заполнения выпадающих списков в Totum. Он позволяет интегрировать данные из других таблиц и настраивать отображение значений в зависимости от различных условий и параметров.

#### <a name="creation-of-the-select-field-and-how-it-works-ai5"></a> Какие параметры используются в функции selectRowListForSelect?

Функция `selectRowListForSelect` в системе Totum используется для формирования списка значений и их отображений для поля типа Селект. Она принимает несколько параметров, которые позволяют гибко настраивать выборку данных. Вот основные параметры, которые могут быть использованы в этой функции:

**Обязательные параметры**

1. **table** — имя таблицы, из которой берутся значения.
2. **field** — поле в таблице, из которого берутся отображения.

**Необязательные параметры**

1. **cycle** — число, определяет цикл, если таблица `table` является расчетной в цикле.
2. **hash** — строка, hash таблицы для получения данных из временных таблиц.
3. **where** — name-параметр, условие выбора строки в строчной части. Левая часть определяет поле сравнения в таблице `table`, а правая — значение сравнения.
4. **order** — name-параметр, поле в таблице `table`, по которому будет осуществляться сортировка.
5. **section** — name-параметр, поле в таблице `table`, по которому будут сгруппированы значения.
6. **preview** — множественный, name-параметр, поля, данные которых выводятся в панель по клику правой кнопки мыши или при выборе значения.
7. **bfield** — name-параметр, поле, выводящееся в параметр "value" итогового rowList.
8. **previewscode** — код для формирования дополнительных превью, получает параметр `$#val`, содержащий `bfield` селекта. Должен возвращать rowlist формата `[{title: "", value: "", name: ""}]`.

Эти параметры позволяют настроить выборку данных для поля Селект, определяя, какие значения и отображения будут доступны пользователю, а также как они будут сортироваться и фильтроваться.

#### <a name="creation-of-the-select-field-and-how-it-works-ai6"></a> Что хранится в поле типа select значение или отображение?

В поле типа "Селект" в системе Totum хранится значение, которое представляет собой `id` строки в таблице-источнике или другое кодовое значение, если задан параметр `bfield`. Это значение называется "основание" или "значение". Пользователь же видит в интерфейсе "отображение", которое рассчитывается по формуле, заданной в параметре поля "код селекта".

**Пример кода селекта:**

```totum
=: selectRowListForSelect(table: 'products'; field: 'product'; order: 'product' asc)
```

**Пояснение:**

- **Значение**: Это то, что хранится в поле. Например, `id` продукта.
- **Отображение**: Это то, что видит пользователь. Например, название продукта.

Таким образом, в поле хранится именно значение (`id`), а отображение рассчитывается и показывается пользователю. Если вы хотите получить значение из поля "Селект", вы получите именно `id` или кодовое значение, а не отображение.

#### <a name="creation-of-the-select-field-and-how-it-works-ai7"></a> Что такое отображение в контексте select?

В контексте поля типа "Селект" в системе Totum, "отображение" — это визуальное представление значения, которое видит пользователь в интерфейсе. Хотя в ячейке хранится "значение" (обычно это `id` строки в таблице-источнике), пользователь видит "отображение", которое рассчитывается по формуле, заданной в параметре поля "код селекта".

**Пример работы с отображением:**

1. **Значение**: Это фактическое значение, хранящееся в поле, например, `id` строки в таблице-источнике. Это значение используется для связи между таблицами.

2. **Отображение**: Это текст или другое представление, которое видит пользователь. Оно рассчитывается с помощью кода селекта и может включать в себя дополнительные данные из таблицы-источника.

**Пример кода селекта:**

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name'; order: 'product_name' asc)
```

В этом примере:
- **Значение** — это `id` строки из таблицы `products`.
- **Отображение** — это `product_name`, которое видит пользователь в выпадающем списке.

**Как это работает:**

- **Код селекта**: Определяет, какие данные из таблицы-источника будут использоваться для отображения. Это может быть одно поле или комбинация нескольких полей.
- **Отображение в интерфейсе**: Пользователь видит только отображение, а не значение. Это делает интерфейс более понятным и удобным для пользователя.

Таким образом, отображение в контексте select — это способ представить данные в удобной для пользователя форме, скрывая при этом технические детали, такие как `id` строк.

#### <a name="creation-of-the-select-field-and-how-it-works-ai8"></a> Что происходит, если в таблице на которую ссылается поле select, изменяется значение?

Если в таблице, на которую ссылается поле типа `select`, изменяется значение, то это изменение отразится на отображении в поле `select` при следующем обновлении таблицы, в которой это поле используется. Давайте рассмотрим, что именно происходит в этом случае:

1. **Изменение отображения**: Поле `select` хранит значение (обычно это `id` строки в таблице-источнике), но отображает рассчитанное отображение. Если в таблице-источнике изменяется значение, которое используется для отображения, то при следующем обновлении таблицы, в которой используется поле `select`, это изменение будет видно пользователю.

2. **Обновление отображения**: Обновление отображения происходит автоматически при пересчете таблицы. Это может быть вызвано, например, изменением данных в таблице, на которую ссылается `select`, или при ручном обновлении таблицы пользователем.

3. **Значение остается неизменным**: Важно отметить, что само значение в поле `select` (например, `id` строки) остается неизменным. Изменяется только отображение, которое рассчитывается на основе данных из таблицы-источника.

4. **Индивидуальный расчет селекта**: Если в поле `select` включен параметр индивидуального расчета, то отображение может пересчитываться заново для каждого поля при любом изменении в таблице. Это может замедлить работу таблицы, но гарантирует актуальность отображения.

Таким образом, при изменении значения в таблице-источнике, отображение в поле `select` будет обновлено при следующем пересчете таблицы, в которой это поле используется, но само значение в поле `select` останется неизменным.

#### <a name="creation-of-the-select-field-and-how-it-works-ai9"></a> Как сортируются значения в выпадающем списке select?

В системе Totum значения в выпадающем списке select сортируются в соответствии с параметром `order`, который задается в коде селекта. Этот параметр определяет, по какому полю и в каком порядке будут отсортированы значения в выпадающем списке.

**Пример кода селекта с сортировкой:**

```totum
=: selectRowListForSelect(table: 'products'; field: 'product'; order: 'product' asc)
```

В этом примере значения в выпадающем списке будут отсортированы по полю `product` в порядке возрастания (`asc`).

**Параметры сортировки:**

- **asc**: Сортировка по возрастанию. Значения будут отсортированы от меньшего к большему.
- **desc**: Сортировка по убыванию. Значения будут отсортированы от большего к меньшему.

Если параметр `order` не задан, значения в выпадающем списке могут быть отсортированы в произвольном порядке, зависящем от порядка их извлечения из таблицы. Поэтому, если важен определенный порядок отображения значений, рекомендуется всегда указывать параметр `order` в коде селекта.

#### <a name="creation-of-the-select-field-and-how-it-works-ai10"></a> Что такое 'база select'?

В этом коде селекта отображение будет браться из поля 'name' таблицы 'fruits', и значения будут отсортированы по возрастанию.

Таким образом, 'база select' — это внутреннее значение, которое связывает поле Селект с конкретной строкой в таблице-источнике, а отображение — это то, что видит пользователь в интерфейсе.

- **Логический порядок**: Значения могут быть отсортированы в логическом порядке, например, по алфавиту или по дате, что делает интерфейс более интуитивно понятным.

Таким образом, указание сортировки в коде селекта помогает организовать данные в выпадающем списке в удобном для пользователя порядке.

#### <a name="creation-of-the-select-field-and-how-it-works-ai19"></a> Какие элементы нужно указывать в параметре 'field' функции selectRowListForSelect?

В параметре `field` функции `selectRowListForSelect` необходимо указывать поле в таблице, из которого будут браться значения для отображения в Селекте. Это поле определяет, какие данные будут показаны пользователю в выпадающем списке.

**Пример использования функции `selectRowListForSelect`:**

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name'; order: 'product_name' asc)
```

В этом примере:

- **`table: 'products'`** — указывает, что данные будут браться из таблицы `products`.
- **`field: 'product_name'`** — указывает, что отображения в Селекте будут браться из поля `product_name` таблицы `products`.
- **`order: 'product_name' asc`** — указывает, что отображения в выпадающем списке будут отсортированы по полю `product_name` в порядке возрастания.

Таким образом, параметр `field` определяет, какие именно данные из таблицы будут использоваться для формирования списка значений в поле Селект.

#### <a name="creation-of-the-select-field-and-how-it-works-ai20"></a> Что произойдет, если удалить код селекта?

Если удалить код селекта в системе Totum, выпадающий список перестанет работать. Это связано с тем, что код селекта отвечает за формирование отображения значений в поле типа Селект. Без этого кода система не сможет определить, какие значения должны быть показаны пользователю в выпадающем списке, и как они должны быть отображены.

**Последствия удаления кода селекта:**

1. **Отсутствие отображения**: Поле Селект не будет отображать никакие значения, так как не будет информации о том, какие значения должны быть доступны для выбора.

2. **Невозможность выбора**: Пользователь не сможет выбрать значение из выпадающего списка, так как он просто не будет отображаться.

3. **Ошибки в интерфейсе**: В зависимости от конфигурации системы и других зависимостей, удаление кода селекта может привести к ошибкам в интерфейсе или некорректному отображению данных. Значения в поле Селект в этом случае будут отображаться зачеркнутыми.

**Рекомендации:**

- **Восстановление кода селекта**: Если код селекта был удален случайно, рекомендуется восстановить его, чтобы поле Селект снова начало корректно работать.

- **Проверка зависимостей**: Перед удалением кода селекта убедитесь, что это не повлияет на другие части системы, которые могут зависеть от этого поля, так как некоторые коды могут брать именно отображение селекта, а не значение из поля селекта.

Таким образом, код селекта является важной частью настройки поля типа Селект, и его удаление может привести к проблемам в работе системы.

В системе Totum код селекта имеет доступ ко всем полям текущей таблицы, включая поля хедера и футера. Это позволяет использовать значения из этих полей для формирования условий и параметров в коде селекта. ```

В этом примере код селекта использует значение из поля `#category_filter` текущей таблицы для фильтрации продуктов по категории. Это позволяет динамически изменять содержимое выпадающего списка в зависимости от значений в других полях таблицы.

#### <a name="code-for-forming-a-select-ai4"></a> В какой момент вычисляются коды селектов?

В системе Totum коды селектов вычисляются после выполнения кодов и кодов-действий, но до форматирования. Порядок вычисления следующий:

1. Коды
2. Код действия таблицы
3. Коды-действий
4. Отображения селектов
5. Код форматирования таблицы
6. Коды форматирования строк
7. Коды Форматирования полей

Это означает, что коды селектов выполняются после того, как все коды и коды-действий были выполнены, но до того, как будет применено форматирование к данным.

#### <a name="code-for-forming-a-select-ai8"></a> Что происходит, если в уже созданном селекте добавить параметр base-field?

Если в уже созданном селекте добавить параметр `bfield`, выбрав в качестве основания какое-то из полей таблицы-источника, то отображение в поле может стать недействительным. Это происходит потому, что ранее выбранное значение может не соответствовать новому основанию. Например, если ранее основанием был `id`, а теперь используется другое поле, то отображаемое значение исчезнут (будет отображаться зачеркнутое основание), так как значение в поле больше не соответствует новому основанию.

Давайте рассмотрим, как это работает:

1. **Исходная настройка**: Изначально селект может быть настроен так, что основанием является `id` строки в таблице-источнике. Это стандартное поведение, когда `bfield` не указан.

2. **Добавление `bfield`**: Когда вы добавляете параметр `bfield`, вы указываете, что основанием для выбора значений в селекте должно быть другое поле из таблицы-источника. Например, это может быть поле с уникальными строковыми значениями.

3. **Изменение отображения**: После добавления `bfield`, система пересчитывает отображение для всех значений в селекте. Если ранее выбранное значение не соответствует новому основанию, оно будет показано как недействительное (зачеркнутое).

4. **Обновление значений**: Пользователю может потребоваться выбрать новое значение из обновленного списка, чтобы соответствовать новому основанию.

Пример кода с использованием `bfield`:

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name'; bfield: 'unique_code')
```

В этом примере `unique_code` используется в качестве основания вместо `id`. Если ранее выбранное значение не соответствует `unique_code`, оно будет показано как недействительное, и пользователю потребуется выбрать новое значение.

#### <a name="code-for-forming-a-select-ai10"></a> Какие параметры кода select можно добавить для более детальной настройки?

В системе Totum для более детальной настройки кода select можно использовать следующие параметры:

1. **table** — указывает таблицу, из которой будут браться значения для селекта.

2. **field** — указывает поле в таблице, из которого будут браться значения для отображения в селекте.

3. **cycle** — число, определяет цикл, если таблица является расчетной в цикле.

4. **hash** — строка, hash таблицы для получения данных из временных таблиц.

8. **preview** — множественный параметр, который задает поля, данные которых выводятся в панель по клику правой кнопки мыши или при выборе значения.

9. **bfield** — указывает поле, которое будет использоваться в качестве основания (значения) для селекта. По умолчанию используется `id`.

10. **previewscode** — код для формирования дополнительных превью, получает параметр `$#val`, содержащий bfield селекта. Должен возвращать rowlist формата `[{title: "", value: "", name: ""}]`.

Эти параметры позволяют гибко настраивать поведение и отображение селекта, обеспечивая более точное соответствие требованиям конкретного сценария использования.

### <a name="different-composition-of-select-depending-on-other-fields-ai"></a> Дополнительные вопросы

#### <a name="different-composition-of-select-depending-on-other-fields-ai1"></a> Как работает функция selectRowListForSelect если мне нужно выбрать в выпадающих список только определенные строки на осноеве поля в текущей таблице?

Функция `selectRowListForSelect` в системе Totum используется для формирования выпадающего списка значений из указанной таблицы. Если вам нужно выбрать только определенные строки на основе значения поля в текущей таблице, вы можете использовать параметр `where` для фильтрации данных.

**Пример использования функции selectRowListForSelect с фильтрацией**

Предположим, у вас есть таблица `products`, и вы хотите отобразить в выпадающем списке только те продукты, которые соответствуют определенному типу, указанному в текущей таблице. Для этого вы можете использовать следующий код:

```totum
=: selectRowListForSelect(table: 'products'; field: 'product_name'; where: 'product_type' = #current_type)
```

**Пояснение кода**

- **`table: 'products'`** — указывает таблицу, из которой будут выбраны значения для выпадающего списка.
- **`field: 'product_name'`** — указывает поле, значения которого будут отображаться в выпадающем списке.
- **`where: 'product_type' = #current_type`** — фильтрует строки на основе значения поля `product_type` в таблице `products`. Здесь `#current_type` — это значение из текущей таблицы, которое используется для фильтрации.

**Индивидуальный расчет селекта**

Если значение, на основе которого вы фильтруете данные, может различаться от строки к строке в текущей таблице, вам нужно включить параметр "Индивидуальный расчет селекта для каждой строки". Это обеспечит пересчет содержимого выпадающего списка для каждой строки в зависимости от значения поля `#current_type`.

**Включение индивидуального расчета селекта**

Чтобы включить индивидуальный расчет селекта, выполните следующие шаги:

1. Откройте настройки поля типа Селект в вашей таблице.
2. Найдите параметр "Индивидуальный расчет селекта для каждой строки".
3. Установите галочку, чтобы активировать этот параметр.

После этого выпадающий список будет пересчитываться для каждой строки, учитывая значение поля `#current_type` в текущей строке. Это позволит вам динамически изменять содержимое выпадающего списка в зависимости от данных в вашей таблице.

#### <a name="different-composition-of-select-depending-on-other-fields-ai2"></a> Как реализовать условие для выбора элементов на основе значения чекбокса?

В системе Totum вы можете использовать условие для выбора элементов на основе значения чекбокса, используя функцию `if` в коде селекта. Это позволяет динамически изменять содержимое выпадающего списка в зависимости от состояния чекбокса. Давайте рассмотрим, как это можно сделать.

**Пример реализации условия для выбора элементов на основе значения чекбокса**

Предположим, у вас есть таблица с продуктами, и вы хотите, чтобы в зависимости от состояния чекбокса отображались только определенные продукты.

1. **Создайте поле чекбокс**: В вашей таблице создайте поле типа "Чекбокс", которое будет использоваться для выбора условий.

2. **Настройте код селекта**: Используйте функцию `if` для выбора элементов на основе значения чекбокса. В зависимости от состояния чекбокса (true или false) будет выполняться разный код селекта.

```totum
=: if(condition: #checkbox_field = true; then: $select_fruits; else: $select_all)

select_fruits: selectRowListForSelect(table: 'products'; field: 'name'; where: 'category' = "fruit")
select_all: selectRowListForSelect(table: 'products'; field: 'name')
```

В этом примере:

- `#checkbox_field` — это поле чекбокс в вашей таблице.
- Если чекбокс отмечен (`true`), то будет выполнен код селекта `$select_fruits`, который выбирает только продукты из категории "fruit".
- Если чекбокс не отмечен (`false`), то будет выполнен код селекта `$select_all`, который выбирает все продукты.

3. **Включите индивидуальный расчет селекта**: Чтобы условие работало для каждой строки, необходимо включить параметр "индивидуальный расчет селекта для каждой строки". Это обеспечит пересчет селекта при изменении состояния чекбокса.

**Заключение**

Используя условие с функцией `if` и параметр "индивидуальный расчет селекта", вы можете гибко управлять содержимым выпадающего списка в зависимости от состояния чекбокса, что позволяет создавать более динамичные и адаптивные интерфейсы в системе Totum.

#### <a name="different-composition-of-select-depending-on-other-fields-ai3"></a> Для чего нужен параметр индивидуального расчёта селекта для каждой строки?

Параметр "индивидуальный расчет селекта для каждой строки" в системе Totum используется для того, чтобы пересчитывать содержимое выпадающего списка селекта заново для каждой строки при любом изменении в таблице. Это необходимо в случаях, когда набор значений в селекте различается от строки к строке или зависит от других полей.

**Основные случаи использования:**

1. **Зависимость от других полей**: Если содержимое селекта зависит от значений в других полях текущей строки, то включение этого параметра позволяет обновлять селект при изменении этих значений.

2. **Разные наборы значений**: Если для разных строк требуется отображать разные наборы значений в селекте, то индивидуальный расчет позволяет это сделать.

3. **Обновление данных**: При изменении данных в таблице, которые влияют на содержимое селекта, этот параметр обеспечивает актуальность отображаемых значений.

**Пример использования:**


#### <a name="different-composition-of-select-depending-on-other-fields-ai5"></a> Как работает if в условиях селекта?

В системе Totum функция `if` в условиях селекта позволяет динамически изменять набор значений, доступных для выбора, в зависимости от определенных условий. Это может быть полезно, когда необходимо, чтобы содержимое выпадающего списка селекта изменялось в зависимости от значений других полей или параметров.

**Пример использования `if` в условиях селекта**

Рассмотрим пример, где в зависимости от значения поля `condition_field` мы выбираем данные из разных таблиц:


В этом примере:

- В противном случае, если значение в поле `condition_field` не равно 1, будет использоваться список значений из таблицы `table_2`.

**Индивидуальный расчет селекта**

Для того чтобы условие `if` работало корректно и селект пересчитывался для каждой строки, необходимо включить параметр **индивидуальный расчет селекта для каждой строки**. Это позволяет пересчитывать содержимое выпадающего списка селекта заново для каждого поля при любом изменении в таблице.

**Влияние на производительность**

Важно помнить, что включение индивидуального расчета селекта может значительно повысить нагрузку на сервер, так как для каждой строки селект будет рассчитываться заново. Поэтому использовать эту функцию следует только при необходимости.

**Пример использования `if` для фильтрации значений**

В этом примере значения для селекта фильтруются в зависимости от значения в поле `condition_field`.

Таким образом, функция `if` в условиях селекта в Totum предоставляет гибкие возможности для динамического изменения содержимого выпадающего списка, что позволяет адаптировать интерфейс под различные условия и сценарии использования.

#### <a name="different-composition-of-select-depending-on-other-fields-ai7"></a> Как добавить в селект значение, которого нет в исходной таблице?

  - **`title`**: Отображаемое значение, которое будет показано пользователю в выпадающем списке. В данном примере это строка `"Специальное отображение"`.

Этот код добавляет новое значение в выпадающий список селекта, позволяя пользователю выбрать его, даже если оно не присутствует в таблице-источнике.

#### <a name="different-composition-of-select-depending-on-other-fields-ai8"></a> Что такое функция rowCreate и как она работает?

#### <a name="different-composition-of-select-depending-on-other-fields-ai9"></a> Как влияет на производительность включённый индивидуальный расчёт селекта?

Включённый индивидуальный расчёт селекта в системе Totum может значительно повысить нагрузку на сервер и замедлить работу системы. Это связано с тем, что при включении этой опции содержимое выпадающего списка селекта пересчитывается заново для каждого поля при любом изменении в таблице. Если набор значений в селекте различается от строки к строке или зависит от других полей, то для каждой строки селект будет рассчитан заново.

**Влияние на производительность:**

1. **Увеличение нагрузки на сервер**: Каждый раз, когда происходит изменение в таблице, система должна пересчитывать селект для каждой строки, что требует дополнительных вычислительных ресурсов.

2. **Замедление отображения таблицы**: Поскольку селект пересчитывается для каждой строки, это может замедлить процесс отображения таблицы пользователю, особенно если таблица содержит большое количество строк.

3. **Рекомендуется использовать только по необходимости**: Из-за значительного влияния на производительность, индивидуальный расчёт селекта рекомендуется использовать только в тех случаях, когда это действительно необходимо, например, когда значения в селекте зависят от других полей или условий.

**Пример использования:**

Если у вас есть поле, в котором значения селекта зависят от значения другого поля в той же строке, вы можете использовать индивидуальный расчёт селекта, чтобы обеспечить корректное отображение значений:

```totum
=: selectRowListForSelect(table: 'products'; field: 'product'; where: 'category' = #category_field)
```

В этом примере значения в селекте зависят от значения поля `category_field` в текущей строке, и для каждой строки селект будет пересчитываться заново.

Таким образом, включение индивидуального расчёта селекта может быть полезным в определённых сценариях, но следует учитывать его влияние на производительность и использовать эту функцию с осторожностью.

#### <a name="different-composition-of-select-depending-on-other-fields-ai10"></a> Можно ли использовать индивидуальный расчёт селекта не только в строчной части?

Это switch-подобная конструкция: `$$type` вызывает строку, имя которой определяется в строке type. В данном случае строка type получает значение из поля type: `type: #type`

Значение из поля #type текущей таблицы определяет, код из какой строки будет выбран. Значение из поля #type может быть 1, 2 или 3. Эти строки кода определяют, какие значения будут возвращены в зависимости от значения поля #type.

Если #type равно 2, будет выполнен запрос к таблице table_2 и возвращен список значений из поля name.

**Включение индивидуального расчёта селекта**

Чтобы включить индивидуальный расчёт селекта, необходимо активировать соответствующий параметр в настройках поля. Это позволит пересчитывать селект для каждой строки или элемента интерфейса, где он используется.

Таким образом, индивидуальный расчёт селекта в Totum предоставляет мощные возможности для настройки интерфейса, но требует внимательного подхода к его использованию из-за потенциального влияния на производительность системы.

Аналогично зачеркнутое `основание` будет отображаться, если по условиям текущей выборки это значение стало недоступным. Что бы этого избежать селект строится не напрямую через `where`, а через `id` с добавлением в этот список текущего значения:

```totum
=: selectRowListForSelect(table: 'table'; field: 'name'; where: 'id' = $listAdd)

listAdd: listAdd(list: $list; item: $#nfv)
	list: selectList(table: 'table'; field: 'id'; where: 'condition' = #condition_field)

```

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-q3"></a> Что такое скрытие вместо удаления и как отображаются такие строки?

Иногда настройка таблицы может предполагать, что строки будут [скрываться][108], а не удаляться — в этом случае их можно восстановить и данные из этих строк остаются доступными по `select` с условием `where: 'id' = ...`.

Когда в селекте выбрано значение удаленной строки будет отображаться зачеркнутое `отображение`!

Именно за это зачеркивание и отвечает параметр `is_del: true`, который встречался нам ранее.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-q4"></a> Что будет, если построить селект по селекту?

В этом случае мы увидим в качестве `отображений` — `значения` второго селекта. Как быть, если вы в первом селекте выбираете доступные значения, а во втором уже конкретные:

```totum

=: selectRowListForSelect(table: 'table'; field: 'name'; where: 'id' = #first_select)

// это код-селекта для второго (ведомого) селекта
// table и для первого и для второго селекта одна и таже

```

Те мы выбираем из таблицы источника только те значения, которые выбраны в первом селекте.

### <a name="crossed-out-selects-and-what-it-may-be-related-to-text"></a> Текст урока (по видео)

В этом видео мы поговорим о зачёркнутых значениях в селектах, с чем они могут быть связаны и как их исправить.

Есть несколько абсолютно разных случаев.

Первый случай: строка была удалена

Если в поле селекта было выбрано значение строки, которая была удалена — вы увидите зачеркнутое основание.

Второй случай: отображение не доступно по условиям селекта
Селект — это зависимое поле. Если он поставлен в зависимость от значения чекбокса, от когда галочки в чекбоксе нет, в списке один набор значений, с чекбоксом другой. Допустим, у нас есть селект с овощами и фруктами. А при галочке в чекбоксе выбор происходит только из фруктов. Вот картошка, я добавил также капусту. Когда мы ставим галочку, у нас нет овощей в этом списке, только фрукты и добавленные элементы. Вот пустое значение, и это то, что мы добавили вручную в коде, который генерирует это значение.

Была выбрана картошка, и вместо нее отображается это зачеркнутое значение поля. Это означает, что у нас нет отображения для такой базы, потому что согласно условиям выборки оно не принадлежит интервалу из-за указанного ограничения. Давайте посмотрим, как это выглядит в коде.

```totum
listAdd(list: $if; item: $row)

row: rowCreate(field: "value" = "spec"; field: "title" = "Tomato")
if(condition: #h_checkbox = true; then: $s1; else: $s2)
s1: selectRowListForSelect(table: 'values_for_select'; field: 'str'; where: 'type' = "fruit"; bfield: 'base_field')
s2: selectRowListForSelect(table: 'values_for_select'; field: 'str'; bfield: 'base_field'; order: 'title' asc)
```

Если чекбокс установлен, то мы берем это значение s1. И здесь говорится, что type равно fruit. Когда у нас чекбокс выключен, мы можем выбрать картошку — здесь она выбрана по s2. В этом случае здесь нет такого ограничения. И когда мы ставим галочку, значение остается, но отображения нет, потому что оно не проходит это условие.

Как это можно изменить? Давайте подумаем. Сначала мы убираем fruit отсюда и делаем такую строку. Назовем ее add. Почему add? Нам нужно взять список этих фруктов по полю, которое у нас здесь является base-field, то есть базовым полем, и добавить к нему текущее значение поля. Итак, здесь мы сделаем listAdd и возьмем список. Давайте пока так его назовем. Убираем второй список. И здесь мы ставим быструю переменную now-field-value, то есть значение в текущем поле. Далее, что такое список. Мы должны использовать selectList, чтобы получить список из этой таблицы. Мы собираемся взять значение base_field, которое используется для генерации отображений здесь. Мы берем это условие и переносим его сюда. Type равно fruit, а сортировка нам вообще не нужна.

Если сортировка не нужна, то удалите этот параметр, не устанавливайте его, потому что он создает дополнительную нагрузку на действие. И здесь, поскольку type мы перенесли сюда, вот оно type_fruit стало здесь, нам нужно поставить то же поле, что и base-field.

Итак, что мы здесь делаем? Мы говорим, что не выбираем сразу по типу fruit. Мы выбираем из расширенного списка. Мы расширяем его текущим значением и берем базовый список из значений base-field и из таблицы, из которой мы его выбираем. По base-field, по type. Здесь мы пишем это условие, type равно fruit.

```totum
listAdd(list: $if; item: $row)
	row: rowCreate(field: "value" = "spec"; field: "title" = "Tomato")

if(condition: #h_checkbox = true; then: $s1; else: $s2)

	s1: selectRowListForSelect(table: 'values_for_select'; field: 'str'; where: 'type' = 'fruit'; bfield: 'base_field')
    	add: listAdd(list: $list; item: $#nfv)
    	list: selectList(table: 'values_for_select'; field: 'base_field'; where: 'type' = "fruit")

	s2: selectRowListForSelect(table: 'values_for_select'; field: 'str'; bfield: 'base_field'; order: 'title' asc)
```

Теперь посмотрим, как это выглядит. Вот у нас картошка, и теперь она не зачеркнута. Мы убираем галочку, и теперь у нас есть капуста в дополнение к картошке. Ставим галочку обратно. Мы видим только картошку, то есть то, что мы выбрали, мы не видим капусту, но если мы уберем галочку, мы видим и картошку, и капусту и можем их выбрать. То же самое работает с капустой. Когда у нас выбрана капуста, это значение добавляется в выборку, и все работает нормально.

Третий случай: это скрытиестроки из исходной таблицы.

Как это выглядит? Вот у нас есть исходная таблица, и в настройках таблицы в разделе удаления строк тип удаления по умолчанию — удаление. Это когда мы нажимаем удалить, строка будет удалена из базы данных без возможности восстановления. Второй вариант, который можно здесь выбрать, это опция скрыть. Я установлю в этой таблице скрытие строк, вместо удаления. Видите, здесь появились кнопки восстановления и вернуться. И что здесь происходит? Когда мы удаляем (теперь кнопка помечена как скрыть), мы скрываем эту строку, и она перемещается вот сюда, в скрытые. Мы можем вернуться. Из скрытых мы можем восстановить ее. В тех таблицах, которые обращались к этому значению, это значение будет зачеркнуто. Мы все еще видим отображение по этой базе. При этом, если по правой кнопке мыши посмотреть основание селекта, то мы его увидим без зачеркивания. То есть, основание селекта осталось. Но в поле, куда берется селект, мы видим именно отображение, и оно зачеркнуто. Это означает, что таблица, из которой берутся эти значения, имеет настройку удаления — скрытие. И именно эта строка там скрыта.

Почему в селекте могут отображаться не основания и не отображения, а какие-то другие данные?

Такое возможно, если вы берете селект из селекта.

Возьмем список. Он проще предыдущего примера. Так как селект используется чаще всего без какого-либо base_field, с id в качестве оснований, то здесь рассматривается именно такой пример. Нам дана таблица и поле, которое мы отображаем.

```totum
= : selectRowListForSelect(table: 'values_for_select'; field: 'str'; order: 'title' asc)
```

В первом селекте в сточной части мы видим отображения из первого селекта. И мы сделаем еще один селект, который содержит только эти значения. В реальной ситуации мы можем сделать так, например, доступные документы для отправки, а затем уже конкретный документ, который мы отправляем.

Давайте добавим здесь селект. И я назову его select. Это селект. Это тип select. И что люди обычно делают здесь? Я сейчас делаю неправильно, как пример. Здесь, в текущей таблице, мы берем селект по select — поле select_in_row.

```totum
= : selectRowListForSelect(table: $#ntn; field: 'select_in_row')
```

И что мы здесь видим? Да, мы видим эти значения: 4, и вот здесь 4. То есть мы действительно видим только значения, которые у нас есть здесь, но мы видим их в какой-то странной форме. Мы не видим orange, potato и passion, но мы видим 1, 5 и 3. Почему так? Мы нажимаем здесь и видим, что есть база. У нас есть 2. Так что это id отсюда. А отображение — пять. Дело в том, что orange-potato-passion — это виртуальные отображения значений. А реальные значения — это: 1, 5 и 3, и при таком коде отображаются значения (основания) селекта из первоначальной таблицы.

Как сделать так, чтобы это работало правильно?

Идея в том, что вы должны ссылаться на ту же таблицу здесь, в этом поле, что и этот select в части строк. Итак, мы говорим здесь, что берем из таблицы values_for_select и говорим, что берем здесь поле title, и чтобы показывать только значения, которые находятся в Строчной части, мы должны указать ограничения. `where` id — потому что у этого селекта нет bfield — id используется как значения — равно списку. Что такое список? Список — это selectList. Мы берем значения из текущей таблицы из поля select_in_row. Мы берем все значения. Итак, мы также берем из исходной таблицы — из той же таблицы, из которой берутся эти selectList, мы берем поля title с ограничением по id.

```totum
= : selectRowListForSelect(table: 'values_for_select'; field: 'title'; where: 'id' = $list)

list: selectList(table: $#ntn; field: 'select_in_row')
```

Теперь всё работает корректно.
Давайте выберем другое значение, passionfruit — будет три. И вот оно — passionfruit — три! То есть база та же. В этом суть селектов — мы привязываемся к одним и тем же базам, но могут быть разные отображения, и мы можем привязываться из разных мест. Но важно то, что мы привязываемся к одной и той же исходной таблице.

Если мы сейчас перейдем в таблицк values_for_select и, например, добавим к orange двойку, мы увидим двойку, когда обновим в поле селекта из селекта. То есть все места, которые привязаны к этой исходной таблице, они все обновляются без перерасчета таблиц, в которых они размещены, потому что значения в них остаются неизменными.

Итак, если взять селект по селекту, то в этом случае мы увидим в качестве отображений — значения первого селекта, выбранные во втором. Чтобы этого избежать, нужно брать селект из первого селекта, в котором основание равно списку значений второго селекта.

### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai"></a> Дополнительные вопросы

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai1"></a> Что произойдет, если строка, на которую ссылался селект, будет удалена?

Если строка, на которую ссылался селект, будет удалена, в поле селекта будет отображаться зачеркнутое значение. Это связано с тем, что селект хранит `id` строки из таблицы-источника, и если эта строка удалена, то отображение для этого `id` больше не доступно. В результате, в интерфейсе Totum вы увидите зачеркнутое отображение, указывающее на то, что выбранное значение больше не существует в таблице-источнике.

Аналогичная ситуация может произойти, если включен Индивидуальный расчет селекта, код селекта имеет условие выборки и отображение для выбранного в поле значения, перестало попадать в условие выборки.

Чтобы избежать такой ситуации, можно использовать подход, при котором текущее значение всегда добавляется в выборку, даже если оно больше не соответствует условиям выборки. Это можно сделать, добавив текущее значение в список `id`, используемый в выборке. Пример кода селекта для этого:

```totum
=: selectRowListForSelect(table: 'table_name'; field: 'field_name'; where: 'id' = $listAdd)

listAdd: listAdd(list: $list; item: $#nfv)
	list: selectList(table: 'table_name'; field: 'id'; where: 'condition' = #condition_field)
```

В этом примере, даже если строка была удалена или больше не соответствует условиям выборки, отображение для текущего значения будет добавлено в выборку, и его отображение не будет зачеркнуто.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai2"></a> Что произойдет, если в поле селекта выбрано значение строки, которая была скрыта в таблице источнике?

Если в поле селекта было выбрано значение строки, которая была скрыта в таблице источнике, то в веб-интерфейсе Totum это значение будет отображаться зачеркнутым.

Это связано с тем, что скрытые строки в таблице источнике остаются доступными для выборки, но их отображение в селекте помечается как недоступное (`is_del = true`), чтобы пользователь мог видеть, что это значение больше не активно.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai3"></a> Что сделать, чтобы значение, которое было выбрано, когда оно было доступно, а потом стало недоступным, корректно отображалось в поле селекта?

Чтобы значение, которое было выбрано в поле селекта, когда оно было доступно, а потом стало недоступным, корректно отображалось в поле селекта, необходимо расширить выборку значений, добавив в нее текущее выбранное значение. Это позволит избежать ситуации, когда выбранное значение отображается зачеркнутым из-за того, что оно больше не соответствует условиям выборки.

Для этого можно использовать функцию `listAdd`, чтобы добавить текущее значение в список `id`, используемый в выборке. Вот пример кода, который демонстрирует, как это сделать:

```totum
=: selectRowListForSelect(table: 'table_name'; field: 'field_name'; where: 'id' = $listAdd)

listAdd: listAdd(list: $list; item: $#nfv)
	list: selectList(table: 'table_name'; field: 'id'; where: 'condition' = #condition_field)
```

**Объяснение кода:**

1. **selectRowListForSelect**: Используется для получения списка значений из таблицы `table_name`, которые будут отображаться в селекте.

2. **listAdd**: Функция, которая добавляет текущее значение поля в список `id`, используемый для выборки. Это гарантирует, что текущее значение всегда будет присутствовать в выборке, даже если оно больше не соответствует условиям.

3. **$#nfv**: Переменная, представляющая текущее значение в поле селекта.

4. **selectList**: Получает список `id` из таблицы `table_name`, которые соответствуют заданному условию `where: 'condition' = #condition_field`.

Таким образом, даже если значение больше не соответствует условиям выборки, оно будет корректно отображаться в поле селекта, так как всегда будет добавлено в выборку.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai4"></a> По какой причине в поле селекта могут быть зачеркнутые данные?

В поле селекта в системе Totum зачеркнутые данные могут появляться по нескольким причинам:

1. **Удаленная строка**: Если строка, на которую ссылался селект, была удалена из таблицы-источника, то в поле селекта будет отображаться зачеркнутое значение. Это связано с тем, что селект хранит `id` строки, и если эта строка удалена, то отображение для этого `id` больше не доступно.

2. **Недоступное отображение по условиям селекта**: Если отображение для выбранного значения стало недоступным из-за изменения условий выборки, то оно будет показано зачеркнутым. Это может произойти, если селект настроен с использованием условий, и выбранное значение больше не соответствует этим условиям.

Чтобы избежать ситуации с зачеркнутыми значениями в этом случае, можно использовать подход, при котором текущее значение всегда добавляется в выборку, даже если оно больше не соответствует условиям выборки. Это можно сделать, добавив текущее значение в список `id`, используемый в выборке. Пример кода селекта для этого:

```totum
=: selectRowListForSelect(table: 'table_name'; field: 'field_name'; where: 'id' = $listAdd)

listAdd: listAdd(list: $list; item: $#nfv)
	list: selectList(table: 'table_name'; field: 'id'; where: 'condition' = #condition_field)
```

3. **Скрытая строка**: Если строка в таблице-источнике была скрыта (но не удалена), то в веб-интерфейсе Totum это значение будет отображаться зачеркнутым. Скрытые строки остаются доступными для выборки, но их отображение помечается как недоступное.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai5"></a> Как выглядит код для построения селекта с учетом текущего значения?

Для построения селекта с учетом текущего значения в системе Totum, необходимо использовать функцию `selectRowListForSelect` и добавить текущее значение в список значений, которые будут отображаться в селекте. Это позволяет гарантировать, что текущее значение будет отображаться, даже если оно не соответствует условиям выборки.

Вот пример кода, который демонстрирует, как это сделать:

```totum
=: selectRowListForSelect(table: 'table_name'; field: 'display_field'; where: 'id' = $listAdd)

listAdd: listAdd(list: $list; item: $#nfv)
    list: selectList(table: 'table_name'; field: 'id'; where: 'condition_field' = #condition_value)
```

**Объяснение кода:**

1. **`selectRowListForSelect`**: Эта функция используется для получения списка значений, которые будут отображаться в селекте. Она принимает параметры `table` и `field`, которые указывают, из какой таблицы и какое поле брать для отображения.

2. **`listAdd`**: Эта функция добавляет текущее значение поля в список значений, которые будут отображаться в селекте. Это гарантирует, что текущее значение будет отображаться, даже если оно не соответствует условиям выборки.

3. **`$#nfv`**: Это быстрая переменная, которая возвращает текущее значение поля. Она используется для добавления текущего значения в список значений селекта.

4. **`selectList`**: Эта функция используется для получения списка `id` из таблицы, которые соответствуют заданному условию. В данном случае, условие задается через `where: 'condition_field' = #condition_value`.

Таким образом, данный код позволяет построить селект, который будет учитывать текущее значение, даже если оно не соответствует условиям выборки.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai6"></a> Почему отображается зачеркнутое значение поля?

В системе Totum зачеркнутое значение в поле типа "Селект" может отображаться по нескольким причинам:

1. **Удаленная строка**: Если строка, на которую ссылался селект, была удалена из таблицы-источника, то в поле селекта будет отображаться зачеркнутое значение. Это связано с тем, что селект хранит `id` строки, и если эта строка удалена, то отображение для этого `id` больше не доступно.

2. **Недоступное отображение по условиям селекта**: Если отображение для выбранного значения стало недоступным из-за изменения условий выборки, то оно будет показано зачеркнутым. Это может произойти, если селект настроен с использованием условий, и выбранное значение больше не соответствует этим условиям.

Чтобы избежать ситуации с зачеркнутыми значениями в этом случае, можно использовать подход, при котором текущее значение всегда добавляется в выборку, даже если оно больше не соответствует условиям выборки. Это можно сделать, добавив текущее значение в список `id`, используемый в выборке. Пример кода селекта для этого:

```totum
=: selectRowListForSelect(table: 'table_name'; field: 'field_name'; where: 'id' = $listAdd)

listAdd: listAdd(list: $list; item: $#nfv)
	list: selectList(table: 'table_name'; field: 'id'; where: 'condition' = #condition_field)
```

3. **Скрытая строка**: Если строка в таблице-источнике была скрыта (но не удалена), то в веб-интерфейсе Totum это значение будет отображаться зачеркнутым. Скрытые строки остаются доступными для выборки, но их отображение помечается как недоступное.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai7"></a> Как происходит выбор значений в селекте без base-field?

В системе Totum, когда вы используете поле типа "Селект" без указания параметра `bfield` (base-field), основанием для выбора значений в селекте по умолчанию является `id` строки в таблице-источнике. Это означает, что в ячейке поля "Селект" хранится `id` строки, а отображение этого значения рассчитывается на основе кода селекта.

**Как происходит выбор значений в селекте без base-field:**

1. **Код селекта**:
   - Код селекта определяет, какие значения будут доступны для выбора в выпадающем списке. Он может использовать функции, такие как `selectRowListForSelect`, для получения списка значений из таблицы-источника.

   Пример кода селекта:

```totum
=: selectRowListForSelect(table: 'products'; field: 'product'; order: 'product' asc)
```

2. **Формирование списка значений**:
   - Функция `selectRowListForSelect` возвращает список ассоциированных массивов, где каждый элемент содержит `value` (основание) и `title` (отображение).

   Пример результата:

   ```json
   [
     {"value": 1, "title": "Product A", "is_del": false},
     {"value": 2, "title": "Product B", "is_del": false},
     {"value": 3, "title": "Product C", "is_del": false}
   ]
   ```

3. **Отображение значений**:
   - В интерфейсе пользователю показывается `title` (отображение) из списка значений, но в ячейке хранится `value` (основание), которое по умолчанию является `id` строки.

4. **Выбор значения**:
   - Пользователь выбирает значение из выпадающего списка, и в ячейке сохраняется соответствующий `id` строки из таблицы-источника.

Таким образом, в селекте без указания `bfield` основанием для выбора значений является `id` строки, а отображение рассчитывается на основе кода селекта, который определяет, какие значения и в каком виде будут доступны для выбора.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai8"></a> Как скрытие строки отличается от её удаления в контексте селектов?

В контексте селектов в системе Totum, скрытие строки отличается от её удаления следующим образом:

1. **Удаление строки**:
   - Когда строка удаляется, она полностью удаляется из базы данных. Это означает, что все ссылки на эту строку в селектах становятся недействительными, и если значение из удаленной строки было выбрано в селекте, оно будет отображаться как зачеркнутое.
   - Удаленные строки не могут быть восстановлены, и данные из этих строк становятся недоступными для выборки через селекты.

2. **Скрытие строки**:
   - Скрытие строки предполагает, что строка остается в базе данных, но помечается как скрытая. Это позволяет восстановить строку в будущем, если это необходимо.
   - В селектах скрытые строки могут отображаться с зачеркнутым отображением, если они были выбраны до того, как стали скрытыми. Однако, данные из скрытых строк остаются доступными для отображения через селекты, но выбрать скрытое значение будет нельзя.

Таким образом, основное отличие заключается в том, что удаленные строки полностью исчезают из базы данных и становятся недоступными, в то время как скрытые строки остаются в базе данных и могут быть восстановлены или продолжать использоваться в селектах, если это необходимо.

#### <a name="crossed-out-selects-and-what-it-may-be-related-to-ai9"></a> Как скрытые строки отображаются в селекте?

В системе Totum скрытые строки в селекте отображаются как зачеркнутые значения. Это происходит в случае, если строка была скрыта в таблице-источнике, из которой берутся значения для селекта.

**Как это работает:**

1. **Скрытие строк**: В настройках таблицы может быть задано, что строки не удаляются, а скрываются. Это позволяет восстановить их в будущем, если потребуется. Такие строки остаются в базе данных, но не отображаются в обычном интерфейсе.

2. **Отображение в селекте**: Если в поле селекта было выбрано значение строки, которая была скрыта, то в выпадающем списке селекта это значение будет отображаться зачеркнутым. Это сигнализирует пользователю о том, что данное значение больше не активно или не доступно по текущим условиям выборки.

В этом примере, если строка была скрыта, но ее значение все еще выбрано в селекте, она будет отображаться зачеркнутой. Это позволяет пользователю видеть, что значение больше не активно.

### <a name="single-or-multiple-selections-ai"></a> Дополнительные вопросы

#### <a name="single-or-multiple-selections-ai1"></a> Какой вид у значения одинарного селекта?

В системе Totum, когда у селекта отключен параметр "множественные значения", это называется одинарным селектом. В этом случае пользователь может выбрать только одно значение из выпадающего списка. В качестве основания в ячейке хранится одно значение, которое представляет собой `id` строки в таблице-источнике или кодовое значение, если используется другой `bfield`. Это значение называется "значением" или "основанием" селекта. Отображение этого значения рассчитывается по формуле, заданной в параметре поля "код селекта".

Пример кода для одинарного селекта:

```totum
=: selectRowListForSelect(table: 'products'; field: 'product'; order: 'product' asc)
```

Таким образом, в одинарном селекте хранится одно значение, которое связано с отображением, видимым пользователю.

#### <a name="single-or-multiple-selections-ai2"></a> Какой вид у значения множественного селекта?

В системе Totum, когда у селекта включен параметр "множественные значения", это называется множественным селектом. В этом случае пользователь может выбрать множество значений, и в качестве основания хранится список. Если выбрано одно значение, то будет храниться список из одного значения.

#### <a name="single-or-multiple-selections-ai3"></a> Что будет, если одинарный селект со значениями изменить на множественный?

Если в системе Totum изменить одинарный селект на множественный, вам потребуется пересчитать строки в таблице. При этом значения сохранятся, но будут преобразованы в список. Это означает, что если ранее в поле было выбрано одно значение, то после изменения на множественный селект это значение будет храниться в виде списка, содержащего одно значение.

**Пример:**

Если у вас был одинарный селект с выбранным значением, например, "картофель", то после изменения на множественный селект это значение будет храниться как список: `["картофель"]`.

**Действия:**

1. **Измените тип селекта**: Перейдите в настройки поля и включите параметр "множественные значения".
2. **Пересчитайте строки**: После изменения типа селекта необходимо пересчитать строки в таблице, чтобы обновить формат хранения значений.

**Важно:**

- **Сохранение данных**: Все текущие значения сохранятся, но будут преобразованы в списки.
- **Обратное изменение**: Если вы решите изменить множественный селект обратно на одинарный, то сохранится только одно значение в каждой строке, выбранное машиной случайным образом. Поэтому будьте осторожны при изменении типа селекта в работающем решении с уже заполненными данными.

#### <a name="single-or-multiple-selections-ai4"></a> Что будет, если множественный селект со значениями изменить на одинарный?

Если в системе Totum изменить множественный селект на одинарный, вам потребуется пересчитать строки в таблице. При этом сохранится только одно значение в каждой строке, выбранное машиной случайным образом. Это означает, что если в поле было выбрано несколько значений, то после изменения на одинарный селект останется только одно из них, и вы не сможете предсказать, какое именно значение будет сохранено. Поэтому важно быть осторожным при изменении типа селекта в работающем решении с уже заполненными данными, чтобы избежать потери информации.

#### <a name="single-or-multiple-selections-ai5"></a> Как изменить селект на множественный?

Чтобы изменить селект на множественный в системе Totum, необходимо выполнить следующие шаги:

1. **Откройте таблицу**, в которой находится поле типа Селект, которое вы хотите изменить на множественный.

2. **Найдите поле Селект**, которое вы хотите изменить.

#### <a name="single-or-multiple-selections-ai6"></a> Что происходит, если множественные значения перевести в одиночные?

Если в системе Totum изменить множественный селект на одинарный, вам потребуется пересчитать строки в таблице. При этом сохранится только одно значение в каждой строке, выбранное машиной случайным образом. Это означает, что если в поле было выбрано несколько значений, то после изменения на одинарный селект останется только одно из них, и вы не сможете предсказать, какое именно значение будет сохранено. Поэтому важно быть осторожным при изменении типа селекта в работающем решении с уже заполненными данными, чтобы избежать потери информации.

#### <a name="single-or-multiple-selections-ai7"></a> Что будет при получении кодом данных из поля с множественным селектом?

Это означает, что если вы используете функцию `select` для получения данных из поля с множественным селектом, вы получите список значений, которые были выбраны в этом поле.

Для того чтобы преобразовать этот список списков в один плоский список, вы можете использовать функцию `listTrain`, которая "склеивает" все внутренние списки в один. Если вам нужно получить уникальные значения из этого списка, вы можете дополнительно использовать функцию `listUniq`.

В этом примере:

- `selectList` получает список списков значений из поля с множественным селектом.
- `listTrain` объединяет все списки в один.

#### <a name="single-or-multiple-selections-ai8"></a> Что будет взято, если значение множественного селекта берется функцией select?

Когда вы берете значение множественного селекта с помощью функции `select` в системе Totum, вы получаете список. Это связано с тем, что множественный селект хранит значения в виде списка, и функция `select` возвращает этот список целиком.

#### <a name="single-or-multiple-selections-ai9"></a> Как преобразовать список-списков в один список?

В системе Totum, чтобы преобразовать список-списков в один список, можно использовать функцию `listTrain`. Эта функция объединяет все внутренние списки в один общий список. Давайте рассмотрим, как это можно сделать на примере.

- **`list_of_lists`**: Это строка кода, содержащая список-списков. В данном примере это JSON-строка, представляющая список из трех списков: `[1, 2]`, `[3, 4]`, и `[5, 6]`.

**Результат**

После выполнения кода, функция `listTrain` вернет один список, содержащий все элементы из внутренних списков: `[1, 2, 3, 4, 5, 6]`.

Таким образом, функция `listTrain` позволяет легко и эффективно преобразовать список-списков в один список в системе Totum.

#### <a name="how-do-I-replace-the-id-with-a-different-identifier-ai1"></a> Можно ли в основании селекта заменить id на другой идентификатор?

Да, в системе Totum можно заменить `id` на другой идентификатор в основании селекта. Для этого используется параметр `bfield` в функции `selectRowListForSelect`. Этот параметр позволяет указать, какое поле будет являться основанием (значением) селекта вместо `id`.

**Пример использования `bfield`:**

```totum
=: selectRowListForSelect(table: 'table_name'; field: 'name'; bfield: 'uuid')
```

В этом примере в качестве основания селекта используется поле `uuid` вместо стандартного `id`. Это может быть полезно, если в вашем решении для соответствий используются уникальные артикулы или другие идентификаторы, отличные от `id`.

**Важные моменты:**

- **Уникальность**: Убедитесь, что значения в поле, указанном в `bfield`, уникальны. Если идентификаторы не уникальны, отображение для одинаковых значений `bfield` будет браться случайным образом.

- **Изменение идентификатора**: Если в поле Селект уже были проставлены значения, то при изменении идентификатора они не будут автоматически изменены на новые. Вы увидите зачеркнутые значения.

- **Склеивание селектов**: Можно склеить селект из нескольких таблиц, используя параметр `bfield` и функцию `listAdd`. `bfield` используется для того, что бы идентификаторы из двух таблиц не пересекались.

**Пример склеивания селектов:**

```totum
=: listAdd(list: $s1; list: $s2)

s1: selectRowListForSelect(table: 'table_1'; field: 'name'; bfield: 'uuid')
s2: selectRowListForSelect(table: 'table_2'; field: 'name'; bfield: 'uuid')
```

Таким образом, использование параметра `bfield` позволяет гибко управлять основаниями селектов в системе Totum.

#### <a name="how-do-I-replace-the-id-with-a-different-identifier-ai2"></a> Можно ли склеить селект из нескольких таблиц?

Да, в системе Totum можно склеить селект из нескольких таблиц. Это обычно делается для селектов, где используется параметр `bfield`, так как `id` из двух разных таблиц могут повторяться. Для склеивания селектов из нескольких таблиц используется функция `listAdd`, которая объединяет списки значений из разных таблиц.

**Пример кода для склеивания селектов из нескольких таблиц:**

```totum
=: listAdd(list: $s1; list: $s2)

s1: selectRowListForSelect(table: 'table_1'; field: 'name'; bfield: 'uuid')
s2: selectRowListForSelect(table: 'table_2'; field: 'name'; bfield: 'uuid')
```

В этом примере:

- `s1` и `s2` — это селекты, полученные из разных таблиц (`table_1` и `table_2`), где в качестве основания используется поле `bfield` с уникальными значениями (`uuid` и `uuid`).
- `listAdd` объединяет эти два списка в один, создавая общий селект, который можно использовать в поле.

**Важные моменты:**

- **Уникальность оснований**: Убедитесь, что значения в полях `bfield` уникальны, чтобы избежать конфликтов при объединении списков.
- **Сортировка**: Если необходимо, можно дополнительно отсортировать объединенный список с помощью функции `listSort`.

Таким образом, склеивание селектов из нескольких таблиц позволяет гибко управлять данными и создавать сложные структуры выбора в системе Totum.

#### <a name="how-do-I-replace-the-id-with-a-different-identifier-ai3"></a> Что делать, если чтобы основания селекта не пересекались в двух таблицах при объединении?

2. **Используйте параметр `bfield`**: При вызове функции `selectRowListForSelect` укажите это поле в качестве `bfield`.

**Пример кода:**

Предположим, у вас есть две таблицы: `table_1` и `table_2`. В каждой из них вы создаете поле `base_field`, которое будет содержать уникальные значения.

Для создания сквозного выбора из двух таблиц в системе Totum следует использовать функцию `listAdd`. Эта функция позволяет объединить селекты из нескольких таблиц в один общий список. #### <a name="how-do-I-replace-the-id-with-a-different-identifier-ai6"></a> Что делает параметр 'bfield' в функции selectRowListForSelect?

Параметр `bfield` в функции `selectRowListForSelect` используется для изменения основания селекта на другое поле, отличное от `id`. По умолчанию основанием (значением) в селекте является `id` строки в таблице источнике. Однако, если в вашем решении для соответствий используются уникальные артикулы или другие уникальные идентификаторы, вы можете указать другое поле в качестве основания, используя параметр `bfield`.

**Пример использования `bfield`:**

```totum
=: selectRowListForSelect(table: 'table_name'; field: 'name'; bfield: 'uuid')
```

В этом примере основанием селекта будет не `id`, а значение из поля `uuid`. Это позволяет использовать уникальные идентификаторы, которые могут быть более подходящими для вашего конкретного случая.

**Важные моменты:**

- Основания в таблице источнике должны быть уникальными. Если это не так, то отображение для одинаковых значений `bfield` будет браться случайным образом.
- Если в поле Селект уже были проставлены значения, то при изменении идентификатора они не будут автоматически изменены на новые, и вы увидите зачеркнутые значения.

#### <a name="how-do-I-replace-the-id-with-a-different-identifier-ai7"></a> Почему после изменения базового поля в select значения становятся зачеркнутыми?

В системе Totum, когда вы изменяете базовое поле (bfield) в настройках селекта, значения, которые уже были выбраны в этом поле, могут стать зачеркнутыми. Это происходит по следующим причинам:

1. **Изменение основания**: Базовое поле (bfield) определяет, какое значение будет использоваться в качестве основания для селекта. По умолчанию это `id` строки в таблице источнике. Когда вы изменяете bfield на другое поле, например, на уникальный артикул, система больше не может сопоставить старые значения с новыми основаниями, так как они теперь ссылаются на другие данные.

2. **Несоответствие значений**: Если в поле селекта уже были проставлены значения, то при изменении идентификатора (основания) они не будут автоматически изменены на новые. Вместо этого, система не сможет найти соответствие между старым значением и новым основанием, и такие значения будут отображаться зачеркнутыми.

3. **Отсутствие отображения**: Зачеркнутые значения указывают на то, что система не может найти отображение для текущего значения в новом наборе данных, определяемом измененным bfield. Это визуальный индикатор того, что текущее значение больше не соответствует ни одному из доступных значений в селекте.

**Как исправить ситуацию:**

- **Обновление значений**: После изменения bfield, вам может потребоваться обновить значения в поле селекта, чтобы они соответствовали новым основаниям. Это можно сделать вручную или с помощью кода, который пересчитает и обновит значения в соответствии с новым bfield.

- **Проверка уникальности**: Убедитесь, что новое базовое поле содержит уникальные значения, чтобы избежать конфликтов и обеспечить корректное отображение данных.

- **Использование кода**: Если у вас много строк, вы можете использовать код для автоматического обновления значений в поле селекта, чтобы они соответствовали новым основаниям.

Таким образом, изменение базового поля в селекте требует внимательного подхода к обновлению данных, чтобы избежать появления зачеркнутых значений и обеспечить корректное отображение информации.

#### <a name="how-do-I-replace-the-id-with-a-different-identifier-ai8"></a> Как отсортировать объединенный список значений из двух таблиц?

Чтобы отсортировать объединенный список значений из двух таблиц в системе Totum, вы можете использовать функции `listAdd` и `listSort`. Сначала объедините списки значений из двух таблиц с помощью `listAdd`, а затем отсортируйте объединенный список с помощью `listSort`.

**Пример кода**

```totum
=: listSort(list: $combinedList; type: "string"; direction: "asc"; key: "title")

combinedList: listAdd(list: $list1; list: $list2)

list1: selectRowListForSelect(table: 'table_1'; field: 'name'; bfield: 'uuid_1')
list2: selectRowListForSelect(table: 'table_2'; field: 'name'; bfield: 'uuid_2')
```

**Объяснение кода**

1. **`list1` и `list2`**: Эти строки кода используют функцию `selectRowListForSelect` для получения списков значений из двух разных таблиц (`table_1` и `table_2`). Параметр `bfield` указывает на поле, которое будет использоваться в качестве основания для селекта.

2. **`combinedList`**: Используется функция `listAdd` для объединения двух списков (`list1` и `list2`) в один.

3. **`listSort`**: Функция `listSort` сортирует объединенный список `combinedList`. Параметры `type: "string"` и `direction: "asc"` указывают, что сортировка будет по строкам в порядке возрастания. Параметр `key: "title"` указывает, что сортировка будет по полю `title` в ассоциированных массивах.

Этот код позволяет объединить и отсортировать значения из двух таблиц, обеспечивая удобное отображение данных в интерфейсе Totum.

Выражение `=: select(table: $#ntn; field: ‘h_field_name’)` при обращении к полю типа select в системе Totum вернет значение (основание) этого поля. Если вам необходимо получить отображение значения, а не его основание, следует использовать параметр `sfield` вместо `field` в функции `select`. Например:

```totum
=: select(table: $#ntn; sfield: 'h_field_name')
```

Это выражение вернет отображение значения из поля select.

В системе Totum, когда вы обращаетесь к полю селекта через `#`, вы получаете значение, которое хранится в этом поле, а не его отображение. В случае, если основанием является `id`, именно это значение будет возвращено.

#### <a name="how-do-I-take-the-value-of-a-select-ai4"></a> Что вернет выражение ´#field_name´ если основание указано в параметре ‘bfield’?

В системе Totum, если основание указано в параметре `bfield` для поля типа Селект, то выражение `#field_name` вернет значение из `bfield`. Это означает, что вместо стандартного `id` строки в таблице источнике, в качестве значения будет использоваться то, что указано в `bfield`.

Таким образом, `#field_name` будет возвращать значение, которое хранится в поле, указанном в `bfield`, и это значение будет использоваться как основание для селекта.

#### <a name="how-do-I-take-the-value-of-a-select-ai5"></a> Как работает функция select при обращении к полю с селектом?

В системе Totum функция `select` при обращении к полю с типом "Селект" возвращает значение основания селекта, а не его отображение. Это означает, что если в поле "Селект" хранится значение, которое является `id` строки в таблице-источнике, то функция `select` вернет именно это значение `id`, а не отображаемое значение, которое видит пользователь.

**Пример использования функции `select`:**

```totum
=: select(table: 'table_name'; field: 'select_field'; where: 'id' = 1)
```

В этом примере функция `select` возвращает значение основания (например, `id`), которое хранится в поле `select_field` в таблице `table_name`.

**Как получить отображение?**

Если вам необходимо получить отображение, а не значение основания, вы можете использовать параметр `sfield` вместо `field` в функции `select`. Это позволит вам получить отображаемое значение, которое видит пользователь.

**Пример получения отображения:**

```totum
=: select(table: 'table_name'; sfield: 'select_field'; where: 'id' = 1)
```

В этом примере функция `select` с параметром `sfield` вернет отображаемое значение из поля `select_field`.

**Важные замечания:**

- Использование `sfield` может быть более нагруженной операцией, так как требует дополнительного расчета отображения.
- Если селект индивидуальный и зависит от других полей, необходимо указать эти поля в параметре `tfield`.

Таким образом, функция `select` позволяет гибко работать с полями типа "Селект", предоставляя возможность получать как значения оснований, так и их отображения в зависимости от ваших потребностей.

#### <a name="how-do-I-take-the-value-of-a-select-ai6"></a> Как взять отображение селекта вместо его значения?

В системе Totum, чтобы взять отображение селекта вместо его значения, можно использовать несколько подходов. Давайте рассмотрим их подробнее.

**Способ 1: Использование префикса `s` для поля**

Если вы хотите получить отображение селекта непосредственно из текущей таблицы, вы можете использовать префикс `s` перед именем поля. Это позволяет получить отображение, а не значение.

Пример:
```totum
=: #s.select_field
```

**Способ 2: Использование параметра `sfield` в функции `select`**

Если вы используете функцию `select` для получения данных из таблицы, вы можете использовать параметр `sfield` вместо `field`, чтобы получить отображение селекта.

Пример:
```totum
=: select(table: 'table_name'; sfield: 'select_field'; where: 'id' = 1)
```

**Способ 3: Прямой запрос к таблице-источнику**

Если вы знаете таблицу-источник и поле, из которого берется отображение, вы можете сделать прямой запрос к этой таблице, чтобы получить отображение на основе значения селекта.

Пример:
```totum
=: select(table: 'source_table'; field: 'display_field'; where: 'id' = #select_value)
```

**Важные замечания**

- Использование префикса `s` и параметра `sfield` может быть нагруженной операцией, так как при каждом использовании рассчитываются отображения вызываемых селектов. Поэтому, если это возможно, лучше использовать прямой запрос к таблице-источнику.
- Убедитесь, что вы правильно указываете таблицу и поле, из которого берется отображение, чтобы избежать ошибок в коде.

Эти методы позволяют гибко получать отображение селекта в зависимости от ваших потребностей и структуры данных в системе Totum.

#### <a name="how-do-I-take-the-value-of-a-select-ai7"></a> Что делает префикс s в выражении ´#s.field_name´?

Префикс `s` в выражении `#s.field_name` используется для получения отображения значения из поля типа Селект в текущей таблице. Например, если в поле `field_name` хранится значение, выбранное из Селекта, то выражение `#s.field_name` вернет отображение этого значения, а не само значение.

**Контекст использования**

- **Значение vs. Отображение**: В поле типа Селект хранится значение (обычно это `id` строки в таблице-источнике), но пользователю отображается не это значение, а его отображение, которое рассчитывается по формуле, заданной в параметре поля 'код селекта'.

- **Нагрузка на сервер**: Обращение через `#s.field_name` может быть нагруженной операцией, так как при каждом использовании рассчитывается отображение вызываемого селекта. Это может замедлить работу системы, особенно если таких обращений много.

**Пример использования**

Если у вас есть поле Селект, которое хранит `id` продукта, но вы хотите отобразить название продукта, вы можете использовать `#s.field_name` для получения названия:

```totum
=: #s.product_name
```

В этом примере `product_name` — это поле типа Селект, и `#s.product_name` вернет название продукта, а не его `id`.

**Альтернативы**

Если вам нужно часто получать отображение, и вы хотите снизить нагрузку на сервер, вы можете использовать функцию `select` для получения отображения из таблицы источника селекта:

```totum
=: select(table: 'source_table'; field: 'display_field'; where: 'id' = #select_value)
```

В этом примере `select` вернет отображение для `select_value`, используя поле `display_field` в таблице `source_table`.

#### <a name="how-do-I-take-the-value-of-a-select-ai8"></a> Почему использование ´#s.field_name´ нагружает сервер?

Использование `#s.field_name` в системе Totum нагружает сервер, потому что в момент, когда исполняется такое обращение, отображение селекта рассчитывается еще раз. Это означает, что система должна повторно вычислить и загрузить данные для отображения селекта, что может потребовать дополнительных ресурсов и времени, особенно если селект основан на сложных условиях или больших объемах данных.

**Подробное объяснение:**

1. **Повторный расчет**: При обращении к `#s.field_name` система выполняет повторный расчет отображения для селекта. Это включает в себя выполнение кода селекта, который может содержать сложные условия, фильтры и сортировки.

2. **Доступ к данным**: Для расчета отображения система должна получить доступ к данным из таблицы-источника, что может включать выполнение запросов к базе данных. Если таблица-источник содержит большое количество данных, это может увеличить нагрузку на сервер.

Таким образом, использование `#s.field_name` может быть удобным для получения отображения селекта, но следует учитывать его влияние на производительность системы и использовать его с осторожностью, особенно в сценариях с большими объемами данных или частыми обращениями.

#### <a name="how-do-I-take-the-value-of-a-select-ai9"></a> Для чего используется параметр функции select - `tfield`

В системе Totum параметр `tfield` в функции `select` используется для указания полей, от которых зависит расчет отображения в индивидуальных селектах при запросе функцией `select` отображения поля Селект через параметр `sfield`.

**Пример использования параметра `tfield`**

Предположим, у вас есть таблица с полем типа Селект, и отображение значений в этом поле зависит от других полей в той же строке. В этом случае вы можете использовать параметр `tfield`, чтобы указать, от каких полей зависит расчет отображения, когда вам нужно кодом взять отображение:

```totum
=: select(table: 'products'; sfield: 'product_name'; tfield: 'category'; tfield: 'price')
```

В этом примере:

- **`sfield: 'product_name'`** — указывает поле, из которого берется отображение.
- **`tfield: 'category'` и `tfield: 'price'`** — указывают поля, от которых зависит расчет отображения. Это означает, что поля `category` или `price` будут загружены в процессе вычисления списка отображений.

Использование параметра `tfield` позволяет динамически обновлять отображение значений в поле Селект в зависимости от изменений в других полях, что делает систему более гибкой и адаптивной к изменениям данных.

#### <a name="how-do-I-take-the-value-of-a-select-ai10"></a> Как в параметрах функции select взять отображение поля селект вместо основания менее нагруженным для сервера способом чем #s.field или sfield?

В системе Totum, чтобы взять отображение поля типа Селект менее нагруженным для сервера способом, чем использование `#s.field` или параметра `sfield`, вы можете сделать прямой запрос к таблице-источнику, откуда берется отображение. В этом примере:
- **`table: 'products'`** — указывает таблицу, из которой берется отображение.
- **`field: 'product_name'`** — указывает поле, содержащее отображение.
- **`where: 'id' = #select_value`** — условие, которое связывает значение в поле Селект с `id` в таблице `products`.

**Объяснение**

- **Прямой запрос**: Вы делаете прямой запрос к таблице-источнику, что позволяет избежать повторного расчета селекта.
- **Условие**: Использование условия `where` позволяет точно выбрать нужное отображение на основе значения, хранящегося в поле Селект.

Этот подход позволяет эффективно получать отображение для значений в поле Селект, минимизируя нагрузку на сервер.

```totum
=: if(condition: #cond_field = 1; then: $t1; else: $t2)
t1: linkToPanel(table: 'table_1'; id: $#nfv)
t2: linkToPanel(table: 'table_2'; id: $#nfv)
```

В этом случае при добавлении новой позиции через поле селекта поле 'type' уже будет предзаполнено значением "fruit". Таким образом можно предзаполнить как одно поле, так и несколько полей в исходной таблице, из которой берется селект.

Если у вас есть селект, который берет отображения из разных таблиц в зависимости от условий, вы можете использовать условие `if` для выбора нужной таблицы:

```totum
=: if(condition: #cond_field = 1; then: $t1; else: $t2)

t1: linkToPanel(table: 'table_1'; id: $#nfv)

t2: linkToPanel(table: 'table_2'; id: $#nfv)
```

В этом примере:
- Если значение поля `#cond_field` равно 1, будет открыта таблица `table_1`.
- В противном случае будет открыта таблица `table_2`.

**Заключение**

Функция `linkToPanel` позволяет гибко настраивать открытие таблиц для редактирования значений селекта, что делает работу с данными более удобной и эффективной. Вы можете использовать эту функцию для создания динамических ссылок на таблицы в зависимости от условий и значений в других полях.

#### <a name="editing-a-source-ai10"></a> Как передать предзаполненное значение полю при добавлении нового значения в селект?

В системе Totum, чтобы передать предзаполненное значение полю при добавлении нового значения в селект, можно использовать параметр "панель селекта для изменения" и функцию `linkToPanel`. Это позволяет задать предзаполненные значения для полей в открывшейся панели добавления нового элемента.

**Шаги для передачи предзаполненного значения:**

1. **Откройте настройки поля типа Селект**: Перейдите в таблицу, где находится поле Селект, и откройте его настройки.

2. **Включите параметр "Таблица селекта для изменения"**: Убедитесь, что этот параметр активирован, так как он необходим для использования "панели селекта для изменения".

3. **Активируйте параметр "панель селекта для изменения"**: Включите этот параметр, чтобы использовать кастомный код для вызова панели.

4. **Напишите код с использованием `linkToPanel`**: Используйте функцию `linkToPanel` для передачи предзаполненных значений. Укажите таблицу, из которой осуществляется селект, и задайте предзаполненные значения для полей.

**Пример кода:**

```totum
=: linkToPanel(table: 'values_for_select'; id: $#nfv; field: 'type' = "fruit")
```

В этом примере:

- **`table: 'values_for_select'`** — указывает таблицу, из которой осуществляется селект.
- **`id: $#nfv`** — указывает идентификатор текущего значения.
- **`field: 'type' = "fruit"`** — задает предзаполненное значение для поля 'type' в открывшейся панели.

Таким образом, при добавлении нового значения через поле Селект, поле 'type' будет предзаполнено значением "fruit". Вы можете передать предзаполненные значения для нескольких полей, добавив дополнительные параметры `field` в функцию `linkToPanel`.

#### <a name="editing-a-source-ai11"></a> Какие значения можно предзаполнить при добавлении нового значения через селект?

В системе Totum при добавлении нового значения через селект можно предзаполнить любые поля в открываемой таблице. Это делается с помощью параметра `field` в функции `linkToPanel`. Вы можете указать, какие именно поля и какими значениями будут предзаполнены при открытии панели для добавления нового значения.

**Пример использования**

Допустим, у вас есть таблица, из которой вы берете значения для селекта, и вы хотите, чтобы при добавлении нового значения через селект поле `type` было предзаполнено значением `"fruit"`. Вы можете сделать это следующим образом в параметре поля "Панель селекта для изменения":

```totum
=: linkToPanel(table: 'values_for_select'; id: $#nfv; field: 'type' = "fruit")
```

В этом примере:

- `table: 'values_for_select'` — это таблица, из которой берутся значения для селекта.
- `id: $#nfv` — это идентификатор текущего значения в селекте.
- `field: 'type' = "fruit"` — это параметр, который указывает, что поле `type` в открываемой панели будет предзаполнено значением `"fruit"`.

Таким образом, при добавлении нового значения через селект, поле `type` уже будет иметь значение `"fruit"`, что упрощает процесс добавления и позволяет избежать ручного ввода повторяющихся данных. Вы можете предзаполнить как одно поле, так и несколько полей, указав их в параметре `field`.
