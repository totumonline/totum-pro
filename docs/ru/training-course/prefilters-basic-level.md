### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai"></a> Дополнительные вопросы

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai1"></a> Что такое префильтр и для чего он используется?

Префильтр в системе Totum — это инструмент, который позволяет ограничивать количество отображаемых строк в таблице на основе заданных условий. Он используется для фильтрации данных по определенным критериям, что позволяет быстро находить нужную информацию и улучшать производительность при работе с большими объемами данных.

**Основные функции префильтра:**

1. **Фильтрация строк**: Префильтр позволяет фильтровать строки, выводимые в браузер, в зависимости от заданных условий. Это особенно полезно, когда таблица содержит большое количество строк, и необходимо быстро найти определенные данные.

2. **Ограничение доступа**: Префильтр может ограничивать доступ для редактирования строк в зависимости от роли пользователя. Это позволяет контролировать, какие данные могут быть изменены пользователями с различными уровнями доступа.

3. **Использование как временной переменной**: Префильтр может использоваться как временная переменная для строчной части таблицы. Это позволяет использовать значения префильтра в вычислениях и логике таблицы.

4. **Автоподстановка значений**: Префильтр может автоматически подставлять значения в привязанные поля строчной части в строке добавления. Это упрощает процесс ввода данных и снижает вероятность ошибок.

**Пример использования префильтра:**

Префильтр может быть привязан к полю в строчной части таблицы, и в зависимости от введенного значения, таблица будет отображать только те строки, которые соответствуют этому значению. Например, если у вас есть таблица с заказами, вы можете использовать префильтр для отображения только тех заказов, которые были сделаны в определенный день или для определенного клиента.

**Заключение:**

Префильтр в системе Totum — это мощный инструмент, который позволяет гибко управлять отображением и доступом к данным в таблице в зависимости от различных условий. Это делает работу с большими объемами данных более эффективной и удобной.

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai2"></a> Почему таблицу с большим количеством строк невозможно полностью загрузить?

Таблицу с большим количеством строк невозможно полностью загрузить, потому что это может привести к перегрузке системы и замедлению работы приложения. Рассмотрим основные причины, почему это происходит:

1. **Ограничения производительности**: Загрузка большого объема данных требует значительных вычислительных ресурсов, таких как процессорное время и оперативная память. Если таблица содержит, например, 4 миллиона строк, попытка загрузить все их сразу может занять слишком много времени и ресурсов, что сделает приложение непригодным для использования.

2. **Ограничения браузера**: Браузеры имеют ограничения на количество данных, которые они могут обработать и отобразить одновременно. Загрузка слишком большого объема данных может привести к зависанию браузера.

3. **Пользовательский интерфейс**: Отображение большого количества строк в пользовательском интерфейсе может быть неудобным и неэффективным для пользователя. Пользователю будет сложно ориентироваться в таком объеме данных, и это может ухудшить пользовательский опыт.

4. **Сетевые ограничения**: Передача большого объема данных через сеть может занять значительное время, особенно если у пользователя медленное интернет-соединение. Это может привести к задержкам и ухудшению производительности приложения.

Для решения этой проблемы в системе Totum используются механизмы, такие как разбивка на страницы и префильтры, которые позволяют загружать и обрабатывать только необходимые данные. Это помогает оптимизировать производительность и улучшить пользовательский опыт, обеспечивая доступ к нужной информации без перегрузки системы.

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai3"></a> Почему разбивка таблицы на страницы не решает проблему фильтрации?

Разбивка таблицы на страницы в системе Totum не решает проблему фильтрации, потому что она лишь ограничивает количество отображаемых строк на одной странице, но не позволяет выбрать строки по определенным условиям. Это связано с тем, что фильтрация по колонке работает только с загруженной страницей, а не со всеми данными в таблице.

**Проблемы с разбивкой на страницы:**

1. **Ограничение видимости**: Разбивка на страницы ограничивает видимость данных только теми строками, которые загружены на текущей странице. Это не позволяет пользователю видеть и фильтровать данные, которые находятся на других страницах.

2. **Фильтрация только по загруженной странице**: Фильтры по колонкам применяются только к данным, которые загружены на текущей странице. Это означает, что если нужные данные находятся на другой странице, они не будут учтены при фильтрации.

3. **Неэффективность при большом объеме данных**: Если таблица содержит большое количество строк, разбивка на страницы может замедлить процесс поиска нужных данных, так как пользователю придется вручную переключаться между страницами.

**Решение проблемы с помощью префильтра:**

Для решения проблемы фильтрации в Totum используется префильтр. Префильтр позволяет фильтровать данные перед их загрузкой в таблицу, что обеспечивает более эффективный и точный отбор строк по заданным условиям.

- **Фильтрация на сервере**: Префильтр выполняет фильтрацию на стороне сервера, что позволяет отобрать только те строки, которые соответствуют заданным условиям, еще до их загрузки в браузер пользователя.

- **Гибкость и точность**: Префильтр позволяет задавать сложные условия фильтрации, включая интервальные фильтры и фильтры по нескольким полям одновременно.

- **Улучшение производительности**: Поскольку префильтр уменьшает объем данных, загружаемых в браузер, это может значительно улучшить производительность, особенно при работе с большими таблицами.

Таким образом, префильтр является более мощным и гибким инструментом для фильтрации данных в Totum, чем простая разбивка на страницы.

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai4"></a> Как можно отфильтровать строки по определенным условиям?

В системе Totum для фильтрации строк по определенным условиям используется механизм префильтров. Префильтры позволяют задавать условия фильтрации, которые применяются на сервере, и отображать только те строки, которые соответствуют заданным условиям. Давайте рассмотрим, как это можно сделать.

**Шаги для фильтрации строк с использованием префильтров:**

1. **Создание поля префильтра:**
   - Перейдите в настройки таблицы и создайте новое поле, которое будет использоваться в качестве префильтра.
   - Установите тип поля, соответствующий типу данных, по которым вы хотите фильтровать (например, строка, число, дата и т.д.).
   - Убедитесь, что поле размещено в плейсменте "Префильтр".

2. **Привязка префильтра к полю в строчной части:**
   - В настройках поля префильтра укажите `Name поля в строчной части`, к которому вы хотите привязать префильтр. Это позволит префильтру фильтровать строки на основе значений в указанном поле.

3. **Настройка видимости и редактирования:**
   - Убедитесь, что параметр "Показывать в web" включен, чтобы префильтр был активен.
   - Настройте видимость и доступ к редактированию префильтра для нужных ролей.

4. **Использование префильтра:**
   - В интерфейсе таблицы введите значение в поле префильтра и нажмите кнопку `GO`, чтобы применить фильтрацию.
   - Префильтр будет фильтровать строки по полному соответствию значений в привязанном поле.
   - Если в поле строчной части содержится список, то префильтр работает по пересечению значений. Т.е. если в поле в строчной части в списке есть хотя бы одно из введенных в префильтр значений — строка будет показана.

5. **Сброс фильтрации:**
   - Чтобы сбросить фильтрацию и отобразить все строки, нажмите на иконку ластика рядом с полем префильтра.

**Пример использования префильтра:**

Допустим, у вас есть таблица с полем `status`, и вы хотите отфильтровать строки, где статус равен "active". Вы можете создать префильтр, привязанный к полю `status`, и ввести значение "active" в поле префильтра, чтобы отобразить только строки с этим статусом.

**Примечания:**

- Префильтры работают по полному соответствию значений. Частичное соответствие не поддерживается.
- Если в поле строчной части содержится список, то префильтр работает по пересечению значений. Т.е. если в поле в строчной части в списке есть хотя бы одно из введенных в префильтр значений — строка будет показана.
- Если префильтр содержит пустое значение, он не активен и фильтрация не применяется.
- Несколько префильтров работают по пересечению, то есть отображаются только те строки, которые соответствуют всем активным префильтрам.

Таким образом, префильтры в Totum предоставляют мощный инструмент для фильтрации строк по различным условиям, позволяя пользователям гибко управлять отображением данных в таблице.

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai5"></a> Что нужно сделать, чтобы префильтр начал работать?

Чтобы префильтр начал работать в системе Totum, необходимо выполнить несколько шагов. Давайте рассмотрим их подробно:

1. **Создать поле префильтра**:
   - Добавьте новое поле в таблицу и укажите его размещение в плейсменте "Префильтр". Это поле будет использоваться для ввода значений, по которым будет осуществляться фильтрация.

2. **Указать привязку**:

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai10"></a> Каким образом осуществляется фильтрация строк таблицы на стороне сервера?

Фильтрация строк таблицы на стороне сервера в системе Totum осуществляется с помощью префильтров. Префильтры позволяют ограничивать выборку данных по определенным условиям, которые применяются до загрузки данных в таблицу. Это позволяет эффективно обрабатывать большие объемы данных, фильтруя их на уровне сервера. Рассмотрим, как это работает более подробно.

**Основные аспекты фильтрации с помощью префильтров:**

1. **Префильтр** — это особая часть таблицы, которая существует индивидуально в каждой вкладке браузера, в которой открыта таблица. У разных пользователей и на разных вкладках у одного пользователя в префильтре одновременно могут быть введены разные данные.

2. **Привязка к полю**: Поле префильтра может быть привязано к полю в строчной части таблицы. Для этого в настройках поля префильтра указывается `name` поля, к которому оно привязано. Это позволяет префильтру фильтровать строки на сервере по заданным условиям.

3. **Типы полей**: Для правильной работы префильтра рекомендуется использовать типы полей, аналогичные типу поля привязки. Это обеспечивает корректное сравнение значений и фильтрацию.

4. **Интервальная настройка**: Возможно использование интервальной настройки поля префильтра. Для этого используются два поля префильтра, привязанных к одному полю строчной части с параметром `интервальный`. Сравнение в интервальном префильтре идет по условию `>=` и `<=`.

5. **Специальные значения**: В селектах префильтра можно использовать специальные значения, такие как `*ALL*` для вывода всех значений и `*NONE*` для блокировки фильтрации.

6. **Активность префильтра**: Префильтр активен только если в нем введено непустое значение. Если префильтр содержит пустое значение, то он не активен и фильтрация не осуществляется.

7. **Пересечение условий**: Если задано несколько префильтров, то они работают по пересечению значений. Это означает, что будут выданы строки, по которым найдено заданное значение по каждому из примененных префильтров.

8. **Показывать в web**: Если параметр "показывать в web" отключен, то префильтр выключается и фильтрация не осуществляется.

Таким образом, префильтры в Totum позволяют эффективно фильтровать данные на стороне сервера, обеспечивая высокую производительность и гибкость в работе с большими объемами данных.

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai18"></a> Фильтрует ли префильтр только по полному соответствию или допускает частичное совпадение?

В системе Totum базовые префильтры, доступные в mit-версии, фильтруют только по полному соответствию. Это означает, что префильтр будет активен и фильтровать строки только в том случае, если значение в поле префильтра полностью совпадает с соответствующим значением в привязанном поле строчной части таблицы. Частичное совпадение в базовых префильтрах не обрабатывается.

Если в поле строчной части содержится список, то префильтр работает по пересечению значений. Т.е. если в поле в строчной части в списке есть хотя бы одно из введенных в префильтр значений — строка будет показана.

#### <a name="adding-a-prefilter-field-and-linking-it-to-a-line-part-field-ai19"></a> Активен ли префильтр, если его значение пустое?

Нет, если префильтр содержит пустое значение, то он не активен. В системе Totum префильтр начинает работать только тогда, когда в нем указано непустое значение. Это означает, что если значение префильтра пустое, то он не будет фильтровать строки таблицы, и все данные будут отображаться без ограничений, заданных префильтром.

#### <a name="how-to-filter-by-select-ai1"></a> Что происходит, когда в селекте не выбрано ничего (селект имеет значение null)?

Когда в селекте не выбрано ничего и селект имеет значение `null`, фильтрация не происходит. Это означает, что по умолчанию все данные отображаются, и никакие фильтры не применяются до тех пор, пока пользователь не выберет конкретное значение из селекта.

В контексте префильтра, если поле префильтра не заполнено, то фильтрация не применяется, и таблица отображает все строки. Это позволяет пользователю видеть все доступные данные, пока он не решит применить фильтр, выбрав значение из селекта.

Пустое значение в поле типа селект в префильтре является плохой практикой, так как есть ситуации, когда необходимо отфильтровать строки по пустому значению. Для отображения всех строк необходимо использовать специальное значение `*ALL*`.

Если необходимо, чтобы селект по умолчанию показывал все значения, можно использовать специальное значение `*ALL*`, которое указывает системе, что фильтрация должна быть отключена и все данные должны быть отображены.

#### <a name="how-to-filter-by-select-ai5"></a> Для чего используется опция «Ничего (*NONE*)» в селекте?

Опция «Ничего (*NONE*)» в селекте используется для запрета показа любых значений. Это может быть полезно в ситуациях, когда необходимо, чтобы пользователь не видел никаких данных, пока не выберет определенное значение в префильтре.

**Применение:**

1. **Блокировка отображения данных**: Когда в поле префильтра выбрано значение `*NONE*`, это блокирует отображение всех строк, связанных с этим префильтром. Это может быть полезно для предотвращения случайного отображения большого объема данных или для обеспечения того, чтобы пользователь сначала выбрал конкретные параметры фильтрации.

2. **Управление доступом**: Опция `*NONE*` может использоваться для управления доступом к данным, требуя от пользователя выбора определенных условий перед тем, как данные будут отображены.

3. **Оптимизация производительности**: В больших таблицах, где загрузка всех данных может быть ресурсоемкой, использование `*NONE*` позволяет избежать ненужной загрузки данных до тех пор, пока пользователь не уточнит свои критерии поиска.

**Настройка:**

Чтобы активировать опцию `*NONE*` в селекте, необходимо включить соответствующий параметр в настройках поля. Также в расширенных параметрах селекта, где можно также задать название, которое будет видеть пользователь при выборе этой опции.

Таким образом, опция `*NONE*` предоставляет дополнительный уровень контроля над отображением данных в системе Totum, позволяя более гибко управлять доступом и производительностью.

В системе Totum для установки значения по умолчанию для поля типа Селект необходимо воспользоваться параметром "Значение по умолчанию" в настройках поля. #### <a name="how-to-filter-by-select-ai9"></a> Что означает значение *ALL* в селекте и как оно используется?

Значение `*ALL*` в селекте в системе Totum используется для указания, что необходимо показать все значения. Это специальное значение, которое позволяет отключить фильтрацию и отобразить все возможные элементы в выпадающем списке селекта.

**Использование значения `*ALL*`:**

1. **Префильтр**:
   - В префильтре, если поле является селектом, значение `*ALL*` используется для того, чтобы показать все строки, не применяя фильтрацию. Это удобно, когда вы хотите, чтобы при открытии таблицы отображались все данные без каких-либо ограничений.

2. **Установка значения по умолчанию**:
   - Значение `*ALL*` может быть установлено в качестве значения по умолчанию для селекта в префильтре. Это означает, что при открытии таблицы или создании ячейки, селект будет автоматически настроен на отображение всех значений.

3. **Настройки селекта**:
   - В настройках поля типа Селект можно включить опцию "Все (`*ALL*`)", которая позволяет использовать это значение. В настройках также можно изменить название, которое будет видеть пользователь при выборе этого значения.

**Пример использования:**

Если у вас есть таблица с префильтром, и вы хотите, чтобы при открытии таблицы в окне отображались все строки, вы можете установить значение `*ALL*` в качестве значения для селекта в префильтре.

Пример кода-действия:

```totum
=: linkToTable(table: 'your_table'; target: "iframe"; filter: 'fl_select_field' = "*ALL*")
```

В этом примере `fl_select_field` — это поле префильтра, в который будет подставлено значение `*ALL*` при открытии таблицы в окне, чтобы показать все строки таблицы.

Таким образом, значение `*ALL*` в селекте позволяет гибко управлять отображением данных, предоставляя возможность быстро переключаться между полным списком значений и фильтрованным представлением.

#### <a name="how-to-filter-by-select-ai10"></a> Как фильтруются строки при выборе определенного значения в префильтре?

В системе Totum фильтрация строк при выборе определенного значения в префильтре осуществляется в зависимости от типа поля и настроек префильтра. Давайте рассмотрим, как это работает:

**Основные принципы фильтрации:**

1. **Префильтр и строчная часть**:
   - Префильтр может быть привязан к полю в строчной части таблицы. Это означает, что значения, выбранные в префильтре, будут использоваться для фильтрации строк в строчной части.

2. **Типы полей**:
   - Для правильной работы фильтрации, рекомендуется, что бы типы полей в префильтре и строчной части были аналогичными. Например, если в строчной части используется поле типа Селект, то и в префильтре рекомендуется использование типа Селект.

3. **Фильтрация по значению**:
   - Если в префильтре выбран одинарный селект, а в строчной части множественный, фильтрация будет осуществляться по вхождению значения. Это значит, что строки, содержащие выбранное значение в любом из элементов множественного селекта, будут отображены.
   - Если и в префильтре, и в строчной части множественные селекты, фильтрация будет осуществляться по любому пересечению. Это значит, что строки, содержащие хотя бы одно из выбранных значений, будут отображены.

4. **Специальные значения**:
   - В префильтре для селектов можно использовать специальные значения, такие как `*ALL*` для отображения всех значений (фильтрация выключена) и `*NONE*` для блокировки фильтрации (не выводить ни одного значения).

5. **Фильтрация по пустым значениям**:
   - Если необходимо отфильтровать строки по пустым значениям, это можно сделать, используя селект, одно из значений которого будет равно пустоте. Пустое значение можно включить параметром "Пустое ()".

Таким образом, фильтрация строк в Totum при выборе значения в префильтре зависит от типа полей, настроек префильтра и выбранных значений, что позволяет гибко управлять отображением данных в таблице.

#### <a name="how-to-filter-by-select-ai11"></a> Как фильтруются строки при выборе нескольких значений в префильтре?

В системе Totum, когда в префильтре типа Селект выбрано несколько значений, фильтрация строк осуществляется по любому пересечению. Это означает, что строка будет отображена, если она содержит хотя бы одно из выбранных значений.

**Пример:**

Предположим, у вас есть таблица с полем, в котором могут быть множественные значения, например, цвета: "красный", "синий", "зеленый". Если в префильтре вы выберете значения "красный" и "синий", то будут отображены все строки, которые содержат хотя бы одно из этих значений. Это может быть строка, содержащая только "красный", только "синий", или оба значения одновременно.

**Как это работает:**

1. **Префильтр**: Вы выбираете несколько значений в префильтре, например, "красный" и "синий".

2. **Фильтрация**: Система проверяет каждую строку на наличие хотя бы одного из выбранных значений.

3. **Отображение**: Строки, которые содержат хотя бы одно из выбранных значений, отображаются в таблице.

Таким образом, фильтрация по нескольким значениям в префильтре позволяет гибко управлять отображением данных, показывая только те строки, которые соответствуют хотя бы одному из выбранных условий.

#### <a name="how-to-filter-by-select-ai12"></a> Как отфильтровать строки с пустыми значениями в поле селекта?

В системе Totum, чтобы отфильтровать строки с пустыми значениями в поле типа Селект, необходимо использовать префильтр. Для этого нужно выполнить следующие шаги:

1. **Создайте поле префильтра**: Убедитесь, что у вас есть поле префильтра, связанное с полем Селект в строчной части таблицы.

2. **Настройте поле префильтра**: В настройках поля префильтра включите параметр "Пустое ()". Это позволит вам выбрать пустое значение в префильтре.

3. **Выберите пустое значение в префильтре**: Откройте префильтр и выберите опцию "Пустое". Это значение будет доступно, если вы включили параметр "Пустое ()" в настройках поля префильтра.

4. **Примените фильтр**: Нажмите кнопку "GO" в префильтре, чтобы применить фильтрацию. Таблица отобразит только те строки, в которых поле Селект имеет пустое значение.

#### <a name="how-to-filter-by-select-ai13"></a> Как происходит фильтрация, если в префильтре одиночный селект, а в строчной части множественный?

В системе Totum, если в префильтре используется одиночный селект, а в строчной части таблицы — множественный селект, фильтрация осуществляется по вхождению значения. Это означает, что строки будут отфильтрованы таким образом, чтобы отображать те, в которых хотя бы одно из значений множественного селекта совпадает с выбранным значением в одиночном селекте префильтра.

**Пример**

Предположим, у вас есть таблица с множественным селектом в строчной части, где в одной строке могут быть выбраны несколько значений, например, "яблоко", "банан", "апельсин". В префильтре у вас одиночный селект, и вы выбираете значение "яблоко". В результате фильтрации будут отображены все строки, в которых среди множественных значений есть "яблоко".

**Код для фильтрации**

Для реализации такой фильтрации в Totum, вы можете использовать следующий подход:

1. **Настройка префильтра**: Убедитесь, что префильтр настроен на использование одиночного селекта.

2. **Настройка строчной части**: Убедитесь, что поле в строчной части настроено как множественный селект.

3. **Фильтрация по вхождению**: Фильтрация будет происходить автоматически по вхождению значения из префильтра в множественные значения строчной части.

Таким образом, система Totum автоматически обрабатывает фильтрацию по вхождению, когда в префильтре используется одиночный селект, а в строчной части — множественный. Это позволяет гибко управлять отображением данных в таблице в зависимости от выбранных условий.

#### <a name="how-to-filter-by-select-ai14"></a> Как происходит фильтрация при множественных селектах в префильтре и строчной части?

В системе Totum фильтрация при использовании множественных селектов в префильтре и строчной части осуществляется по принципу пересечения значений. Давайте рассмотрим, как это работает более подробно.

**Фильтрация при множественных селектах**

1. **Множественные селекты в префильтре**:
   - В префильтре можно выбрать несколько значений. Это позволяет задать условия фильтрации, которые будут применяться к данным в строчной части таблицы.

2. **Множественные селекты в строчной части**:
   - В строчной части таблицы также могут быть поля типа множественный селект, которые содержат несколько значений.

3. **Принцип пересечения**:
   - Фильтрация осуществляется по любому пересечению значений между префильтром и строчной частью. Это означает, что строка будет отображена, если хотя бы одно из значений, выбранных в префильтре, совпадает с любым из значений в соответствующем поле строчной части.

**Пример**

Предположим, у вас есть таблица с товарами, и в префильтре вы выбрали значения "Апельсин" и "Картофель". В строчной части у вас есть строки, где поле множественного селекта содержит следующие значения:

- Строка 1: ["Апельсин", "Яблоко"]
- Строка 2: ["Картофель", "Морковь"]
- Строка 3: ["Банан", "Груша"]

В этом случае, строки 1 и 2 будут отображены, так как они содержат хотя бы одно значение, совпадающее с выбранными в префильтре ("Апельсин" или "Картофель"). Строка 3 не будет отображена, так как ни одно из её значений не совпадает с выбранными в префильтре.

**Заключение**

Таким образом, фильтрация при множественных селектах в префильтре и строчной части в Totum позволяет гибко управлять отображением данных, основываясь на пересечении значений. Это делает процесс фильтрации более интуитивным и удобным для пользователей, позволяя им быстро находить нужные данные.

#### <a name="using-manual-selections-in-prefilters-ai2"></a> Что такое ручной селект и как он используется в префильтрах?

Ручной селект в системе Totum — это механизм, который позволяет задавать значения и отображения селекта вручную, без использования кода селекта. Это может быть полезно в ситуациях, когда необходимо задать фиксированный набор значений для выбора, который не зависит от данных в таблице.

**Как работает ручной селект?**

1. **Ручное создание селекта**:
   - При включении опции "Ручное создание селекта" в настройках поля, код селекта не используется, даже если он задан. Вместо этого значения и отображения задаются вручную в формате JSON, где указывается соответствие между значением (основанием) и отображением.

2. **Основания и отображения**:
   - В качестве оснований и отображений можно использовать как числовые, так и строковые данные. Это позволяет гибко настраивать селект в зависимости от потребностей.

**Использование в префильтрах**

Ручной селект часто используется в префильтрах для создания фильтров, которые не зависят от данных в таблице. Например, это может быть полезно для фильтрации по чекбоксу или для создания интервальных фильтров.

**Пример использования:**

1. **Префильтр по чекбоксу**:
   - Для создания префильтра по чекбоксу можно использовать селект с ручными значениями `true` и `false`. Это позволяет фильтровать строки, где чекбокс установлен или не установлен.

```json
{
  "true": "Checked",
  "false": "Unchecked"
}
```

2. **Интервальный префильтр**:
   - Ручной селект можно использовать для создания интервальных фильтров, например, для выбора диапазонов сумм.

```json
{
  "100": "0-100",
  "200": "100-200",
  "10000": "200+"
}
```

**Преимущества ручного селекта**

- **Гибкость**: Позволяет задавать фиксированные значения, которые не зависят от данных в таблице.
- **Простота**: Упрощает настройку селектов, так как не требует написания кода.
- **Контроль**: Позволяет точно контролировать, какие значения доступны для выбора.

Таким образом, ручной селект в Totum предоставляет удобный способ настройки селектов и префильтров, когда требуется фиксированный набор значений.

#### <a name="using-manual-selections-in-prefilters-ai4"></a> Почему важно привязывать префильтр к базе, а не к отображению?

Привязывание префильтра к базе, а не к отображению, важно по нескольким причинам:

1. **Точность фильтрации**: Фильтрация данных происходит на основе значений, хранящихся в базе данных, а не на основе их отображений. Отображения могут быть изменены или обновлены, но значения в базе остаются постоянными. Это обеспечивает точность и надежность фильтрации данных.

2. **Уникальность значений**: В базе данных значения обычно уникальны (например, `id` строки), тогда как отображения могут быть неуникальными (например, одинаковые названия товаров). Привязка к базе позволяет избежать ошибок, связанных с неоднозначностью отображений.

3. **Производительность**: Фильтрация по значениям базы данных может быть более эффективной с точки зрения производительности, так как она использует индексы и другие оптимизации базы данных. Фильтрация по отображениям может требовать дополнительных вычислений и преобразований.

4. **Стабильность**: Значения более стабильны и менее подвержены изменениям, чем отображения, которые могут зависеть от бизнес-логики или пользовательских настроек. Это делает фильтрацию более предсказуемой и устойчивой к изменениям.

5. **Универсальность**: Привязка к значениям позволяет использовать префильтр в различных контекстах и сценариях, не завися от конкретных отображений, которые могут меняться в зависимости от языка, формата или других факторов.

Таким образом, привязывание префильтра к базе данных обеспечивает более точную, надежную и производительную фильтрацию, что особенно важно в системах, работающих с большими объемами данных и сложными бизнес-логиками.

Таким образом, значение `*ALL*` в префильтре предоставляет пользователю возможность легко управлять отображением данных в таблице, переключаясь между полным списком и отфильтрованными результатами.

### <a name="interval-prefilters-ai"></a> Дополнительные вопросы

#### <a name="interval-prefilters-ai1"></a> Что такое интервальные префильтры?

Интервальные префильтры в системе Totum — это специальные настройки префильтров, которые позволяют задавать диапазон значений для фильтрации данных в таблице. Они доступны для полей типа число, селект и дата. Интервальные префильтры позволяют пользователю указать начальное и конечное значения, чтобы отфильтровать строки, попадающие в этот диапазон.

**Основные особенности интервальных префильтров:**

1. **Типы полей**: Интервальные префильтры доступны для полей типа число, селект и дата. Это означает, что вы можете использовать их для фильтрации данных, основанных на числовых значениях, датах или значениях из выпадающего списка.

2. **Начальное и конечное значения**: Пользователь может задать начальное и конечное значения для фильтрации. Например, для числового поля можно указать, что нужно отобразить только строки, где значение находится между 10 и 20.

3. **Включение границ**: Значения, указанные в префильтре, включаются в диапазон. Это означает, что если вы укажете начальное значение 10 и конечное значение 20, то строки с этими значениями также будут включены в результат фильтрации.

4. **Гибкость настройки**: Если одно из значений (начальное или конечное) не установлено, фильтрация будет происходить только по одному краю интервала. Например, если указано только начальное значение, будут отображены все строки, где значение больше или равно этому значению.

5. **Пример использования**:
   - Для числового поля: можно задать начальное значение 10 и конечное значение 20, чтобы отобразить строки с числами от 10 до 20.
   - Для поля типа дата: можно задать начальную дату 2023-01-01 и конечную дату 2023-12-31, чтобы отобразить строки с датами в течение 2023 года.

Интервальные префильтры предоставляют мощный инструмент для фильтрации данных в таблицах Totum, позволяя пользователям гибко управлять отображением данных на основе заданных диапазонов значений.

#### <a name="interval-prefilters-ai2"></a> Какие типы полей поддерживают интервальные префильтры?

В системе Totum интервальные префильтры поддерживаются для следующих типов полей:

1. **Число**: Поля с числовыми значениями могут использовать интервальные префильтры для задания диапазонов чисел.

2. **Селект**: Поля типа селект могут использовать интервальные префильтры, если значения селекта имеют числовую природу или могут быть упорядочены.

3. **Дата**: Поля с датами могут использовать интервальные префильтры для задания временных диапазонов.

Эти типы полей позволяют задавать начальные и конечные значения для фильтрации данных в таблице, что делает их удобными для работы с диапазонами значений.

#### <a name="interval-prefilters-ai10"></a> Отличается ли порядок сортировки для строк и чисел?

В системе Totum порядок сортировки зависит от типа поля, и действительно, он отличается для чисел и строк.

**Числовые поля**
- **Сравнение как числа**: Если тип поля — число, то значения будут сравниваться и сортироваться как числовые значения. Это означает, что порядок будет определяться на основе числового значения, например, 5 будет меньше, чем 10.

**Строковые поля**
- **Сравнение как строки**: Если тип поля — строка, селект или дата, то значения будут сравниваться и сортироваться как строки. Это означает, что порядок будет определяться на основе лексикографического порядка, например, "100" будет меньше, чем "20", потому что сравнение идет по символам.

**Даты**
- **Сравнение как строки**: Даты также сравниваются как строки, но с учетом их формата. Это означает, что даты будут упорядочены в хронологическом порядке, если они записаны в стандартном формате (например, "2023-01-01" будет меньше, чем "2023-12-31").

**Селекты**
- **Сравнение как строки**: Значения в полях типа селект также сравниваются как строки, если они не имеют числовой природы. Если вам нужно значения сравнивать как числа, для этого необходимо создать дополнительное техническое поле тип число, в которое кодом взят значение из селекта и проводить сравнение, например интервального префильта с этим техническим полем.

Таким образом, порядок сортировки в Totum зависит от типа поля, и важно учитывать это при настройке таблиц и фильтров, чтобы получить ожидаемый результат.

#### <a name="interval-prefilters-ai11"></a> Как сравниваются даты в интервальном префильтре?

В системе Totum даты в интервальном префильтре сравниваются как даты. Это означает, что при использовании интервального префильтра для полей типа "Дата" сравнение значений происходит на основе их хронологического порядка. Давайте рассмотрим, как это работает более подробно.

**Основные особенности сравнения дат в интервальном префильтре:**

1. **Тип поля**: Интервальные префильтры доступны для полей типа "Дата". Это позволяет задавать временные диапазоны для фильтрации данных в таблице.

2. **Задание интервала**: Пользователь может задать начальную и конечную даты для фильтрации. Например, можно указать, что нужно отобразить только строки, где дата находится между 2023-01-01 и 2023-12-31.

3. **Включение границ**: Значения, указанные в префильтре, включаются в диапазон. Это означает, что если вы укажете начальную дату 2023-01-01 и конечную дату 2023-12-31, то строки с этими датами также будут включены в результат фильтрации.

4. **Гибкость настройки**: Если одно из значений (начальная или конечная дата) не установлено, фильтрация будет происходить только по одной границе интервала. Например, если указана только начальная дата, будут отображены все строки, где дата больше или равна этой дате.

**Пример использования**

Допустим, у вас есть поле с датами `event_date` в таблице, и вы хотите настроить интервальный префильтр для фильтрации строк по диапазону дат.

1. Создайте два поля префильтра: `fl_date_from` и `fl_date_to`.
2. Для поля `fl_date_from` установите параметр "Интервальный" как "Стартовый" и привяжите его к полю `event_date`.
3. Для поля `fl_date_to` установите параметр "Интервальный" как "Завершающий" и также привяжите его к полю `event_date`.
4. Введите значения в поля `fl_date_from` и `fl_date_to`, чтобы задать диапазон дат, и нажмите "GO" для применения фильтрации.

Таким образом, интервальные префильтры для дат в Totum позволяют гибко управлять отображением данных на основе заданного временного диапазона, что делает их удобным инструментом для фильтрации данных в таблицах.

#### <a name="interval-prefilters-ai12"></a> Как производится сравнение строк, если в строковом поле есть числа с разделителем дроби?

В системе Totum, если в строковом поле содержатся числа с разделителем дроби, то сравнение будет производиться как со строками. Это связано с тем, что тип поля определяет, как данные в нем будут обрабатываться.

**Особенности сравнения строк с числами:**

1. **Тип поля**: Если поле имеет строковый тип, то значения в нем будут сравниваться как строки, даже если они выглядят как числа. Это означает, что сравнение будет происходить на основе лексикографического порядка, а не числового.

2. **Лексикографический порядок**: В лексикографическом порядке сравнение происходит символ за символом. Например, строка `"555"` будет считаться меньше, чем строка `"6"`, потому что первый символ `"5"` меньше, чем `"6"`.

3. **Числовой вид**: Если в строковом поле числа записаны с разделителем дроби, например, `"3.14"`, то они все равно будут сравниваться как строки. Это значит, что `"3.14"` будет меньше, чем `"30"`, потому что сравнение начинается с первого символа.

4. **Математические операции**: Хотя сравнение происходит как со строками, над такими значениями можно выполнять математические операции. Однако для задач сравнения приоритетным является тип поля.

**Пример:**

Если у вас есть строковое поле с значениями `"3.14"`, `"2.71"`, и `"10.0"`, то при сортировке они будут упорядочены как: `"10.0"`, `"2.71"`, `"3.14"`, потому что сравнение идет по символам, а не по числовому значению.

Таким образом, для корректного числового сравнения таких значений рекомендуется использовать числовой тип поля, если это возможно.

### <a name="dates-in-the-prefilter-ai"></a> Дополнительные вопросы

#### <a name="dates-in-the-prefilter-ai1"></a> Что такое префильтр по датам и как он создается?

Префильтр по датам в системе Totum — это инструмент, который позволяет фильтровать данные в таблице по определенным датам или диапазонам дат. Он может быть настроен на фильтрацию по полям, содержащим даты, с учетом различных форматов дат и времени.

**Создание префильтра по датам**

1. **Создание поля префильтра**:
   - В таблице создайте поле префильтра и укажите тип данных 'дата'. Это поле будет использоваться для ввода даты, по которой будет осуществляться фильтрация.

2. **Настройка формата даты**:
   - Убедитесь, что формат даты в префильтре соответствует формату даты в строчной части таблицы. Например, если в строчной части используется формат 'Y-m-d', то в префильтре также должен быть использован этот формат.

3. **Привязка к строчной части**:

#### <a name="dates-in-the-prefilter-ai5"></a> Почему дата-время в строчной части не совпадает с простой датой в префильтре?

В системе Totum дата-время и простая дата хранятся в разных форматах, что может привести к несовпадению при использовании префильтров. Дата-время включает часы и минуты (например, `2023-10-01 12:00`), тогда как простая дата включает только год, месяц и день (например, `2023-10-01`). Префильтры работают по полному совпадению значений, поэтому если формат данных не совпадает, фильтрация не будет работать корректно.

**Причина несовпадения**

1. **Разные форматы**: Дата-время содержит дополнительную информацию о времени, которая отсутствует в простой дате. Это приводит к тому, что значения не совпадают при сравнении.

2. **Полное совпадение**: Префильтры в Totum работают по принципу полного совпадения значений. Это означает, что если в строчной части используется дата-время, а в префильтре указана только дата, фильтрация не будет работать, так как значения не совпадают полностью.

**Решение проблемы**

Чтобы решить эту проблему, можно использовать несколько подходов:

1. **Техническое поле для преобразования**: Создайте техническое поле в строчной части, где через функцию `dateFormat` преобразуйте дату-время в формат 'Y-m-d'. Это позволит использовать префильтр с простой датой.

   Пример кода для преобразования даты-времени в дату:

```totum
=: dateFormat(date: #date_time_field; format: "Y-m-d")
```

2. **Интервальные префильтры**: Используйте два скрытых поля префильтра с параметрами интервальный. Привяжите их к дате-времени в строчной части и рассчитывайте значение кодом:

   Для стартового:

```totum
=: dateFormat(date: #fl_date; format: "Y-m-d 00:00")
```

   Для завершающего:

```totum
=: dateFormat(date: #fl_date; format: "Y-m-d 23:59")
```

   Сравнение стартового и завершающего идет по принципу больше/меньше или равно — то есть, крайние значения входят в интервал.

Эти подходы позволяют корректно фильтровать данные по дате, даже если в строчной части используется дата-время.

В этом примере, стартовое значение префильтра устанавливается на первый день месяца, а завершающее — на последний день месяца. Это позволяет включить весь месяц в интервал фильтрации.

**Заключение**

Скрытые поля в Totum предоставляют мощный инструмент для выполнения сложных фильтраций, таких как фильтрация по месяцу, без необходимости отображения дополнительных полей пользователю. Это позволяет создавать более гибкие и удобные интерфейсы для работы с данными.
