# Коды действия базовый уровень

## <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one"></a> Назначить новое значение в другое поле при изменении в текущем

видео: [VK Video](https://vk.ru/video873495087_456239071) · [YouTube](https://www.youtube.com/watch?v=o1oJUIpL8B8) · пример в демо-наборе курса: `code_action`

### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-qa"></a> Вопросы и ответы

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q1"></a> Какой блок кода отвечает за действия?

За действия отвечают [коды действия][511]. Из кода вчисляющего значения полей выполнить действие нельзя.

Помимо специальной секции кодов нужно использовать функции вполняющие действия, например [set][294] — функция изменяющая значение в поле.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q2"></a> Что отслеживает система, что может являться условием выполнения действия?

Тотум отслеживает несколько триггеров — которые могут служить сигналом к запуску действия:

+ изменение значения в поле

+ добавление строки

+ удаление строки

+ двойной клик в заблокированном поле

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q3"></a> Будет ли исполнен код действия если выключены все триггеры?

Нет, активность хотя бы одного триггера обязательна.

Коды действия подсвечиваются в заголовке поля `звездочкой` — если звездочка `пустая`, значит нет ни одного активного триггера.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q4"></a> В какой момент исполняются коды действий?

Коды действий исполняются после кодов. Те сначала рассчитываются все значения изменяемых строк и далее срабатывают триггеры и выполняются действия.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q5"></a> В каком порядке выполняются коды действий?

В таком же, в каком вычисляются коды. В таком же порядке плейсментов и `sort` внутри плейсмента.

`Хедер` — `Строчная часть` — `футер`

Строки по возрастанию `id` или `n`, а внутир по возрастанию `sort`.

В случае поколоночного пересчета то поколоночно по возрастанию `id` или `n`.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q6"></a> Какова разница между set и setList?

+ [set][294] изменяет одно значение, даже если под условия подходят несколько строк.

+ [setList][295] изменяет все значения подходящие под условия.

В Totum все функции действий изменяющие значения разделены на единичный и множественный вариант.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q7"></a> Можно назначить значение только одному полю или нескольким сразу?

[set][294] позволяет за одно действие указать несколько изменяемых полей в одной строке:

```totum

=: set(table: 'table'; field: 'field_1' = "value_1"; field: 'field_2' = "value_2"; where: 'condition_field' = #condition)

```

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q8"></a> Могут ли функции действий использоваться из кодов или кодов форматирования?

Нет — не могут. Функции действия выполняют действие только из кода действия.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q9"></a> Вызывает ли код действия пересчет таблицы в которой выполняется действие?

Да.

Для простых таблиц — это пересчет изменяемых строк и хедера.

Для расчетных и временных — вся таблица.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q10"></a> При set в расчетную таблицу будет пересчитана вся таблица или только строка в которой производится изменение?

Вся таблица.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q11"></a> Что произойдет, если в изменяемом поле тоже есть код-действия?

Если там включен триггер на изменение — сработает триггер и запустится код действия того поля.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-q12"></a> Если в таблице изменяется несколько строк, то код действия будет выполнен на каждую строку отдельно или будет выполнен один общий?

Код действия запустится на каждую измененную строку. Иногда это ведет к огромному перепробегу.

Особенно это важно для таблиц расчитывающихся целиком - для них есть хитрость:

Например, нам нужно пересчитать какую-то таблицу по результатам изменения нескольких полей, но сделать это только один раз:

1. Делаем в футере колонки техническое поле тип Данные, берущее в коде спикок значений изменяемого поля.

```totum
=: selectList(table: $#ntn; field: 'field'; order: 'field' asc)

//Использование order важно!
```

2. В коде действвия по триггеру на изменение выполняем действие.

```totum
=: recalculate(table: 'table_to_recalc')

```

Тотум автоматически будет отслеживать состав поля, и когда оно измениться по изменению одного или нескольких отслеживаемых значений — выполнит код-действия один раз.

Для простых таблиц тоже есть подобная хитрость — но о ней чуть позже.

### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-text"></a> Текст урока (по видео)

Начнем рассказывать о кодах действий, которые позволяют выполнять некоторые действия в системе, автоматически изменять значение
Как это выглядит? Вот для примера таблица, которая содержит 3 поля: поле 1, поле 2, поле 3. Со значениями.
Я хочу, чтобы значение в поле 2 автоматически менялось на 100 в той же строке при изменении значения в поле 1. Это условие. Сейчас в поле 2 строки 1 значение 20, и я хочу, чтобы при изменении оно стало 100. Что мы делаем для этого? Переходим к полю 1. В настройках поля есть блок - Код действия. Включаем его и здесь нам нужно написать код с функцией действия. Он начинается со знака равенства и двоеточия. Одна из основных функций действия - `set`. `Set` устанавливает новое значение в указанной ячейке.

```totum
=: set(table: $#ntn; field: 'field_2' = 100; where: 'id' = #id; log: true)
```

Какой блок кода отвечает за действия?
За действия отвечают коды действия. Из кода вчисляющего значения полей выполнить действие нельзя.
Помимо специальной секции кодов нужно использовать функции вполняющие действия, например set — функция изменяющая значение в поле.

Здесь мы указываем нужную таблицу - текущую. Мы хотим: поле 2 равно новому значению 100. Где? - в той же строке - id равно #id. Параметр `log: true` включает ведение журнала. Нажимаем сохранить - попробуем поэкспериментировать.
Например, здесь у нас было B. Меняем его на D. Сохраняем - и ничего не происходит. Посмотрите на заголовки полей – звездочка, обозначающая код действия, прозрачная. Недостаточно просто включить код действия и написать в нем код. Вы должны указать, какой триггер вызовет действие. Это указывается под областью, в которую пишется код действия. Один из них - выполнение при изменении. Когда указан хотя бы один триггер, мы сохраняем, звезда становится закрашенной. Это показывает, что код действия не просто есть, а ему присвоен триггер.

Что отслеживает система, что может являться условием выполнения действия?
Тотум отслеживает несколько триггеров — которые могут служить сигналом к запуску действия:
•	Выполнять код действия при добавлении
•	Выполнять код действия при изменении
•	Выполнять код действия при удалении
•	Выполнять код действия при клике

Будет ли исполнен код действия если выключены все триггеры?
Нет, активность хотя бы одного триггера обязательна.
Коды действия подсвечиваются в заголовке поля звездочкой — если звездочка пустая, значит нет ни одного активного триггера.

Вводим в поле 1 новое значение. И вот мы видим, что изменилось не только поле, в котором мы делали изменения, но и изменилось значение в поле 2.
Если мы перейдем к журналу, то увидим, что я как администратор от пользователя Administrator произвел изменение с помощью скрипта и после изменения значение этого поля стало 100.
В какой момент выполняется код действия? Он выполняется после всех кодов. То есть, сначала вычисляются все коды, а затем машина смотрит, какие поля были изменены. Если в измененных полях есть триггер изменения, то коды действий выполняются в том же порядке, в котором выполнялись коды расчета значений полей. То есть выполняется в строчной части для блока вычисления строк слева направо в порядке возрастающей сортировки. Сначала выполняются коды хедера, затем префильтра, затем в строчной части, затем футеры столбцов, затем общий фут, если он есть, например, в расчетных и временных таблицах.
Теперь рассмотрим подобную ситуацию. У нас есть код действия, меняющий значение в поле 2 при изменении поля 1. Что произойдет, если мы напишем код действия в поле 2, который изменит значение в поле 3.
В этом случае если мы изменим значение в поле 1, то увидим, что у нас произошли изменения. В поле 1 мы внесли изменения вручную. Затем был выполнен код действия, изменивший поле 2, затем был выполнен код действия в поле 2, потому что в нем произошло изменение. Неважно, кто его сделал, вручную человек или машина сделала это с помощью кода, - изменение произошло. И это инициирует выполнение кода действия поля 2, который изменяет значение в поле 3.
Такой каскад приводит к каскаду пересчетов. Мы изменили - таблица пересчиталась, вызвали действие - оно изменило эту таблицу. В данном случае только эту строку, потому что это была строка в строчной части простой таблице, а в простой таблице, как мы помним, пересчет построчный. Произошел пересчет, далее он отметил, что здесь есть изменения, и выполнил еще одно действие, и произошел еще 1 пересчет. То есть получается каскад пересчетов, и это увеличивает нагрузку на сервер. Поэтому, если вы хотите одним действием внести изменения сразу в несколько полей, логичнее поступить следующим образом. `field` - это множественный параметр. Пишем в поле 1 код действия, который изменяет и поле 2, и поле 3.

```totum
=: set(table: $#ntn; field: 'field_2' = 100; field: 'field_2' = «A»; where: 'id' = #id; log: true)
```

 При этом код действия из поля 2 убираем. В поле 2 звездочка исчезла – это означает, что код действия в этом поле не включен.

И теперь, когда мы меняем значение поля, происходит пересчет. И есть одно действие, которое изменяет сразу оба поля, это и есть второй пересчет. Это значительная оптимизация. Не стоит забывать о ней в реальных проектах. В тестовой таблице вы можете не увидеть разницы, но в реальных проектах на больших таблицах разница может быть очень заметной.
Что происходит, если у нас одновременно изменяется несколько строк? Мы указываем, например, «U» и говорим, что это групповое изменение. Это такая опция в строчной части таблицы можно применять изменения сразу ко всем выделенным полям. В этом случае значения всех выделенных полей изменилось на «U». Несколько кодов действий выполняются последовательно сверху вниз. В порядке возрастания id или в порядке возрастания n, если это N-сортированная таблица.

У нас было изменено поле 1 в двух строках, поэтому вызывается 2 кода действий. Сначала была пересчитана первая строка, а затем вторая. Такой способ организации вызовов кодов действий приводит к сильному перерасходу времени для расчетных и временных таблиц, потому что в них единица расчета это не отдельная строка, а таблица целиком. В основном это критично для расчетных таблиц внутри циклов.

Существует продвинутый подход, который позволяет выполнять одно действие при изменении нескольких строк, но мы рассмотрим его в продвинутой части. Знайте, что такая возможность есть.

В каком порядке выполняются коды действий?
В таком же, в каком вычисляются коды. В таком же порядке плейсментов и sort внутри плейсмента.
Хедер — Строчная часть — футер
Строки по возрастанию id или n, а внутри по возрастанию sort.
В случае поколоночного пересчета – поколоночно по возрастанию id или n.

Могут ли функции действия выполняться из кодов форматирования? По общему правилу – нет. Функции действия выполняются только из кода действия. Есть пара исключений, которые специально упоминаются в документации и учебниках - это функция `recalculate` и функция `getFromScript`, которая позволяет получать данные с другого сервера. Вы должны быть очень осторожны при использовании `recalculate` и `getFromScript` не в кодах действия, а просто в кодах, потому что можно легко 	зациклиться или подвесить таблицу.
Последнее, что я хочу показать, это разницу между `set` и `setList`. Я сделаю кнопку в заголовке, назову ее кнопкой, и это будет именно кнопка. Давайте напечатаем здесь “PRESS ME”.  Теперь мы установим ширину поля равной 300 – как общая ширина полей в строчной части, чтобы было красиво. Применить. А затем пишем код. В кнопке нет кода вычисления значения, есть только код действия, и он будет выполняться не триггером, а когда мы нажмем на кнопку, или мы можем вызвать этот код из функции действия. Существует функция действия, которая называется `execButton` или `execButtonList`.
А теперь я покажу вам разницу между `set` и `setList`. Установим в текущей таблице в поле 3. Мы установим букву B - где id не равен 0. То есть это все строки, которые есть в таблице. Под это условие подходит любая строка.
```totum
=: set(table: $#ntn; field: 'field_3' = "B"; where: 'id' ≠ 0; log: true)
```
Нажимаем сохранить, нажимаем кнопку и видим, что одна строка изменилась. Postgres выбирает эту строку случайным образом. В 99 раз это может быть 1, а в 100-й раз - 3, 30, 35. Угадать абсолютно невозможно.
Далее. Если мы хотим, чтобы по условиям менялось сразу несколько строк, в Totum есть разделение между одиночными и множественными операциями. Например, `select`, `selectList`. Лучше сказать, что это будет `setList`. В этом случае изменение будет происходить во всех строках, которые удовлетворяют условию where.

```totum
=: setList(table: $#ntn; field: 'field_3' = "B"; where: 'id' ≠ 0; log: true)
```

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai1"></a> Что такое коды действий и для чего они используются?

Коды действий в системе Totum — это специальные секции кода, которые выполняют действия после изменения данных в таблице. Они используются для автоматизации процессов, таких как изменение значений в полях, пересчет таблиц, выполнение внешних запросов и другие операции. Коды действий позволяют автоматизировать процессы в системе Totum, выполняя различные действия между полями и таблицами в зависимости от условий и триггеров.

**Основные аспекты кодов действий:**

1. **Триггеры**: Коды действий запускаются при срабатывании определенных триггеров, таких как изменение значения в поле, добавление или удаление строки, а также двойной клик на заблокированном поле.

2. **Функции действий**: Для выполнения действий используются специальные функции, такие как `set`, `setList`, `recalculate`, `insert`, `delete` и другие. Эти функции позволяют изменять значения в полях, пересчитывать таблицы, добавлять или удалять строки и выполнять другие операции.

3. **Порядок выполнения**: Коды действий выполняются после расчета всех значений изменяемых строк. Они исполняются в том же порядке, в каком рассчитываются коды, то есть в порядке плейсментов и `sort` внутри плейсмента.

4. **Автоматизация процессов**: Коды действий позволяют автоматизировать различные процессы в системе, такие как автоматическое изменение значений в полях при изменении других полей, пересчет таблиц при изменении данных и другие операции.

5. **Оптимизация**: Использование кодов действий позволяет оптимизировать процессы в системе, уменьшая количество ручных операций и повышая эффективность работы с данными.

**Пример использования**

В данном примере мы изменяем значение в поле 'field_2' на 100 при изменении значения в поле 'field_1'.

```totum
=: set(table: $#ntn; field: 'field_2' = 100; where: 'id' = #id; log: true)
```

**Пояснение**

- **set**: функция действия, которая изменяет значение в указанной ячейке.
- **table: $#ntn**: Указывает текущую таблицу.
- **field: 'field_2' = 100**: Устанавливает новое значение 100 для поля 'field_2'.
- **where: 'id' = #id**: Условие, по которому выбирается строка для изменения (в той же строке).
- **log: true**: Включает ведение журнала изменений.

Таким образом, коды действий в Totum позволяют автоматизировать и оптимизировать работу с данными, выполняя различные действия в зависимости от условий и триггеров.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai6"></a> Какие триггеры могут запускать коды действий?

В системе Totum коды действий могут запускаться при срабатывании следующих триггеров:

1. **Выполнять код действия при добавлении** (`CodeActionOnAdd`): Этот триггер активирует код действия, когда в таблицу добавляется новая строка или создается новый цикл или временная таблица.

2. **Выполнять код действия при изменении** (`CodeActionOnChange`): Этот триггер активирует код действия, когда изменяется значение в поле. Это позволяет автоматически выполнять действия при изменении данных в таблице.

3. **Выполнять код действия при удалении** (`CodeActionOnDelete`): Этот триггер активирует код действия, когда строка удаляется из таблицы. Это может быть полезно для выполнения действий, связанных с удалением данных.

4. **Выполнять код действия при клике** (`CodeActionOnClick`): Этот триггер активирует код действия при двойном клике на заблокированном поле. Это позволяет выполнять действия по запросу пользователя, когда он взаимодействует с интерфейсом.

Эти триггеры позволяют гибко настраивать автоматизацию процессов в системе Totum, выполняя различные действия в зависимости от изменений в данных или взаимодействия пользователя с интерфейсом.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai7"></a> Что произойдет, если не активирован ни один триггер в коде действия?

Если в коде действия не активирован ни один триггер, то код действия не будет выполнен. В системе Totum триггеры служат сигналом к запуску кода действия, и без активного триггера код действия останется неактивным, даже если он прописан в настройках поля. Это означает, что никакие автоматические изменения или действия, которые должны были быть выполнены кодом действия, не произойдут.

Коды действия подсвечиваются в заголовке поля звездочкой — если звездочка в заголовке поля, обозначающая наличие кодов действий, пустая, это указывает на то, что нет ни одного активного триггера. Для активации кода действия необходимо включить хотя бы один из доступных триггеров, таких как:

- Выполнять код действия при добавлении.
- Выполнять код действия при изменении.
- Выполнять код действия при удалении.
- Выполнять код действия при клике.

Только после активации одного из этих триггеров код действия начнет выполняться в ответ на соответствующие события в таблице.

Пустая звездочка в заголовке поля с кодом действия в системе Totum обозначает, что в поле есть код действия, но ни один из триггеров не активирован. Это означает, что код действия прописан, но он не будет выполняться, так как не задано ни одно условие (триггер), при котором этот код должен срабатывать. Чтобы код действия начал выполняться, необходимо активировать хотя бы один из доступных триггеров, таких как:

- Выполнять код действия при добавлении.
- Выполнять код действия при изменении.
- Выполнять код действия при удалении.
- Выполнять код действия при клике.

Только после активации одного из этих триггеров код действия начнет выполняться в ответ на соответствующие события в таблице.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai9"></a> В какой момент выполняется код действия?

Коды действий в системе Totum выполняются после завершения расчета всех значений изменяемых строк. Это означает, что сначала система рассчитывает все значения полей, которые были изменены, а затем, если срабатывают триггеры, выполняются коды действий.

**Порядок выполнения кодов действий:**

1. **Расчет значений**: Сначала рассчитываются все значения полей в таблице, которые были изменены. Это включает в себя выполнение всех кодов, которые определяют значения полей.

2. **Срабатывание триггеров**: После расчета значений система проверяет, какие поля были изменены и какие триггеры сработали. Триггеры могут быть настроены на выполнение кода действия при добавлении, изменении, удалении или клике.

3. **Выполнение кодов действий**: Если триггеры сработали, выполняются коды действий в том же порядке, в каком рассчитывались коды значений. Это означает, что коды действий выполняются в порядке плейсментов и `sort` внутри плейсмента: сначала хедер, затем строчная часть, затем футер.

Таким образом, коды действий выполняются после того, как все значения полей были рассчитаны, и сработали соответствующие триггеры. Это позволяет автоматизировать процессы и выполнять действия на основе изменений в данных.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai10"></a> Какой порядок выполнения кодов действий и вычислений?

В системе Totum порядок выполнения кодов действий и вычислений определяется следующим образом:

**1. Вычисления**

Сначала выполняются все вычисления в полях, включая коды, которые определяют значения ячеек. Это происходит в соответствии с установленным порядком плейсментов и параметром `sort` для полей в составе таблиц. Плейсменты рассчитываются последовательно:

- **Хедер**: Сначала рассчитываются поля в хедере таблицы.
- **Префильтр**: Затем рассчитываются поля в префильтре, если он используется.
- **Строчная часть**: Далее рассчитываются поля в строчной части таблицы. Поля рассчитываются построчно слева-направо по возрастанию `sort` и сверху-вниз в порядке возрастания их `id`. Если строки выровнены по полю сортировки `n`, то они рассчитываются в порядке возрастания `n`.
- **Футер**: В конце рассчитываются поля в футере таблицы, если он есть.

**2. Коды действий**

После завершения всех вычислений выполняются коды действий, если сработали триггеры. Коды действий запускаются в том же порядке, в каком рассчитывались коды значений. Это означает, что коды действий выполняются в порядке плейсментов и `sort` внутри плейсмента:

- **Хедер**: Сначала выполняются коды действий в хедере.
- **Строчная часть**: Затем выполняются коды действий в строчной части.
- **Футер**: В конце выполняются коды действий в футере.

**3. Порядок выполнения кодов действий**

Коды действий выполняются в порядке, определяемом плейсментом и сортировкой внутри плейсмента:

- **Строки**: Обрабатываются по возрастанию `id` или `n`, а внутри по возрастанию `sort`.
- **Поколоночный пересчет**: В случае поколоночного пересчета, коды действий выполняются поколоночно по возрастанию `id` или `n`.

**Пример**

Допустим, у вас есть таблица с полями A, B и C и строками 1, 2, 3. Также есть поле H, которое находится в хедере таблицы. Если вы измените значение в поле A в строках 1 и 3, то сначала будет вычислено значение поля H в хедере, потом поля B и С будут пересчитаны сначала в строке 1, а потом в строке 3. После этого, если сработают триггеры, выполнятся коды действий в том же порядке.

Таким образом, в Totum сначала выполняются все вычисления значений полей, а затем, если срабатывают триггеры, выполняются коды действий в порядке, определяемом плейсментом и сортировкой.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai11"></a> Что произойдет, если в поле 1 добавить код действие с триггером на изменение, изменяющий поле 2, а в поле2 добавить код действия с триггером на изменение, изменяющий значение в поле 3?

Если в поле 1 добавить код действия с триггером на изменение, который изменяет значение в поле 2, а в поле 2 добавить код действия с триггером на изменение, который изменяет значение в поле 3, то при изменении значения в поле 1 произойдет следующее:

1. **Изменение в поле 1**: Когда вы измените значение в поле 1, это вызовет выполнение кода действия, связанного с этим полем.

2. **Код действия в поле 1**: Код действия в поле 1 изменит значение в поле 2. Это изменение сработает как триггер для кода действия в поле 2.

3. **Код действия в поле 2**: Изменение значения в поле 2 вызовет выполнение кода действия, связанного с этим полем. Код действия в поле 2 изменит значение в поле 3.

Таким образом, изменение в поле 1 приведет к каскадному выполнению кодов действий, сначала изменяя поле 2, а затем поле 3. Это может привести к каскаду пересчетов, что может увеличить нагрузку на сервер, особенно если в таблице много строк или если коды действий выполняют сложные операции.

**Пример кода действий:**

**Код действия в поле 1:**
```totum

```

**Код действия в поле 2:**
```totum
=: set(table: $#ntn; field: 'field_3' = "new_value_3"; where: 'id' = #id; log: true)
```

**Важные моменты:**
- Убедитесь, что коды действий не создают бесконечные циклы, которые могут привести к зацикливанию и зависанию системы.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai13"></a> Как изменить значения сразу нескольких полей в одной строке с помощью одного кода действия?

- **field: 'field_2' = "new_value_2"**: Устанавливает новое значение для поля `field_2`.
- **where: 'id' = #id**: Условие, по которому выбирается строка для изменения (в данном случае строка с текущим `id`).
- **log: true**: Включает ведение журнала изменений.

**Пример использования:**

Предположим, у вас есть таблица с полями `status` и `updated_at`, и вы хотите изменить их значения в одной строке:


В этом примере поле `status` будет установлено в значение `"completed"`, а поле `updated_at` будет обновлено до текущей даты и времени. Условие `where: 'id' = #id` гарантирует, что изменения будут применены только к текущей строке.

Таким образом, вы можете эффективно изменять значения нескольких полей в одной строке с помощью одного кода действия в Totum.

2. **Каскад пересчетов**: Если код действия в одной строке вызывает изменение в другой строке, это может привести к каскадному выполнению кодов действий. Это может увеличить нагрузку на сервер, особенно если в таблице много строк или если коды действий выполняют сложные операции.

3. **Оптимизация**: Чтобы избежать каскадного выполнения и уменьшить нагрузку на сервер, рекомендуется объединять изменения в одном коде действия, если это возможно. Например, если необходимо изменить несколько полей одновременно, лучше сделать это в одном коде действия.

Если код действия в строке 1 изменяет значение в поле B, это изменение может вызвать выполнение кода действия для поля B, если в нем есть триггер на изменение.

**Хитрость для оптимизации**

Для таблиц, рассчитывающихся целиком, можно использовать технические поля для отслеживания, чтобы выполнить одно действие при изменении нескольких строк:


2. **Код действия по триггеру**: В коде действия по триггеру на изменение выполните действие.

```totum

```

Тотум автоматически будет отслеживать состав поля, и когда оно изменится по изменению одного или нескольких отслеживаемых значений, выполнит код-действия один раз.

Таким образом, коды действий в Totum выполняются на каждую измененную строку отдельно, и для оптимизации можно использовать объединение изменений в одном коде действия или специальные техники для таблиц, рассчитывающихся целиком.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai18"></a> В чем разница между `set` и `setList`?

В системе Totum функции `set` и `setList` используются для изменения значений в таблицах, но они имеют различия в том, как они применяются к данным.

**`set`**

- **Назначение**: Функция `set` используется для изменения значения в одном конкретном поле одной строки таблицы.
- **Применение**: Даже если под условия подходят несколько строк, `set` изменит значение только в одной из них. Какая именно строка будет изменена, зависит от порядка строк в базе данных, и это может быть непредсказуемо.
- **Пример использования**:

```totum
=: set(table: 'table_name'; field: 'field_name' = "new_value"; where: 'condition_field' = #condition)
```

В этом примере значение поля `field_name` будет изменено на `"new_value"` в одной строке, которая соответствует условию `where`.

**`setList`**

- **Назначение**: Функция `setList` используется для изменения значений в нескольких строках таблицы, которые соответствуют заданным условиям.
- **Применение**: `setList` изменяет все значения, подходящие под условия, что делает её более подходящей для массовых изменений.
- **Пример использования**:

```totum
=: setList(table: 'table_name'; field: 'field_name' = "new_value"; where: 'condition_field' = #condition)
```

В этом примере значение поля `field_name` будет изменено на `"new_value"` во всех строках, которые соответствуют условию `where`.

**Основные различия**

- **Область применения**: `set` изменяет только одну строку, даже если под условия подходят несколько, в то время как `setList` изменяет все строки, которые соответствуют условиям.
- **Использование**: `set` подходит для точечных изменений, когда нужно изменить только одну строку, а `setList` — для массовых изменений, когда нужно изменить несколько строк одновременно.

Таким образом, выбор между `set` и `setList` зависит от того, сколько строк вы хотите изменить: одну или несколько.

Таким образом, выбор между `set` и `setList` зависит от того, сколько строк вы хотите изменить: одну или несколько.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai20"></a> Можно ли указать изменение нескольких полей одновременно с помощью функции `set`?

Да, в системе Totum функция `set` позволяет за одно действие указать изменение нескольких полей одновременно. Это можно сделать, указав все изменяемые поля и их новые значения в одном вызове функции `set`.

Вот пример, как это сделать:

```totum
=: set(table: 'table_name'; field: 'field_1' = "new_value_1"; field: 'field_2' = "new_value_2"; where: 'id' = #id; log: true)
```

**Пояснение:**

- **table: 'table_name'**: Указывает таблицу, в которой будут изменены значения.
- **field: 'field_1' = "new_value_1"**: Устанавливает новое значение для поля `field_1`.
- **field: 'field_2' = "new_value_2"**: Устанавливает новое значение для поля `field_2`.
- **where: 'id' = #id**: Условие, по которому выбирается строка для изменения (в данном случае строка с текущим `id`).
- **log: true**: Включает ведение журнала изменений.

**Пример использования:**

Предположим, у вас есть таблица с полями `status` и `updated_at`, и вы хотите изменить их значения в одной строке:

```totum
=: set(table: 'orders'; field: 'status' = "completed"; field: 'updated_at' = $#ndt; where: 'id' = #id; log: true)
```

В этом примере поле `status` будет установлено в значение `"completed"`, а поле `updated_at` будет обновлено до текущей даты и времени. Условие `where: 'id' = #id` гарантирует, что изменения будут применены только к текущей строке.

Таким образом, вы можете эффективно изменять значения нескольких полей в одной строке с помощью одного кода действия в Totum.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai21"></a> Какая функция позволяет установить значения сразу для нескольких строк?

В системе Totum функция, которая позволяет установить значения сразу для нескольких строк, называется `setList`. Эта функция изменяет все значения, подходящие под заданные условия, что делает её более подходящей для массовых изменений.

**Пример использования `setList`:**

```totum
=: setList(table: 'table_name'; field: 'field_name' = "new_value"; where: 'condition_field' = #condition)
```

В этом примере значение поля `field_name` будет изменено на `"new_value"` во всех строках, которые соответствуют условию `where: 'condition_field' = #condition`.

Таким образом, `setList` позволяет эффективно изменять значения в нескольких строках одновременно, что особенно полезно для массовых обновлений данных в таблице.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai22"></a> Как функция `execButton` используется в кодах действий?

Функция `execButton` в системе Totum используется для выполнения кода действия, связанного с кнопкой, из другого кода действия. Это позволяет автоматизировать выполнение действий, которые обычно требуют нажатия кнопки пользователем. Давайте рассмотрим, как это работает и как использовать `execButton` в кодах действий.

**Основные аспекты использования `execButton`:**

1. **Назначение**: `execButton` позволяет программно инициировать выполнение кода действия, связанного с кнопкой в таблице. Это может быть полезно для автоматизации процессов, которые обычно требуют ручного вмешательства.

2. **Параметры**:
   - **table**: Указывает таблицу, в которой находится кнопка.
   - **field**: Указывает поле, которое является кнопкой и содержит код действия.

3. **Пример использования**:

Предположим, у вас есть таблица с кнопкой, которая выполняет определенное действие, например, отправку уведомления. Вы можете использовать `execButton` в коде действия другой кнопки или триггера, чтобы инициировать выполнение этого действия.

```totum
=: execButton(table: 'orders'; field: 'send_notification_button')
```

В этом примере функция `execButton` инициирует выполнение кода действия, связанного с кнопкой `send_notification_button` в таблице `orders`.

4. **Контекст выполнения**: Код действия, связанный с кнопкой, будет выполнен в том же контексте, как если бы пользователь нажал на кнопку вручную. Это означает, что все условия и триггеры, связанные с кнопкой, будут учтены.

5. **Ограничения**: Код действия кнопки, которую вы хотите выполнить, будет выполнен в любом случае, даже если кнопка недоступна для текущего пользователя по своим настройкам видимости.

**Заключение**

Функция `execButton` предоставляет мощный инструмент для автоматизации процессов в Totum, позволяя инициировать выполнение действий, связанных с кнопками, из других кодов действий. Это может значительно упростить и ускорить выполнение повторяющихся задач, требующих ручного вмешательства.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai23"></a> Что произойдет, если в расчетной таблице применяется `set`?

В системе Totum, если в расчетной таблице применяется функция `set`, это приведет к пересчету всей таблицы. Это связано с тем, что расчетные таблицы имеют табличную единицу пересчета, что означает, что при любом изменении данных в таблице, вся таблица пересчитывается целиком.

**Последствия применения `set` в расчетной таблице:**

1. **Пересчет всей таблицы**: Вся таблица будет пересчитана, включая все строки и поля, даже если изменение было внесено только в одно поле одной строки.

2. **Нагрузка на сервер**: Пересчет всей таблицы может увеличить нагрузку на сервер, особенно если таблица содержит большое количество строк или сложные вычисления.

**Пример использования `set` в расчетной таблице:**

```totum
=: set(table: 'calculation_table'; field: 'field_name' = "new_value"; where: 'condition_field' = #condition)
```

В этом примере значение поля `field_name` будет изменено на `"new_value"` в строках, которые соответствуют условию `where`. После этого вся таблица будет пересчитана.

**Рекомендации:**

- **Оптимизация**: Если возможно, старайтесь минимизировать количество вызовов `set` записывающих в расчетную таблицу, чтобы уменьшить нагрузку на сервер.
- **Анализ производительности**: Периодически анализируйте производительность таблиц и оптимизируйте коды и структуры данных, чтобы уменьшить время пересчета.

Таким образом, применение `set` в расчетной таблице приводит к пересчету всей таблицы, что может повлиять на производительность системы.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai24"></a> Что произойдет, если в изменяемом поле также есть код действия с триггером на изменение?

Если в изменяемом поле также есть код действия с триггером на изменение, то при изменении значения в этом поле сработает триггер, и код действия будет выполнен. Это может привести к каскадному выполнению кодов действий, если изменение в одном поле вызывает изменение в другом, и так далее.

**Пример сценария:**

1. **Изменение в поле 1**: Вы изменяете значение в поле 1, что вызывает выполнение кода действия, связанного с этим полем.

2. **Код действия в поле 1**: Код действия в поле 1 изменяет значение в поле 2. Это изменение срабатывает как триггер для кода действия в поле 2.

3. **Код действия в поле 2**: Изменение значения в поле 2 вызывает выполнение кода действия, связанного с этим полем. Код действия в поле 2 может изменить значение в поле 3, и так далее.

**Важные моменты:**

- **Каскад пересчетов**: Такой каскад может привести к увеличению нагрузки на сервер, особенно если в таблице много строк или если коды действий выполняют сложные операции.

- **Оптимизация**: Чтобы избежать каскадного выполнения и уменьшить нагрузку на сервер, рекомендуется объединять изменения в одном коде действия, если это возможно. Например, если необходимо изменить несколько полей одновременно, лучше сделать это в одном коде действия.

- **Зацикливание**: Будьте осторожны, чтобы не создать бесконечный цикл изменений, который может привести к зацикливанию и зависанию системы.

**Пример кода действий:**

**Код действия в поле 1:**
```totum
=: set(table: $#ntn; field: 'field_2' = "new_value_2"; where: 'id' = #id; log: true)
```

**Код действия в поле 2:**
```totum
=: set(table: $#ntn; field: 'field_3' = "new_value_3"; where: 'id' = #id; log: true)
```

Таким образом, изменение в поле 1 может привести к каскадному выполнению кодов действий, сначала изменяя поле 2, а затем поле 3.

#### <a name="assign-a-new-value-to-another-field-when-you-change-the-current-one-ai25"></a> Как работает выполнение кодов действий, если изменяется несколько строк одновременно?

В системе Totum, когда изменяется несколько строк одновременно, коды действий выполняются на каждую измененную строку отдельно. Это означает, что если вы измените значения в нескольких строках, код действия будет выполнен для каждой из этих строк в отдельности.

**Порядок выполнения**

1. **Последовательность выполнения**: Коды действий выполняются последовательно для каждой измененной строки. Это происходит в порядке возрастания `id` или `n`, если таблица отсортирована по этому полю.

2. **Каскад пересчетов**: Если код действия в одной строке вызывает изменение в другой строке, это может привести к каскадному выполнению кодов действий. Это может увеличить нагрузку на сервер, особенно если в таблице много строк или если коды действий выполняют сложные операции.

3. **Оптимизация**: Чтобы избежать каскадного выполнения и уменьшить нагрузку на сервер, рекомендуется объединять изменения в одном коде действия, если это возможно. Например, если необходимо изменить несколько полей одновременно, лучше сделать это в одном коде действия.

**Пример**

Предположим, у вас есть таблица с полями A, B и C, и вы изменяете значения в поле A в строках 1 и 3. В этом случае код действия будет выполнен сначала для строки 1, а затем для строки 3. Если код действия в строке 1 изменяет значение в поле B, это изменение может вызвать выполнение кода действия для поля B, если в нем есть триггер на изменение.

**Хитрость для оптимизации**

Для таблиц, рассчитывающихся целиком, можно использовать технические поля для отслеживания, чтобы выполнить одно действие при изменении нескольких строк:

1. **Техническое поле в футере**: Создайте техническое поле в футере таблицы, которое будет содержать список значений изменяемого поля.

```totum
=: selectList(table: $#ntn; field: 'field'; order: 'field' asc)
```

2. **Код действия по триггеру**: В коде действия по триггеру на изменение выполните действие.

```totum
=: recalculate(table: 'table_to_recalc')
```

Тотум автоматически будет отслеживать состав поля, и когда оно изменится по изменению одного или нескольких отслеживаемых значений, выполнит код-действия один раз.

Таким образом, коды действий в Totum выполняются на каждую измененную строку отдельно, и для оптимизации можно использовать объединение изменений в одном коде действия или специальные техники для таблиц, рассчитывающихся целиком.

**1. Использование технических полей**

Создайте техническое поле в футере таблицы, которое будет содержать список значений изменяемого поля. Это позволит отслеживать изменения и выполнять код действия только один раз, когда состав поля изменится в одной или нескольких строках.

Если необходимо пересчитать таблицу по результатам изменения любого поля в таблице, но сделать это только один раз, используйте код действия таблицы с функцией `recalculate`.

Эти подходы помогут оптимизировать выполнение кода действия в таблицах, рассчитывающихся целиком, и уменьшить нагрузку на сервер, повышая производительность системы Totum.

### <a name="perform-several-actions-in-sequence-qa"></a> Вопросы и ответы

#### <a name="perform-several-actions-in-sequence-q1"></a> Может ли код-действия иметь несколько секций = ?

Да. Коды действий могут. Выглядит так:

```totum
a1=: set(table: 'table'; field: 'fild_name' = #new_value)

a2=: recalculate(table: 'summary')

```

Префиксы `a` означают действие по любому триггеру — добавление, удаление, изменение или двойной клик.

Порядок выполнения будет в порядке указанной цифры, обработанной как строка.

Те `a11` будет раньше чем `a2`.

#### <a name="perform-several-actions-in-sequence-q2"></a> Какой префикс надо использовать, чтобы выполнить код действия только по определенному триггеру?

+ `a` — общий (он будет вполнен раньше всех прочих).

+ `ch` — только изменение.

+ `ad` — только добавление.

+ `dl` — только при удалении.

+ `cl` — при двойном клике на заблокированное поле.

Получается, что в одном поле можно задать разные действия по разным триггерам:

```totum
a1=: pin(table: $#ntn; field: 'name'; where: 'id' = #id)

ad1=: set(table: 'table_1'; field: 'set_field' = $#nfv; where: 'link' = #id)

dl1=: set(table: 'table_1'; field: 'set_field' = ""; where: 'link' = #old.id)

a2=: recalculate(table: 'summary')

// Про предыдущие значения #old.** будет чуть дальше

```

В этом коде:

+ cекция `a`, состоящая из двух действий `a1` и `a2` будет выполнятся всегда (должен быть включен хотябы один триггер).

+ `ad1` только по триггеру `добавление` (триггер должен быть включен).

+ `dl1` только по триггеру `удаление` (триггер должен быть включен).

#### <a name="perform-several-actions-in-sequence-q3"></a> Какие два способа доступны, что бы последовательно выполнить несколько действий?

1. Использовать несколько секций `=:` с префиксами.

2. Использовать функцию [while][284]. Пример:

```totum

=: while(action: $action1; action: $action2)

action1: set(table: 'table'; field: 'set_field' + #new_value)

action2: recalculate(table: 'summary')

// Про относительное изменение при помощи set — field: 'set_field' + #new_value, будет рассказано чуть дальше

```

Если использовать только параметры `action` в [while][284], то они последовательно выполнятся один раз.

#### <a name="perform-several-actions-in-sequence-q4"></a> Можно ли добавить условия, проверяющие нужно ли выполнять действие?

Да, можно через [if][283], например:

```totum
=: if(condition: $#nfv != ""; then: $action)

	action: insert(table: 'table'; field: 'field' = $#nd)

	// параметр else можно не указвать

	// insert добавляет строки

```

В этом примере, если при изменении текущее поле не будет пустоты, то в таблицу `table` будет добавлена строка, и в ней в поле `field` будет установлена текущая дата.

Или через `condition` в [while][284]:

```totum
=: while(condition: $#nfv != ""; action: $action)

	action: insert(table: 'table'; field: 'field' = $#nd)

	// action будет выполнен только если все condition выполнятся в true

```

В качестве примера, в поле 3 не было кода, а здесь мы напишем код действия, который будет выполняться при добавлении. Используем функцию действия `linkTo-DataText` - это функция, которая показывает всплывающее окно. Напишем в ней тест, и поставим здесь триггер на добавление.


Давайте посмотрим, что произойдет. Здесь у нас есть новая строка. Мы помещаем сюда какое-то значение, сохраняем его, а затем, независимо от того, есть ли у меня здесь в поле, в котором активен код на добавление, или нет, код действия добавления был выполнен для этого поля.
То же самое верно и для удаления. Если мы удаляем строку, то никакого действия не происходит. Если мы установим триггер удаления, то он активируется при удалении, не зависим от того, была ли в момент удаления сохраненная информация в поле с кодом действия на удаление.

Здесь у меня поле с чекбоксом, и нажатием кнопки я хочу поставить здесь, например, значение 200 и галочку в чекбоксе. Одним действием это не получится, потому что у нас есть одно действие - это будет setList в строчной части – этим действием в поле 2, мы поставим значение 200 во все строки. Поэтому нельзя две строки начать с `=:`. Если мы хотим выполнить действие на любом триггере, то делаем так: первая строка будет `a1=:`,  вторая строка`a2=:`. Как и при форматировании, имена начальных строк сравниваются и сортируются как строки. Если вы добавите `a11=:`, то триггер будет выполнен между `a1=:` и`a2=:`. a1= : setList(table: $#ntn; field: 'field_2' = 200; where: 'id' ≠ 0; log: true)
```totum
a2= : set(table: $#ntn; field: 'h_checkbox' = $calc; log: true)
calc: if(condition: #h_checkbox = true; then: false; else: true)
```
При нажатии на кнопку сначала выполнится первое действие, а затем следующее.
В кодах действия существует несколько таких префиксов.
`a` – это общий префикс, который выполняется раньше остальных. То есть сначала будут выполнены `a1=:`, `a2=:`, `a3=:`, `a4=:` и так далее. Затем идут `ch`, которые происходят от слова chage. Они будут срабатывать только при изменении.

У кнопки нет других триггеров, задаваемых в интерфейсе, только клик. Но код действия имеет разные триггеры в этом поле. Например, на добавление, на изменение. Если мы укажем, что эта строка `ch1=:`, то эта строка будет выполняться только триггером на изменение. Если триггер отключен, то вообще ничего не будет выполняться.
Остается только add: если строка начинается, например, `ad1=:`,  то эта строка будет выполняться триггером только при добавлении. Для удаления используется триггер `dl=:`, и он выполняется только при удалении.
Существует такой триггер двойного щелчка. Он вызывается в поле, когда оно заблокировано и пользователь делает на нем двойной щелчок, как для редактирования. Для этого действия отводится отдельная строка, тогда она будет обозначена `cl1=:`. При этом `cl1=:`и `cl2=:` не будут пересекаться с триггерами по другим действиям, например с `dl1=:`и `dl2=:`. Между этими блоками не нужно выстраивать сквозную нумерацию. Все они будут работать и так.
Какой префикс надо использовать, чтобы выполнить код действия только по определенному триггеру?
•	a — общий (он будет выполнен раньше всех прочих).
•	ch — только изменение.
•	ad — только добавление.
•	dl — только при удалении.
•	cl — при двойном клике на заблокированное поле.
Получается, что в одном поле можно задать разные действия по разным триггерам:
```totum
a1=: pin(table: $#ntn; field: 'name'; where: 'id' = #id)

ad1=: set(table: 'table_1'; field: 'set_field' = $#nfv; where: 'link' = #id)

dl1=: set(table: 'table_1'; field: 'set_field' = ""; where: 'link' = #old.id)

a2=: recalculate(table: 'summary')
```

В этом коде:
•	cекция a, состоящая из двух действий a1 и a2 будет выполнятся всегда (должен быть включен хотябы один триггер).
•	ad1 только по триггеру добавление (триггер должен быть включен).
•	dl1 только по триггеру удаление (триггер должен быть включен).

Ладно, с этим мы разобрались, теперь следующий вопрос. Как еще, кроме этих участков кода a1 и a2, можно сделать так, чтобы несколько последовательных действий выполнялись одно за другим. Например, нужно, чтобы внутри a2 выполнялось еще несколько действий. Это делается следующим образом. Я закомментирую пока а2. Мы используем функцию `while`; она последовательно выполняет действия, указанные внутри нее. В ней мы укажем два действия, задаваемые множественным параметром `action`, action, и в каждом из действий сошлемся на строчку кода через $. А расчет, выполняемый calc, оставим таким же как был, т.к. тут у нас ничего не меняется.
```totum
=: while(action: $code_1; action: $code_2)
code_1: setList(table: $#ntn; field: 'field_2' = 200; where: 'id' ≠ 0; log: true)
code_2: set(table: $#ntn; field: 'h_checkbox' = $calc; log: true)
calc: if(condition: #h_checkbox = true; then: false; else: true)
```

И так, здесь у нас есть `while`, он сначала перейдет сюда, выполнит первое действие, затем перейдет к действию 2 и выполнит это действие. И в `while` мы можем писать условия, потому что есть параметр `condition`. Например, мы можем сказать, что если `h_checkbox = true`, то выполните это. Если это условие не выполняется, то ни одно из этих действий не будет выполнено.

```totum
=: while(condition: h_checkbox = true; action: $code_1; action: $code_2)
code_1: setList(table: $#ntn; field: 'field_2' = 200; where: 'id' ≠ 0; log: true)
code_2: set(table: $#ntn; field: 'h_checkbox' = $calc; log: true)
calc: if(condition: #h_checkbox = true; then: false; else: true)
```

Давайте попробуем это сделать. У нас есть чекбокс, не отмеченный как true, мы щелкаем, ничего не происходит, мы ставим чекбокс, и тогда происходят эти действия.

Условия также могут быть добавлены и непосредственно в основную строку кода действия. Есть множество случаев, когда это применяется. Например, сделаем вот так: У нас есть коды действия, например, вызывающий всплывающее окно с помощью функции действия `linkToDataText`. Если мы хотим, чтобы он выполнялся только в том случае, если наш checkbox равен `true`, мы можем сделать это с простой помощью простой функции `if`, а на код действия сошлемся уже в этой функции. Если `h_checkbox = true`, то условие выполняется. И ничего больше не указываем. Здесь нам не нужно указывать else, это необязательно. Если условие истинно, то выполняется код действия. Если нет, то ничего не происходит.
```totum
ad1 =: if(condition: #h_checkbox = true; then: $link)
link: linkToDataText(title: "test"; text: "test")
```
Вот и все. Давайте попробуем. Чекбокс не установлен. Добавляем что-то сюда, и ничего не происходит, окно не открывается, пробуем еще раз: ставим чекбокс, пишем что-то здесь, сохраняем, и тогда условие выполняется - код действия переходит в then.

Может ли код-действия иметь несколько секций = ?
Да. Коды действий могут. Выглядит так:
```totum

a2=: recalculate(table: 'summary')
```

Префиксы a означают действие по любому триггеру — добавление, удаление, изменение или двойной клик.
Порядок выполнения будет в порядке указанной цифры, обработанной как строка.
Те a11 будет раньше, чем a2.
Какие два способа доступны, что бы последовательно выполнить несколько действий?
1.	Использовать несколько секций =: с префиксами.
2.	Использовать функцию while. Пример:

```totum
=: while(action: $action1; action: $action2)
action1: set(table: 'table'; field: 'set_field' + #new_value)
action2: recalculate(table: 'summary')

// Про относительное изменение при помощи set — field: 'set_field' + #new_value, будет рассказано чуть дальше
```

Если использовать только параметры action в while, то они последовательно выполнятся один раз.
Можно ли добавить условия, проверяющие нужно ли выполнять действие?
Да, можно через if, например:

```totum
=: if(condition: $#nfv != ""; then: $action)
    action: insert(table: 'table'; field: 'field' = $#nd)
    // параметр else можно не указвать
    // insert добавляет строки
```

В этом примере, если при изменении текущее поле не будет пустоты, то в таблицу table будет добавлена строка, и в ней в поле field будет установлена текущая дата.
Или через condition в while:
```totum
=: while(condition: $#nfv != ""; action: $action)
    action: insert(table: 'table'; field: 'field' = $#nd)
    // action будет выполнен только если все condition выполнятся в true
```

### <a name="perform-several-actions-in-sequence-ai"></a> Дополнительные вопросы

#### <a name="perform-several-actions-in-sequence-ai1"></a> Что такое триггер кода действия на изменение?

Триггер кода действия на изменение в системе Totum — это условие, при котором выполняется код действия, связанный с изменением значения в определенном поле таблицы. Когда происходит изменение значения в этом поле, срабатывает триггер, и выполняется соответствующий код действия. Это позволяет автоматизировать выполнение определенных операций в ответ на изменения данных в таблице.

**Пример использования триггера на изменение:**

Допустим, у вас есть таблица с полем, в котором хранится количество товара на складе. Вы можете настроить код действия, который будет срабатывать при изменении этого количества. Например, если количество товара становится меньше определенного значения, можно автоматически отправить уведомление о необходимости пополнения запасов.

**Пример кода действия с триггером на изменение:**

```totum
ch1=: if(condition: #quantity < 10; then: $notify)

notify: notificationSend(users: json`[1,2,3]`; title: "Low Stock Alert"; ntf: "The stock for item is below 10.")
```

В этом примере, если значение в поле `quantity` становится меньше 10, срабатывает триггер, и выполняется код действия, который отправляет уведомление пользователям с ID 1, 2 и 3 о низком уровне запасов.

**Как настроить триггер на изменение:**

1. **Откройте настройки поля**: Перейдите в настройки таблицы и выберите поле, для которого вы хотите настроить триггер.

2. **Включите триггер на изменение**: В настройках поля найдите параметр "Код действия на изменение" и включите его.

3. **Напишите код действия**: Введите код, который должен выполняться при изменении значения в поле.

Таким образом, триггер кода действия на изменение позволяет автоматизировать выполнение операций в ответ на изменения данных, что может быть полезно для различных сценариев автоматизации в системе Totum.

#### <a name="perform-several-actions-in-sequence-ai2"></a> Почему при введении значения в строку добавления никакого действия не происходит, хотя в добавляемой строке заполнено поле с активным кодом действия?

При введении значения в строку добавления никакого действия не происходит, потому что коды действий не работают до тех пор, пока данные не будут сохранены. Введенные данные существуют только на стороне клиента, и действие происходит только при сохранении данных в базу данных. Код действия срабатывает только при добавлении строки, а не при вводе данных в строку добавления.

Чтобы код действия сработал на добавление после сохранения добавляемой строки, в нем должен быть включен триггер "выполнение действия при добавлении". Также это действие среди прочих в коде-действия можно выделить используя префикс `ad`, например:

```totum
ad1=: set(table: 'table_name'; field: 'field_name' = #new_value)
```

В этом примере код действия `ad1` будет выполнен только при добавлении строки, если триггер на добавление активирован.

#### <a name="perform-several-actions-in-sequence-ai3"></a> Когда происходит запись данных в базу данных?

В системе Totum запись данных в базу данных происходит в момент сохранения изменений в таблице. До этого введенные данные существуют только на стороне клиента. Это означает, что любые изменения, которые вы вносите в таблицу, не будут сохранены в базе данных до тех пор, пока вы не нажмете кнопку "Сохранить" или не выполните действие, которое инициирует сохранение данных.

**Примеры ситуаций, когда происходит запись данных:**

1. **Сохранение строки**: Когда вы вводите данные в строку добавления и нажимаете "Сохранить", данные записываются в базу данных.

2. **Изменение существующей строки**: Если вы изменяете данные в уже существующей строке и сохраняете изменения, они записываются в базу данных.

3. **Выполнение кода действия**: Некоторые коды действий могут инициировать запись данных в базу, например, через функции `set`, `insert`, `delete` и другие.

4. **Автоматическое сохранение**: В некоторых случаях, например, при выполнении определенных действий или триггеров, система может автоматически сохранять изменения в базе данных.

**Важные моменты:**

- **Коды действий**: Коды действий выполняются после окончания расчета кодов и могут инициировать запись данных в базу, если это предусмотрено логикой кода.

- **Триггеры**: Запись данных может быть инициирована триггерами, такими как добавление, изменение или удаление строки.

- **Проверка данных**: Перед записью данных в базу система может выполнять проверки и валидацию данных, чтобы убедиться в их корректности.

Таким образом, запись данных в базу данных в Totum происходит в момент сохранения изменений, что позволяет пользователям вносить изменения и проверять их перед окончательной фиксацией в базе данных.

#### <a name="perform-several-actions-in-sequence-ai4"></a> Какое действие срабатывает при изменении данных в существующей строке?

При изменении данных в существующей строке в системе Totum срабатывает код действия с триггером на изменение. Это означает, что если в поле настроен код действия, который должен выполняться при изменении значения, то этот код будет выполнен, когда происходит изменение данных в этом поле.

**Пример кода действия с триггером на изменение:**

```totum
ch1=: if(condition: #quantity < 10; then: $notify)

notify: notificationSend(users: json`[1,2,3]`; title: "Low Stock Alert"; ntf: "The stock for item is below 10.")
```

#### <a name="perform-several-actions-in-sequence-ai13"></a> Как работает функция `while` в коде действия?

Функция `while` в коде действия в системе Totum используется для выполнения нескольких действий последовательно. Она позволяет задать условия, при которых действия будут выполняться, и может быть использована для выполнения действий в цикле, пока выполняется определенное условие. Давайте рассмотрим, как это работает более подробно.

**Основные аспекты функции `while`:**

1. **Параметры функции**:
   - **`condition`**: Условие, при выполнении которого будут выполняться действия. Если условие истинно (`true`), действия будут выполняться. Если условие ложно (`false`), выполнение прекращается.
   - **`action`**: Действия, которые будут выполняться. Можно указать несколько действий, которые будут выполняться последовательно.

2. **Последовательное выполнение**:
   - Если указаны только параметры `action`, то они выполнятся один раз последовательно.
   - Если указано условие `condition`, то действия будут выполняться в цикле, пока условие истинно.

3. **Пример использования**:

```totum
ch1=: while(condition: $#nfv != ""; action: $action1; action: $action2)

action1: set(table: 'table_name'; field: 'field_name' = #new_value)

action2: recalculate(table: 'summary')
```

**Объяснение примера:**

- **`condition: $#nfv != ""`**: Условие, при котором будут выполняться действия. В данном случае, действия будут выполняться, если в результате изменения текущее значение поля не пустое.
- **`action1` и `action2`**: Действия, которые будут выполняться последовательно. В данном примере, сначала будет выполнено действие `action1`, затем `action2`.

**Применение:**

Функция `while` может быть полезна в ситуациях, когда необходимо выполнить несколько действий последовательно или в цикле, пока выполняется определенное условие. Это может быть полезно для автоматизации процессов, таких как обновление данных, выполнение расчетов или выполнение других операций, требующих последовательного выполнения нескольких действий.

Таким образом, функция `while` в коде действия в Totum предоставляет гибкий инструмент для управления выполнением действий, позволяя задавать условия и выполнять действия в цикле.

Функция `if` позволяет задать условие, при выполнении которого будет выполнено определенное действие. Если условие истинно (`true`), выполняется действие, указанное в параметре `then`. **Объяснение примера:**

1. **`condition: #field_name = "some_value"`**: Это условие, которое проверяется. В данном случае, условие проверяет, равно ли значение в поле `field_name` строке `"some_value"`.

2. **`then: $set`**: Если условие истинно, выполняется действие, указанное в параметре `then`. В данном примере это действие `set`, которое устанавливает новое значение `"new_value"` в поле `field_name` в таблице `table_name`.

3. **`else` (необязательный параметр)**: Если условие ложно, можно указать действие, которое будет выполнено. В данном примере параметр `else` не используется, но его можно добавить при необходимости.

**Пример с параметром `else`:**

```totum
=: if(condition: #field_name = "some_value"; then: $set; else: $notify)

set: set(table: 'table_name'; field: 'field_name' = "new_value"; where: 'where_field' = #id)

notify: notificationSend(users: json`[1,2,3]`; title: "Condition Not Met"; ntf: "The condition was not met.")
```

В этом примере, если условие не выполняется, будет отправлено уведомление пользователям с ID 1, 2 и 3.

Таким образом, функция `if` в Totum позволяет гибко управлять выполнением действий в зависимости от заданных условий, что может быть полезно для автоматизации различных процессов в системе.

#### <a name="perform-several-actions-in-sequence-ai15"></a> Какие два способа доступны для выполнения нескольких действий последовательно?

В системе Totum для выполнения нескольких действий последовательно в одном коде действия можно использовать два основных подхода:

**1. Использование нескольких секций `=:` с префиксами**

Каждое действие в коде действия может быть определено в отдельной секции с уникальным префиксом. Префиксы определяют порядок выполнения действий и могут быть использованы для указания, при каком триггере будет выполняться соответствующее действие.

Пример:

```totum
a1=: set(table: 'table_name'; field: 'field_name' = #new_value)

a2=: recalculate(table: 'summary')
```

В этом примере действия `a1` и `a2` будут выполнены последовательно. Префиксы `a1` и `a2` определяют порядок выполнения.

**2. Использование функции `while`**

Функция `while` позволяет выполнять несколько действий последовательно, указанных в параметрах `action`. Это может быть полезно, если необходимо выполнить несколько действия в определенной последовательности с предварительной проверкой.

Пример:

```totum
=: while(condition: #status = 1; action: $action1; action: $action2)

action1: set(table: 'table'; field: 'set_field' + #new_value)

action2: recalculate(table: 'summary')
```

В этом примере `while` выполняет действия `action1` и `action2` последовательно если выполняется условие в `condition`. Каждое действие определяется в отдельной строке кода и вызывается через `$`.

**Условия выполнения**

Для добавления условий, проверяющих необходимость выполнения действия, можно использовать функцию `if`:

```totum
=: if(condition: $#nfv != ""; then: $action)

action: insert(table: 'table'; field: 'field' = $#nd)
```

В этом примере действие `action` будет выполнено только в том случае, если текущее значение поля не пустое.

Таким образом, в системе Totum можно гибко настраивать выполнение нескольких действий последовательно, используя секции с префиксами или функцию `while`, а также добавлять условия для выполнения действий.

#### <a name="perform-several-actions-in-sequence-ai16"></a> Можно ли добавить условие в функцию `while` для проверки необходимости выполнения действия?

Да, в системе Totum можно добавить условие в функцию `while` для проверки необходимости выполнения действия. Это делается с помощью параметра `condition`, который позволяет задать условие, при выполнении которого будут выполняться действия, указанные в параметрах `action`. Если условие истинно (`true`), действия будут выполняться. Если условие ложно (`false`), выполнение прекращается.

**Пример использования функции `while` с условием:**

```totum
=: while(condition: #status = "active"; action: $action1; action: $action2)

action1: set(table: 'table_name'; field: 'field_name' = "new_value"; where: 'id' = #id)

action2: recalculate(table: 'summary')
```

**Объяснение примера:**

- **`condition: #status = "active"`**: Это условие, при котором будут выполняться действия. В данном случае, действия будут выполняться, если значение в поле `status` равно `"active"`.

- **`action1` и `action2`**: Действия, которые будут выполняться последовательно. В данном примере, сначала будет выполнено действие `action1`, затем `action2`.

Таким образом, функция `while` в Totum предоставляет возможность гибко управлять выполнением действий, позволяя задавать условия и выполнять действия в цикле только при выполнении определенных условий.

#### <a name="perform-several-actions-in-sequence-ai17"></a> Какие действия выполняются при префиксах `a`, `ch`, `ad`, `dl` и `cl`?

В системе Totum префиксы `a`, `ch`, `ad`, `dl` и `cl` используются для указания, при каком триггере будет выполняться соответствующее действие в коде действия. Давайте рассмотрим, какие действия выполняются при каждом из этих префиксов:

1. **`a` (общий префикс)**:
   - Действие с префиксом `a` выполняется при любом триггере. Это означает, что код действия будет выполнен независимо от того, произошло ли добавление, изменение, удаление или двойной клик. Префикс `a` позволяет задать универсальное действие, которое будет выполняться в любом случае.

   Пример:
```totum
a1=: set(table: 'table_name'; field: 'field_name' = #new_value)
```

2. **`ch` (изменение)**:
   - Действие с префиксом `ch` выполняется только при изменении значения поля. Это позволяет задать код действия, который будет выполнен только в случае, если произошло изменение данных в поле.

   Пример:
```totum
ch1=: notificationSend(users: json`[1,2,3]`; title: "Field Changed"; ntf: "The field value has been changed.")
```

3. **`ad` (добавление)**:
   - Действие с префиксом `ad` выполняется только при добавлении строки. Это позволяет задать код действия, который будет выполнен только в случае, если была добавлена новая строка в таблицу.

   Пример:
```totum
ad1=: insert(table: 'log_table'; field: 'action' = "Row added"; field: 'timestamp' = $#ndt)
```

4. **`dl` (удаление)**:
   - Действие с префиксом `dl` выполняется только при удалении строки. Это позволяет задать код действия, который будет выполнен только в случае, если строка была удалена из таблицы.

   Пример:
```totum
dl1=: set(table: 'log_table'; field: 'action' = "Row deleted"; field: 'timestamp' = $#ndt)
```

5. **`cl` (двойной клик)**:
   - Действие с префиксом `cl` выполняется при двойном клике на заблокированном поле. Это позволяет задать код действия, который будет выполнен только в случае, если пользователь дважды кликнул на поле, которое заблокировано для редактирования.

   Пример:
```totum
cl1=: linkToDataText(title: "Double Click"; text: "You double-clicked on a locked field.")
```

Таким образом, префиксы в кодах действий позволяют гибко настраивать выполнение действий в зависимости от различных событий, происходящих с полем, и обеспечивают автоматизацию процессов в системе Totum.

#### <a name="perform-several-actions-in-sequence-ai18"></a> Как выполняется порядок выполнения действий с префиксами в коде действия?

В системе Totum порядок выполнения действий с префиксами в коде действия определяется по строчной сортировке префиксов. Префиксы используются для указания, при каком триггере будет выполняться соответствующее действие, и также для определения порядка выполнения этих действий.

**Префиксы для триггеров:**

1. **`a`** — общий префикс, который выполняется при любом триггере (добавление, изменение, удаление, двойной клик).
2. **`ch`** — используется для выполнения кода действия только при изменении значения поля.
3. **`ad`** — используется для выполнения кода действия только при добавлении строки.
4. **`dl`** — используется для выполнения кода действия только при удалении строки.
5. **`cl`** — используется для выполнения кода действия при двойном клике на заблокированном поле.

**Порядок выполнения:**

Порядок выполнения действий определяется по строчной сортировке цифр в префиксе. Например, `a1` будет выполнено раньше, чем `a2`, а `ch1` будет выполнено только при изменении значения поля. Если у вас есть несколько действий с одинаковым префиксом, они будут выполнены в порядке возрастания номера, например, `a1`, `a2`, `a3`.

**Пример кода с разными действиями для разных триггеров:**

```totum
a1=: pin(table: $#ntn; field: 'name'; where: 'id' = #id)

ad1=: set(table: 'table_1'; field: 'set_field' = $#nfv; where: 'link' = #id)

dl1=: set(table: 'table_1'; field: 'set_field' = ""; where: 'link' = #old.id)

ch1=: notificationSend(users: json`[1,2,3]`; title: "Field Changed"; ntf: "The field value has been changed.")

cl1=: linkToDataText(title: "Double Click"; text: "You double-clicked on a locked field.")
```

**Объяснение:**

- **`a1`**: Это действие будет выполнено при любом триггере.
- **`ad1`**: Это действие будет выполнено только при добавлении строки.
- **`dl1`**: Это действие будет выполнено только при удалении строки.
- **`ch1`**: Это действие будет выполнено только при изменении значения поля.
- **`cl1`**: Это действие будет выполнено при двойном клике на заблокированном поле.

Таким образом, в одном поле можно задать разные действия для различных триггеров, что позволяет гибко настраивать автоматизацию процессов в системе Totum.

### <a name="executing-code-from-the-button-logging-qa"></a> Вопросы и ответы

#### <a name="executing-code-from-the-button-logging-q1"></a> У кнопки есть триггеры?

У кнопок код действия без триггеров. Он выполняется при нажатии кнопки.

#### <a name="executing-code-from-the-button-logging-q2"></a> Можно ли нажать кнопку в строке добавления?

По умолчанию нет. Но есть случаи в которых это возможно — они будут рассмотрены позже.

#### <a name="executing-code-from-the-button-logging-q3"></a> Можно ли кнопку выполнить удаленно, кодом?

Да. При помощи функции [execButton][444] можно нажать кнопку дистанционно.

А при помощи [execButtonList][445] — нажать последовательно кнопки в нескольких строках подходящих по условию.

#### <a name="executing-code-from-the-button-logging-q4"></a> Как посмотреть логи по полю?

Если у поля включен параметр [с логгированием][185], то при изменении поля вручную — будет записано время изменения, пользователь от которого выполнено действие, а также введенное значение и итоговое значение.

Если параметр [с логгированием][185] выключен, то никакие логи не записываются.

Из контекстной панели по правой кнопке мыши в поле есть доступ к этим логам. Он может бть ограничен определенными ролями при помощи параметра [лог доступен ролям][179].

Если он был включен, а потом выключен, то старые логи стерты не будут, но пропадет доступ к ним. Если включить обратно, то доступ восстановится.

#### <a name="executing-code-from-the-button-logging-q5"></a> Когда записывается лог действия?

Если изменение вызвано кодом действия — например записано через [set][294], то в для того, что бы записать значение в лог, надо указать параметр `log: true`.

```totum

=: set(table: 'table:'; field: 'field' = #new_value; log: true)

```

#### <a name="executing-code-from-the-button-logging-q6"></a> Можно ли записать произвольный текст?

В логе действие будет отмечено во введенном значении как `Скрипт`.

Если выхотите сделать там специальную надпись, то передайте ее параметр `log`:

```totum

=: insert(table: 'table:'; field: 'field' = #new_value; log: "Успешные оплаты")

```

### <a name="executing-code-from-the-button-logging-text"></a> Текст урока (по видео)

Это видео посвящено коду действия кнопки. Но мы уже немного знаем о нем, поэтому речь пойдет не только о кнопке, но и о других вещах.
В нашей таблице есть кнопка «PRESS ME». Поскольку она имеет тип поля `кнопка`, в ее настройках нет обычных кодов вычисления, только код действия и условное форматирование ячейки. В кнопках также нет триггеров кодов действия, потому что у кнопки есть только один триггер - нажатие кнопки.
В нашей таблице есть кнопка «PRESS ME» находится в заголовке.  Давайте добавим кнопку в строчную часть. Создадим поле тоже с типом кнопка, но с плейсментом в строчной части, и назовем ее «Press me» – с маленькими буквами, для отличия.  Когда мы нажмем кнопку добавления новой стоки, то увидим, что кнопка здесь в добавляемой строке по умолчанию заблокирована.

Я хочу показать вам следующее. Под блоком кода действия кнопки в настройках форматирования поля есть не флажки установки триггеров, а другие флажки. Это действия, которые связаны с нажатием на кнопку. Вот перечень возможных действий, осуществление которых можно включить в связи с выполнением кода действия кнопки:
−	Снимать галочки после выполнения
−	Закрыть окно после выполнения
−	Действие доступно при просмотре
−	Включить кнопку в строке добавления
−	Открыть контекстную панель

Рассмотрим их подробнее.

Опция: «снять флажки после выполнения». В случае, если здесь есть флажки, пользователь может нажать на кнопку, в коде можно получить список id тех строк, которые отмечены флажками. Это можно сделать через переменную под названием $#ids. Это можно использовать для выполнения действия только для отмеченных галочками строк. Если выбрана опция снять флажки, то после выполнения этого действия все флажки будут сняты. Мы рассмотрим это подробнее в разделе «Всплывающие окна».
«Закрыть окно после выполнения». Этот параметр закрывает окно с кнопкой после выполнения действия.
«Действие доступно при просмотре». Когда таблица доступна только для чтения, но, например, чтобы попасть в цикл или выполнить какое-то действие, кнопку нужно разблокировать. То есть, пользователь не может ничего изменить, но может нажать на кнопку. В этом случае, чтобы кнопка была доступна, мы должны включить доступность при просмотре.
«Доступна в строке добавления». При включении этого параметра кнопка будет доступна в строке добавления и сможет выполнять действие в строке добавления, до ее сохранения в базу. Это необходимо для открытия всплывающих окон из строки добавления. Мы рассмотрим эту опцию именно во всплывающих окнах. Пока же здесь представлена общая информация.
«Открыть контекстную панель». В этом случае при нажатии на кнопку открывается та же панель, что и при нажатии правой кнопки мыши. Это полезно, например, если у вас есть куча дополнительных кнопок, и вы хотите, чтобы пользователь мог нажать на эту кнопку и далее выбрать определенное действие из перечня, имеющегося в контекстной панели. Если такой необходимости нет, от обычно всплывающее меню не активируется, потому что в кнопках оно чаще всего не нужно.

Также чтобы улучшить внешний вед кнопки, особенно расположенной в хедере, можно удалить ее название.
На примере этой кнопки я покажу следующее. У нас есть функция `execButton`, которая позволяет нам нажать из кода действия другую кнопку. Например, у нас есть кнопка в хедере, и ее Name – ‘h_ button’. Давайте напишем этот код действия здесь, в кнопке строчной части. Параметры `where`и `order` здесь нам не нужны.
```totum
= : execButton(table: $#ntn; field: 'h_button')
```

И что же происходит? Мы нажимаем на кнопку, и ничего не происходит, но не потому, что кнопка не работает, а потому, что в нажимаемой кнопке есть условие, что она нажимается только если чекбокс равен true. Если мы поставим флажок, нажимаем на нашу кнопку, и вот произошло изменение. То есть нажатие на кнопку в строчной части вызвало действие, которое автоматически нажало на кнопку в хедере.
Соответственно, есть не только `execButton`, но и `execButtonList`. Для того, чтобы нажимать несколько кнопок одновременно, если речь идет о строчной части.
Теперь последний трюк. Если лог верен, мы видим, что скрипт записывает значение в поле. И мы можем записать вместо значения скрипта какой-то свой текст. В данном случае мы передаем текст вместо true.

```totum

=: setList(table: $#ntn; field: 'field_2' = 300; where: 'id' ≠ 0; log: "button from header")
```

Что ж, давайте поместим сюда значение 300. Сохраняем. И снова делаем эту цепочку, ставим чекбокс, жмем «я», и теперь мы можем посмотреть в лог и увидеть, что это написан не скрипт, а кнопка из заголовка. Это полезно для отладки и для записи важных операций.

#### <a name="executing-code-from-the-button-logging-ai13"></a> В чем разница между `execButton` и `execButtonList`?

В системе Totum функции `execButton` и `execButtonList` используются для программного выполнения действий кнопок, но они имеют разные назначения и способы применения.

**`execButton`**

- **Назначение**: `execButton` используется для выполнения действия одной конкретной кнопки в указанной таблице.
- **Применение**: Эта функция позволяет программно "нажать" на кнопку, находящуюся в другой таблице, по указанным условиям.
- **Пример использования**:

```totum
=: execButton(table: 'table_name'; field: 'button_field')
```

  В этом примере `table_name` — это таблица, в которой находится кнопка, а `button_field` — это поле типа "кнопка", которое нужно нажать.

**`execButtonList`**

- **Назначение**: `execButtonList` используется для последовательного выполнения действий кнопок в нескольких строках, подходящих по условию.
- **Применение**: Эта функция позволяет программно "нажать" на кнопки в нескольких строках таблицы, сортируя их в соответствии с указанным порядком.
- **Пример использования**:

```totum
=: execButtonList(table: 'table_name'; field: 'button_field'; where: 'status' = 1)
```

  В этом примере `table_name` — это таблица, в которой находятся кнопки, `button_field` — это поле типа "кнопка", а `where: 'status' = 1` — это условие, по которому выбираются строки для нажатия кнопок.

**Основные отличия**

- **Количество кнопок**: `execButton` выполняет действие одной кнопки, тогда как `execButtonList` может выполнять действия нескольких кнопок в разных строках.
- **Условия выполнения**: `execButtonList` позволяет задавать условия для выбора строк, в которых будут нажаты кнопки, в то время как `execButton` выполняет действие для одной конкретной кнопки.

Таким образом, выбор между `execButton` и `execButtonList` зависит от того, нужно ли вам выполнить действие одной кнопки или нескольких кнопок в разных строках таблицы.

#### <a name="executing-code-from-the-button-logging-ai14"></a> Как использовать логирование в коде действия кнопки?

В системе Totum логирование в коде действия кнопки осуществляется с помощью параметра `log`. Этот параметр позволяет записывать изменения, произведенные кодом действия кнопки, в лог. Давайте рассмотрим, как это работает и как его можно использовать.

**Пример кода действия с логированием**

Когда вы хотите записать изменения, произведенные кодом действия кнопки, в лог, вы можете использовать параметр `log: true`. Это позволит зафиксировать изменения в журнале действий.

```totum
=: set(table: 'table_name'; field: 'field_name' = #new_value; log: true)
```

В этом примере изменение значения в таблице будет записано в лог. Это полезно для отслеживания изменений, произведенных кодом действия кнопки.

**Пример кода действия с записью произвольного текста в лог**

Вы также можете записать произвольный текст в лог вместо стандартного сообщения "Скрипт". Для этого передайте текст в параметр `log`.

```totum
=: insert(table: 'table_name'; field: 'field_name' = #new_value; log: "Успешные оплаты")
```

В этом примере в лог будет записан текст "Успешные оплаты" вместо стандартного сообщения "Скрипт". Это позволяет более точно описывать действия, выполненные кнопкой.

**Просмотр логов**

Логи можно просмотреть из контекстной панели по правой кнопке мыши в поле. Доступ к логам может быть ограничен определенными ролями при помощи параметра "лог доступен ролям". Если параметр логирования был включен, а потом выключен, то старые логи не будут стерты, но доступ к ним пропадет. Если включить параметр обратно, то доступ к логам восстановится.

**Заключение**

Логирование в Totum позволяет отслеживать изменения, произведенные кодом действия кнопок, и записывать их в лог с возможностью просмотра и ограничения доступа к логам для определенных ролей. Это полезно для отладки и для записи важных операций.

#### <a name="executing-code-from-the-button-logging-ai15"></a> Что происходит, если в лог записать произвольный текст вместо значения true?

В системе Totum, если в лог записать произвольный текст вместо значения `true`, то в лог будет записана указанная строка, что позволяет более точно описать выполненное действие. Это может быть полезно для отладки и для записи важных операций, чтобы в журнале действий было понятно, какое именно действие было выполнено.

**Пример использования**

Если вы хотите записать в лог произвольный текст, вы можете передать его в параметр `log` вместо `true` в функции, которая изменяет данные. Например, при использовании функции `set`:

```totum
=: set(table: 'table_name'; field: 'field_name' = #new_value; log: "Успешные оплаты")
```

В этом примере в лог будет записан текст "Успешные оплаты" вместо стандартного сообщения "Скрипт". Это позволяет более точно описывать действия, выполненные кнопкой или кодом действия, и облегчает понимание изменений, внесенных в таблицу.

#### <a name="executing-code-from-the-button-logging-ai16"></a> Как получить список id строк с отмеченными флажками?

В системе Totum, чтобы получить список `id` строк, отмеченных флажками, можно использовать быструю переменную `$#ids`. Эта переменная доступна в коде-действия кнопок и возвращает список `id` строк, которые были выделены галочками в интерфейсе.

**Пример использования переменной `$#ids`:**

```totum
=: set(table: 'some_table'; field: 'status' = "processed"; where: 'id' = $#ids)
```

В этом примере код-действия устанавливает значение поля `status` в "processed" для всех строк, `id` которых содержатся в списке `$#ids`, то есть для всех строк, отмеченных флажками.

**Важные моменты:**

- Переменная `$#ids` доступна только в коде-действия кнопок, так как она используется для выполнения действий над выделенными строками.
- Если ни одна строка не выделена, переменная `$#ids` будет пустым списком.
- Использование этой переменной позволяет выполнять массовые операции над выбранными строками, что может быть полезно для автоматизации процессов в таблице.

#### <a name="executing-code-from-the-button-logging-ai17"></a> Где можно просмотреть логи по полю и от чего зависит доступ к ним?

В системе Totum логи по полю можно просмотреть из контекстной панели, которая открывается по правой кнопке мыши на поле. Доступ к логам может быть ограничен определенными ролями, и это настраивается через параметр "Лог доступен ролям" в настройках поля.

**Как просмотреть логи по полю:**

1. **Откройте контекстное меню**: Кликните правой кнопкой мыши на поле, для которого вы хотите просмотреть логи.

2. **Выберите "Лог"**: В контекстном меню выберите опцию "Лог", чтобы открыть журнал изменений для этого поля.

**От чего зависит доступ к логам:**

1. **Параметр "С логированием"**: Для того чтобы логи записывались, в настройках поля должен быть включен параметр "С логированием". Если этот параметр выключен, то никакие логи не записываются.

2. **Параметр "Лог доступен ролям"**: Доступ к логам может быть ограничен определенными ролями. В настройках поля можно указать, какие роли имеют доступ к просмотру логов (по умолчанию все, кто имеет доступ к видимости поля). Если роль пользователя не указана в этом параметре, то он не сможет просмотреть логи.

3. **История изменений**: Если параметр "С логированием" был включен, а потом выключен, то старые логи не будут стерты, но доступ к ним пропадет. Если включить параметр обратно, то доступ к логам восстановится.

Таким образом, доступ к логам по полю в Totum зависит от настроек логирования и ролей, которым разрешен доступ к этим логам.

#### <a name="add-or-delete-rows-in-the-table-q1"></a> Какой функцией добавляется строка?

#### <a name="add-or-delete-rows-in-the-table-q2"></a> Как добавить несколько строк с разными данными?

```totum
=: insertList(table: 'table'; field: 'field_1' = $listValue1; field: 'field_2' = $listValue2)

listValue1: listCreate(item: "value_1_1"; item: "value_1_2"; item: "value_1_3")
listValue2: listCreate(item: "value_2_1"; item: "value_2_2"; item: "value_2_3")
```

#### <a name="add-or-delete-rows-in-the-table-q4"></a> Как удалить несколько строк?

### <a name="add-or-delete-rows-in-the-table-text"></a> Текст урока (по видео)

Коды действий могут не только изменять значения в полях, но и добавлять и удалять строки. Рассмотрим автоматическое добавление и удаление строк.
Давайте добавим две кнопки - добавить и удалить. Пока что они пустые. Теперь перейдем к коду действия для каждой кнопки. Чтобы добавить строку, нужно использовать функцию `insert`. Она, как и все функции, действия доступна в двух вариантах – одиночном и множественном: `insert` и `insertList`. `insertList` добавляет одну строку, а `insertList`– несколько.

Сначала мы разберемся с `insert`. Мы будем добавлять строки в текущую таблицу, а затем нам нужно указать, какие поля из текущей таблицы будут заполняться при добавлении и какие значения они будут иметь. Например, поле ‘field_1’ будет равно «DDD». Вы видите, что это множественный параметр. Поле ‘field_2’ будет равно «500». Если в таблице есть поля, которые вы не хотите заполнять при создании, то их можно не указывать. Больше никакие параметры функции `insert` сейчас мы использовать не будем, только логирование оставим включенным.

```totum
=: insert(table: $#ntn; field: 'field_1' = "DDD"; field: 'field_2' = 500; log: true)
```
Хорошо, давайте сохраним. Сохраняем. Нажмите кнопку Добавить строки, и вот наша добавленная строка. Она появляется в самом верху. Когда мы перезагрузим страницу, она будет располагаться в порядке сортировки. Вот добавленные нами значения в заполненных полях - мы добавили DDD в ‘field_1’  и 500 в ‘field_2’.
Теперь, когда мы хотим автоматически удалять строки, мы используем функцию `delete`. Она также есть в двух вариантах: `delete` или `deleteList`. Мы говорим, что удаляем из текущей таблицы, и должны указать условие `where`, по которому мы будем удалять. Допустим, мы нажатием этой кнопки удалим строку, в которой поле ‘field_1’ равно DDD, и мы можем писать или не писать логи в журнал. Обратите внимание, что при использовании функции `delete` всегда будет удалена только одна строка, даже если несколько строк удовлетворяют условиям.

```totum
=: delete(table: $#ntn; where: 'field_1' = "DDD")
```
Сохраняем, нажмем кнопку и вот строка с полем 'field_1' = "DDD" удалена.

Как удалить строку?
Для удаления одной строки используется функция delete. Она удалит только одну строку, подходящую под условие:
```totum
=: delete(table: 'table'; where: 'id' = $#nfv)
```

Со списком все немного сложнее. Если мы хотим добавить несколько строк, то, во-первых, нужно использовать `insertList`. Во-вторых, в поле `field` мы передаем не одно значение, а список. Поэтому здесь мы должны использовать ссылку на строку кода, список данных в формате json, либо данные из другого источника.  Мы создадим `listCreate`, и мы должны передать в параметры `field` значения в том порядке, в котором мы хотим добавить их в строки. Списки должны быть одинаковой длины. Здесь будет 600, затем 700 и 800. В том, что здесь должны быть списки, и заключается основное отличие `insertList` от просто `insert`.
```totum
=: insertList(table: $#ntn; field: 'field_1' = $list_1; field: 'field_2' = $list_2; log: true)
list_1: listCreate(item: "DDD"; item: "CCC"; item: "FFF")
list_2: listCreate(item: 600; item: 700; item: 800)
```
Хорошо, сохраните и посмотрите, что получится. Здесь добавляются 3 строки:
1.	'field_1' = DDD, 'field_2' = 600
2.	'field_1' = CCC, 'field_2'= 700
3.	'field_1' = FFF,  'field_2' = 800.

Как добавить несколько строк с разными данными?
Добавление нескольких строк производится функцией insertList. Что бы внести разные значения в разные строки в field должны быть переданы не единичные значения, а списки значений:
```totum
=: insertList(table: 'table'; field: 'field_1' = $listValue1; field: 'field_2' = $listValue2)

listValue1: listCreate(item: "value_1_1"; item: "value_1_2"; item: "value_1_3")
listValue2: listCreate(item: "value_2_1"; item: "value_2_2"; item: "value_2_3")
```

Теперь об удалении. Первое, о чем я хотел сказать, это о параметре `where`. Если параметр `where` не задан, то все строки в таблице будут удалены, но лучше так не делать, потому что это не очень читабельно. Если же мы хотим удалить все строки в таблице, то нужно указать `where: ‘id’ != 0. Таким образом, все строки будут удовлетворять этому условию, потому что ни одна строка по id не может быть равна 0. Id начинается с единицы. Также здесь можно использовать любое сравнение. Например, я выберу все строки с id больше 10, и здесь мы должны указать не delete, а `deleteList` - множественное действие, потому что строк с id больше 10 может быть несколько.
```totum
=: deleteList(table: $#ntn; where: 'id' > 10)
```
Строки с id больше 10 удалены.

Как удалить несколько строк?
Используется функция deleteList. Она удалит все строки, подходящие под условие:
```totum
=: deleteList(table: 'table'; where: 'type' = 4)
```

Как удалить все строки в таблице?
Указать, что надо удалить все строки, у которых id неравен 0:
```totum
=: deleteList(table: 'table'; where: 'id' != 0)
```
Или не указывать параметр where вообще (но с удалением лучше так не делать — указание where более читаемо!).
Есть ли в Totum undo?
Нет!
Какие строки будут удалены если используется функция deleteList без параметра where?
Удалятся все строки - будьте внимательны!

Теперь следующий подход. Довольно часто бывает так, что нужно вставить очень большое количество столбцов, и это доставляет неудобства, особенно когда есть вероятность, что придется что-то добавлять или изменять. Поэтому для упрощения задачи можно добавить техническое поле в начале строчной части. Мы назовем его «данные», тип поля ‘данные’. Делаем поле видимыми только для создателя. Поместим его первым по сортировке, раньше всех остальных полей. Сохраняем.
Здесь у нас данные поля. И теперь мы не передаем из кнопки с кодом действия `insertList` списки полей, мы передаем все, что нам нужно, в поле данных. Для этого создаем с помощью функции `listCreate`список строк, в котором в параметрах `item` делаем ссылки на создаваемые стоки.
```totum
=: insertList(table: $#ntn; field: 'data' = $list; log: true)
list: listCreate(item: $row_1; item: $row_2; item: $row_3)
row_1: rowCreate(field: "field_1" = "DDD"; field: "field_2" = 600)
row_2: rowCreate(field: "field_1" = "CCC"; field: "field_2" = 700)
row_3: rowCreate(field: "field_1" = "FFF"; field: "field_2" = 800)
```

Таким образом, мы передаем в поле с данными json-список сгенерированных вручную строк. Но чтобы в создаваемых строках поля заполнились, нужно добавить простые коды в те поля, которые у нас должны быть заполнены при создании строк.

Например, для поля field_1 нам нужно взять те данные, которые у нас заполняются в field: "field_1".
```totum
=: #data[field_1]
```
Указываем, что код будет выполняться только при добавлении.

Сохраняем. Итак, мы добавляем сюда данные, а затем они подтягиваются сюда с помощью кодов. Фиолетовый цвет означает, что этот код при добавлении и последующем изменении значения может быть изменен вручную, без всяких рук и прочей логики, связанной с прикрепленными значениями.
Такой подход к техническим полям является самым надежным. И если вы точно знаете, что у вас маленькая таблица, туда нужно всего несколько полей вставить, то прямо в коде прописываете все эти поля. Если у вас большая таблица, то удобнее использовать стартовое техническое поле.

Как можно комбинировать добавление строк кодом и расчет значений в последующих полях кодом?
Если вы добавляете строку в таблицу, в которой много полей в строчной части, то правильным подходом является передать массив данных row в ведущее техническое поле с типом Данные и из него разобрать значение кодами.

### <a name="add-or-delete-rows-in-the-table-ai"></a> Дополнительные вопросы

#### <a name="add-or-delete-rows-in-the-table-ai1"></a> Какие функции используются для добавления строк в таблицу?

В Totum для добавления строк в таблицу используются функции `insert` и `insertList`.

**Функция `insert`**

Функция `insert` используется для добавления одной строки в таблицу. Вы можете указать значения для полей, которые будут заполнены при добавлении строки. Если значения не указаны, то поля будут заполнены их значениями по умолчанию, кодами и кодами при добавлении.

Пример использования функции `insert`:

```totum
=: insert(table: 'table_name'; field: 'field_1' = $value1; field: 'field_2' = $value2)

value1: 10
value2: "Cool text"
```

**Функция `insertList`**

Функция `insertList` используется для добавления нескольких строк в таблицу. Для этого в параметрах `field` должны быть переданы списки значений, которые будут соответствовать добавляемым строкам.

Пример использования функции `insertList`:

```totum
=: insertList(table: 'table_name'; field: 'field_1' = $listValue1; field: 'field_2' = $listValue2)

listValue1: listCreate(item: "value_1_1"; item: "value_1_2"; item: "value_1_3")
listValue2: listCreate(item: "value_2_1"; item: "value_2_2"; item: "value_2_3")
```

Эти функции позволяют гибко управлять добавлением строк в таблицу, задавая значения для каждого поля как для одной строки, так и для нескольких строк одновременно.

#### <a name="add-or-delete-rows-in-the-table-ai2"></a> В чем разница между функциями insert и insertList?

Функции `insert` и `insertList` в Totum используются для добавления строк в таблицу, но они имеют различия в количестве добавляемых строк и формате параметров. Давайте рассмотрим основные различия:

**1. Количество добавляемых строк:**
- **insert**: Добавляет одну строку в таблицу.
- **insertList**: Добавляет несколько строк в таблицу.

**2. Параметры:**
- **insert**: Указание списка в параметре `field` записывает список в поле в одной строке.
- **insertList**: Указание списка в параметре `field` записывает по одному значению из этого списка в несколько строк.

**Пример использования insert:**
```totum
=: insert(table: 'table'; field: 'field_1' = $value1; field: 'field_2' = $value2)

value1: 10
value2: "Some text"
```

**Пример использования insertList:**
```totum
=: insertList(table: 'table'; field: 'field_1' = $listValue1; field: 'field_2' = $listValue2)

listValue1: listCreate(item: "value_1_1"; item: "value_1_2"; item: "value_1_3")
listValue2: listCreate(item: "value_2_1"; item: "value_2_2"; item: "value_2_3")
```

**Заключение**
Функции `insert` и `insertList` используются для добавления строк в таблицу, но отличаются количеством добавляемых строк и форматом параметров. `insert` подходит для добавления одной строки, тогда как `insertList` используется для добавления нескольких строк с различными значениями.

#### <a name="add-or-delete-rows-in-the-table-ai3"></a> Как добавить строку в таблицу с заполнением определенных полей?

Для добавления строки в таблицу с заполнением определенных полей в Totum используется функция `insert`. Эта функция позволяет добавить одну строку в указанную таблицу и заполнить поля значениями, которые вы укажете.

Вот пример использования функции `insert`:

```totum
=: insert(table: 'table_name'; field: 'field1' = 'value1'; field: 'field2' = 'value2')
```

В этом примере:

- `table: 'table_name'` — указывает на таблицу, в которую будет добавлена строка.
- `field: 'field1' = 'value1'` — задает значение `'value1'` для поля `'field1'` в новой строке.
- `field: 'field2' = 'value2'` — задает значение `'value2'` для поля `'field2'` в новой строке.

Вы можете указать любое количество полей и значений, которые хотите заполнить при добавлении строки. Если вы не укажете какое-либо поле, оно будет заполнено значением по умолчанию, если такое задано, или останется пустым.

#### <a name="add-or-delete-rows-in-the-table-ai4"></a> Что делает функция delete?

Функция `delete` в Totum используется для удаления одной строки из таблицы, которая соответствует заданному условию. Она удаляет только одну строку, подходящую под условие, указанное в параметре `where`.

**Синтаксис функции `delete`:**

```totum
=: delete(table: 'table_name'; where: 'field_name' = "value")
```

**Параметры:**

- **table**: Имя таблицы, из которой будет удалена строка.
- **where**: Условие выбора строки для удаления. В данном случае, строка будет выбрана, если значение в указанном поле соответствует заданному значению.

**Пример использования:**

1. Удаление строки с определенным `id`:

```totum
=: delete(table: 'tablename'; where: 'id' = 1)
```

В этом примере строка будет удалена из таблицы 'tablename', если значение в поле 'id' равно 1.

2. Удаление строки с определенным значением в поле:

```totum
=: delete(table: 'tablename'; where: 'field' = "value")
```

В этом примере строка будет удалена из таблицы 'tablename', если значение в поле 'field' равно "value".

**Дополнительные параметры:**

- **cycle**: Используется, если таблица является расчетной в цикле.
- **hash**: Используется для выполнения действия во временной таблице.
- **log**: Если `true`, операция будет записана в лог.

**Важные замечания:**

- Если по условиям выбираются значения из нескольких строк, то будет удалена только одна строка, соответствующая условиям.
- Если по условиям не выбирается ни одной строки, то действие не будет выполнено.
- Если в `where` передать значение `*ALL*`, то этот `where` будет выключен, и условие не будет применяться.

#### <a name="add-or-delete-rows-in-the-table-ai5"></a> В чем разница между delete и deleteList?

Функции `delete` и `deleteList` в Totum используются для удаления строк из таблицы, но они имеют различия в том, как именно происходит удаление.

**`delete`**

Функция `delete` используется для удаления **одной** строки из таблицы, которая соответствует заданному условию `where`. Если по условию `where` выбирается несколько строк, то будет удалена только **одна** из них, которая первая соответствует условию. Если по условию не выбирается ни одной строки, то действие не будет выполнено.

Пример использования `delete`:
```totum
=: delete(table: 'table_name'; where: 'id' = 2)
```
В этом примере будет удалена строка из таблицы `table_name`, у которой `id` равно 2.

**`deleteList`**

Функция `deleteList` используется для удаления **нескольких** строк из таблицы, которые соответствуют заданному условию `where`. Все строки, которые соответствуют условию, будут удалены. Если по условию не выбирается ни одной строки, то действие не будет выполнено.

Пример использования `deleteList`:
```totum
=: deleteList(table: 'table_name'; where: 'status' = 4)
```
В этом примере будут удалены все строки из таблицы `table_name`, у которых `status` равен 4.

**Основные различия**

- **Количество удаляемых строк**: `delete` удаляет только одну строку, соответствующую условию, тогда как `deleteList` удаляет все строки, соответствующие условию.
- **Применение**: `delete` используется, когда нужно удалить конкретную строку, а `deleteList` — когда нужно удалить несколько строк, соответствующих определенному критерию.

**Важные замечания**

- Если в `deleteList` не указать параметр `where`, то будут удалены **все строки** в таблице. Это может привести к потере данных, поэтому всегда следует указывать условия удаления.
- В Totum нет функции "undo", поэтому удаленные строки не могут быть восстановлены, если они не были предварительно сохранены или заархивированы.

#### <a name="add-or-delete-rows-in-the-table-ai6"></a> Как удалить строку, удовлетворяющую определенному условию?

Для удаления строки, удовлетворяющей определенному условию, в системе Totum используется функция `delete`. Эта функция удаляет только одну строку, которая соответствует заданному условию.

Вот пример использования функции `delete`:

```totum
=: delete(table: 'table_name'; where: 'field_name' = "value")
```

В этом примере строка будет удалена из таблицы с именем `'table_name'`, если значение в поле `'field_name'` равно `"value"`.

Если необходимо удалить несколько строк, удовлетворяющих определенному условию, используется функция `deleteList`. Она удаляет все строки, которые соответствуют заданному условию:

```totum
=: deleteList(table: 'table_name'; where: 'field_name' = "value")
```

В этом примере все строки, в которых значение в поле `'field_name'` равно `"value"`, будут удалены из таблицы `'table_name'`.

#### <a name="add-or-delete-rows-in-the-table-ai7"></a> Как удалить несколько строк по определенному условию?

Для удаления нескольких строк по определенному условию в системе Totum используется функция `deleteList`. Эта функция позволяет удалить все строки, которые соответствуют заданному условию.

Вот пример использования функции `deleteList`:

```totum
=: deleteList(table: 'table_name'; where: 'field_name' = "value")
```

В этом примере `table_name` — это имя таблицы, из которой вы хотите удалить строки, а `field_name` — это имя поля, по которому будет производиться фильтрация. Условие `where: 'field_name' = "value"` определяет, какие строки будут удалены. Все строки, у которых значение в поле `field_name` равно `"value"`, будут удалены.

Если вы хотите удалить строки, которые соответствуют более сложным условиям, вы можете использовать несколько параметров `where:`. Например, чтобы удалить строки, у которых `field_name` равно `"value1"` и `another_field` больше 10, вы можете использовать следующий код:

```totum
=: deleteList(table: 'table_name'; where: 'field_name' = "value1"; where: 'another_field' > 10)
```

Если вы хотите удалить все строки в таблице, вы можете использовать условие, которое всегда истинно, например:

```totum
=: deleteList(table: 'table_name'; where: 'id' != 0)
```

Или просто не указывать параметр `where` (но с удалением лучше так не делать — указание `where` более читаемо и безопасно!).

#### <a name="add-or-delete-rows-in-the-table-ai8"></a> Как удалить все строки в таблице?

Чтобы удалить все строки в таблице в системе Totum, вы можете использовать функцию `deleteList`. Для этого необходимо указать условие, которое будет соответствовать всем строкам в таблице. Одним из способов сделать это — указать условие, что `id` не равен `0`, так как `id` всегда начинается с `1` и не может быть равен `0`. Вот пример кода:

```totum
=: deleteList(table: 'table_name'; where: 'id' != 0)
```

Также можно не указывать параметр `where` вообще, но это не рекомендуется, так как указание `where` делает код более читаемым и понятным:

```totum
=: deleteList(table: 'table_name')
```

Однако, будьте осторожны с использованием функции `deleteList` без параметра `where`, так как это приведет к удалению всех строк в указанной таблице.

#### <a name="add-or-delete-rows-in-the-table-ai9"></a> Что произойдет, если использовать deleteList без параметра where?

Если использовать функцию `deleteList` без параметра `where`, то будут удалены все строки из таблицы. Это действие приведет к полному удалению всех данных в строчной части таблицы, поэтому следует быть крайне осторожным при использовании этой функции без указания условий. Указание параметра `where` делает код более читаемым и безопасным, так как позволяет точно определить, какие строки должны быть удалены.

Пример использования `deleteList` без параметра `where`:

```totum
=: deleteList(table: 'table_name')
```

В этом случае все строки в таблице `table_name` будут удалены.

#### <a name="add-or-delete-rows-in-the-table-ai10"></a> Есть ли возможность отменить удаление строк в Totum?

В Totum нет возможности отменить удаление строк. Если строка была удалена, то она не может быть восстановлена, если только не была расположена в таблице, которая позволяет скрывать строки вместо их удаления.

Однако в этом случае, если вы используете функцию `deleteList` с параметром `force: true`, то строки будут удалены окончательно, и их восстановление будет невозможно.

Если вы хотите иметь возможность восстановить удаленные строки в таблице с режимом скрывать, вы можете использовать функцию `restoreList`, которая позволяет восстанавливать скрытые строки. Но для этого строки должны быть изначально скрыты, а не удалены окончательно.

Пример использования функции `restoreList`:

```totum
=: restoreList(table: 'tablename'; where: 'id' >= 2)
```

Этот код восстановит все строки в таблице `tablename`, у которых `id` больше или равно 2, если они были скрыты, а не удалены окончательно.

#### <a name="add-or-delete-rows-in-the-table-ai11"></a> Как добавить несколько строк с разными значениями полей?

Для добавления нескольких строк с разными значениями полей в Totum используется функция `insertList`. Эта функция позволяет передать списки значений для каждого поля, которые будут использоваться для заполнения добавляемых строк. Количество строк, которые будут добавлены, соответствует количеству элементов в переданных списках.

Вот пример использования функции `insertList` для добавления нескольких строк с разными значениями:

```totum
=: insertList(table: 'table_name'; field: 'field_1' = $listValue1; field: 'field_2' = $listValue2)

listValue1: listCreate(item: "value_1_1"; item: "value_1_2"; item: "value_1_3")
listValue2: listCreate(item: "value_2_1"; item: "value_2_2"; item: "value_2_3")
```

В этом примере:

- `table_name` — это имя таблицы, в которую вы хотите добавить строки.
- `field_1` и `field_2` — это имена полей, которые вы хотите заполнить.
- `$listValue1` и `$listValue2` — это списки значений, которые будут использоваться для заполнения полей `field_1` и `field_2` соответственно.

Каждое значение из списка `listValue1` будет соответствовать значению из списка `listValue2` в одной строке. Таким образом, будут добавлены три строки с комбинациями значений из этих списков.

#### <a name="add-or-delete-rows-in-the-table-ai12"></a> Для чего используется параметр where в функции deleteList?

Параметр `where` в функции `deleteList` используется для указания условия выбора строк, которые будут удалены из таблицы. Он определяет, какие строки в таблице должны быть удалены, основываясь на заданных условиях.

Вот как это работает:

- **Условие выбора строк**: Параметр `where` позволяет задать условие, по которому будут выбраны строки для удаления. Это условие может быть основано на значениях одного или нескольких полей в таблице. Например, вы можете удалить все строки, где значение в поле `status` равно 4.

- **Множественные условия**: Вы можете указать несколько условий `where`, и в этом случае строки будут выбраны, если они удовлетворяют всем указанным условиям одновременно (логическое "и").

- **Операторы сравнения**: В условиях `where` можно использовать различные операторы сравнения, такие как `=`, `!=`, `<`, `>`, `<=`, `>=`, а также сравнение со списками значений.

- **Удаление всех строк**: Если вы хотите удалить все строки в таблице, вы можете использовать условие, которое всегда истинно, например, `where: 'id' != 0`, или не указывать параметр `where` вообще (хотя это не рекомендуется, так как может привести к случайному удалению всех данных).

Пример использования функции `deleteList` с параметром `where`:

```totum
=: deleteList(table: 'table_name'; where: 'status' = 4)
```

В этом примере будут удалены все строки из таблицы `table_name`, где значение в поле `status` равно 4.

 Зачем нужно пересчитывать строки?
Что бы обновить в них данные. Например:
У вас две таблицы привязанные к третей — стартовой. Все это простые таблицы.
Привязаны через указание в поле key в ведомых id строки из ведущей.
Эти ведомые таблицы берут какие-то данные кодами из стартовой.
Если м изменим что-то в ведущей таблице — данные в строках ведомых не обновятся пока мы их не пересчитаем:
```totum

a2=: recalculate(table: 'slave_2'; where: 'key' = #id)
```

Итак, в качестве примера у нас есть две простых таблицы. В одной из них Таблице1 (`table1`) в первом поле перечислены различные овощи, и для каждого овоща в следующем поле приведен количественный итог из Таблицы2 (`table2`).

```totum
=: listSum(list: $list)
list: selectList(table: table2'; field: 'field_2'; where: 'field_1' = #id)
```

Давайте посмотрим, что у нас есть в таблице `table2`. Здесь есть поле 1, по которому мы берем select из поля 1 таблицы `table1`по id. Выбираем без дополнительных параметров по id. Базовое поле не установлено. А в Поле 2 таблицы `table2` указывается количество.

Мы можем добавить строку: добавим, например, морковь с количеством 15. Сохраняем.

`table2` – это простая таблица. И `table1`– это простая таблица. Если вручную инициировать пересчет сроки в таблице `table1`, то увидим, что одно из значений - для моркови - изменилось. Но пока мы не сделали вручную пересчет, значения не менялись. Если бы мы изменили название в строке морковь, значение в поле 2 пересчиталось бы, потому что это было бы изменением единицы расчета. Но когда мы просто добавляем в `table2` новую строку, в `table1`ничего не происходит.

Как нам автоматизировать пересчет? Для этого мы используем код действия и функцию `recalculate`. Давайте напишем ее пока для общего случая.
```totum
=: reCalculate(table: 'table1'; where: 'id' = #field_1)
```

Укажем триггеры на добавление, изменение значения и удаление.
Теперь при добавлении и изменении значения в Таблице2 все работает. Значения в Таблице1 изменяются. Но при удалении строки из Таблицы2 в Таблице1 ничего не происходит.

В чем причина? Дело в том, что в этом коде `recalculate` привязывается в параметре `where` к значению в поле `field1`, но в момент удаления поле `field1` пустое. Получается, что мы ничего не пересчитываем, потому что если `where` сопоставить с пустым или вообще не указать `where`, то в простой таблице будет пересчитан только хедер.

Хорошо, давайте вернемся к нашему примеру. Здесь у нас было поле id, равное полю 1, и мы помним, что это работает и для добавления, и для изменения. И мы можем сказать, что эта строка кода имеет префикс `a1`, то есть, это общий случай. Но для удаления нам все равно нужно взять id, который был до удаления. И мы сделаем это отдельной строкой в коде действия. Вот как: мы сделаем секцию удаления с префиксом `dl1` и укажем здесь тот же код. У Totum есть возможность ссылаться на старые значения, которые были до изменения. Это делается так: нужно написать ‘old.’ перед Name поля, на которое вы ссылаетесь.

```totum
a1=: reCalculate(table: 'table1'; where: 'id' = #field_1)
d1l=: reCalculate(table: 'select_for_recalc'; where: 'id' = #old.field_1)
```
Теперь пересчет в Таблице1 будет работать и при удалении.

Если вы хотите пересчитать все строки в простой таблице, вы должны указать `where id != 0`, потому что не существует id, равного 0, и все строки в простой таблице удовлетворяют этому условию. Если вы хотите пересчитать расчетную таблицу, вам вообще не нужно where, потому что вы просто пишете, что вы хотите пересчитать, и если это расчетная таблица, она всегда пересчитывается целиком. Это относится и к временным таблицам. И вам вообще не нужно указывать условий.

Почему при пересчете данных в расчетной таблице она будет пересчитана вся независимо от where?
Она всегда рассчитывается целиком, поэтому расчетные таблицы можно пересчитывать так:
```totum

=: recalculate(table: 'table')
```
Как пересчитать только хэдер простой таблицы?
Так же как и расчетную таблицу, без указания where:
```totum

=: recalculate(table: 'table')
```

Как пересчитать все строки в простой таблице?
Все строки у который id неравен 0:
```totum
=: recalculate(table: 'table'; where: 'id' != 0)
```

У функции `recalculate` есть еще одна важная особенность - параметр поля. Дело в том, что для оптимизации решения можно включить параметр «выполнять код только при добавлении». В этом случае, если мы пересчитаем, никаких вычислений не произойдет, потому что код был выполнен только при добавлении. В таком случае, поскольку эти строки уже добавлены, они не будут пересчитаны по созданному нами ранее коду действия, когда происходят изменения в строках или когда мы пересчитываем эти строки. Но нам нужно, чтобы при изменении, добавлении, удалении этой строки она пересчитывалась и значение обновлялось.

Чтобы код работал в текущих условиях, нам нужно добавить еще один параметр к пересчету. Нужно указать в параметре `field` те поля с кодом только при добавлении, которые нужно пересчитать. Например, в нашем случае это поле ‘sum’.

```totum
a1=: reCalculate(table: 'table1'; where: 'id' = #field_1; field: 'sum')
d1l=: reCalculate(table: 'table1'; where: 'id' = #old.field_1; field: 'sum')
```

Если код действия написан таким образом, то есть в нем указано непосредственно поле, которое мы хотим пересчитывать, код действие будет работать, даже если в поле, в котором должно быть выполнено действие, указано выполнять код только при добавлении.

Как пересчитать строки и заново выполнить поля с кодами только при добавлении?

Например это нужно если вы добавляете товар в заказ и берете ео цену кодом из прайса и эта цена должна остаться неизменной в этом заказе навсегда.
Но иногда требуется сделать так, что бы такие коды выполнились повторно.
В этом случае используется параметр field функции recalculate — он сообщает, что код в поле должен быть выполнен при этом пересчете, даже если он только при добавлении.
```totum
=: recalculate(table: 'table'; where: 'id' = $#nfv; field: 'code_only_on_add_field_1'; field: 'code_only_on_add_field_1')
```

Теперь еще одна важная особенность функции: recalculate – это специальная функция, которая может быть выполнена из кода, несмотря на то что это функция кода действия.  Сделано это для того, чтобы в очень редких случаях пересчитать таблицу-источник перед тем, как брать из нее данные. Например, если добавление данных в таблице, где указан код, должно изменять данные в таблице, из которой этот код берет данные для расчета.
```totum
 =: while(action: $rec; action: $select)
rec: recalculate(table: 'table'; where: 'id' = $#nfv)
select: select(table: 'table'; field: 'field'; where: 'id' = $#nfv)
```
while тоже работает в коде и в качестве значения в коде возвращает последний action или postaction.

Внимание!!! Пользоваться функциями действия в коде, в том числе, функцией `recalculate` нужно с большой осторожностью, потому что если вызвать пересчет одной и той же таблицы, она зациклится.

### <a name="how-to-recalculate-rows-in-a-table-ai"></a> Дополнительные вопросы

#### <a name="how-to-recalculate-rows-in-a-table-ai1"></a> Для чего нужен пересчет строк в таблице?

Пересчет строк в таблице необходим для обновления данных в этих строках. Это особенно важно в ситуациях, когда данные в одной таблице зависят от данных в другой таблице. Рассмотрим несколько примеров, когда пересчет строк может быть необходим:

1. **Обновление зависимых данных**: Если у вас есть две таблицы, которые связаны между собой, и данные в одной из них зависят от данных в другой, то при изменении данных в ведущей таблице необходимо пересчитать строки в ведомой таблице, чтобы обновить их в соответствии с изменениями.

2. **Автоматизация процессов**: Пересчет строк позволяет автоматизировать обновление данных. Например, если у вас есть таблица с заказами и таблица с товарами, и вы изменяете цену товара, то пересчет строк в таблице заказов позволит автоматически обновить итоговую стоимость заказа.

3. **Оптимизация работы**: Пересчет строк может быть использован для оптимизации работы системы, чтобы избежать ручного обновления данных. Это особенно важно в больших системах, где данные могут часто изменяться.

4. **Поддержание актуальности данных**: Пересчет строк помогает поддерживать актуальность данных в таблицах, что важно для принятия правильных решений на основе актуальной информации.

В Totum пересчет строк может быть выполнен с помощью функции `recalculate`, которая позволяет пересчитать данные в строках таблицы в зависимости от заданных условий. Это может быть полезно как для простых, так и для расчетных таблиц.

#### <a name="how-to-recalculate-rows-in-a-table-ai2"></a> Как пересчитать строки в ведомых таблицах при изменении данных в ведущей таблице?

Для пересчета строк в ведомых таблицах при изменении данных в ведущей таблице в системе Totum, необходимо использовать функцию `recalculate`. Эта функция позволяет инициировать пересчет данных в указанных таблицах на основе определенных условий.

Предположим, у вас есть две ведомые таблицы, которые привязаны к ведущей таблице через поле `key`, содержащее `id` строки из ведущей таблицы. Если вы измените данные в ведущей таблице, вам нужно будет пересчитать строки в ведомых таблицах, чтобы обновить их данные.

Вот пример кода, который можно использовать для пересчета строк в ведомых таблицах:

```totum
a1=: recalculate(table: 'slave_1'; where: 'key' = #id)

a2=: recalculate(table: 'slave_2'; where: 'key' = #id)
```

В этом примере:
- `slave_1` и `slave_2` — это имена ведомых таблиц.
- `key` — это поле в ведомых таблицах, которое содержит `id` строки из ведущей таблицы.
- `#id` — это идентификатор строки в ведущей таблице, который изменился.

Этот код нужно разместить в коде действия ведущей таблицы, чтобы он выполнялся автоматически при изменении данных в этой таблице. Таким образом, при изменении данных в ведущей таблице, строки в ведомых таблицах будут пересчитаны, и их данные будут обновлены.

#### <a name="how-to-recalculate-rows-in-a-table-ai3"></a> Какая функция используется для пересчета строк в Totum?

В Totum для пересчета строк используется функция `recalculate`. Эта функция позволяет обновлять данные в строках таблицы, пересчитывая их на основе заданных условий. Например, если у вас есть две таблицы, связанные через поле `key`, и вы изменяете данные в одной из них, то для обновления данных в другой таблице необходимо использовать `recalculate` с указанием соответствующих условий в параметре `where`.

Пример использования функции `recalculate` для пересчета строк в таблице:

```totum
=: recalculate(table: 'slave_1'; where: 'key' = #id)
```

Эта функция также может быть использована для пересчета всей таблицы или только ее хедера, в зависимости от указанных параметров.

#### <a name="how-to-recalculate-rows-in-a-table-ai4"></a> Как пересчитать все строки в простой таблице?

Чтобы пересчитать все строки в простой таблице в Totum, вы можете использовать функцию `recalculate` с условием `where`, которое охватывает все строки. В простой таблице строки имеют `id`, начиная с 1, поэтому условие `where: 'id' != 0` будет охватывать все строки, так как не существует строки с `id`, равным 0. Вот как это можно сделать:

```totum
=: recalculate(table: 'table'; where: 'id' != 0)
```

Этот код пересчитает все строки в указанной таблице `table`. Условие `where: 'id' != 0` гарантирует, что все строки будут пересчитаны, так как все строки в таблице имеют `id`, отличное от 0.

#### <a name="how-to-recalculate-rows-in-a-table-ai5"></a> Как пересчитать только хедер простой таблицы?

Чтобы пересчитать только хедер простой таблицы в Totum, необходимо использовать функцию `recalculate` без указания условий `where`. Это связано с тем, что при отсутствии условия `where` пересчитывается только хедер таблицы, а не ее строчная часть. Вот как это можно сделать:

```totum
=: recalculate(table: 'table_name')
```

В данном примере `table_name` — это имя таблицы, хедер которой вы хотите пересчитать.

#### <a name="how-to-recalculate-rows-in-a-table-ai6"></a> Как пересчитать строки в простой таблице при удалении записи в другой таблице?

Для пересчета строк в простой таблице при удалении записи в другой таблице, необходимо использовать функцию `recalculate` в коде действия. Важно учитывать, что при удалении записи поле, на которое мы ссылаемся, становится пустым. Поэтому нужно использовать старое значение поля, которое было до удаления. Это достигается с помощью префикса `old.` перед именем поля.

Рассмотрим пример, где у нас есть две таблицы: `table1` и `table2`. В `table1` мы хотим пересчитать строки, когда запись удаляется из `table2`.

1. В `table2` создаем код действия, который будет срабатывать при удалении записи. Для этого используем триггер на удаление.

2. В коде действия используем функцию `recalculate`, указывая старое значение поля, которое связывает таблицы.

Пример кода действия:

```totum
dl1=: reCalculate(table: 'table1'; where: 'id' = #old.field_1)
```

В этом примере `#old.field_1` — это поле, которое связывает `table2` с `table1`. Мы используем `old.` для получения значения поля до удаления записи.

Таким образом, при удалении записи в `table2`, строки в `table1`, связанные с удаленной записью, будут пересчитаны.

#### <a name="how-to-recalculate-rows-in-a-table-ai7"></a> Что произойдет, если функция recalculate используется без указания условия where?

Если функция `recalculate` используется без указания условия `where`, то поведение будет зависеть от типа таблицы:

1. **Простая таблица**: В этом случае будет пересчитан только хэдер таблицы. Это означает, что пересчет затронет только заголовочные данные, а не строчные части таблицы.

2. **Расчетная таблица**: Расчетные таблицы всегда пересчитываются целиком, независимо от того, указано условие `where` или нет. Это связано с тем, что расчетные таблицы предназначены для выполнения вычислений на основе всех данных, и их пересчет всегда охватывает всю таблицу.

3. **Временная таблица**: Подобно расчетным таблицам, временные таблицы также пересчитываются полностью, если используется функция `recalculate` без условия `where`.

Таким образом, отсутствие условия `where` в функции `recalculate` приводит к пересчету только хедера в простых таблицах и полному пересчету в расчетных и временных таблицах.

#### <a name="how-to-recalculate-rows-in-a-table-ai8"></a> Как пересчитать конкретное поле с кодом, который исполняется только при добавлении?

Чтобы пересчитать конкретное поле с кодом, который исполняется только при добавлении, в Totum используется функция `recalculate` с параметром `field`. Этот параметр позволяет указать, что код в поле должен быть выполнен при пересчете, даже если он настроен на выполнение только при добавлении.

Вот пример, как это можно сделать:

```totum
=: recalculate(table: 'table_name'; where: 'id' = #id; field: 'field_name')
```

В этом примере:

- `table_name` — это имя таблицы, в которой находится поле, которое нужно пересчитать.
- `id` — это идентификатор строки, в которой находится поле.
- `field_name` — это имя поля, код которого нужно пересчитать.

Таким образом, даже если в поле `field_name` установлен флаг "выполнять код только при добавлении", использование параметра `field` в функции `recalculate` заставит код в этом поле выполниться заново при пересчете.

#### <a name="how-to-recalculate-rows-in-a-table-ai9"></a> Почему параметр field в recalculate полезен при работе с кодами, исполняемыми только при добавлении?

Параметр `field` в функции `recalculate` полезен при работе с кодами, исполняемыми только при добавлении, потому что он позволяет пересчитать и выполнить код в указанных полях, даже если они настроены на выполнение только при добавлении. Это может быть необходимо, если нужно обновить данные в полях, которые обычно не пересчитываются при изменении или удалении строк.

Рассмотрим более подробно, почему это важно:

1. **Оптимизация вычислений**: В некоторых случаях, для оптимизации, коды в полях могут быть настроены на выполнение только при добавлении. Это значит, что при обычном пересчете такие коды не будут выполняться, что экономит ресурсы системы.

2. **Обновление данных**: Однако, бывают ситуации, когда необходимо обновить данные в таких полях. Например, если в поле хранится цена товара, которая берется из прайса при добавлении, но должна обновляться при изменении или удалении, параметр `field` позволит пересчитать и обновить эти данные.

3. **Гибкость управления**: Используя параметр `field`, вы можете точно указать, какие поля должны быть пересчитаны, что дает большую гибкость в управлении процессом пересчета и позволяет избежать ненужных вычислений.

Пример использования параметра `field` в функции `recalculate`:

```totum
=: recalculate(table: 'table'; where: 'id' = $#nfv; field: 'code_only_on_add_field_1'; field: 'code_only_on_add_field_2')
```

В этом примере, даже если поля `code_only_on_add_field_1` и `code_only_on_add_field_2` настроены на выполнение кода только при добавлении, они будут пересчитаны и их код будет выполнен заново при вызове функции `recalculate`. Это позволяет обновить данные в этих полях в случае необходимости.

#### <a name="how-to-recalculate-rows-in-a-table-ai10"></a> Можно ли использовать функцию recalculate для пересчета таблицы перед получением данных из нее?

Да, в Totum функция `recalculate` может быть использована для пересчета таблицы перед получением данных из нее. Это может быть полезно в редких случаях, когда необходимо обновить данные в таблице-источнике перед тем, как использовать их в расчетах или других операциях.

Пример использования функции `recalculate` в коде:


В этом примере сначала выполняется пересчет таблицы `table` для строки с определенным `id`, а затем из этой же строки выбирается значение из поля `field`. Функция `while` здесь используется для выполнения последовательности действий, и в качестве результата возвращается последний выполненный `action` или `postaction`.

Важно помнить, что использование функций действия, таких как `recalculate`, в коде требует осторожности, чтобы избежать зацикливания или других нежелательных эффектов.

#### <a name="how-to-recalculate-rows-in-a-table-ai11"></a> Как использовать функцию while для последовательного выполнения recalculate и других действий?

Функция `while` в Totum позволяет последовательно выполнять несколько действий в коде и в коде действия. Это может быть полезно, когда вам нужно сначала выполнить одно действие, а затем другое, основываясь на результатах первого. В контексте использования функции `recalculate`, это может быть полезно, если вам нужно пересчитать данные в таблице-источнике перед тем, как брать из нее данные.

Вот пример использования функции `while` для последовательного выполнения `recalculate` и других действий:

```totum
=: while(action: $rec; action: $select)

rec: recalculate(table: 'table'; where: 'id' = $#nfv)

select: select(table: 'table'; field: 'field'; where: 'id' = $#nfv)
```

**Объяснение:**

1. **Функция `while`**:
   - Она принимает несколько действий, которые будут выполняться последовательно. В данном случае это действия `$rec` и `$select`.

2. **Действие `$rec`**:
   - Использует функцию `recalculate` для пересчета данных в указанной таблице.
   - Параметр `where: 'id' = $#nfv` указывает, что пересчитываться будет только строка с текущим значением `id`.

3. **Действие `$select`**:
   - Использует функцию `select` для получения данных из таблицы после пересчета.
   - Параметр `where: 'id' = $#nfv` указывает, что выбирается строка с текущим значением `id`.

**Важные моменты:**

- **Порядок выполнения**: `while` гарантирует, что действия выполняются последовательно. Сначала выполняется пересчет, затем выборка данных.
- **Осторожность**: Использование функций действия, таких как `recalculate`, в коде требует осторожности, чтобы избежать зацикливания. Убедитесь, что пересчет не вызывает повторный вызов того же кода, что может привести к бесконечному циклу.
- **Контекст использования**: В данном примере `while` и `recalculate` используются не в коде действия, а в коде расчета значения, поскольку следующим действием вычисляется значение того поля, в котором написан этот код.

Таким образом, функция `while` позволяет организовать последовательное выполнение действий, что может быть полезно для сложных вычислений и манипуляций с данными в Totum.

#### <a name="how-to-recalculate-rows-in-a-table-ai12"></a> Что может произойти, если вызвать из кода поля в таблице пересчет этой же самой таблицы?

Если вызвать из кода поля в таблице пересчет этой же самой таблицы, это может привести к зацикливанию процесса. Таблица будет постоянно пересчитываться, что может вызвать перегрузку системы и сделать таблицу недоступной для использования. Это происходит потому, что каждый пересчет вызывает новый пересчет, и процесс продолжается бесконечно. Это может привести к значительным проблемам с производительностью и стабильностью системы, поэтому использование функций действия, таких как `recalculate`, в коде должно быть очень осторожным и хорошо продуманным.

#### <a name="how-to-recalculate-rows-in-a-table-ai13"></a> Какие меры предосторожности следует учитывать при использовании функции recalculate в коде?

При использовании функции `recalculate` в коде Totum, важно учитывать несколько мер предосторожности, чтобы избежать потенциальных проблем и обеспечить корректную работу системы. Вот основные из них:

1. **Избегать зацикливания**: Не вызывайте пересчет одной и той же таблицы, так как это может привести к зацикливанию. Это особенно важно, если пересчет инициируется в коде, который может быть вызван в результате изменения в той же таблице.

2. **Осторожность с функциями действия в коде**: Использование функций действия в коде, включая `recalculate`, должно быть ограничено и тщательно продумано. Эти функции могут вызывать изменения в данных, что может привести к непредсказуемым результатам, если не учитывать все возможные сценарии.

3. **Проверка условий**: Убедитесь, что условия пересчета (`where`) заданы корректно, чтобы избежать ненужных пересчетов. Например, пересчет всех строк таблицы может быть ресурсоемким, поэтому старайтесь ограничивать пересчет только необходимыми строками.

Следуя этим рекомендациям, вы сможете более безопасно и эффективно использовать функцию `recalculate` в своих проектах на Totum.

#### <a name="how-to-recalculate-rows-in-a-table-ai14"></a> В чем разница между recalculate для простой таблицы и расчетной таблицы?

Разница между использованием функции `recalculate` для простой таблицы и расчетной таблицы заключается в том, как происходит пересчет данных в этих таблицах.

**Простая таблица:**
- **Пересчет строк**: В простой таблице функция `recalculate` пересчитывает только те строки, которые соответствуют условиям, заданным в параметре `where`. Это позволяет обновлять данные только в определенных строках, что может быть полезно для оптимизации производительности.
- **Пересчет хедера**: Если параметр `where` не указан, то пересчитывается только хедер таблицы, а не все строки. Это может быть полезно, если необходимо обновить только агрегированные данные или данные, которые зависят от всего набора данных.
- **Пример**:

```totum
=: recalculate(table: 'simple_table'; where: 'id' != 0)
```

  Этот код пересчитает все строки в простой таблице, так как условие `id != 0` будет истинным для всех строк.

**Расчетная таблица:**
- **Полный пересчет**: В расчетной таблице функция `recalculate` всегда пересчитывает всю таблицу целиком, независимо от условий, заданных в параметре `where`. Это связано с тем, что расчетные таблицы обычно содержат данные, которые зависят от всего набора данных, и их пересчет должен быть полным для обеспечения корректности результатов.
- **Пример**:

```totum
=: recalculate(table: 'calc_table')
```

  Этот код пересчитает всю расчетную таблицу, так как расчетные таблицы всегда пересчитываются целиком.

**Заключение:**
- Для простой таблицы `recalculate` позволяет более гибко управлять пересчетом данных, пересчитывая только необходимые строки.
- Для расчетной таблицы `recalculate` всегда выполняет полный пересчет.

#### <a name="how-to-recalculate-rows-in-a-table-ai15"></a> Когда следует указывать параметр where: 'id' != 0 при пересчете строк в простой таблице?

Параметр `where: 'id' != 0` следует указывать при пересчете строк в простой таблице, когда вы хотите пересчитать все строки этой таблицы. В Totum, если вы не укажете параметр `where`, то пересчет будет применен только к хедеру таблицы, а не к ее строчной части. Указание условия `where: 'id' != 0` гарантирует, что пересчет будет применен ко всем строкам таблицы, так как в простой таблице не существует строки с `id`, равным 0. Это условие охватывает все существующие строки, обеспечивая их пересчет.

Пример использования:

```totum
=: recalculate(table: 'table'; where: 'id' != 0)
```

Таким образом, это условие позволяет пересчитать все строки в простой таблице, что может быть необходимо, если вы хотите обновить данные во всех строках после внесения изменений в таблицу или связанные данные.

```totum
=: setListExtended(table: 'your_table'; field: 'field_2' + $list[[field_2]]; where: 'field_1' = $list[[field_1]]; log: true)

```

**Объяснение кода**

1. **Таблица и поле**: Указываем таблицу `your_table` и поле `field_2`, в котором будут изменяться данные.

2. **Списки значений**: Используем списки для передачи значений, которые будут добавлены к `field_2`. Эти значения берутся из списка строк, созданного с помощью `listCreate`.

3. **Условие `where`**: Указываем условие, по которому будет происходить изменение. В данном случае, изменение происходит в зависимости от значения в `field_1`.

4. **Логирование**: Параметр `log: true` указывает на то, что изменения будут записаны в журнал.

**Когда использовать**

- Когда нужно изменить значения в нескольких строках и колонках одновременно, передав в них список ассоциированных массивов.
- Когда необходимо применить разные изменения к строкам в зависимости от условий.

Функция `setListExtended` особенно полезна в сложных сценариях, где требуется массовое обновление данных с различными условиями и значениями.

#### <a name="how-do-I-set-different-values-depending-on-the-values-in-the-column-ai2"></a> Как добавить значение к существующему значению в поле, а не заменить его?

В Totum, чтобы добавить значение к существующему значению в поле, а не заменить его, можно использовать оператор `+`. Это позволяет увеличить числовое значение в поле на указанное число. Помимо `+`, доступны и другие операторы для выполнения различных математических операций. Давайте рассмотрим их:

**Операторы для изменения значений в поле:**

1. **`+` (плюс)**: Добавляет указанное значение к текущему значению в поле.

```totum
=: set(table: 'table_name'; field: 'field_name' + 10; where: 'search_field' = "search_value")
```

2. **`-` (минус)**: Вычитает указанное значение из текущего значения в поле.

```totum
=: set(table: 'table_name'; field: 'field_name' - 5; where: 'search_field' = "search_value")
```

3. **`*` (умножение)**: Умножает текущее значение в поле на указанное число.

```totum
=: set(table: 'table_name'; field: 'field_name' * 2; where: 'search_field' = "search_value")
```

4. **`/` (деление)**: Делит текущее значение в поле на указанное число.

```totum
=: set(table: 'table_name'; field: 'field_name' / 2; where: 'search_field' = "search_value")
```

5. **`+ %` (прибавление процента)**: Увеличивает текущее значение в поле на указанный процент.

```totum
=: set(table: 'table_name'; field: 'field_name' + 10%; where: 'search_field' = "search_value")
```

6. **`- %` (вычитание процента)**: Уменьшает текущее значение в поле на указанный процент.

```totum
=: set(table: 'table_name'; field: 'field_name' - 10%; where: 'search_field' = "search_value")
```

Эти операторы позволяют гибко управлять значениями в полях таблиц, выполняя различные математические операции.

#### <a name="how-do-I-set-different-values-depending-on-the-values-in-the-column-ai3"></a> Какой синтаксис в коде Totum используется, чтобы взять столбец из rowlist?

В Totum, чтобы взять столбец из `rowList`, используется функция `listSection`. Однако, для удобства предусмотрено быстрое обращение к секции через двойные квадратные скобки `[[ ]]`.

Вот пример использования:

```totum
=: $rowList[[key]]
```

Где `$rowList` — это ваш `rowList`, а `key` — это название ключа (столбца), который вы хотите извлечь.

Пример использования функции `listSection`:

```totum
=: listSection(list: $rowList; item: "key")
```

Где `$rowList` — это ваш `rowList`, а `"key"` — это название ключа (столбца), который вы хотите извлечь.

Оба способа вернут список значений из указанного столбца `rowList`.

#### <a name="how-do-I-set-different-values-depending-on-the-values-in-the-column-ai4"></a> Для чего используется параметр where в функции setListExtended?

Параметр `where` в функции `setListExtended` используется для указания условия выбора строк в строчной части таблицы, в которых будут изменены значения. Он задается в виде `where: 'field' = "value"` и является множественным параметром, что означает, что можно указать несколько условий выбора строк. Это позволяет гибко управлять изменениями в таблице, применяя их только к тем строкам, которые соответствуют заданным условиям.

**Пример использования функции `setListExtended`**

Предположим, у вас есть таблица, в которой вы хотите изменить значения в зависимости от значений в другой колонке. Например, вы хотите прибавить разные числа к данным в колонке `Поле 2`, в зависимости от значений в `Поле 1`. Если `Поле 1` имеет значение "A", вы хотите добавить 100, если "B" — 200, если "C" — 300.

Вот как это можно сделать с помощью `setListExtended`:

```totum
=: setListExtended(table: 'your_table'; field: 'field_2' + $list[[field_2]]; where: 'field_1' = $list[[field_1]]; log: true)
	~list: listCreate(item: $row_1; item: $row_2; item: $row_3)
		row_1: rowCreate(field: "field_1" = "A"; field: "field_2" = 100)
		row_2: rowCreate(field: "field_1" = "B"; field: "field_2" = 200)
		row_3: rowCreate(field: "field_1" = "C"; field: "field_2" = 300)
```

**Объяснение кода**

1. **Таблица и поле**: Указываем таблицу `your_table` и поле `field_2`, в котором будут изменяться данные.

2. **Списки значений**: Используем списки для передачи значений, которые будут добавлены к `field_2`. Эти значения берутся из списка строк, созданного с помощью `listCreate`.

3. **Условие `where`**: Указываем условие, по которому будет происходить изменение. В данном случае, изменение происходит в зависимости от значения в `field_1`.

4. **Логирование**: Параметр `log: true` указывает на то, что изменения будут записаны в журнал.

Таким образом, параметр `where` позволяет точно определить, в каких строках будут применены изменения, что делает функцию `setListExtended` очень гибкой и мощной для массового обновления данных с различными условиями и значениями.

#### <a name="how-do-I-set-different-values-depending-on-the-values-in-the-column-ai5"></a> Почему поле, к которому добавляется значение, должно быть формата 'число'?

В Totum, когда вы добавляете значение к существующему значению в поле, важно, чтобы поле было формата 'число', чтобы сложение происходило по математическим правилам. Если поле будет формата 'строка', то вместо математического сложения будет произведена конкатенация, то есть значения будут объединены как текст. Это связано с тем, что строки и числа обрабатываются по-разному: числа складываются, а строки объединяются.

**Операции с полями типа 'Селект множественный'**

Для полей типа 'Селект множественный' в Totum доступны операции добавления и удаления оснований. Это позволяет гибко управлять значениями в таких полях. Давайте рассмотрим, как это работает:

1. **Добавление оснований**: Вы можете добавлять основания в поле 'Селект множественный' с помощью оператора `+`. Это позволяет добавить одно или несколько значений к уже существующим в поле.

```totum
=: set(table: 'table_name'; field: 'select_field' + json`[1, 2, 3]`; where: 'id' = 1)
```

   В этом примере к полю `select_field` добавляются значения `1`, `2` и `3`.

2. **Удаление оснований**: Вы можете удалять основания из поля 'Селект множественный' с помощью оператора `-`. Это позволяет удалить одно или несколько значений из поля.

```totum
=: set(table: 'table_name'; field: 'select_field' - json`[2, 3]`; where: 'id' = 1)
```

   В этом примере из поля `select_field` удаляются значения `2` и `3`.

Эти операции позволяют динамически изменять содержимое полей типа 'Селект множественный', добавляя или удаляя значения в зависимости от ваших нужд.

#### <a name="how-do-I-set-different-values-depending-on-the-values-in-the-column-ai6"></a> Что произойдет, если поле формата 'строка' используется для добавления числовых значений?

Если в Totum поле формата 'строка' используется для добавления числовых значений, то вместо математического сложения будет произведена конкатенация. Это означает, что числовые значения будут объединены как текст. Например, если в поле 'строка' значение '100' и мы добавляем 100, то результат будет '100100'.

Это связано с тем, что строки и числа обрабатываются по-разному: числа складываются, а строки объединяются. Поэтому, если необходимо выполнить математическое сложение, поле должно быть формата 'число'.

#### <a name="how-do-I-set-different-values-depending-on-the-values-in-the-column-ai7"></a> В чем отличие между setListExtended и обычной функцией setList?

Функции `setListExtended` и `setList` в Totum используются для изменения значений в нескольких строках таблицы, но они имеют разные возможности и предназначены для различных сценариев использования. Давайте рассмотрим их отличия:

**setListExtended**

1. **Гибкость в изменении значений**:
   - Позволяет изменять значения в нескольких строках одновременно в зависимости от условий.
   - Условие выбора строк и значения для изменения передаются в виде списка ассоциированных массивов.
   - Это позволяет применять разные изменения к строкам в зависимости от условий.

2. **Пример использования**:

```totum
=: setListExtended(table: 'table_name'; field: 'field_name' = $values[[value]]; where: 'condition_field' = $values[[condition]])
	~values: rowlistCreate(field: "value" = $value_list; field: "condition" = $condition_list)
		value_list: listCreate(item: "value1"; item: "value2"; item: "value3")
		condition_list: listCreate(item: "condition1"; item: "condition2"; item: "condition3")
```

**setList**

1. **Одинаковое изменение для всех строк**:
   - Позволяет изменять значения в нескольких строках одновременно, но без учета условий.
   - Условие выбора строк передается в виде одного значения.
   - Все выбранные строки получают одинаковое изменение.

2. **Пример использования**:

```totum
=: setList(table: 'table_name'; field: 'field_name' = "new_value"; where: 'condition_field' = "condition_value")
```

**Заключение**

- **setListExtended** более гибкая функция, позволяющая изменять значения в зависимости от условий, тогда как **setList** изменяет значения без учета условий.
- **setListExtended** подходит для сложных сценариев, где требуется массовое обновление данных с различными условиями и значениями, в то время как **setList** используется для простых массовых изменений.
