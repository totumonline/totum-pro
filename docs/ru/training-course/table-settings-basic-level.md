### <a name="sort-field-reverse-order-and-main-field-qa"></a> Вопросы и ответы

#### <a name="sort-field-reverse-order-and-main-field-q1"></a> Можно задать только одно поле сортировки или несколько?

Для [сортировки][100] можно задать только одно поле. Есть хитрость. Если у вас комплексная сортировка типа: «сначала со статусом Заказано и Оплачено по убыванию даты доставки, потом остальные», то можно создать скрытое поле, в котором кодом считать приоритет и сортировать по этому скрытому полю.

#### <a name="sort-field-reverse-order-and-main-field-q2"></a> Можно ли задать для сортировки скрытое поле?

Да, скрытое поле может быть полем сортировки.

#### <a name="sort-field-reverse-order-and-main-field-q3"></a> При обновлении страницы сортировка будет сброшена на установленную по умолчанию?

Да. Поле сортировки — это сортировка строк по умолчанию. По умолчанию поле сортировки — это `id`.

#### <a name="sort-field-reverse-order-and-main-field-q4"></a> При добавлении где отображаются строки, а после перезагрузки страницы?

Если у вас **отключены** параметры [сортировка по полю порядок][97] и [показывать по месту сортировки][102] то новая строка показывается сверху.

Она показывается даже в том случае, если не входит в интервал фильтрации, что бы можно было убедится, что строка добавлена корректно.

После обновления страницы она встанет на свое место по сортировке или будет скрыта если она не входит в условия фильтрации.

#### <a name="sort-field-reverse-order-and-main-field-q5"></a> Можно ли выводить строки в обратном порядке — новые всегда сверху?

Да, за это отвечает параметр [обратный порядок][101]. Он не применяется, если у вас включена опция [сортировка по полю порядок][97].

#### <a name="sort-field-reverse-order-and-main-field-q6"></a> Какой параметр нужно включить, чтобы строки при добавлении показывались по месту своей сортировки?

Надо **включить** параметры [сортировка по полю порядок][97] и [показывать по месту сортировки][102].

В этом случае строки сортируются по порядку заданному полем `n` и при добавлении сразу будет добавлена по месту сортировки.

Поле сортировки при включенном `n` перестает действовать.

По умолчанию строка добавляется в конец.

#### <a name="sort-field-reverse-order-and-main-field-q7"></a> Зачем нужно основное поле?

[Основное поле][103] выводится в контекстной панели и в панелях при редактировании строки через панель. По умолчанию выбрано `id`.

#### <a name="sort-field-reverse-order-and-main-field-q8"></a> Может ли основное поле быть скрытым?

Да, может.

### <a name="sort-field-reverse-order-and-main-field-ai"></a> Дополнительные вопросы

#### <a name="sort-field-reverse-order-and-main-field-ai1"></a> Сколько полей можно задать для сортировки таблицы по умолчанию

В системе Totum для сортировки таблицы по умолчанию можно задать только одно поле. Это поле указывается в настройках таблицы в параметре "Поле сортировки". Если вам требуется более сложная сортировка, например, по нескольким критериям, вы можете создать скрытое поле, в котором будет рассчитан приоритет сортировки на основе ваших условий, и использовать это поле в качестве поля сортировки по умолчанию.

Таким образом, хотя непосредственно задать несколько полей для сортировки нельзя, вы можете реализовать сложную логику сортировки через дополнительное вычисляемое поле.

#### <a name="sort-field-reverse-order-and-main-field-ai2"></a> Какое поле используется для сортировки по умолчанию?

В системе Totum поле сортировки по умолчанию — это поле `id`. Это означает, что если не задано другое поле для сортировки в настройках таблицы, строки будут сортироваться по возрастанию их `id`. Поле `id` является уникальным идентификатором для каждой строки в таблице и используется для определения порядка строк по умолчанию.

#### <a name="sort-field-reverse-order-and-main-field-ai3"></a> Как изменить поле сортировки в таблице?

Чтобы изменить поле сортировки в таблице в системе Totum, выполните следующие шаги:

1. **Откройте настройки таблицы**: Перейдите в нужную таблицу и откройте её настройки. Это можно сделать, выбрав таблицу в дереве и нажав на иконку настроек (это первая кнопка справа от name таблицы).

2. **Найдите параметр "Поле сортировки"**: В настройках таблицы найдите параметр "Поле сортировки" (order_field). Этот параметр определяет, по какому полю будет осуществляться сортировка строк при открытии таблицы в web-интерфейсе.

3. **Выберите новое поле для сортировки**: В выпадающем списке или поле ввода выберите новое поле, по которому вы хотите сортировать строки. Убедитесь, что выбранное поле подходит для сортировки и не является полем типа Селект или Селект-дерево, если таблица имеет строчную единицу пересчета, так как это может привести к проблемам с производительностью.

4. **Сохраните изменения**: После выбора нового поля для сортировки сохраните изменения в настройках таблицы.

5. **Перезагрузите таблицу**: После сохранения изменений перезагрузите таблицу, чтобы применить новую сортировку.

**Важно**

- Убедитесь, что новое поле для сортировки содержит уникальные или подходящие для сортировки значения, чтобы избежать ошибок или некорректного отображения данных.
- Если вы используете поле типа Селект или Селект-дерево, убедитесь, что оно не используется в таблицах со строчной единицей пересчета, чтобы избежать проблем с производительностью.

#### <a name="sort-field-reverse-order-and-main-field-ai4"></a> Можно ли использовать скрытое поле для сортировки?

Да, в системе Totum можно использовать скрытое поле для сортировки. Скрытое поле может быть назначено в качестве поля сортировки в настройках таблицы. Это позволяет вам управлять порядком отображения строк в таблице, используя данные, которые не видны пользователям.

**Пример использования скрытого поля для сортировки:**

1. **Создайте скрытое поле**: В настройках таблицы создайте поле, которое будет скрыто для пользователей. Это можно сделать, указав, что поле видно только для роли "Создатель".

2. **Назначьте поле для сортировки**: В настройках таблицы выберите это скрытое поле в качестве поля сортировки. Это можно сделать в параметре таблицы "Поле сортировки" (order_field).

3. **Сохраните изменения**: После настройки поля сортировки сохраните изменения в настройках таблицы.

Таким образом, вы можете использовать скрытое поле для управления порядком строк в таблице, не отображая это поле пользователям. Это может быть полезно, если вам нужно сортировать данные по сложным критериям, которые не должны быть видны пользователям.

#### <a name="sort-field-reverse-order-and-main-field-ai5"></a> Что происходит с сортировкой после обновления страницы?

После обновления страницы в системе Totum сортировка будет сброшена на установленную по умолчанию, которая задана в параметрах "Настройки таблицы". Это означает, что если пользователь изменил сортировку вручную, например, отсортировал данные по другому полю или в обратном порядке, то после обновления страницы сортировка вернется к той, которая была задана в настройках таблицы. По умолчанию, если не указано иное, сортировка осуществляется по полю `id` в порядке возрастания.

#### <a name="sort-field-reverse-order-and-main-field-ai6"></a> Как пользователь может временно изменить сортировку в таблице?

В системе Totum пользователь может временно изменить сортировку в таблице, используя интерфейс веб-приложения. Для этого необходимо выполнить следующие шаги:

1. **Клик на заголовок столбца**: Пользователь может кликнуть на заголовок столбца, по которому он хочет изменить сортировку. Это действие откроет меню сортировки.

2. **Выбор направления сортировки**: В меню сортировки пользователь может выбрать направление сортировки — по возрастанию или по убыванию. Это делается с помощью треугольников, которые указывают направление сортировки.

3. **Применение сортировки**: После выбора направления сортировки, данные в таблице будут отсортированы в соответствии с выбранным столбцом и направлением. Эта сортировка действует в пределах одной страницы в случаях, когда таблица разделена на них параметром Разбивка на таблицы (pagination).

4. **Сброс сортировки**: Временная сортировка будет действовать до тех пор, пока пользователь не обновит страницу. После обновления страницы сортировка вернется к значению, установленному по умолчанию в настройках таблицы.

Таким образом, пользователь может временно изменить порядок отображения строк в таблице, выбрав нужный столбец и направление сортировки, но эти изменения не сохранятся после обновления страницы.

**Шаги для реализации сложной сортировки:**

1. **Создайте скрытое поле**:
   - В таблице создайте новое поле, которое будет скрыто от пользователей. Это поле будет использоваться для хранения приоритета сортировки.

2. **Рассчитайте приоритет сортировки**:
   - В коде этого поля реализуйте логику, которая будет рассчитывать приоритет сортировки на основе значений других полей. Например, вы можете использовать условные операторы, чтобы задать порядок сортировки в зависимости от значений нескольких полей.

   Пример кода для расчета приоритета сортировки:

```totum
=: if(condition: #status = "Active"; then: 1; else: $if2)

if2: if(condition: #status = "Pause"; then: 2; else: 3)
```

   В этом примере строки со статусом "Active" получат приоритет 1, со статусом "Pause" — 2, а все остальные — 3.

3. **Установите поле сортировки**:
   - В настройках таблицы установите созданное скрытое поле в качестве поля сортировки. Это обеспечит сортировку строк в соответствии с рассчитанным приоритетом.

4. **Сохраните изменения**:
   - Убедитесь, что все изменения сохранены, и таблица пересчитана для применения новой логики сортировки.

**Преимущества такого подхода:**

- **Гибкость**: Вы можете задать любую логику сортировки, используя доступные функции и операторы.
- **Управляемость**: Логика сортировки сосредоточена в одном месте, что упрощает её изменение и поддержку.
- **Скрытость**: Пользователи не видят техническое поле, используемое для сортировки, что делает интерфейс более чистым и понятным.

Таким образом, использование скрытого поля для расчета приоритета сортировки позволяет реализовать сложные сценарии сортировки в системе Totum.

#### <a name="sort-field-reverse-order-and-main-field-ai9"></a> Как включить обратный порядок сортировки?

Для включения обратного порядка сортировки строк в таблице в системе Totum, необходимо выполнить следующие шаги:

1. **Откройте настройки таблицы**: Перейдите в нужную таблицу и откройте её настройки. Это можно сделать, выбрав таблицу в дереве и нажав на иконку настроек справа от name таблицы.

2. **Найдите параметр "Обратный порядок"**: В настройках таблицы найдите параметр "Обратный порядок" (order_desc).

3. **Включите параметр**: Установите галочку чтобы включить обратный порядок сортировки.

4. **Сохраните изменения**: После включения параметра сохраните изменения в настройках таблицы.

**Ограничения**

- Обратный порядок не применяется, если у вас включена опция "Сортировка по полю порядок" (with_order_field). В этом случае обратный порядок не будет работать.

После выполнения этих шагов строки в таблице будут отображаться в порядке убывания, то есть большие значения будут вверху, а меньшие — внизу.

#### <a name="sort-field-reverse-order-and-main-field-ai10"></a> Где показывается новая строка после ее добавления в таблицу?

После добавления новой строки в таблицу в системе Totum, её отображение зависит от настроек таблицы:

1. **Если параметры "Сортировка по полю порядок" и "Показывать по месту сортировки" включены**: Новая строка будет добавлена и сразу показана по месту своей сортировки в соответствии с текущими настройками сортировки таблицы. Это означает, что строка будет автоматически вставлена в правильное место в зависимости от значения в поле `n`.

2. **Если параметры "Сортировка по полю порядок" и "Показывать по месту сортировки" отключены**: Новая строка будет показана сверху таблицы сразу после добавления. Это сделано для того, чтобы пользователь мог сразу увидеть добавленную строку и убедиться в корректности её добавления. Однако, после обновления страницы, строка встанет на своё место в соответствии с установленной сортировкой или будет скрыта, если она не соответствует условиям фильтрации.

Таким образом, поведение отображения новой строки после добавления зависит от настроек сортировки и фильтрации в таблице.

#### <a name="sort-field-reverse-order-and-main-field-ai11"></a> Как сделать так, чтобы новая строка сразу отображалась по порядку сортировки?

В системе Totum, чтобы новая строка сразу отображалась по порядку сортировки, необходимо включить параметры "Сортировка по полю порядок" и "Показывать новую строку по месту сортировки" в настройках таблицы. Эти параметры позволяют автоматически размещать новую строку в соответствии с текущей сортировкой таблицы.

**Шаги для настройки:**

1. **Откройте настройки таблицы**: Перейдите в нужную таблицу и откройте её настройки.

2. **Включите параметр "Сортировка по полю порядок"**: Найдите параметр "Сортировка по полю порядок" (with_order_field) и включите его. Это позволит сортировать строки по значению в поле `n`.

3. **Включите параметр "Показывать новую строку по месту сортировки"**: Найдите параметр "Показывать новую строку по месту сортировки" (new_row_in_sort) и включите его. Это обеспечит автоматическое отображение новой строки в правильном порядке сразу после её добавления.

**Пример кода действия для добавления строки после определенной строки:**

```totum
=: insert(table: 'table_name'; field: 'new_row_in_sort' = true; after: 100)
```

**Результат:**

После включения этих параметров, при добавлении новой строки она будет автоматически отображаться в правильном порядке, что упрощает работу с таблицей и повышает её удобство использования.

#### <a name="sort-field-reverse-order-and-main-field-ai12"></a> Для чего используется параметр «Основное поле»?

**Основное поле (main_field)**

Параметр **Основное поле** в системе Totum определяет, значение какого поля будет показано в заголовке контекстной панели по клику правой кнопкой мыши в поле в строчной части таблицы. Это позволяет пользователям быстро идентифицировать строку по значимому значению, а не по системному идентификатору.

**Применение в таблицах циклов**

Для таблиц циклов основное поле определяет заголовок цикла в дереве при его открытии. Это значит, что вместо номера цикла в дереве навигации будет отображаться значение основного поля, что может быть более информативным для пользователей.

**Возможности и настройки**

- **Скрытые поля**: В качестве основного поля можно использовать поле, видимое только для роли Создатель. Это позволяет использовать техническое поле с конкатенированным значением нескольких других полей.

- **Тип поля Селект**: Если в качестве основного поля выбрано поле с типом Селект, будет показано его отображение, а не основание.

**Пример использования**

Если в настройках таблицы циклов установить параметр Основное поле, выбрав поле, содержащее, например, название проекта, то при открытии цикла в дереве навигации слева в качестве идентификатора цикла будет показано название проекта, а не номер цикла.

Таким образом, параметр Основное поле в системе Totum позволяет улучшить навигацию и восприятие данных, предоставляя пользователям более значимую информацию в интерфейсе.

#### <a name="sort-field-reverse-order-and-main-field-ai13"></a> Можно ли использовать скрытое поле в качестве основного поля?

Да, в системе Totum скрытое поле может быть использовано в качестве основного поля. Основное поле определяет, значение какого поля будет показано в заголовке контекстной панели по клику правой кнопкой мыши в поле в строчной части таблицы. Для таблиц циклов основное поле определяет заголовок цикла в дереве при его открытии.

**Как использовать скрытое поле в качестве основного:**

1. **Настройка основного поля**: В настройках таблицы выберите скрытое поле в качестве основного. Это можно сделать, указав его в параметре "Основное поле" (main_field).

2. **Преимущества использования скрытого поля**: Использование скрытого поля в качестве основного позволяет отображать в заголовке контекстной панели или в дереве навигации информацию, которая может быть технической или не предназначенной для отображения в таблице, но важной для идентификации строки или цикла.

3. **Пример использования**: Если у вас есть скрытое поле, содержащее конкатенированное значение нескольких других полей, вы можете использовать его в качестве основного, чтобы отображать это значение в заголовке контекстной панели.

Таким образом, использование скрытого поля в качестве основного позволяет гибко настраивать отображение данных в системе Totum, предоставляя пользователям доступ к важной информации без необходимости отображения этого поля в таблице.

#### <a name="sort-field-reverse-order-and-main-field-ai14"></a> Можно ли выводить строки в обратном порядке, чтобы новые всегда были сверху?

Да, в системе Totum можно выводить строки в обратном порядке, чтобы новые всегда были сверху. Для этого используется параметр **Обратный порядок** (order_desc) в настройках таблицы. Таким образом, включение параметра **Обратный порядок** позволяет автоматически отображать новые строки сверху, что может быть полезно для быстрого доступа к последним добавленным данным.

#### <a name="split-into-pages-q1"></a> Зачем нужно разделение на страницы?

Если у вас большая таблица, в которую постоянно добавляются строки, то рано или поздно браузеры не смогут ее открыть из-за ее размера.

#### <a name="split-into-pages-q2"></a> Замедляет ли разделение на страницы показ данных?

Нет. Она осуществляется н уровне базы данных — это быстраz операция.

#### <a name="split-into-pages-q3"></a> Можно ли задать разное количество строк для десктопной версии и для мобильной?

Можно задать разное количество строк для десктопной и для мобильной версии. Параметр имеет два значения указанные через дробь:

+ `слева` — десктоп.

+ `справа` — мобильная.

В мобильной версии у таблицы загружаются все строки сразу — поэтому мы рекомендуем ограничивать показ 50-100 строками.

#### <a name="split-into-pages-q4"></a> Каким образом можно показать не первую, а последнюю страницу?

Через вторую дробь можно задать:

+ `desc` — показать последнюю страницу, полностью заполнив ее значениями до лимита.

+ `last` — показать последнюю страницу не дозаполняя неиспользованный лимит.

#### <a name="split-into-pages-q5"></a> Сортировка по Полю сортировки работает до разделения на страницы или после?

До. Сначала таблица сортируется, потом разбивается на страницы.

#### <a name="split-into-pages-q6"></a> Фильтры и сортировка по колонкам работают для всей таблицы, или только для страницы?

Только для страницы! Там для этого в выпадающем меню предупреждение красным выводится.

Таким образом, разделение на страницы в Totum помогает оптимизировать работу с большими таблицами, улучшая производительность и удобство использования.

- **desc** — указывает, что при открытии таблицы необходимо автоматически перейти на последнюю страницу и заполнить её значениями до лимита.

Таким образом, использование параметра 'desc' позволяет удобно работать с таблицами, где важно видеть самые последние данные, например, в журналах или отчетах.

#### <a name="split-into-pages-ai14"></a> Как ограничить максимальное количество строк для отображения на странице, которое может задать пользователь?

В системе Totum для ограничения максимального количества строк, которое может задать пользователь для отображения на странице, используется параметр "Разбивка на страницы" (pagination) в настройках таблицы. Для этого после заданных значений по умолчанию необходимо поставить `**` и далее ввести через дробь максимальное число строк для десктопной и мобильной версии.

**Пример:**

```plaintext
100/50**150/100
```

В данном случае, максимальное количество строк, которое может ввести пользователь, для десктопа установлено на 150, а для мобильных устройств — на 100. Это ограничение позволяет предотвратить перегрузку браузера пользователя при попытке отобразить слишком большое количество строк на одной странице.

#### <a name="split-into-pages-ai15"></a> Что произойдет, если пользователь введет количество строк больше максимального значения, заданного для введения пользователем?

Если пользователь введет количество строк больше максимального значения, заданного для введения пользователем в системе Totum, то будет выведено заданное максимальное значение. Это означает, что система автоматически ограничит количество строк, отображаемых на странице, до установленного максимального значения, даже если пользователь попытался ввести большее количество. Это позволяет предотвратить перегрузку системы и обеспечить стабильную работу интерфейса.

### <a name="simultaneous-access-options-qa"></a> Вопросы и ответы

#### <a name="simultaneous-access-options-q1"></a> Какой тип доступа установлен по умолчанию?

Тип одновременного доступа называется [актуальность][104].

Определяет, как система должна реагировать при одновременных действиях в одной таблице нескольких пользователей.

По умолчанию установлена в — `нестрогое`.

#### <a name="simultaneous-access-options-q2"></a> Что произойдет, если два пользователя по очереди изменят одно и то же поле?

По разному в разных режимах:

+ `необязательное` и `необязательное без показа` — пользователь на милисекунду позже нажавший сохранить перезапишет данные первого. Если к полю были прикреплены действия, то они сначала выполнятся для первого, а потом еще раз для второго пользователя.

+ `строгое` — второму пользователю будет отказано в редактировании. Ему надо будет обновить таблицу и попробовать еще раз.

+ `без отслеживания` — аналогично `необязательно`, но действия начнут выполнятся одновременно с непредсказуемыми последствиями.

#### <a name="simultaneous-access-options-q3"></a> Как увидеть, что таблица была изменена другим пользователем с момента ее открытия?

Нотификация в верхнем правом углу экрана.

Для режимов `нестрогое без показа` и `без отслеживания` она не показывается.

+ `нестрогое без показа` — ставится в том случае, когда с таблицей бедет работать несколько пользователей, но они будут работать каждый со своими строками и им не надо видеть, что другой пользователь внес в таблицу изменение.

+ `без отслеживания` — ставится для нагруженнх таблиц в которые идет односторонняя запись, или запись и изменение четко разделены и не могут пересечься.

Нотификация будет показана и в таком случае:

`Пользователь 1` в `Таблице 1` внес изменение вызвавшее действие (о них будет позже), которое изменило данные в `Таблице 2`.

`Пользователь 2` в этот момент смотрит в `Таблицу 2` — он увидит нотификацию, что эта `Таблица 2` была изменена `Пользователем 1`.

#### <a name="simultaneous-access-options-q4"></a> Как запретить вносить изменения в неактуальную таблицу?

Поставить для нее `строгое` соответствие.

#### <a name="simultaneous-access-options-q5"></a> Как действия выполняемые кодами проверяют, что они взаимодействуют с актуальными данными?

Для всех кроме `Без отслеживания изменений` действует автоматический перезапуск действий и кодов. Пример:

1. — Одновременно начали выполнятся два действия изменяющие Таблицу_1.

1.1. — В момент запуска они оба взяли код отслеживания изменения таблицы — `updated`.

2. — Одно из действий завершилось первым и в процессе записи новых данных в Таблиц_1 снова взяло ее `updated`.

2.1. — Убедившись что в `updated` небыло изменений записало обновленные данные в Таблицу_1 и **изменило** ее `updated`.

3. — Второй действие, завершившееся позже, тоже проверило `updated` таблицы.

3.1. — Проверка `updated` не прошла, тк действие_1 его изменило, поэтому транзакция действия_2 откатывается и оно запускается повторно с повторным получением данных.

#### <a name="simultaneous-access-options-q6"></a> Что происходит с кодом, если он столкнулся с изменением таблицы пока выполнял вычисления?

Он перезапускается во всех режимах кроме `без отслеживания`.

#### <a name="simultaneous-access-options-q7"></a> Как отключить отслеживание одновременного доступа?

Поставить `без отслеживания`!

#### <a name="simultaneous-access-options-q8"></a> Для каких таблиц это актуально?

Для таблиц в которые идет односторонняя запись.

Для таблиц в которых запись и последующие действия гарантировано разнесены по времени.

Для таблиц циклов (про это будет дальше в курсе).

#### <a name="simultaneous-access-options-q9"></a> Как отключить только информирование об изменениях?

Поставить `нестрогое без показа нотификаций`!

### <a name="simultaneous-access-options-ai"></a> Дополнительные вопросы

#### <a name="simultaneous-access-options-ai1"></a> Что такое параметр Актуальность в контексте одновременного доступа к таблицам?

**Параметр Актуальность в контексте одновременного доступа к таблицам**

Параметр Актуальность в системе Totum определяет, как система должна реагировать при одновременных действиях в одной таблице нескольких пользователей. Он регулирует, как обрабатываются изменения, внесенные разными пользователями, и как система уведомляет об этих изменениях. Параметр Актуальность может быть установлен в следующие режимы:

1. **Нестрогое** (WEAK по умолчанию):
   - Позволяет изменять данные даже если таблица неактуальна.
   - Пользователи получают уведомление о том, что таблица была изменена другим пользователем.
   - Если два пользователя по очереди изменят одно и то же поле, то пользователь, нажавший "Сохранить" позже, перезапишет данные первого.

2. **Строгое** (SRONG):
   - Запрещает вносить изменения в неактуальную таблицу.
   - Пользователь должен обновить таблицу перед внесением изменений.
   - Если два пользователя пытаются изменить одно и то же поле, второму пользователю будет отказано в редактировании, и ему нужно будет обновить таблицу и попробовать еще раз.

3. **Нестрогое без показа** (NONE):
   - Позволяет изменять данные без отображения уведомлений о неактуальности таблицы.
   - Используется, когда с таблицей работают несколько пользователей, но они работают каждый со своими строками и им не нужно видеть изменения других пользователей.

4. **!Без отслеживания изменений** (DISABLE):
   - Отключает проверку параллельности и уведомления о неактуальности таблицы.
   - Используется для нагруженных таблиц, в которых идет односторонняя запись или запись и изменение четко разделены.
   - Действия начинают выполняться одновременно с непредсказуемыми последствиями.

**Применение параметра Актуальность**

- **Нотификация об изменениях**: В режимах `нестрогое` и `строгое` пользователи получают уведомления о том, что таблица была изменена другим пользователем. В режимах `нестрогое без показа` и `без отслеживания` такие уведомления не показываются.

- **Автоматический перезапуск действий**: Для всех режимов, кроме `без отслеживания`, действует автоматический перезапуск действий и кодов, если они столкнулись с изменением таблицы во время выполнения.

- **Отключение отслеживания**: Режим `без отслеживания` отключает проверку параллельности, что может быть полезно для таблиц, в которые идет односторонняя запись или где запись и изменение четко разделены.

Таким образом, параметр Актуальность позволяет гибко настраивать поведение системы при одновременном доступе к таблицам, обеспечивая баланс между удобством работы и безопасностью данных.

#### <a name="simultaneous-access-options-ai2"></a> Какой тип доступа установлен по умолчанию?

В системе Totum тип одновременного доступа, называемый "актуальность", по умолчанию установлен в режим "нестрогое". Этот режим позволяет изменять данные даже если таблица неактуальна, и пользователи получают уведомление о том, что таблица была изменена другим пользователем. Если два пользователя изменят одно и то же поле по очереди в системе Totum, результат будет зависеть от настроек одновременного доступа, которые называются "актуальность". Рассмотрим, как это работает в разных режимах:

Таким образом, поведение системы Totum при одновременном изменении одного и того же поля двумя пользователями зависит от настроек актуальности, которые определяют, как система должна реагировать на такие ситуации.

Таким образом, режим нестрогой актуальности обеспечивает гибкость в многопользовательской среде, позволяя пользователям вносить изменения без блокировки, но требует внимательности, чтобы избежать потери данных из-за перезаписи.

4. **Уведомления об изменениях**: Пользователи получают уведомления о том, что таблица была изменена другим пользователем. Это позволяет им быть в курсе изменений и своевременно обновлять данные.

5. **Автоматический перезапуск действий и кодов**: Если код или действие сталкивается с изменением таблицы во время выполнения, оно перезапускается, чтобы работать с актуальными данными. Это происходит во всех режимах, кроме режима "без отслеживания".

- Пользователь 2 обновляет таблицу, получает актуальные данные и может внести свои изменения.

Таким образом, режим строгой актуальности обеспечивает надежность и целостность данных, предотвращая одновременные изменения и конфликты между пользователями. Это делает его подходящим для использования в ситуациях, где требуется высокий уровень безопасности и точности данных.

4. **Риски**: Поскольку система не отслеживает изменения, внесенные другими пользователями, это может привести к конфликтам данных и непредсказуемым результатам, если несколько пользователей одновременно изменяют одни и те же данные.

**Применение**

В системе Totum пользователь получает уведомление о том, что таблица была изменена другим пользователем через нотификацию в верхнем правом углу экрана. 1. **Нестрогое**:
   - В этом режиме нотификация будет показана, если другой пользователь изменил таблицу. Вы сможете увидеть уведомление и обновить таблицу, чтобы увидеть изменения.

2. **Нестрогое без показа**:
   - В этом режиме нотификация не показывается. Этот режим используется, когда с таблицей работают несколько пользователей, но они работают каждый со своими строками, и им не нужно видеть изменения, внесенные другими пользователями.

3. **Строгое**:
   - В этом режиме, если другой пользователь изменил таблицу, вам будет отказано в редактировании, и вы увидите сообщение об ошибке. Вам нужно будет обновить таблицу и попробовать еще раз.

4. **Без отслеживания**:
   - В этом режиме нотификация также не показывается. Этот режим используется для нагруженных таблиц, в которые идет односторонняя запись, или когда запись и изменение четко разделены и не могут пересечься.

Таким образом, система Totum предоставляет гибкие настройки для управления уведомлениями о изменениях в таблицах, что позволяет адаптировать поведение системы под конкретные сценарии использования.

#### <a name="simultaneous-access-options-ai10"></a> В каком случае будет показана нотификация об изменении таблицы?

В системе Totum нотификация об изменении таблицы будет показана в следующих случаях:

1. **Изменение таблицы другим пользователем**: Если один пользователь внес изменения в таблицу, а другой пользователь в это время просматривает эту же таблицу, то второй пользователь увидит нотификацию о том, что таблица была изменена. 2. **Изменение таблицы через действие**: Если в таблице было выполнено действие, которое изменило данные в другой таблице, и в этот момент кто-то просматривает измененную таблицу, то этот пользователь также увидит нотификацию об изменении.

3. **Изменение таблицы через программное действие**: Если изменения в таблице были вызваны программным действием, например, через крон или другой автоматизированный процесс, и в это время таблица открыта у пользователя, то нотификация об изменении будет показана.

4. **Режимы актуальности**: Нотификация об изменении таблицы показывается в режимах актуальности, таких как "нестрогое". В режимах "нестрогое без показа" и "без отслеживания" нотификация не показывается.

Таким образом, нотификация об изменении таблицы в Totum помогает пользователям оставаться в курсе изменений, происходящих в таблицах, и обеспечивает актуальность данных, которые они просматривают.

#### <a name="simultaneous-access-options-ai11"></a> Что происходит, если код сталкивается с изменением таблицы во время выполнения?

Если код в системе Totum сталкивается с изменением таблицы во время выполнения, он перезапускается. Это происходит во всех режимах, кроме режима "без отслеживания изменений".

1. **Начало выполнения**: Когда код начинает выполняться, он фиксирует текущее состояние таблицы, включая код отслеживания изменений.

2. **Изменение таблицы**: Если в процессе выполнения кода другая операция изменяет таблицу, код отслеживания изменений обновляется.

3. **Проверка изменений**: По завершении выполнения кода, система проверяет, совпадает ли текущий код отслеживания изменений с тем, который был зафиксирован в начале выполнения.

4. **Перезапуск кода**: Если код отслеживания изменений изменился, это означает, что таблица была изменена во время выполнения кода. В этом случае транзакция откатывается, и код перезапускается с обновленными данными.

5. **Исключение — режим "без отслеживания изменений"**: В этом режиме код не перезапускается, даже если таблица была изменена. Это может привести к непредсказуемым результатам, так как код будет работать с устаревшими данными.

**Пример:**

Предположим, два пользователя одновременно запускают действия, которые изменяют одну и ту же таблицу. Если одно из действий завершится первым и изменит таблицу, второе действие, завершившееся позже, обнаружит изменение и будет перезапущено, чтобы работать с актуальными данными.

Таким образом, механизм перезапуска кода в Totum обеспечивает целостность данных и корректность выполнения операций, предотвращая конфликты и ошибки, которые могут возникнуть из-за одновременного доступа к таблице.

3. **Установите значение `!Без отслеживания изменений`**: Установите для этого параметра значение `!Без отслеживания изменений`. Это отключит отслеживание одновременного доступа и позволит выполнять действия без проверки на актуальность данных.

4. **Сохраните изменения**: После изменения параметра актуальности, сохраните изменения в настройках таблицы.

После выполнения этих шагов, таблица будет работать в режиме без отслеживания изменений, что может быть полезно для таблиц, в которые идет односторонняя запись или где запись и последующие действия гарантировано разнесены по времени.

#### <a name="simultaneous-access-options-ai13"></a> Для каких таблиц актуально отключение отслеживания изменений?

В системе Totum отключение отслеживания изменений актуально для следующих типов таблиц:

1. **Таблицы с односторонней записью**: Если в таблицу идет только запись данных без их последующего изменения, то отключение отслеживания изменений может быть полезно для повышения производительности. Это актуально, например, для логов или журналов, где данные записываются, но не изменяются.

2. **Таблицы, в которых запись и последующие действия гарантировано разнесены по времени**: Если вы уверены, что запись данных и их последующая обработка не пересекаются по времени, то можно отключить отслеживание изменений. Это может быть полезно в сценариях, где данные сначала собираются, а затем обрабатываются в отдельный период времени.

3. **Таблицы циклов**: В таблицах циклов часто происходит большое количество операций, и отключение отслеживания изменений может помочь избежать задержек, связанных с проверкой актуальности данных. Это особенно актуально, если циклы используются для массовой обработки данных.

Отключение отслеживания изменений позволяет избежать автоматического перезапуска действий и кодов при изменении данных, что может быть полезно для повышения производительности в определенных сценариях. Однако, стоит быть осторожным с этой настройкой, так как она может привести к непредсказуемым последствиям, если данные в таблице изменяются одновременно несколькими пользователями или процессами.

#### <a name="simultaneous-access-options-ai14"></a> Как отключить только уведомления о изменениях в таблице?

Чтобы отключить только уведомления о изменениях в таблице в системе Totum, необходимо установить параметр актуальности в значение **Нестрогое без показа** (NONE). Это позволит отключить показ уведомлений о том, что таблица была изменена другим пользователем, но при этом сохранит возможность одновременного редактирования таблицы несколькими пользователями.

Вот шаги, которые нужно выполнить:

1. **Откройте настройки таблицы**: Перейдите в нужную таблицу и откройте её настройки. Это можно сделать, выбрав таблицу в дереве и нажав на иконку настроек справа от name таблицы.

2. **Установите актуальность**: В настройках таблицы найдите параметр "Актуальность" и установите его в значение "Нестрогое без показа" (NONE).

3. **Сохраните изменения**: После изменения параметра актуальности, сохраните изменения в настройках таблицы.

Таким образом, вы отключите уведомления о изменениях в таблице, но сохраните возможность одновременного редактирования таблицы несколькими пользователями.

#### <a name="simultaneous-access-options-ai15"></a> В каких случаях рекомендуется использовать режим «!Без отслеживания изменений»?

Режим «!Без отслеживания изменений» в системе Totum рекомендуется использовать в следующих случаях:

1. **Нагруженные таблицы с односторонней записью**: Если в таблицу идет только запись данных без последующих изменений, этот режим позволяет отключить проверку параллельных действий, что может улучшить производительность.

2. **Таблицы, где запись и последующие действия разнесены по времени**: Если запись данных и последующие действия происходят в разные временные интервалы, отключение отслеживания изменений может быть полезным.

3. **Таблицы циклов**: В таблицах циклов, где действия внутри циклов могут накладываться друг на друга в общей таблице циклов, отключение отслеживания изменений может предотвратить замедление работы.

Использование этого режима позволяет избежать лишних проверок и перезапусков, что может быть критично для производительности в определенных сценариях. Однако, следует быть осторожным, так как отключение отслеживания изменений может привести к непредсказуемым последствиям при одновременном доступе нескольких пользователей.

#### <a name="manual-sorting-of-lines-q2"></a> Как меняется порядок расчета строк при включенном «порядок по полю сортировки»?

Строки в строчной части при одновременном изменении по умолчанию рассчитываются в порядке возрастания их `id`. Но если включена сортировка по полю порядок — то в порядке возрастания `n`.

#### <a name="manual-sorting-of-lines-q3"></a> В каком техническом поле записан порядок строк?

Поле `n`. Номер сортировки строки можно получить как `#n` или `select` ... `field: 'n'`. Если ручная сортировка строк выключена, то такие обращения будут возвращать ошибку.

Когда идет изменение порядка, то `n` переназначаются.

Когда идет добавление в конец, то `n` идет с шагом `1`.

Когда идет добавление между строк, то втавляемая строка получает дробное `n`.

Там используется большое дробное число, но если у вас ситуация в которой вставка всегда идет между строк, то тогда надо на задание по расписанию (о них будет позже) поставить функцию [normalizeN][323] — она убирает эти дробные хвосты.

#### <a name="manual-sorting-of-lines-q4"></a> Зачем нужен автоматический пересчет при изменении порядка?

Параметр [автоматический пересчет при изменении порядка][99] используется, когда у вас строки ссылаются в кодах на предыдущие — тогда при сохранении нового порядка ищется самый ранний `n` и все строки с большим `n` будут пересчитаны

Пример кода считающего последовательную нумерацию строк:

```totum

=: if(condition: $sel = ""; then: 1; else: $calc)

calc: $sel + 1

	// у строки добавления #id = "" — поэтому делаем еще проверку

	~sel: if(condition: #id = ""; then: $s1; else: $s2)
		s1: select(table: $#ntn; field: 'id'; order: 'n' desc)
		s2: select(table: $#ntn; field: 'id'; where: 'n' < #n; order: 'id' desc)

```

С чем это связано? Порядок строк хранится в специальном техническом поле. Оно называется N, и мы можем вызвать его из кода вот так: `#n`. Если включена ручная сортировка,

Рассмотрим следующий вариант использования n-сортировки. Имеются поля продолжительность и время окончания. А также поле - время начала. Это текущая дата, и здесь мы считаем время окончания. Пишется небольшой код.
```totum
=: if(condition: $sel = ""; then: 1; else: $calc)
calc: $sel + 1
    // у строки добавления #id = "" — поэтому делаем еще проверку
    ~sel: if(condition: #id = ""; then: $s1; else: $s2)

```

Мы берем предыдущее значение методом n-сортировки. То есть мы ищем значение времени предыдущей строки по n-сортировке и прибавляем длительность. Таким образом, отсчет начинается с 00 минут.
Например, если продолжительность мероприятия составляет один час - в 1:00 оно заканчивается. Следующий начинается в час, длительность час - в 2:00 оно закончилось, следующий начинается в 2 часа, продолжается 3 часа - в 5:00 утра закончилось.
И есть дополнительный код действия, который пересчитывает строки, которые больше на N, чем текущая, и это дает нам следующее: мы меняем продолжительность, и все, что следует за этой строкой, обновляется автоматически. Подробнее об этом в разделе «коды действия»

Что происходит, когда мы сортируем по N. Например, мы перемещаем выше строку. Сохраняем. По идее значения должны были обновиться, но этого не произошло. Таким образом, происходит действие, аналогичное триггеру изменения (о кодах действий мы поговорим позже). В параметре «Сортировка по полю Порядок» можно выбрать опцию «перерасчет при изменении порядка». Тогда система будет перерассчитывать последующие строки после текущей при изменении порядка на N. То есть, значения пересчитываются в строке, порядок которой изменен, и во всех последующих.
Мы также можем ограничить роли, которые могут изменять порядок сортировки. Это настраивается в опции «Ролевой доступ на изменение порядка».

Также  есть опция «Показывать по месту сортировки», при активизации которой  добавляемые строки будут сразу показываться по выбранному порядку сортировки.

Таким образом, включение сортировки по полю Порядок изменяет порядок расчета строк на основе значения в поле `n`, что позволяет более гибко управлять порядком строк в таблице.

#### <a name="manual-sorting-of-lines-ai5"></a> Что произойдет, если добавить строку между существующими строками при ручной сортировке?

**Пример:**

Допустим, у вас есть таблица с тремя строками, у которых значения `n` равны 1, 2 и 3. Если вы добавите новую строку между строками с `n` = 1 и `n` = 2, то новая строка получит значение `n`, например, 1.5. Это дробное значение позволяет вставить строку между существующими без изменения значений `n` у других строк.

**Важные моменты:**

1. **Дробные значения**: Использование дробных значений позволяет вставлять строки между существующими без изменения порядка других строк.

2. **Функция `normalizeN`**: Если в проекте происходит частая вставка строк между существующими, рекомендуется периодически выполнять функцию `normalizeN`, чтобы нормализовать значения `n` и убрать дробные хвосты.

3. **Автоматический пересчет**: При изменении порядка строк, если включен параметр "Пересчет при изменении порядка", строки с `n` больше минимального `n` у строк, участвующих в изменении порядка, будут пересчитаны.

Таким образом, добавление строки между существующими строками при ручной сортировке позволяет гибко управлять порядком строк без необходимости пересчитывать все значения `n`.

#### <a name="manual-sorting-of-lines-ai6"></a> Для чего используется функция normalizeN?

Функция `normalizeN` в системе Totum используется для нормализации значений в поле `n`, которое отвечает за порядок строк в таблице. Это необходимо в случаях, когда происходит частая вставка строк между существующими, что может привести к увеличению дробной части значений в поле `n`.

**Основные цели использования функции `normalizeN`:**

1. **Устранение дробных значений**: При частой вставке строк между существующими, значения в поле `n` будет иметь большую дробную часть. Функция `normalizeN` пересчитывает эти значения, присваивая им новые значения с шагом 1, что упрощает дальнейшую работу с таблицей.

2. **Поддержание порядка строк**: Нормализация значений в поле `n` помогает поддерживать порядок строк в таблице, особенно если строки часто перемещаются или добавляются между существующими.

3. **Оптимизация производительности**: Упрощение значений в поле `n` может улучшить производительность системы, так как уменьшает сложность вычислений при сортировке и отображении строк.

**Пример использования функции `normalizeN`:**

```totum
=: normalizeN(table: 'table_name'; num: 12)
```

В данном примере значения `n` будут нормализованы для таблицы `table_name`, если их дробная часть превышает 12 символов. Параметр `num` позволяет управлять нагрузкой при нормализации и не нормализовывать цепочки вставок малого размера.

**Периодическое выполнение**

Рекомендуется поставить нормализацию в задания по расписанию Кроны, через таблицу Кронов в время минимальной нагрузки на систему:

```totum
=: normalizeN(table: 'table_name')
```

Таким образом, функция `normalizeN` помогает поддерживать порядок и оптимизировать работу с таблицами в системе Totum, особенно в случаях частой вставки строк между существующими.

Допустим, у нас есть таблица с полем `end_time`, которое вычисляется на основе порядка строк. Если мы изменим порядок строк, то значение поля `end_time` будет пересчитано для всех строк, у которых `n` больше, чем минимальный `n` у строк, участвующих в изменении порядка.

**Заключение:**

Функция "Пересчет при изменении порядка" позволяет автоматически пересчитывать значения в таблице при изменении порядка строк, что обеспечивает актуальность данных и предотвращает возможные ошибки.

#### <a name="manual-sorting-of-lines-ai12"></a> Как изменить порядок строк при активной n-сортировке?

В системе Totum изменение порядка строк при активной n-сортировке осуществляется через интерфейс или с помощью кода. Давайте рассмотрим оба способа:

**Изменение порядка строк через интерфейс**

1. **Включите параметр 'Сортировка по полю Порядок' в настройках таблицы.**

2. **Нажмите на кнопку с двумя треугольниками**, которая находится левее заголовков строчной части таблицы.

3. **Выберите id перемещаемой строки или строк.**

4. В открывшемся поле Порядок (Order) **выберите строку, до или после которой необходимо поставить перемещаемые строки**. И нажмите, соответственно, кнопку вверх (тогда строки будут поставлены до) или вниз (тогда строки будут поставлены после).

5. **Нажмите 'сохранить'** (дискетка в заголовке поля Порядок).

Если параметр 'Сортировка по полю Порядок' не активен, то сортировка вручную доступна, но не активна функция 'сохранить'. Поэтому строки можно отсортировать, но после перезагрузки страницы порядок строк вернется к прежнему. Такая ручная сортировка без сохранения может быть полезна, чтобы вывести данные на печать или для их демонстрации.

**Изменение порядка строк с помощью кода действия**

Для изменения порядка строк с помощью кода можно использовать функцию `reorder`. Эта функция позволяет перемещать строки в таблице, указывая их `id` и новое положение.

Пример кода-действия:

```totum
=: reorder(table: 'table_name'; ids: json`[1, 2, 3]`; after: 100)
```

В этом примере строки с `id` 1, 2 и 3 будут перемещены после строки с `id` 100.

**Важно**

- Убедитесь, что в настройках таблицы включен параметр 'Сортировка по полю Порядок', чтобы изменения порядка строк сохранялись.
- Если вы часто вставляете новые строки между существующими, рекомендуется периодически выполнять функцию `normalizeN` для нормализации значений в поле `n`.

Таким образом, в Totum можно гибко управлять порядком строк как через интерфейс, так и с помощью кода, обеспечивая удобство работы с данными.

#### <a name="manual-sorting-of-lines-ai13"></a> Почему при сортировке по полю N обратный порядок недоступен?

В системе Totum сортировка по полю N используется для ручной сортировки строк в таблице. Поле N автоматически присваивает значения, которые упорядочивают строки в порядке возрастания. Обратный порядок не предусмотрен, так как это противоречит логике работы поля N, которое предназначено для последовательного упорядочивания строк.

**Причины недоступности обратного порядка при сортировке по полю N:**

1. **Логика сортировки**: Поле N используется для ручной сортировки строк, и его значения автоматически обновляются при изменении порядка строк. Это позволяет пользователям вручную управлять порядком строк, перемещая их вверх или вниз.

2. **Автоматическое обновление**: При изменении порядка строк значения в поле N автоматически обновляются, чтобы сохранить последовательность. Это делает невозможным использование обратного порядка, так как значения N всегда должны увеличиваться.

3. **Технические ограничения**: Обратный порядок может привести к конфликтам с логикой автоматического обновления значений N, что может вызвать ошибки в системе.

4. **Функциональные особенности**: Поле N предназначено для обеспечения стабильного и предсказуемого порядка строк, что особенно важно при использовании функций, зависящих от порядка строк, таких как пересчет значений на основе предыдущих строк.

Таким образом, сортировка по полю N в Totum предназначена для обеспечения последовательного и предсказуемого порядка строк, что делает использование обратного порядка невозможным.

#### <a name="manual-sorting-of-lines-ai14"></a> Как включить отображение добавленных строк по месту их сортировки?

В системе Totum, чтобы включить отображение добавленных строк по месту их сортировки, необходимо активировать соответствующую настройку в параметрах таблицы. Эта функция доступна для таблиц, в которых включена сортировка по полю порядок (n-сортировка). Вот как это сделать:

1. **Откройте настройки таблицы**: Перейдите в нужную таблицу и откройте её настройки. Это можно сделать, выбрав таблицу в дереве и нажав на иконку настроек справа от name таблицы.

2. **Активируйте параметр**: Найдите параметр **Показывать новую строку по месту сортировки** (new_row_in_sort) и установите его в активное состояние. Это позволит автоматически размещать новую строку в соответствии с текущей сортировкой таблицы.

3. **Сохраните изменения**: После активации параметра сохраните изменения в настройках таблицы.

После выполнения этих шагов новые строки будут автоматически отображаться в правильном порядке, что упрощает работу с таблицей и повышает её удобство использования.

#### <a name="manual-sorting-of-lines-ai15"></a> Можно ли ограничить доступ к изменению порядка сортировки для определенных ролей?

Да, в системе Totum можно ограничить доступ к изменению порядка сортировки строк для определенных ролей. Это делается с помощью параметра **Ролевой доступ на изменение порядка (order_roles)** в настройках таблицы.

**Как настроить ролевой доступ на изменение порядка строк:**

1. **Откройте настройки таблицы**: Перейдите в нужную таблицу и откройте её настройки.

2. **Найдите параметр "Ролевой доступ на изменение порядка"**: В настройках таблицы найдите параметр **Ролевой доступ на изменение порядка (order_roles)**.

3. **Укажите роли**: В этом параметре укажите роли, которые будут иметь возможность изменять порядок строк. Только пользователи с этими ролями смогут изменять порядок строк в таблице.

4. **Сохраните изменения**: После указания необходимых ролей, сохраните изменения в настройках таблицы.

**Пример настройки:**

Если вы хотите, чтобы только роли "Менеджер" и "Администратор" могли изменять порядок строк, укажите эти роли в параметре **Ролевой доступ на изменение порядка**.

**Важно:**

- Если параметр **Ролевой доступ на изменение порядка** не указан, то все пользователи, имеющие доступ к таблице на редактирование, могут изменять порядок строк.
- Убедитесь, что в таблице включена сортировка по полю порядок, чтобы изменения порядка строк были возможны.

Таким образом, вы можете гибко управлять доступом к изменению порядка строк в таблице, ограничивая его только для определенных ролей.
