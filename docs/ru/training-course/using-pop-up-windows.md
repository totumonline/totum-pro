# Использование всплывающих окон

## <a name="how-do-I-open-another-table-at-the-click-of-a-button"></a> Как открыть другую таблицу по нажатию кнопки?

### <a name="how-do-I-open-another-table-at-the-click-of-a-button-qa"></a> Вопросы и ответы

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-q1"></a> Какой функцией можно открыть другую таблицу?

Базовая функция для открытия другой таблицы это [linkToTable][305].

```totum

=: linkToTable(table: 'table'; title: "Заголовок окна"; target: "iframe")

```

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-q2"></a> Можно ли ее открыть во всплывающем окне и задать его размер?

Да, за это отвечает параметр `target`:

+ `iframe` — в iframe поверх остальных окон.

+ `blank` — в новом окне (для корректной работы требуется разрешить открытие всплывающих окон в браузере)

+ `parent` — в базовом нижнем окне, все открытые вложенные окна будут закрыты.

+ `self` — в текущем окне. Если параметр не указан — обрабатывается как self.

Должно быть указано что-то одно из этого списка.

Для задания размера окна `iframe` по ширине используется параметр `width: 800`. Цифра — это жесткая ширина в пикселях.

Можно передать не цифру, а `"80vw"`, тогда цифра перед vw будет определять процент от ширины окна браузера.

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-q3"></a> Можно ли передать в открываемую таблицу значения префильтров, что бы увидеть нужные строки?

Если в целевой странице у вас есть префильтр, то в него можно передать значение, параметром `filter`:

```totum

=: linkToTable(table: 'table'; title: "Заголовок окна"; filter: 'fl_filter' = #number; target: "iframe")

```

Значение передаваемого префильтра будет зашифровано сессионнм ключом и передано в адресной строке. Поэтому такая передача имеет ограничение на объем — нельзя в `filter` передать большие списки или массивы!

Поле префильтра должно быть [редактируемым][162] для роли. Оно может быть [скрытым][178], но редактируемым должно быть обязательно.

Таким образом можно связывать таблицы между собой.

Например из таблицы Склад иметь возможность открыть список Движений по товару по конкретному товару.

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-q4"></a> Как избежать ошибки при передаче в префильтры больших списков?

Для того, что бы иметь возможность обрабатывать **большие** списки в `linkToTable` есть такой подход:

1. Вы создаете два! поля префильтра.

2. В первое передаете значение по `filter`. Это должно быть короткое значение, например список ролей или номер роли от которой посчитается ограничивающий список категорий. Любо набор параметров, который вам позволит посчитать ограничивающий список во втором поле.

3. Первое поле префильтра не привязывается к строчной части. Настройка [name поля в строчной части][138] остается пустой.

4. Во втором поле префильтра считаете нужный список ограничений кодом и это поле привязывается к строчной части.

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-q5"></a> Какие настройки видимости и изменения должны быть у полей префильтра, чтобы это сработало?

Первое поле должно быть редактируемым, но может быть скрыто для роли. по `filter` значения можно передать только в редактируемые для роли поля префильтров.

Второе поле, которое рассчитывается кодом может быть нередактируемым и скрытым.

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-q6"></a> Как открыть таблицу и сразу открыть строку добавления с заполненными параметрами?

У linkToTable есть еще один параметр, понижающий количество кликов пользователей и повышающий удобство — это `field`.

Если вы передаете значение в `field` и в целевой таблице [доступна строка добавления][106], то при открытии окна сразу будет открыта строка добавления и в указанне поля будут подставлены значения.

Например: у нас есть заказ и мы по `linkToTable` открывает таблицу оплат, мы сразу можем в сумму оплаты ставить рассчитанный остаток оплаты по этому заказу.

```totum

=: linkToTable(table: 'payments'; filter: 'fl_order' = #order_number; field: 'summ' = $calc)

calc: #order_summ - $payments
	payments: listSum(list: $list)
		list: selectList(table: 'payments'; field: 'summ'; where: 'order' = #order_number)

```

Как открыть другую таблицу по нажатию кнопки?
Функции, открывающие всплывающие окна, начинаются с link. Это функции кода действия.
Базовая функция для открытия другой таблицы это `linkToTable`.
```totum
=: linkToTable(table: ''; cycle: ; hash: ; title: ; filter: '' = ; field: '' = ; target: "iframe|blank|self|parent"; width: 800; refresh: false; header: true; footer: true)
```
В качестве примера у нас есть таблицы с товарами. В одной из них (name таблицы ‘link_to_table’) есть названия товаров и информация по ним: цена и количество на складе. Есть таблица (name таблицы ‘table_for_link’), в которой у нас есть движение этих товаров. В ней мы можем указать, что добавили, например, кубик - два предмета. Он пришел к нам, например, поступил на склад. Здесь мы считаем в таблице ‘link_to_table’ остаток после того, как мы выполнили эту операцию в ‘table_for_link’ и в ней выполнился код действия, меняющий значение в значение. Здесь мы добавили куб, он стоит 7.
Что бы мы хотели? Мы хотели бы иметь возможность отсюда из таблицы ‘link_to_table’ видеть движение конкретно по кубу или видеть движение в целом по таблице ‘table_for_link’. И как мы это сделаем? Мы создаем поле типа «кнопка» и пишем код действия с функцией `linkToTable`.
Мы берем таблицу для ссылки, вот она. Если мы собираемся открывать таблицу во всплывающем окне, нам нужно указать заголовок, который будет находиться в верхней части этого окна. Например, мы назовем его «Движения». Нам нужны далеко не все параметры, которые автопредзаполняются при создании этой функции. Стираем лишнее. В параметре `target`выберем вид и размер всплывающего окна

•	iframe — в iframe поверх остальных окон.
•	blank — в новом окне (для корректной работы требуется разрешить открытие всплывающих окон в браузере)

Давайте выберем iframe. Это наиболее часто используемый вариант. `Refresh`, `header`, `footer` пока не рассматриваем. У нас получился такой код:
```totum
=: linkToTable(table: 'table_for_link'; title: "Movements"; target: "iframe"; width: "80vw")
```

Нажимаем на кнопку с созданным нами кодом. Открывается таблица ‘table_for_link’, и мы видим все строки этой таблицы прямо сейчас, потому что мы не задали в коде действия никаких условий выборке. Во всплывающем окне видны не все данные отображаемой таблицы. Это сделано для упрощения просмотра. Если во всплывающем окне в правом нижнем углу нажать кнопку «Tab», мы можем открыть эту таблицу, например, в новой вкладке, и увидим, что у нас здесь есть префильтр. Вы можете выбрать куб в предварительном фильтре, и будут показаны только строки по кубу, потому что этот фильтр связан с полем заголовка.
И следующее, что мы хотим сделать, - это открыть это всплывающее окно, чтобы мы могли видеть строки для конкретного продукта. Для этого нам нужно установить параметр фильтрации в функции `linkToTable`. Мы его стерли. Указываем параметр `filter`. Выбираем name поля префильтра, к которому мы привязываемся. По умолчанию в префильтрах используются префиксы fl. Выбираем поле префильтра ‘fl_title. И нам нужно привязаться к id.

``` totum
=: linkToTable(table: 'table_for_link'; filter: 'fl_title' = #id; title: "Movements"; target: "iframe"; width: "80vw")
```
Сохраняем. Теперь, если мы кликаем на кнопку из строки с конкретным товаром, мы видим движение только по указанной позиции.
Теперь следующий момент: открываем это окно - там заголовок, и это поле должно быть разрешено редактировать, чтобы этот фильтр-переход работал. Давайте уберем редактирование и посмотрим, что произойдет. Мы переходим в ‘link_to_table’, и передача параметров префильтра не работает. Параметры префильтра передаются здесь в зашифрованном виде. Они зашифрованы с помощью «соли» - это случайная или псевдослучайная строка данных, которая добавляется к данным, например к паролю или адресу, перед хешированием. Соль является сессионной. То есть, если вы скопируете эту ссылку, передадите ее другому человеку или используете ее после смены сессии. Если вы выйдите из системы и войдите в нее, чтобы закрыть сессию, эта ссылка не сработает, потому что код является сессионным.
Поскольку у нас есть заблокированное поле, никакие данные из него не попадают в поле префильтра. Это сделано для безопасности, чтобы даже если человек возьмет здесь значение, он не смог получить доступ к префильтру, к которому у него нет доступа для редактирования.
Мы разблокируем его обратно, и вот он, извлеченный прямо из url. Если вам нужно сделать какой-то защищенный фильтр, чтобы у пользователя не было к нему доступа, нужно поступить следующим образом: сделать его видимым только для какой-то роли. Например, если мы являемся создателем, то сделаем видимость только для создателя. Сделайте его видимым только для одной роли. Для создателя есть хитрость: даже те поля, которые он не видит в своей роли, все равно отображаются, так что вы не можете «выстрелить себе в ногу» и потом долго и мучительно искать это поле в другом месте.
Логика в этом следующая: когда поле префильтра, не видимое для роли, доступно для редактирования, значения из адресной строки применяются, но у пользователя значительно меньше возможностей взломать это поле и получить к нему доступ, потому что он даже не знает, что это за поле и как оно работает.
Для особо сложных случаев может быть следующая система: у вас есть поле, которое доступно для редактирования. Например, оно может быть даже не видно, открыто для редактирования, но не является связанным полем. Кстати, обычно скрытые поля делаются видимыми только для создателя, и такое техническое поле не видно пользователям. А вот другое техническое поле делается связанным - оно уже вычисляется кодом, например, на основе текущего пользователя, проверяется на стороне сервера, и уже привязывается к нужному полю в строчной части. Таким образом, значение попадает в редактируемое поле, но мы дополнительно проверяем, действительно ли у этого пользователя есть доступ к этим значениям, и только после этого работает фильтрация. Это как раз то, что нужно для самых параноидальных мест, таких как деньги или другие ответственные операции.
Давайте разберемся еще с одним моментом. Например, когда мы нажимаем на кнопку, открывающую таблицу 'table_for_link', мы хотим не просто открыть таблицу, а сразу открыть строку сложения и подставить в количество значение. Как мы это сделаем? В нашем коде действия мы указываем, что хотим передать параметр поля, и смотрим, какие поля у нас здесь есть. Здесь у нас есть количество, и мы говорим, что передаем значение. Допустим, 1. Когда у нас есть параметр поля, мы нажимаем на кнопку, которая выполняет ссылку на таблицу. У нас открывается строка добавления. И заметьте: мы не передали куб, мы передали только количество 1. Почему же подставляется куб? Потому что у нас есть куб в префильтре. Это поле, связанное с полем заголовка. Вот здесь. В префильтре есть автозаполнение. Если это поле доступно для редактирования пользователю, значение отсюда будет автоматически подставлено в это поле.
А затем пользователь может сразу же нажать кнопку сохранения, и в этой таблице произойдет перерасчет. Теперь мне нужно нажать на кнопку обновления. ### <a name="how-do-I-open-another-table-at-the-click-of-a-button-ai"></a> Дополнительные вопросы

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-ai1"></a> Как открыть другую таблицу во всплывающем окне по нажатию кнопки?

Для открытия другой таблицы во всплывающем окне по нажатию кнопки в системе Totum, вы можете использовать функцию `linkToTable`. Эта функция позволяет открыть указанную таблицу в различных режимах, включая всплывающее окно. Давайте рассмотрим, как это можно сделать.

**Шаги для открытия таблицы во всплывающем окне:**

1. **Создайте поле типа "Кнопка"**: В таблице, из которой вы хотите открыть другую таблицу, создайте поле типа "Кнопка". Это поле будет использоваться для вызова функции `linkToTable`.

2. **Напишите код действия для кнопки**: В коде действия кнопки используйте функцию `linkToTable`, чтобы открыть нужную таблицу. Укажите параметры, такие как название таблицы, заголовок окна и режим открытия.

Пример кода действия для кнопки:

```totum
=: linkToTable(table: 'target_table'; title: "Заголовок окна"; target: "iframe"; width: "80vw")
```

**Параметры функции `linkToTable`:**

- **table**: Укажите имя таблицы, которую вы хотите открыть.
- **title**: Укажите заголовок окна, который будет отображаться в верхней части всплывающего окна.
- **target**: Укажите режим открытия. Для всплывающего окна используйте `"iframe"`.
- **width**: Укажите ширину окна. Вы можете задать фиксированную ширину в пикселях, например, `width: 800`, или использовать относительную ширину, например, `"80vw"` для 80% от ширины окна браузера.

В системе Totum передача значений в префильтры возможна только в редактируемые для роли поля. Если поле префильтра заблокировано для редактирования, то данные в него не могут быть переданы. Это сделано для обеспечения безопасности и предотвращения несанкционированного доступа к данным.

**Причины, по которым передача префильтров не работает для заблокированных полей:**

1. **Безопасность данных**: Если поле заблокировано, это означает, что пользователь не имеет права изменять его значение.

2. **Ограничение доступа**: Заблокированные поля могут содержать чувствительную информацию, доступ к которой ограничен.

3. **Сессионная защита**: Значения префильтров передаются в зашифрованном виде с использованием сессионного ключа. Это обеспечивает дополнительный уровень безопасности, предотвращая возможность подмены данных.

**Как обойти ограничение:**

Если необходимо передать данные в префильтр, который заблокирован для редактирования, можно использовать следующий подход:

1. **Создайте два поля префильтра**:
   - Первое поле должно быть редактируемым и может быть скрыто для роли. В него передается значение через `filter`.
   - Второе поле рассчитывается кодом на основе значения из первого поля и привязывается к строчной части.

2. **Используйте скрытые поля**: Поле может быть скрытым, но доступным для редактирования. Это позволяет передавать значения в префильтр, не отображая его пользователю.

Таким образом, передача префильтров в заблокированные поля невозможна из соображений безопасности, но можно использовать альтернативные подходы для достижения нужного результата.

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-ai11"></a> Как связана сессия и передача зашифрованных параметров в префильтр?

В системе Totum передача зашифрованных параметров тесно связана с сессией пользователя. Давайте разберем, как это работает и почему это важно для безопасности.

**Связь сессии и зашифрованных параметров префильтров**

1. **Сессионный ключ**:
   - В Totum зашифрованные параметры передаются с использованием сессионного ключа. Этот ключ уникален для каждой сессии пользователя и генерируется при входе в систему.
   - Сессионный ключ используется для шифрования и дешифрования параметров, что обеспечивает их безопасность при передаче.

2. **Шифрование параметров**:
   - Когда параметры передаются, например, через префильтры или другие механизмы, они шифруются с использованием сессионного ключа.
   - Это предотвращает возможность их перехвата и использования злоумышленниками, так как без сессионного ключа расшифровать параметры невозможно.

3. **Ограничение по времени**:
   - Поскольку сессионный ключ привязан к сессии, он действует только в течение времени жизни этой сессии. Если сессия завершается (например, пользователь выходит из системы или сессия истекает по времени), сессионный ключ становится недействительным.
   - Это означает, что зашифрованные параметры, переданные в рамках этой сессии, также становятся недействительными и не могут быть использованы повторно.

**Пример использования**

Когда вы используете функцию `linkToTable` с параметром `filter`, значения фильтров шифруются сессионным ключом и передаются в адресной строке. Это позволяет безопасно передавать параметры между таблицами, обеспечивая их защиту от подделки или перехвата.

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-ai15"></a> Какие настройки видимости и изменения должны быть у полей префильтра что бы передать в него значение через linkToTable?

Для того чтобы передать значение в префильтр через функцию `linkToTable`, необходимо настроить видимость и возможность изменения полей префильтра следующим образом:

1. **Редактируемость поля префильтра**: Поле префильтра, в которое вы хотите передать значение, должно быть доступно для редактирования для роли пользователя, который выполняет действие. Это обязательное условие, так как значения могут быть переданы только в редактируемые поля префильтров.

2. **Видимость поля префильтра**: Поле префильтра может быть скрытым, но оно должно быть редактируемым. Это означает, что даже если поле не отображается пользователю, оно все равно должно быть настроено как редактируемое для роли, чтобы в него можно было передать значение.

3. **Привязка к строчной части**: Поле префильтра должно быть привязано к полю в строчной части таблицы, если вы хотите, чтобы значение из префильтра фильтровало строки в таблице.

Пример использования `linkToTable` с передачей значения в префильтр:

```totum
=: linkToTable(table: 'target_table'; title: "Заголовок окна"; filter: 'fl_filter' = #some_value; target: "iframe")
```

В этом примере значение `#some_value` будет передано в поле префильтра `fl_filter` таблицы `target_table`. Убедитесь, что `fl_filter` настроено как редактируемое для роли пользователя, выполняющего действие.

#### <a name="how-do-I-open-another-table-at-the-click-of-a-button-ai16"></a> Что делает параметр field в linkToTable?

Параметр `field` в функции `linkToTable` используется для автоматического заполнения полей в строке добавления при открытии таблицы. Если в целевой таблице доступна строка добавления, то при открытии окна сразу будет открыта строка добавления, и в указанные поля будут подставлены значения, переданные через параметр `field`.

**Пример использования параметра `field`:**

```totum
=: linkToTable(table: 'payments'; filter: 'fl_order' = #order_number; field: 'sum' = $calc)
	calc: #order_sum - $payments
    	payments: listSum(list: $list)
        	list: selectList(table: 'payments'; field: 'sum'; where: 'order' = #order_number)
```

В этом примере, при открытии таблицы `payments`, будет сразу открыта строка добавления, и в поле `sum` будет подставлено значение, рассчитанное в строке `calc`. Это позволяет пользователю сразу видеть рассчитанное значение и, при необходимости, внести изменения или сохранить его.

Таким образом, параметр `field` упрощает процесс добавления новых записей, снижая количество необходимых действий со стороны пользователя.

### <a name="hide-the-header-or-footer-ai"></a> Дополнительные вопросы

#### <a name="hide-the-header-or-footer-ai1"></a> Как заставить таблицу-источник обновиться после закрытия окна с целевой таблицей?

Чтобы таблица-источник обновилась после закрытия окна с целевой таблицей, необходимо использовать параметр `refresh` в функции `linkToTable`. Этот параметр позволяет указать, как именно должна обновляться таблица-источник после закрытия окна.

Вот три варианта использования параметра `refresh`:

1. **refresh: true**: Обновление произойдет только если таблица-источник была изменена в результате действий, которые пользователь сделал в целевой таблице.

```totum
=: linkToTable(table: 'target_table'; title: "Target Table"; target: "iframe"; refresh: true)
```

2. **refresh: "recalculate"**: Этот вариант заставляет таблицу-источник пересчитаться. Это полезно если данные в аблице источнике не изменяются действием напрямую.

```totum
=: linkToTable(table: 'target_table'; title: "Target Table"; target: "iframe"; refresh: "recalculate")
```

3. **refresh: "reload"**: В этом случае таблица-источник будет перезагружена, как будто пользователь нажал обновить в браузере.

```totum
=: linkToTable(table: 'target_table'; title: "Target Table"; target: "iframe"; refresh: "reload")
```

Если параметр `refresh` не указан, то по умолчанию он считается равным `false`, и таблица-источник не будет обновляться автоматически. Выбор конкретного варианта зависит от того, как именно вы хотите обновить таблицу-источник после закрытия окна с целевой таблицей.

#### <a name="hide-the-header-or-footer-ai2"></a> Какой параметр функции linkToTable отвечает за обновление таблицы-источника при закрытии окна?

Параметр функции `linkToTable`, который отвечает за обновление таблицы-источника при закрытии окна, называется `refresh`. Он может принимать значения `true`, `false`, `"recalculate"` или `"reload".

- `refresh: true` — обновляет таблицу-источник, если она была изменена в результате действий, выполненных в открытой таблице.
- `refresh: "recalculate"` — принудительно пересчитывает таблицу-источник при закрытии окна.
- `refresh: "reload"` — не просто пересчитает таблицу источник, а перезагрузит ее, что бы в том числе сработала сортировка по умолчанию для таблицы.

Пример использования:

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; refresh: true)
```

или

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; refresh: "recalculate")
```

#### <a name="hide-the-header-or-footer-ai3"></a> Что делает параметр refresh со значением true в функции linkToTable?

Параметр `refresh` со значением `true` в функции `linkToTable` используется для автоматического обновления таблицы-источника после закрытия окна, в котором была открыта целевая таблица. Это обновление происходит только в том случае, если таблица-источник была изменена в результате действий, выполненных в открытой таблице. Например, если вы открываете таблицу "Движение по позиции" из таблицы "Склад" и вносите изменения в движении и это изменение изменяет остаток по позиции в таблице "Склад", то при закрытии окна с таблицей "Движение по позиции" таблица "Склад" будет автоматически обновлена, чтобы отразить изменения.

Пример использования:

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; refresh: true)
```

Таким образом, параметр `refresh: true` обеспечивает актуализацию данных в таблице-источнике после взаимодействия с целевой таблицей.

#### <a name="hide-the-header-or-footer-ai4"></a> Какое значение параметра refresh используется для пересчета таблицы при закрытии окна?

Для пересчета таблицы при закрытии окна используется значение параметра `refresh: "recalculate"`. Это значение заставляет таблицу-источник пересчитываться полностью, когда пользователь закрывает окно, открытое с помощью функции `linkToTable`.

Пример использования:

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; refresh: "recalculate")
```

В этом случае, после закрытия окна, таблица-источник будет пересчитана, что может быть полезно, если в целевой таблице были внесены изменения, которые должны отразиться в таблице-источнике, но небыло прямого действия, изменяющего данные в таблице источнике.

#### <a name="hide-the-header-or-footer-ai5"></a> В каких случаях используется значение recalculate для параметра refresh?

Значение `recalculate` для параметра `refresh` используется в случаях, когда необходимо пересчитать таблицу-источник при закрытии окна, даже если в ней не было прямых изменений. Это может быть полезно для временных таблиц или таблиц внутри цикла, чтобы гарантировать актуальность данных.

Когда вы открываете таблицу через `linkToTable` и указываете `refresh: "recalculate"`, это гарантирует, что таблица-источник будет пересчитана при закрытии окна, независимо от того, были ли в ней прямые изменения. Это может быть необходимо, если данные в таблице-источнике зависят от сложных вычислений или временных данных, которые должны быть обновлены для корректного отображения.

Пример использования:

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; refresh: "recalculate")
```

Этот подход увеличивает нагрузку на систему, так как пересчет может быть ресурсоемким, но иногда это необходимо для обеспечения актуальности данных.

#### <a name="hide-the-header-or-footer-ai6"></a> Какие данные обновляются в таблице при использовании refresh: recalculate?

При использовании параметра `refresh: "recalculate"` в функции `linkToTable`, для расчетный и временных таблиц происходит полное обновление данных в таблице-источнике, из которой было открыто окно. Это означает, что пересчитываются все данные таблицы, включая хедер, футер и строчную часть.

Однако стоит отметить, что в простых таблицах пересчитывается только хедер, а строчная часть не пересчитывается автоматически. Для пересчета строчной части в простых таблицах необходимо использовать дополнительные механизмы, такие как вызов функции `reCalculate` с указанием конкретных строк или полей, которые нужно пересчитать.

Пример использования `refresh: "recalculate"`:

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; refresh: "recalculate")
```

Этот параметр увеличивает нагрузку на систему, так как требует пересчета всех данных таблицы, но иногда это необходимо, особенно в сочетании с расчетными и временными таблицами, где требуется гарантированное обновление всех данных.

#### <a name="hide-the-header-or-footer-ai7"></a> Как включить автоматическое закрытие окна после выполнения действия кнопки?

Чтобы включить автоматическое закрытие окна после выполнения действия кнопки в Totum, необходимо воспользоваться параметром "Закрыть окно после выполнения" в настройках поля типа "Кнопка". Этот параметр позволяет автоматически закрыть окно после выполнения действия, описанного в кнопке.

Вот как это можно сделать:

1. Перейдите в целевую таблицу, где находится кнопка, для которой вы хотите настроить автоматическое закрытие окна.
2. Найдите поле типа "Кнопка", для которого вы хотите включить эту функцию.
3. В настройках этого поля найдите параметр "Закрыть окно после выполнения действия". Этот параметр находится под кодом действия кнопки, там где у полей других типов находятся триггеры действия.
4. Установите галочку напротив этого параметра, чтобы активировать его.

После этого, когда пользователь нажимает на кнопку и выполняется действие, окно автоматически закроется. Это удобно в случаях, когда после выполнения действия пользователю больше не нужно оставаться в этом окне.

#### <a name="hide-the-header-or-footer-ai8"></a> Где находится параметр 'закрыть окно после выполнения' для кнопки?

Параметр 'закрыть окно после выполнения' для кнопки находится в настройках поля типа "Кнопка". Этот параметр расположен под кодом действия кнопки, там где у полей других типов находятся триггеры действия. Чтобы активировать этот параметр, необходимо установить галочку напротив него. После этого, когда пользователь нажимает на кнопку и выполняется действие, окно автоматически закроется.

#### <a name="hide-the-header-or-footer-ai9"></a> Когда стоит включить параметр 'закрыть окно после выполнения' для кнопки?

Параметр 'закрыть окно после выполнения' для кнопки стоит включить, когда после нажатия на кнопку и выполнения её действия пользователю уже не нужно будет текущее окно. Это позволяет автоматически закрыть окно после выполнения действия, описанного в кнопке, что может улучшить пользовательский опыт, особенно если дальнейшие действия пользователя не требуют взаимодействия с текущим окном.

#### <a name="hide-the-header-or-footer-ai10"></a> Как скрыть хедер таблицы во всплывающем окне?

Чтобы скрыть хедер таблицы во всплывающем окне, вы можете использовать функцию `linkToTable` с параметром `header: false`. Этот параметр отключает показ хедера в открываемой таблице, если она открывается в `iframe`.

Пример использования:

```totum
=: linkToTable(table: 'tablename'; target: 'iframe'; header: false)
```

Если параметр `header` не указан, то по умолчанию он равен `true`, что означает, что хедер будет показан, если он есть. Указание `header: false` явно отключает его отображение.

#### <a name="hide-the-header-or-footer-ai11"></a> Какой параметр функции linkToTable используется для управления отображением хедера?

Параметр `header` функции `linkToTable` используется для управления отображением хедера. Если вы хотите отключить показ хедера, вы можете установить этот параметр в `false`. По умолчанию, если параметр не указан, он считается равным `true`, что означает, что хедер будет отображаться, если он есть.

Пример использования:

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; header: false)
```

В этом примере хедер не будет отображаться при открытии таблицы.

#### <a name="hide-the-header-or-footer-ai12"></a> Что по умолчанию происходит с хедером при открытии таблицы во всплывающем окне?

По умолчанию, когда таблица открывается во всплывающем окне с использованием функции `linkToTable`, хедер (заголовок) таблицы отображается. Это означает, что если вы не укажете параметр `header` в функции `linkToTable`, то он будет установлен в значение `true`, и хедер будет виден пользователю. Если вы хотите отключить показ хедера, вы можете явно указать `header: false` в параметрах функции `linkToTable`.

Пример кода, где хедер отключен:

```totum
=: linkToTable(table: 'movements'; title: "Движение по позиции"; filter: 'fl_unit' = #id; target: "iframe"; header: false)
```

Таким образом, по умолчанию хедер отображается, если не указано иное.

#### <a name="hide-the-header-or-footer-ai13"></a> В каких случаях бывает полезно скрыть хедер и футер во всплывающем окне?

Скрытие хедера и футера во всплывающем окне бывает полезно в следующих случаях:

1. **Упрощение интерфейса**: Если хедер и футер содержат информацию, которая не является критически важной для текущего взаимодействия пользователя, их скрытие может сделать интерфейс более простым и понятным. Это особенно актуально, если пользователю нужно сосредоточиться на строчной части таблицы.

2. **Экономия пространства**: В некоторых случаях пространство на экране может быть ограничено, особенно на устройствах с небольшими экранами. Скрытие хедера и футера позволяет использовать больше пространства для отображения основной информации.

3. **Снижение отвлекающих факторов**: Если хедер и футер содержат элементы, которые могут отвлекать пользователя от основной задачи, их скрытие может помочь сосредоточиться на важной информации.

4. **Ускорение загрузки**: В некоторых случаях скрытие дополнительных элементов интерфейса может ускорить загрузку и отображение данных, особенно если хедер и футер содержат сложные элементы или данные, которые требуют дополнительного времени на обработку.

5. **Специфические задачи**: Если всплывающее окно используется для выполнения конкретной задачи, например, для ввода данных или редактирования, хедер и футер могут быть не нужны и даже мешать выполнению этой задачи.

В Totum для скрытия хедера и футера во всплывающем окне используются параметры `header: false` и `footer: false` в функции `linkToTable`. Если эти параметры не указаны, они по умолчанию равны `true`, что означает, что хедер и футер будут отображаться, если они есть.

### <a name="creating-a-temporary-table-and-its-features-qa"></a> Вопросы и ответы

#### <a name="creating-a-temporary-table-and-its-features-q1"></a> Что такое временная таблица?

[Временная таблица][34] — особый тип таблиц, создающихся при открытии их пользователем и существующих ограниченное время (по умолчанию 1 час). Потом они стираются из базы данных.

Те если несколько пользователей откроют одну и туже временную таблицу — они увидят разные таблицы. Структура у них будет одинаковая, но наполнение данными разное.

#### <a name="creating-a-temporary-table-and-its-features-q2"></a> Зачем они используются?

Например для отчетов или как промежуточне технические таблицы.

#### <a name="creating-a-temporary-table-and-its-features-q3"></a> Можно ли временную таблицу открыть из дерева?

По умолчанию временная таблица доступна из дерева, но если она создается как техническая, то скорее всего из дерева ее надо будет скрыть — задав параметр [роли «скрыть в дереве»][121].

#### <a name="creating-a-temporary-table-and-its-features-q4"></a> Какая функция используется для открытия временной таблицы?

Чтобы открыть временную таблицу, как обыкновенную таблицу из дерева подойдет [linkToTable][305] с которым мы уже знакомы.

Особенностью временной таблицы является то, что в ней нет префильтра. Поэтому параметры `filter` применятся не будут.

Но если мы хотим открыть временную и заполнить ее определенными данными — нам нужна функция [linkToDataTable][308].

#### <a name="creating-a-temporary-table-and-its-features-q5"></a> Какая функция используется для открытия временной таблицы и передачи в нее данных?

Если мы хотим открыть временную и заполнить ее определенными данными — нам нужна функция [linkToDataTable][308].

У нее есть два отличающих ее от linkToTable параметра — `data: $rowList` и `params: $row`.

+ `data` — данные для заполнения строчной части.

+ `params` — данные для заполнения хедера и футера.

Как это выглядит. Например у нас есть таблица с полем `client` и `order` в хедере и мы хотим при открытии сразу подставить туда значение нужного нам клиента, которого мы определяем из строки и з которой выполняется кнопка открытия:

```totum

=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row)
    row: rowCreate(field: "client" = #client; field: "order" = #order_num)

```

Те в `params` надо передать `row` состоящее из `name` полей, которые нужно заполнить и их значений.

Обратите внимание, что в `rowCreate` и аналогичных функциях создающих структуру со значениями `name`-параметры функций заполняются через **двойные** кавычки. Это правило не является обязательным для правильной работоспособности — оно относится к правилам оформления кода.

#### <a name="creating-a-temporary-table-and-its-features-q6"></a> Можно ли заполнить строчную часть, а не только хедер или футер?

Если мы хотим заполнить строчную часть при открытии временной таблицы, то в `data` надо передать `rowList`, каждая строка которого будет строкой во временной таблице.

```totum

=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "client" = #client; field: "order" = #order_num)
	rowlist:rowListCreate(field: "goods" = $list[[goods]]; field: "price" = $list[[price]])
		~list: selectRowList(table: 'order'; cycle: #order_num; field: 'goods'; field: 'price')

```

Мы в этом коде забегаем немного вперед обращаясь к таблице цикла используя `cycle` и берем `rowList` из которого в `goods` используем колонку `goods`, а в `price` колонку `price` при помощи `[[column]]`.

Подробнее про вложенные обращения [здесь][557], но мы их будем разбирать дальше.

#### <a name="creating-a-temporary-table-and-its-features-q7"></a> Можно ли передать только часть данных, а остальные рассчитать уже в таблице?

Достаточно часто в строчную часть данные передаются построчно в скрытое ведущее техническое поле, а потом уже растаскиваются по полям:

```totum

=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "client" = #client; field: "order" = #order_num)
	rowlist: rowListCreate(field: "teh" = $list)
		list: selectRowList(table: 'order'; cycle: #order_num; field: 'goods'; field: 'price')

```

А уже в поле `goods` делается код:

```totum

=: #teh[goods]

```

У нее есть два отличающих ее от `linkToTable` параметра — `data: $rowList` и `params: $row`.
•	`data` — данные для заполнения строчной части.
•	`params` — данные для заполнения хедера и футера.
Как это выглядит. Например, у нас есть таблица с полем 'h_client' и 'h_order' в хедере и мы хотим при открытии сразу подставить туда значение нужного нам клиента, которого мы определяем из строки и з которой выполняется кнопка открытия:

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row)
    row: rowCreate(field: "h_client" = #client; field: "h_order" = #order_num)
```
То есть, в `params` надо передать `row` состоящее из ‘name’ полей, которые нужно заполнить, и их значений.
Обратите внимание, что в `rowCreate` и аналогичных функциях создающих структуру со значениями, name-параметры функций заполняются через двойные кавычки. Это правило не является обязательным для правильной работоспособности — оно относится к правилам оформления кода.
Можно ли заполнить строчную часть, а не только хедер или футер?
Если мы хотим заполнить строчную часть при открытии временной таблицы, то в `data` надо передать `rowList`, каждая строка которого будет строкой во временной таблице.
```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "h_client" = #client; field: "h_order" = #order_num)
    rowlist:rowListCreate(field: "goods" = $list[[goods]]; field: "price" = $list[[price]])
        ~list: selectRowList(table: 'order'; cycle: #order_num; field: 'goods'; field: 'price')
```
Мы в этом коде забегаем немного вперед , обращаясь к таблице цикла, используя cycle, и берем rowList, из которого в goods используем колонку goods, а в price – колонку price, при помощи [[column]].

Можно ли передать только часть данных, а остальные рассчитать уже в таблице?
Достаточно часто в строчную часть данные передаются построчно в скрытое ведущее техническое поле, а потом уже растаскиваются по полям:
```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "h_client" = #client; field: "h_order" = #order_num)
    rowlist: rowListCreate(field: "teh" = $list)
        list: selectRowList(table: 'order'; cycle: #order_num; field: 'goods'; field: 'price')
```
А уже в поле goods делается код:
```totum
=: #teh[goods]
```

### <a name="creating-a-temporary-table-and-its-features-ai"></a> Дополнительные вопросы

#### <a name="creating-a-temporary-table-and-its-features-ai1"></a> Что такое временная таблица в Totum?

Временная таблица в системе Totum — это особый тип таблиц, которые создаются при открытии их пользователем и существуют ограниченное время (по умолчанию 1 час). После этого они автоматически удаляются из базы данных. Временные таблицы позволяют каждому пользователю работать с уникальным набором данных, даже если несколько пользователей открывают одну и ту же временную таблицу. Структура таблицы остается одинаковой, но данные в ней могут быть разными для каждого пользователя.

**Основные особенности временных таблиц:**

1. **Уникальный набор данных**: Каждый пользователь видит свои данные, даже если открывает одну и ту же временную таблицу.

2. **Ограниченное время существования**: Временные таблицы существуют в течение определенного времени (по умолчанию 1 час) и затем удаляются.

3. **Использование для отчетов и промежуточных таблиц**: Временные таблицы часто используются для создания динамических отчетов, промежуточных таблиц действий и настроечных таблиц.

4. **Вызов через функцию `linkToDataTable`**: Временные таблицы могут быть вызваны с передачей данных в шаблон таблицы, что позволяет заполнять их данными при открытии.

5. **Отсутствие префильтра**: Временные таблицы не имеют префильтра, что отличает их от других типов таблиц.

6. **Анонимный доступ**: Временные таблицы могут быть показаны вне авторизационного контура схемы при помощи анонимного доступа.

**Пример вызова временной таблицы с передачей данных:**

```totum
=: linkToDataTable(table: 'tmp_table'; title: "Title for tmp window"; data: $rowList; params: $row; refresh: false)

rowList: rowListCreate(field: "field1" = json`[1,2]`; field: "field2" = json`[3,4]`)

row: rowCreate(field: "h_field1" = 40; field: "h_field_2" = 50)
```

В этом примере временная таблица `tmp_table` открывается с заголовком "Title for tmp window", и в нее передаются данные для заполнения строчной части и параметров хедера.

#### <a name="creating-a-temporary-table-and-its-features-ai2"></a> Сколько времени хранится временная таблица по умолчанию?

Временная таблица в системе Totum хранится по умолчанию в течение 1 часа после последнего изменения данных в ней. После этого времени она автоматически удаляется из базы данных.

#### <a name="creating-a-temporary-table-and-its-features-ai3"></a> В чем особенность отображения временной таблицы для разных пользователей?

Временная таблица в системе Totum обладает уникальной особенностью: она создается заново каждый раз при её открытии и существует ограниченное время (по умолчанию 1 час). Это означает, что каждый пользователь, открывающий временную таблицу, видит свою собственную версию таблицы с уникальным набором данных. Структура таблицы остается одинаковой для всех пользователей, но данные в ней могут быть разными.

**Особенности отображения временной таблицы для разных пользователей:**

1. **Индивидуальные данные**: Каждый пользователь видит свою собственную версию временной таблицы. Это позволяет нескольким пользователям работать с одной и той же таблицей одновременно, не мешая друг другу.

2. **Изоляция данных**: Данные, введенные одним пользователем, не видны другим пользователям. Это обеспечивает конфиденциальность и изоляцию данных.

3. **Временное хранение**: Данные в временной таблице хранятся временно и автоматически удаляются через определенное время (обычно через 1 час).

4. **Динамическое создание**: Временная таблица создается заново при каждом открытии, что позволяет использовать её для динамических отчетов и промежуточных вычислений.

5. **Отсутствие префильтра**: Временные таблицы не имеют префильтра, что означает, что они не могут быть предварительно отфильтрованы перед открытием.

6. **Вызов через linkToDataTable**: Временные таблицы могут быть вызваны с передачей данных через функцию `linkToDataTable`, что позволяет передавать в них данные для заполнения полей.

**Пример вызова временной таблицы с передачей данных:**

```totum
=: linkToDataTable(table: 'tmp_table'; title: "Title for tmp window"; data: $rowList; params: $row; refresh: false)

rowList: rowListCreate(field: "field1" = json`[1,2]`; field: "field2" = json`[3,4]`)

row: rowCreate(field: "h_field1" = 40; field: "h_field_2" = 50)
```

Таким образом, временные таблицы в Totum обеспечивают гибкость и изоляцию данных, что делает их идеальными для использования в ситуациях, требующих временного хранения и обработки данных.

#### <a name="creating-a-temporary-table-and-its-features-ai4"></a> Для каких задач подходят временные таблицы?

Временные таблицы в системе Totum подходят для решения следующих задач:

1. **Отчеты**: Временные таблицы могут использоваться для создания отчетов, которые требуют временного хранения данных. Это позволяет пользователям генерировать и просматривать отчеты с различными параметрами, не влияя на данные других пользователей.

2. **Промежуточные технические таблицы**: Они могут служить для хранения промежуточных данных в процессе выполнения сложных вычислений или операций. Это позволяет изолировать временные данные от основной базы данных.

3. **Индивидуальные расчеты для пользователей**: Поскольку временная таблица существует для каждого пользователя индивидуально, она может использоваться для выполнения персонализированных расчетов или отображения данных, которые не должны быть видны другим пользователям.

4. **Групповые операции**: Например, для добавления группой товаров в заказ, где данные не должны пересекаться между разными пользователями. Каждый пользователь может работать со своим набором данных, не влияя на других.

5. **Быстрый анализ данных**: Временные таблицы могут использоваться для быстрого анализа данных, который не требует постоянного хранения результатов. Это позволяет пользователям временно сохранять результаты анализа и удалять их после завершения работы.

6. **Тестирование и отладка**: Временные таблицы могут быть полезны для тестирования и отладки кода, позволяя быстро создавать и удалять таблицы с тестовыми данными. Это упрощает процесс разработки и тестирования новых функций.

7. **Настроечные таблицы**: Временные таблицы могут использоваться для временного хранения настроек или параметров, которые могут изменяться пользователями в процессе работы.

Эти особенности делают временные таблицы идеальным инструментом для задач, требующих временного хранения данных и изоляции данных между пользователями.

#### <a name="creating-a-temporary-table-and-its-features-ai5"></a> Можно ли открыть временную таблицу из дерева?

Да, временную таблицу можно открыть из дерева. По умолчанию временная таблица доступна из дерева, и она выглядит как обычная таблица с иконкой в виде кружка с часами, что обозначает, что таблица временная. Однако, если временная таблица создается как техническая, то, скорее всего, из дерева ее надо будет скрыть, задав параметр роли «скрыть в дереве».

Для открытия временной таблицы из дерева можно использовать функцию `linkToTable`, но если необходимо открыть временную таблицу и заполнить ее определенными данными, то лучше использовать функцию `linkToDataTable`. Эта функция позволяет передавать данные в таблицу при ее открытии, что особенно полезно для временных таблиц, так как они не имеют префильтра.

Пример использования `linkToDataTable` для открытия временной таблицы с передачей данных:

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row)
    row: rowCreate(field: "client" = #client; field: "order" = #order_num)
```

В этом примере в `params` передается `row`, состоящий из полей, которые нужно заполнить в хедере временной таблицы.

#### <a name="creating-a-temporary-table-and-its-features-ai7"></a> Почему временные таблицы не поддерживают префильтры?

Временные таблицы в системе Totum не поддерживают префильтры, потому что они предназначены для временного хранения данных, которые создаются и удаляются автоматически для каждого пользователя. Префильтры, которые используются для постоянных таблиц, не применимы к временным таблицам, так как их данные не сохраняются на постоянной основе.

**Причины отсутствия префильтров в временных таблицах:**

1. **Индивидуальность данных**: Временные таблицы создаются заново для каждого пользователя при их открытии, и данные в них уникальны для каждого сеанса. Префильтры, которые обычно применяются к постоянным таблицам для ограничения отображаемых данных, не имеют смысла в контексте временных таблиц, так как данные в них не сохраняются и не передаются между сеансами.

2. **Временное хранение**: Данные во временных таблицах существуют ограниченное время (обычно 1 час) и автоматически удаляются после этого периода. Префильтры, которые предназначены для постоянного ограничения данных, не подходят для временных таблиц, где данные временные и изменяются при каждом новом открытии.

3. **Динамическое создание данных**: Временные таблицы часто используются для динамических отчетов и промежуточных вычислений, где данные создаются и изменяются на лету. Префильтры, которые требуют предварительной настройки и сохранения условий, не соответствуют динамической природе временных таблиц.

4. **Упрощение структуры**: Отсутствие префильтров упрощает структуру временных таблиц, делая их более легкими и быстрыми для создания и удаления. Это позволяет системе эффективно управлять ресурсами и обеспечивать высокую производительность при работе с временными данными.

Таким образом, временные таблицы в Totum предназначены для временного и индивидуального использования, что делает префильтры избыточными и ненужными в их контексте.

#### <a name="creating-a-temporary-table-and-its-features-ai8"></a> Какая функция позволяет открыть временную таблицу и передать в нее данные?

Функция, которая позволяет открыть временную таблицу и передать в нее данные, называется `linkToDataTable`. Эта функция используется для открытия временной таблицы и заполнения ее определенными данными. Она имеет два ключевых параметра: `data` и `params`.

- `data` — это данные для заполнения строчной части таблицы. Они передаются в виде `rowList`, где каждая строка будет представлять собой строку во временной таблице.
- `params` — это данные для заполнения хедера и футера таблицы. Они передаются в виде `row`, где указываются `name` полей и их значения.

Пример использования функции `linkToDataTable`:

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "client" = #client; field: "order" = #order_num)
    rowlist: rowListCreate(field: "goods" = $list[[items]]; field: "price" = $list[[total]])
        ~list: selectRowList(table: 'order'; cycle: #order_num; field: 'items'; field: 'total')
```

В этом примере `params` используется для заполнения полей в хедере, а `data` — для заполнения строчной части временной таблицы.

Тот же пример с использованием назначения имен ключей:

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "client" = #client; field: "order" = #order_num)
    rowlist: selectRowList(table: 'order'; cycle: #order_num; field: 'items' as "goods"; field: 'total' as "price")
```

#### <a name="creating-a-temporary-table-and-its-features-ai13"></a> Как скрытое техническое поле помогает при заполнении данных в строчной части временной таблицы?

Скрытое техническое поле в временной таблице в системе Totum играет важную роль при заполнении данных в строчной части. Оно позволяет передавать данные в это поле при открытии временной таблицы, а затем извлекать эти данные и распределять их по видимым пользователю полям строчной части. Это упрощает процесс заполнения таблицы, особенно если нужно заполнить большое количество полей. Рассмотрим, как это работает на примере.

**Пример использования скрытого технического поля**

1. **Создание скрытого технического поля**: В строчной части временной таблицы создается техническое поле типа "данные". Это поле не отображается пользователю и используется для хранения данных, которые будут распределены по другим полям.

2. **Передача данных в скрытое поле**: При открытии временной таблицы с помощью функции `linkToDataTable`, данные передаются в скрытое техническое поле. Это делается через параметр `data`, который принимает `rowList` с данными.

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
	row: rowCreate(field: "client" = #client; field: "order" = #order_num)
		rowlist: rowListCreate(field: "teh" = $list)
			list: selectRowList(table: 'order'; cycle: #order_num; field: 'goods'; field: 'price')
```

3. **Извлечение данных из скрытого поля**: В видимых пользователю полях строчной части временной таблицы используется код, который извлекает данные из скрытого технического поля и отображает их. Например, для поля `goods` это может выглядеть так:

```totum
=: #teh[goods]
```

А для `price` так:

```totum
=: #teh[price]
```

**Преимущества использования скрытого технического поля**

- **Упрощение кода**: Позволяет избежать сложных конструкций для передачи данных в каждое отдельное поле. Все данные передаются в одно техническое поле, а затем извлекаются по мере необходимости.

- **Гибкость**: Легко добавлять новые поля в таблицу, так как данные уже находятся в скрытом поле и могут быть распределены по новым полям без изменения логики передачи данных.

- **Скорость и эффективность**: Уменьшает количество операций по передаче данных, так как все данные передаются одним списком и распределяются уже внутри таблицы.

Таким образом, скрытое техническое поле является мощным инструментом для эффективного заполнения данных в строчной части временной таблицы в системе Totum.

#### <a name="creating-a-temporary-table-and-its-features-ai14"></a> Что произойдет, если временную таблицу откроют два разных пользователя?

Если временную таблицу откроют два разных пользователя, они увидят разные таблицы. Структура у них будет одинаковая, но наполнение данными будет разное. Временная таблица создается для каждого пользователя индивидуально и существует ограниченное время (по умолчанию 1 час). После этого она автоматически удаляется. Это позволяет каждому пользователю работать с уникальным набором данных, не мешая другим пользователям.

#### <a name="creating-a-temporary-table-and-its-features-ai15"></a> Как временная таблица позволяет работать с разными отчетами для разных пользователей?

Временная таблица в системе Totum позволяет работать с разными отчетами для разных пользователей благодаря своей ключевой особенности — она создается заново каждый раз при открытии и существует в течение ограниченного времени (по умолчанию 1 час). Это означает, что каждый пользователь, открывая временную таблицу, получает уникальный экземпляр таблицы, который может содержать свои собственные данные. Таким образом, структура таблицы остается одинаковой для всех пользователей, но данные в ней могут быть различными.

**Как это работает:**

1. **Уникальный экземпляр для каждого пользователя**: Когда пользователь открывает временную таблицу, создается новая версия этой таблицы, которая существует только для этого пользователя. Это позволяет каждому пользователю работать с отдельным набором данных, не мешая другим пользователям.

2. **Динамическое создание данных**: Данные в временной таблице могут быть созданы динамически на основе параметров, переданных при открытии таблицы. Это позволяет пользователю получать отчет с нужными ему данными.

3. **Изоляция данных**: Поскольку каждый пользователь работает с отдельной версией таблицы, изменения, внесенные одним пользователем, не влияют на данные других пользователей. Это особенно полезно для отчетов, где каждый пользователь может задавать свои параметры фильтрации и отображения данных.

4. **Временное хранение**: Временные таблицы существуют ограниченное время, после чего они автоматически удаляются. Это позволяет эффективно управлять ресурсами и не перегружать систему ненужными данными.

**Пример использования:**

Предположим, у нас есть временная таблица для отчетов о продажах. Каждый менеджер может открыть эту таблицу и задать свои параметры фильтрации, например, выбрать определенный период или категорию товаров. В результате каждый менеджер получит отчет, соответствующий его запросу, и сможет работать с ним, не мешая другим менеджерам.

**Пример кода для открытия временной таблицы с передачей данных:**

```totum
=: linkToDataTable(table: 'tmp_sales_report'; title: "Отчет о продажах"; width: 800; height: "80vh"; params: $row)
    row: rowCreate(field: "manager_id" = #manager_id; field: "report_period" = #selected_period)
```

В этом примере временная таблица `tmp_sales_report` открывается с параметрами, которые определяют, какие данные будут отображаться в отчете для конкретного менеджера.

Достаточно часто, в хедер временной таблицы передаются ключевые данные, а дальнейшее содержимое и набор строчной части определяется кодами в полях и автозаполнением строчной части.

#### <a name="creating-a-temporary-table-and-its-features-ai16"></a> Какой параметр в функции linkToDataTable отвечает за показ хедера и футера в открываемой таблице?

В функции `linkToDataTable` параметры, отвечающие за показ хедера и футера в открываемой таблице, это `header` и `footer`. По умолчанию они установлены в `true`, что означает, что хедер и футер будут отображаться. Если вы хотите скрыть хедер или футер, вы можете установить соответствующий параметр в `false`.

Пример использования функции с указанием параметров `header` и `footer`:

```totum
=: linkToDataTable(table: 'tmp_table'; title: "Title for tmp window"; data: $rowList; params: $row; header: true; footer: true)
```

В этом примере хедер и футер будут отображаться, так как параметры `header` и `footer` установлены в `true`. Если вы хотите скрыть хедер или футер, измените значение на `false`.

#### <a name="creating-a-temporary-table-and-its-features-ai17"></a> Как можно установить начальное значение для поля в хедере временной таблицы?

Для установки начального значения для поля в хедере временной таблицы в системе Totum, вы можете использовать функцию `linkToDataTable`. Эта функция позволяет передать данные в хедер временной таблицы при её открытии.

Вот пример кода, который демонстрирует, как это сделать:

```totum
=: linkToDataTable(table: 'tmp_table'; title: "Окно временной таблицы"; params: $row)

row: rowCreate(field: "h_field_name" = "initial_value")
```

В этом примере:

- `table: 'tmp_table'` — указывает на временную таблицу, которую вы хотите открыть.
- `title: "Окно временной таблицы"` — задает заголовок окна временной таблицы.
- `params: $row` — используется для передачи данных в хедер таблицы.
- `rowCreate(field: "h_field_name" = "initial_value")` — создает row с полем `h_field_name`, которому присваивается начальное значение `"initial_value"`.

Таким образом, при открытии временной таблицы, поле `h_field_name` в хедере будет автоматически заполнено значением `"initial_value"`.

#### <a name="creating-a-temporary-table-and-its-features-ai18"></a> Как использовать параметр refresh в функции linkToDataTable?

Параметр `refresh` в функции `linkToDataTable` используется для управления поведением родительской таблицы после закрытия временной таблицы, открытой с помощью этой функции. Он определяет, будет ли обновляться родительская таблица и каким образом это произойдет. Рассмотрим возможные значения параметра `refresh` и их влияние:

1. **`false` (по умолчанию)**:
   - Родительская таблица не будет обновляться после закрытия временной таблицы. Это значение используется, если обновление данных в родительской таблице не требуется.

2. **`true`**:
   - Родительская таблица будет обновлена после закрытия временной таблицы. Это значение используется, если необходимо обновить данные в родительской таблице, чтобы отобразить изменения, сделанные в временной таблице.

3. **`"recalculate"`**:
   - Родительская таблица будет пересчитана после закрытия временной таблицы, даже если в ней не было изменений. Это значение используется, если необходимо выполнить пересчет данных в родительской таблице независимо от изменений.

4. **`"reload"`**:
   - Родительская таблица будет перезагружена, как если бы пользователь нажал кнопку обновления в браузере. Это значение используется, если необходимо полностью перезагрузить данные в родительской таблице.

**Пример использования:**

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Temporary Table"; refresh: true)
```

В этом примере временная таблица `tmp_test` будет открыта, и после ее закрытия родительская таблица будет обновлена, чтобы отобразить изменения, сделанные в временной таблице.

#### <a name="creating-a-temporary-table-and-its-features-ai19"></a> Можно ли открыть временную таблицу без передачи данных в params?

В этом примере временная таблица `tmp_test` будет открыта с заголовком "Окно временного расчета", но без предварительного заполнения полей в хедере и футере.

#### <a name="creating-a-temporary-table-and-its-features-ai21"></a> Почему параметр `data` функции `linkToDataTable` принимает список строк, а не одну строку?

Параметр `data` функции `linkToDataTable` в системе Totum принимает список строк, потому что он предназначен для заполнения строчной части временной таблицы, которая может содержать множество строк данных. Это позволяет гибко и эффективно управлять данными в таблице, заполняя её сразу несколькими строками.

**Причины использования списка строк:**

1. **Множественные записи**: Временные таблицы часто используются для отображения и обработки множества записей одновременно. Например, при создании отчётов или временных таблиц для обработки заказов, может потребоваться сразу заполнить таблицу несколькими строками данных.

2. **Гибкость**: Использование списка строк позволяет передавать данные из различных источников и формировать таблицу с нужной структурой. Это может быть полезно, когда данные собираются из нескольких таблиц или источников.

3. **Эффективность**: Передача списка строк позволяет избежать многократных вызовов функции для добавления каждой строки по отдельности, что может быть менее эффективно.

4. **Удобство**: Список строк можно легко сформировать с помощью функций Totum, таких как `selectRowList`, что упрощает процесс подготовки данных для временной таблицы.

**Пример использования**

Вот пример кода, который демонстрирует, как можно использовать параметр `data` для заполнения временной таблицы несколькими строками:

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "h_client" = #client; field: "h_order" = #order_num)
    rowlist: selectRowList(table: 'order'; cycle: #order_num; field: 'goods'; field: 'price')
```

В этом примере `rowlist` формируется с помощью `selectRowList`, который выбирает данные из таблицы `order` и передаёт их в виде списка строк в временную таблицу `tmp_test`. Это позволяет сразу заполнить таблицу несколькими строками данных, что делает процесс более эффективным и удобным.

#### <a name="creating-a-temporary-table-and-its-features-ai22"></a> Как извлечь данные из технического поля в видимые поля строчной части?

В системе Totum для извлечения данных из скрытого технического поля в видимые поля строчной части временной таблицы используется код, который обращается к этому техническому полю и извлекает нужные данные. Это позволяет передавать данные в одно техническое поле при открытии временной таблицы, а затем распределять их по видимым полям. Рассмотрим, как это сделать на примере.

**Пример использования скрытого технического поля**

1. **Создание скрытого технического поля**: В строчной части временной таблицы создается техническое поле типа "данные". Это поле не отображается пользователю и используется для хранения данных, которые будут распределены по другим полям.

2. **Передача данных в скрытое поле**: При открытии временной таблицы с помощью функции `linkToDataTable`, данные передаются в скрытое техническое поле. Это делается через параметр `data`, который принимает `rowList` с данными.

```totum
=: linkToDataTable(table: 'tmp_test'; title: "Окно временного расчета"; width: 800; height: "80vh"; params: $row; data: $rowlist)
    row: rowCreate(field: "client" = #client; field: "order" = #order_num)
    rowlist: rowListCreate(field: "teh" = $list)
        list: selectRowList(table: 'order'; cycle: #order_num; field: 'goods'; field: 'price')
```

3. **Извлечение данных из скрытого поля**: В видимых пользователю полях строчной части временной таблицы используется код, который извлекает данные из скрытого технического поля и отображает их. Например, для поля `goods` это может выглядеть так:

```totum
=: #teh[goods]
```

А для `price` так:

```totum
=: #teh[price]
```

**Преимущества использования скрытого технического поля**

- **Упрощение кода**: Позволяет избежать сложных конструкций для передачи данных в каждое отдельное поле. Все данные передаются в одно техническое поле, а затем извлекаются по мере необходимости.

- **Гибкость**: Легко добавлять новые поля в таблицу, так как данные уже находятся в скрытом поле и могут быть распределены по новым полям без изменения логики передачи данных.

- **Скорость и эффективность**: Уменьшает количество операций по передаче данных, так как все данные передаются одним списком и распределяются уже внутри таблицы.

Таким образом, скрытое техническое поле является мощным инструментом для эффективного заполнения данных в строчной части временной таблицы в системе Totum.

### <a name="how-do-I-fill-in-the-line-part-by-passing-data-to-the-header-text"></a> Текст урока (по видео)

Как заполнить строчную часть, передав данные в хедер?

Существует еще один очень часто используемый подход к автоматическому заполнению строчной части временной таблицы.
Временная таблица, как и другие таблицы с потабличным расчетом, имеет возможность автозаполнения строчной части. Выглядит это так: у нас есть поле ‘h_insert’ – это просто поле в хедере. ‘h_insert’ - я рекомендую называть его так, потому что это устоявшееся название. Это поле типа «данные». Оно находится в хедере и обычно скрыто для пользователей. Обычно это техническое поле.
Итак, у нас есть поле в хедере, а теперь мы создадим поле под названием ‘insert’ в строчной части. Это очень важно, оно будет работать только в том случае, если называется ‘insert’. И по сортировке в строчной части оно должно быть самым крайним слева, самым первым. Обычно это также поле типа «данные», скрытое от пользователей, потому что это обычно техническое поле. Сохраните и пока у нас здесь ничего не заполнено, потому что эта ‘h_insert’ не заполнено.
Поле ‘h_insert’ должно содержать список значений. ‘Insert’ берет значение этого списка из ‘h_insert’ и автоматически создает строку для каждого элемента этого списка в строчной части. Давайте посмотрим, как это работает.
Здесь я создал дополнительную кнопку с названием AUTOFILL. В ней мы теперь напишем код `linkToDataTable`. И нам нужно передать одно значение в хедер, остальные параметры можно стереть. Мы передаем строку. Строка выглядит как `rowCreate`. Мы помним, что поле называется ‘h_insert’, и мы передадим туда какое-то значение. Например:

```totum
=: linkToDataTable(table: 'tmp_autofill'; title: "autofill"; width: 800; height: "80vh"; params: $row)
row: rowCreate(field: "h_insert" = $val)
val: selectRowList(table: 'calculationorder'; field: 'string_in_row'; field: 'field_1'; field: 'field_2')
```
Нажимаем сохранить. Смотрим нашу временную таблицу. Пока автозаполнение строчной части не работает, потому что в поле ‘insert’ не указан код. Нужно указать, что мы берем значение из ‘#h_insert’. Сохраняем.
И вот мы имеем полученные данные в ‘h_insert’. Здесь у нас список данных для каждой строки, в каждой строке есть значения для поля 'string_in_row’, ‘field_1’ и ‘field_2’.
Мы уже знаем, как формировать поля в этой таблице. Мы добавляем в строчную часть поле, назовем его, допустим, ‘Field’, тип данных – строка. И мы берем значение из ‘insert’ через # insert и квадратные скобки.
```totum
=: #insert[string_in_row]
```
Хорошо, и вот эти значения извлекаются.

Если вы хотите извлекать их один раз при открытии, то задайте код только при добавлении. И так с остальными полями. Обычно для таких автозаполняемых таблиц мы отключаем добавление строк в таблицу и удаление строк из таблицы. 1. **Упрощение отладки**: Если список вычисляется в отдельном поле, его легче отлаживать и тестировать. Вы можете легко проверить результат вычислений в хедере, прежде чем использовать его в строчной части.

2. **Гибкость и переиспользование**: Если список вычисляется в отдельном поле, его можно легко использовать в других частях таблицы или в других таблицах. Это делает код более гибким и позволяет переиспользовать результаты вычислений без дублирования кода.

3. **Структурированность**: Разделение вычислений на отдельные поля помогает структурировать код и логику таблицы, что делает её более организованной и легкой для понимания.

Пример кода, где список вычисляется в хедере и используется в `insert`:

```totum
=: #h_insert
```

В этом примере список вычисляется в поле `h_insert` в хедере, а затем используется в поле `insert` в строчной части. Это позволяет поддерживать код в чистоте и упрощает его поддержку.

5. **rowCreate**: Эта функция создает строку, в которой указывается поле `h_insert` и список значений, которые вы хотите передать.

6. **val**: В этой строке создается список значений с помощью функции `listCreate`. В данном примере список содержит три значения: "Value1", "Value2" и "Value3".

1. **Создание временной таблицы при каждом вызове**: Временные таблицы создаются при каждом вызове строки кода, что может быть ресурсоемким процессом. 2. **Нагрузка на базу данных**: Временные таблицы записываются в базу данных после расчета и удаляются через час. Это создает дополнительную нагрузку на базу данных, особенно если временные таблицы создаются часто и в большом количестве.

3. **Ресурсоемкость**: Процесс вычисления значений во временной таблице может требовать значительных вычислительных ресурсов. Если таких операций много, это может привести к увеличению времени отклика системы и снижению ее производительности.

4. **Фиксация вызовов**: Внутри кода такие вызовы обязательно надо фиксировать с помощью `~`, чтобы избежать повторного создания временной таблицы при каждом вызове этой строки в коде. Однако, даже с фиксацией, частое использование временных таблиц в строчной части может быть неэффективным.

5. **Альтернативные решения**: В большинстве случаев можно найти более эффективные способы выполнения необходимых вычислений без использования временных таблиц в строчной части. Например, можно использовать другие функции Totum, которые не требуют создания временных таблиц.

Таким образом, временные таблицы следует использовать с осторожностью и только в тех случаях, когда это действительно необходимо для выполнения сложных вычислений, которые невозможно реализовать другими способами.

При нажатии на кнопку вполнения действия (ее название может быть задано параметром `button: "Текст на кнопке"`) вполняется код переданный в `code`.

При выполнении этого кода, введенное в поле ввода значение будет доступно в переменной `$#input`.

#### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-q2"></a> Какими способами в нее можно передать код для последующего выполнения?

`code` может быть указан несколькими способами:

+ текстом — `code: "=: set(table: $#ntn; field: 'field' = $#input)"`

+ `name` поля в этой же таблице из которого будет взят код-дейcтвия — `code: "field_with_code"`.

```totum

stradd: str`'=: linkToTable(table: "sostav_zakaza"; cycle: $number; target: "top")' + $#nl + 'number: select(table: "novye_zakazy"; field: "id"; where: "nomer" = $#input)'`

// Обратите внимание, что мы многостраничный код склеиваем через $#nl
```

```totum

Разберем всплывающее окно для ввода текста, чисел, дат и так далее. Оно называется input.
Для этого используется специальная функция ` linkToInput `. Для примера использования создадим кнопку и откроем настройки этой кнопки. Параметр `value` потребуется, потому что это значение, которое будет заполнено в поле ввода. Например, мы можем написать здесь «sample». И затем в параметре `button` указываем название кнопки, которая будет нажиматься для запуска этого кода. Назовем ее «save». Параметр `Close: false` мы для этого примера тоже не используем. Ключевым параметром является параметр `code`. В этом параметре код должен быть передан в виде строки. Так что это выглядит следующим образом. Это код, который будет выполнен после того, как мы нажмем на кнопку Сохранить. Во всплывающем окне будет две кнопки. Одна из них будет иметь название, как мы передали в параметре `button`. Если мы нажмем на cancel, то ничего не произойдет, просто закроется всплывающее окно; если мы нажмем на save, то выполнится этот код, и ключевая идея, заключается в том, что код должен быть передан сюда в виде строки. ### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-ai"></a> Дополнительные вопросы

#### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-ai1"></a> Как называется функция для открытия окна ввода?

Функция для открытия окна ввода называется `linkToInput`. Она открывает небольшое окно с полем ввода и двумя кнопками — "выполнить действие" и "закрыть".

#### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-ai2"></a> Какие параметры в функции linkToInput являются обязательными?

В функции `linkToInput` обязательными параметрами являются: `code` и `title`.

- `title` — строка, заголовок окна, который будет отображаться в верхней части всплывающего окна ввода.

- `code` — строка, код, который будет выполнен после ввода данных. Этот код может быть передан в виде строки или как ссылка на поле в текущей таблице, из которого будет взят код-действия. Важно, чтобы `code` был передан именно строкой, так как вариант, когда вы ссылаетесь на последующий код, не работает.

Пример использования функции `linkToInput`:

```totum
=: linkToInput(title: "Введите данные"; html: "Пожалуйста, введите значение"; code: $code; button: "Сохранить")

```code:totum
=: set(table: $#ntn; field: 'field_name' = $#input)
```
```

В этом примере `title` задает заголовок окна, а `code` содержит код, который будет выполнен после нажатия кнопки "Сохранить".

#### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-ai9"></a> Почему код должен передаваться в виде строки в параметр code?

Код должен передаваться в виде строки в параметр `code` в функции `linkToInput` по нескольким причинам:

1. **Динамическое выполнение**: Код, переданный в виде строки, может быть выполнен динамически при нажатии на кнопку в окне ввода. Это позволяет изменять и адаптировать логику выполнения в зависимости от контекста или пользовательского ввода.

2. **Гибкость**: Передача кода в виде строки позволяет использовать различные способы формирования и передачи кода, включая использование переменных, строковых операций и других механизмов, которые могут быть полезны для создания более сложной логики.

3. **Изоляция контекста**: Код, переданный в виде строки, изолирован от основного кода, что позволяет избежать конфликтов с переменными и логикой, определенной в других частях программы.

4. **Универсальность**: Такой подход позволяет использовать один и тот же механизм для передачи кода в различных контекстах и сценариях, что упрощает разработку и поддержку кода.

5. **Поддержка различных источников**: Код может быть передан не только напрямую в параметре `code`, но и взят из других полей или таблиц, что позволяет организовать централизованное хранение и управление кодом.

Пример использования передачи кода в виде строки:

```totum
=: linkToInput(title: "Введите данные"; html: "Пожалуйста, введите значение"; code: $execute_code; button: "Сохранить")

```execute_code:totum
=: set(table: $#ntn; field: 'field_name' = $#input)
```
```

В этом примере код, переданный в параметр `code`, будет выполнен при нажатии на кнопку "Сохранить" в окне ввода. Код внутри блока ```code:totum``` будет передан как строка и выполнен динамически.

В параметр `code` функции `linkToInput` код может быть передан несколькими способами. Рассмотрим каждый из них:

1. **Передача строки кода текстом**:

```totum

```

2. **Передача по имени поля в текущей таблице**:
   Код может быть взят из поля в текущей таблице, где он будет взят из аналогичного блока кода. Если код ниже выполняется из кнопки, то будет взят из кода действия поля `field_with_code`:

```totum
=: linkToInput(html: "Введите номер заказа"; title: "Открыть заказ по номеру"; code: "field_with_code"; button: "Открыть")
```

3. **Использование вложенного totum-code**:
   Это более удобный способ для передачи больших объемов кода. Код пишется в специальном блоке, который передается как строка.

```totum
=: linkToInput(html: "Введите номер заказа"; title: "Открыть заказ по номеру"; code: $code; button: "Открыть")

 ```

4. **Передача через обращение к таблице с помощью @**:

Эти способы позволяют гибко управлять передачей кода в параметр `code`, обеспечивая удобство и универсальность в различных сценариях использования.

#### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-ai11"></a> Можно ли использовать Totum-code внутри параметра code?

#### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-ai12"></a> Почему в параметр `code` нельзя передать код действия, написав его отдельной строкой кода и сославшись на него через $?

В параметр `code` функции `linkToInput` нельзя передать код действия, написав его отдельной строкой кода и сославшись на него через `$`, потому что это вызовет выполнение этой строки кода в процессе обработки параметров функции `linkToInput`. Таким образом, код будет выполнен до открытия окна ввода, что не соответствует ожидаемому поведению.

В Totum, когда вы ссылаетесь на строку кода через `$`, это означает, что код в этой строке будет выполнен немедленно, и результат выполнения будет подставлен в место вызова. Однако, в случае с `linkToInput`, нам нужно, чтобы код выполнялся только после того, как пользователь введет данные и нажмет кнопку выполнения действия в окне ввода.

Поэтому, чтобы код выполнялся в нужный момент, его необходимо передать в виде строки текста, который будет интерпретирован и выполнен позже, после взаимодействия пользователя с окном ввода. Это можно сделать несколькими способами:

1. **Передача строки кода текстом**: Код передается непосредственно в виде строки в двойных кавычках.

2. **Использование вложенного totum-code**: Код пишется в специальном блоке, который передается как строка.

3. **Передача через обращение к таблице с помощью @**: Код может быть взят из другого поля, используя обращение через `@`.

Эти методы позволяют передать код в параметр `code` так, чтобы он выполнялся в нужный момент, а не сразу при обработке параметров функции.

#### <a name="how-do-I-open-the-text-input-window-and-how-can-I-modify-it-ai13"></a> Какие переменные окружения доступны в linkToInput?

В функции `linkToInput` по умолчанию доступны некоторые переменные окружения, которые можно использовать в коде, переданном в параметре `code`. Вот основные из них:

2. **`$#nh`** — хэш текущей таблицы. Это может быть полезно для продвинутых кодов действий, где требуется идентификация таблицы.

3. **`#`** — все решетки текущей таблицы. Это позволяет использовать значения полей текущей таблицы в коде, переданном в `linkToInput`.

В этом примере переменная `var_name` будет доступна в коде, выполняемом при нажатии на кнопку "Сохранить". Вы можете передать несколько таких переменных, добавляя их через параметр `var`.

Каждый `row` в параметре `buttons` должен содержать обязательные и может содержать необязательные параметры. Давайте рассмотрим их подробнее:

7. **refresh** — логическое значение, указывающее, нужно ли обновлять таблицу после выполнения кода кнопки. Значение `true` обновит таблицу, а `false` оставит её без изменений. Также можно использовать "recalculate" для пересчета таблицы или "reload" для полной перезагрузки.

#### <a name="calling-a-panel-with-buttons-ai8"></a> Что делает параметр refresh для кнопки в linkToButtons?

Параметр `refresh` в функции `linkToButtons` определяет, нужно ли обновлять таблицу после выполнения кода, связанного с кнопкой. Он может принимать несколько значений, которые определяют поведение обновления:

1. **`true`** — таблица будет обновлена после выполнения кода кнопки. Это стандартное поведение, если требуется обновить данные в таблице после выполнения действия.

2. **`false`** — таблица не будет обновлена после выполнения кода кнопки. Это полезно, если обновление таблицы не требуется и вы хотите сохранить текущее состояние.

3. **`"recalculate"`** — таблица будет пересчитана после выполнения кода кнопки, даже если в ней не было изменений. Это может быть полезно, если необходимо обновить вычисления или формулы в таблице.

4. **`"reload"`** — таблица будет полностью перезагружена, как если бы пользователь нажал кнопку обновления в браузере. Это может быть полезно, если требуется полная перезагрузка данных и интерфейса таблицы.

5. **`"close"`** — позволяет закрыть таблицу источник, если она открыта в iframe, после выполнения кода кнопки. Это используется, когда необходимо закрыть окно после выполнения действия.

Пример использования параметра `refresh` в функции `linkToButtons`:

```totum
=: linkToButtons(title: "Выбор действия"; buttons: json`[$btn1,$btn2]`)

btn1: rowCreate(field: "text" = "Кнопка 1"; field: "code" = '=: linkToDataText(title: "Результат"; text: "Вы нажали Кнопку 1")'; field: "refresh" = true)

btn2: rowCreate(field: "text" = "Кнопка 2"; field: "code" = '=: linkToDataText(title: "Результат"; text: "Вы нажали Кнопку 2")'; field: "refresh" = "reload")
```

В этом примере первая кнопка обновляет таблицу после выполнения кода, а вторая кнопка полностью перезагружает таблицу.

#### <a name="calling-a-panel-with-buttons-ai10"></a> Для чего используется параметр close в linkToButtons?

Параметр `close` в функции `linkToButtons` используется для закрытия таблицы-источника, если она открыта в iframe, после выполнения кода кнопки. Это необходимо в случаях, когда требуется закрыть окно после выполнения действия, но стандартное закрытие окна после выполнения в настройках кнопки, вызывающей `linkToButtons` или `linkToInput`, приводит к их неработоспособности.

Пример использования параметра `close` в функции `linkToButtons`:

```totum
=: linkToButtons(title: "Выбор действия"; buttons: json`[$btn1,$btn2]`; close: true)

btn1: rowCreate(field: "text" = "Кнопка 1"; field: "code" = '=: linkToDataText(title: "Результат"; text: "Вы нажали Кнопку 1")')

btn2: rowCreate(field: "text" = "Кнопка 2"; field: "code" = '=: linkToDataText(title: "Результат"; text: "Вы нажали Кнопку 2")')
```

В этом примере, после выполнения кода любой из кнопок, таблица-источник будет закрыта, если она открыта в iframe. Это позволяет управлять поведением интерфейса и закрывать ненужные окна после выполнения действий.

#### <a name="calling-a-panel-with-buttons-ai11"></a> Какие параметры окружения доступны для кодов в linkToButtons?

В системе Totum, когда вы используете функцию `linkToButtons`, коды, которые выполняются при нажатии на кнопки, получают доступ к некоторым параметрам окружения. Эти параметры позволяют коду взаимодействовать с текущей таблицей и её данными. Вот основные параметры окружения, доступные для кодов в `linkToButtons`:

1. **`$#ntn`** — наименование текущей таблицы, из которой был вызван `linkToButtons`. Это позволяет коду знать, с какой таблицей он работает.

2. **`$#nh`** — хэш текущей таблицы. Этот параметр может быть полезен для идентификации таблицы в более сложных сценариях, особенно когда используется временная таблица.

3. **`#`** — все поля текущей таблицы. Это позволяет коду обращаться к данным в полях таблицы, из которой был вызван `linkToButtons`.

Кроме этих параметров, вы также можете передавать дополнительные переменные в код через параметр `vars` в каждой кнопке. Это позволяет передавать специфичные данные, которые могут быть использованы в коде действия.

Пример использования параметра `vars`:

```totum
=: linkToButtons(title: "Выбор действия"; buttons: json`[$btn1,$btn2]`)

btn1: rowCreate(field: "text" = "Кнопка 1"; field: "code" = '=: linkToDataText(title: "Результат"; text: str`$#var1 ++ "в таблице" ++ $#ntn`)'; field: "vars" = $vars)

btn2: rowCreate(field: "text" = "Кнопка 2"; field: "code" = '=: linkToDataText(title: "Результат"; text: str`$#var2 ++ "в таблице" ++ $#ntn`)'; field: "vars" = $vars)

~vars: rowCreate(field: "var1" = "Вы выбрали действие 1"; field: "var2" = "Вы выбрали действие 2")
```

В этом примере переменные `var1` и `var2` передаются в код действия через параметр `vars`, что позволяет использовать их в коде, выполняемом при нажатии на кнопки.
