# Данные цикла в таблице циклов

## <a name="pt-cycdata-footer"></a> Собрать данные цикла в одно поле

### <a name="pt-cycdata-footer-task"></a> Задача

Таблице циклов нужны данные строчной части таблицы внутри цикла: список позиций заказа, связанные товары, суммы. Брать их из каждой строки таблицы циклов отдельными выборками по строкам цикла неудобно и дорого, а по самой таблице циклов (по всем циклам сразу) с данными внутри циклов не пофильтровать.

### <a name="pt-cycdata-footer-solution"></a> Решение

+ В таблице внутри цикла данные строк собираются в **одно поле футера** (или хедера) — одним `selectRowList` по своей таблице:

	```totum
	=: selectRowList(table: $#ntn; field: 'product'; field: 'type'; order: 'n' asc)
	```

+ Таблица циклов берет это поле целиком: полем [Ярлык][129] на поле таблицы цикла или кодом с `select` из таблицы цикла. В коде строки таблицы циклов `select` из ее расчетной таблицы без параметра `cycle` берет данные цикла этой строки.

Теперь у строки таблицы циклов есть готовое значение: его видно в списке циклов, по нему можно фильтровать и искать по всем циклам, его берут другие таблицы.

### <a name="pt-cycdata-footer-b2m"></a> Пример из B2M

+ `b2m___additional_items` (связанные товары внутри цикла товара: коллекции, «еще варианты», «с этим товаром») собирает свои строки в футер `f_additional_items`:

	```totum
	=: selectRowList(table: $#ntn; field: 'product'; field: 'type'; order: 'n' asc)
	```

	В `b2m___items` поле `additional_items` — ярлык на `b2m___additional_items.f_additional_items`, а `ad_items_type` — ярлык на `b2m___additional_items.h_interesting_items`.

+ `product_name` в `b2m___items` — название из карточки товара в цикле:

	```totum
	=: select(table: 'b2m___item'; field: 'h_product_name')
	```

## <a name="pt-cycdata-cascade"></a> Ловушка каскада: строка таблицы циклов пересчитывается последней

Изменение внутри цикла запускает цепочку: пересчет таблицы цикла, ее коды действия, [автоматический пересчет][379] связанных таблиц цикла. Строка таблицы циклов, которая собирает данные цикла (ярлыками, `select`), пересчитывается **в конце** этой цепочки.

Поэтому код действия внутри цикла, который на этом шаге берет из строки таблицы циклов агрегат того самого значения, что только что изменилось и запустило каскад, получит **старое** значение — агрегат еще не пересчитан.

```
Таблица в цикле: изменилось поле → код действия → берет @cycles_table.aggregate   ← еще старое значение
                                                    …
Таблица циклов: строка цикла пересчитана, aggregate обновился                    ← только здесь
```

Как правильно:

+ **Запускайте целевое действие по триггеру в таблице циклов** — кодом действия на изменение агрегатного поля строки таблицы циклов. Он выполнится, когда агрегат уже новый. В B2M так устроены реакции на хранимые поля товара: например, изменение `catalog_prices` в `b2m___items` вызывает `exec(code: "features_search")` уже в таблице циклов.

+ **Или берите данные напрямую из источника** — из поля таблицы цикла (`select` из таблицы цикла), а не из агрегата в строке таблицы циклов.

Отдельная особенность — код действия «при добавлении» в таблице циклов выполняется **до** создания таблиц цикла: действие внутри создаваемого цикла из него не сработает ([особенность кода действия в таблице циклов][728]).
