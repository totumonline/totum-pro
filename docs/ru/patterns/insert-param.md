# Автозаполнение через h_insert

## <a name="pt-insert-task"></a> Задача

[Автозаполнение таблиц][87]: в таблицах с табличной единицей пересчета ([временных][34], [расчетных в цикле][1]) поле строчной части с `name` `insert` (первое по сортировке) получает список, и таблица сама держит по строке на каждое его значение.

Если список посчитать прямо в коде поля `insert`, его не видно: непонятно, почему строк столько, какие значения должны были появиться, а какие нет. Его нельзя передать при открытии окна, нельзя временно «заморозить» и вернуть к расчету.

## <a name="pt-insert-solution"></a> Решение

+ Список считается в поле хедера `h_insert` (тип [Данные][38], [видно ролям][178] — создателю):

	```totum
	=: selectList(table: 'b2m___price_levels'; field: 'id'; where: 'id' != 1; order: 'n' asc)
	```

+ Поле `insert` только берет его:

	```totum
	=: #h_insert
	```

Что это дает:

+ **Список виден** в хедере — по нему сразу понятно, откуда взялись строки.

+ **Список можно задать извне.** Окно, открытое через [linkToDataTable][308], передает `h_insert` в `params` — поле получает ручное значение вместо расчетного, и таблица строится по переданному списку.

+ **Список можно вернуть к расчету** — кнопка [clear][298] по `h_insert` снимает ручное значение, поле снова считается кодом.

+ **Ручной список можно сравнить с расчетным.** Для поля с ручным значением `#c.h_insert` возвращает [расчетное значение][718], `#h.h_insert` — признак, что значение ручное.

+ **Значения списка могут быть строками `row`.** Тогда остальные колонки берут данные из `#insert[ключ]` без отдельного `select` на каждую строку.

## <a name="pt-insert-b2m"></a> Пример из B2M

**Цены SKU по уровням** — временная таблица `b2m___set_price_levels`, строка — уровень цены. Окно открывается из ячейки `level_prices` таблицы `b2m___sku` и передает текущие уровни SKU в `h_insert`, а их цены — в `h_data`:

```totum
params: rowCreate(field: "h_sku" = #id; field: "h_base_sku_price" = #base_price; field: "h_insert" = $transfom; field: "h_data" = $#nfv; field: "h_product" = #product; …)
```

+ `h_insert` (Данные) — код: все уровни цен системы; при открытии из SKU — ручное значение с уровнями этого SKU.

+ `insert` (селект на уровни) — `=: #h_insert`.

+ `h_all_levels` — `=: #c.h_insert`, все уровни системы, даже когда `h_insert` задан вручную.

+ Форматирование таблицы сравнивает их — показывает комментарий и кнопку «Обновить уровни», если у SKU набор уровней не такой, как в системе:

	```totum
	f0=: setTableFormat(condition: $minus = $#lc; fieldshide: json`["h_update_levels"]`)

	f1=: setTableFormat(condition: $minus != $#lc; tablecomment: "@ набор уровней для этого SKU отличается от общего для системы")

		~minus: listMinus(list: #h_all_levels; list: #h_insert)
	```

+ Кнопка `h_update_levels` возвращает список к расчету:

	```totum
	a1=: clear(table: $#ntn; field: 'h_insert')
	```

+ `h_data` при добавлении (открытии окна) раскладывает переданные цены по строкам — после того как автозаполнение их создало:

	```totum
	a2=: setListExtended(table: $#ntn; field: 'delta' = $#nfv[[delta]]; field: 'fixed' = $#nfv[[fixed]]; field: 'final_sku_price' = $#nfv[[final_sku_price]]; where: 'insert' = $#nfv[[level_id]])
	```

+ Пользователь удалил строку уровня — код действия таблицы фиксирует в `h_insert` оставшийся список, иначе автозаполнение вернуло бы удаленную строку:

	```totum
	=: if(condition: $#changes[deleted] != $#lc; then: $fix_insert)

		fix_insert: set(table: $#ntn; field: 'h_insert' = $list)

			list: selectList(table: $#ntn; field: 'insert'; order: 'id' asc)
	```

Так же устроена `b2m___option_levels` (уровни цен опций).

**Строки из `rowList`** — расчетная таблица цикла `b2m___shipping_method` (настройки метода доставки по регионам):

| Поле | Тип | Код |
|---|---|---|
| `h_insert` (хедер) | Данные | `=: selectRowList(table: 'b2m___regions'; field: 'region_number'; field: 'region_address'; order: 'region_number' asc)` |
| `insert` | Данные | `=: #h_insert` |
| `region_number` | Число | `=: #insert[region_number]` |
| `region_address` | Строка | `=: #insert[region_address]` |

Один запрос на всю таблицу: колонки строк берут данные региона из значения `insert`.

Поле `insert` с кодом `=: #h_insert` есть и в `b2m___item`, `b2m___add_product`, `b2m___add_to_warehouse`, `b2m___stock_movements`, `b2m___front_settings_upload`.

## <a name="pt-insert-traps"></a> Ловушки

+ Значения списка должны быть уникальными и непустыми — это требование [автозаполнения][87].

+ Изменившееся значение списка — это удаление строки со старым значением и добавление новой: ручные изменения в строке пропадут (если они были, старая строка останется зачеркнутой).

+ Пока `h_insert` задан вручную, он не следит за источником: новые значения источника в таблицу не попадут, пока список не вернут к расчету (`clear`). Покажите пользователю, что список отличается от расчетного (`#c.h_insert`), и дайте кнопку сброса.

+ Удаление строки автозаполняемой таблицы без фиксации списка не работает: строка вернется при следующем пересчете — фиксируйте `h_insert` в коде действия таблицы.

+ Ручное значение `h_insert` хранится в таблице: у временной таблицы — пока живет ее окно, у расчетной в цикле — постоянно.
