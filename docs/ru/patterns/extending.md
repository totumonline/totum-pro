# Расширение системы: execSSH, пользовательские функции, ext-функции

Когда стандартных функций Totum не хватает или один и тот же блок кода повторяется по всей системе, есть три уровня расширения — от простого к самому мощному.

## <a name="pt-ext-spec"></a> Повторяющиеся блоки — пользовательская функция

Если один и тот же блок кода нужен во многих полях и таблицах системы, вынесите его в [пользовательскую функцию][657] (`spec…`, таблица `ttm__custom_functions`): логика в одном месте, исправление сразу работает везде.

В B2M так сделаны:

+ `specb2mTreePath` — путь ветки каталога по данным дерева (используется в `tree_path` и в коде действия поля `tree` каталога);

+ `specb2mTemplateProcessing` — разбор шаблонов интерфейса витрины на именованные блоки (используется всеми кодами генерации HTML).

> В коде пользовательской функции все ее параметры существуют всегда (не переданный — `null`), поэтому `var(default:)` для них не работает — проверяйте на пустоту ([значения по умолчанию][657]).

## <a name="pt-ext-execssh"></a> Глобальные вычисления — execSSH

[execSSH][464] (PRO) запускает команду на сервере и возвращает ее вывод. Так в систему подключают внешние утилиты и скрипты: обработку изображений, генерацию файлов, тяжелые расчеты на Python, работу с файлами витрины.

+ Большие объемы данных передавайте через [stdin][739], а не в командной строке: без ограничения длины, без экранирования, данные не видны в списке процессов. Списки и `row` сначала превращайте в текст (`jsonCreate`).

+ Значения в командную строку — только через параметр `vars` (он экранирует) или из доверенных настроек; данные пользователей в строку `ssh` не склеивайте.

+ Домашняя папка `execSSH` — папка, которую отдает nginx (`http`).

В B2M картинки товаров сжимаются ImageMagick: файл передается на `stdin`, результат возвращается в base64 и записывается в поле файла:

```totum
filestring: execSSH(ssh: str`"magick" ++ $input_file ++ "-resize 1500x1500^ -gravity center -extent 1500x1500 -quality" ++ $quality ++ $type + ":- | base64 -w 0"`; stdin: $getcontent)

	input_file: str`$#nfv[0][ext] + ":-"`
	getcontent: fileGetContent(file: $#nfv[0][file])
	quality: @b2m___global_settings.h_image_compression_quality
	type: @b2m___global_settings.h_image_compression_type
```

Шаблоны витрины читаются `execSSH` из файлов интерфейса, сгенерированный HTML меню и фильтров записывается в файлы (`cat > …` со `stdin`).

## <a name="pt-ext-php"></a> Чего нет в Totum — ext-функции на PHP

Если задача требует PHP — работа с внешними библиотеками, файловой системой сервера, особые форматы, — допишите [функцию на PHP][505] (`ext…`, файл `CalculateExtensions.php`). Она вызывается из кодов как встроенная.

В B2M ext-функции закрывают то, чего нет в стандартном наборе:

+ `extSanitize` — очистка JSON и HTML от опасного содержимого перед выдачей на витрину и в поиск;

+ `extTidy` — проверка и форматирование HTML описаний (кнопка «Проверить форматирование HTML»);

+ `extSitemap` — запись страниц в карту сайта;

+ `extRedirects` — редиректы со старых URL на новые.

## <a name="pt-ext-traps"></a> Ловушки

+ `execSSH` и ext-функции, которые пишут файлы или ходят во внешние системы, работают вне транзакции: откат действия не отменит записанный файл или выполненную команду. Отладка MCP блокирует `execSSH` как внешнее действие — для проверки используйте моки.

+ Команды `execSSH` выполняются синхронно: тяжелую команду в действии пользователя он будет ждать. Тяжелое — в фон ([Тяжелые расчеты в фоне][714]) или `exec` с `ssh: true`.

+ ext-функции живут в файле сервера, а не в схеме: при переносе схемы на другой сервер `CalculateExtensions.php` переносите отдельно.
