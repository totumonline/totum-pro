# Хранимые расчеты в таблице циклов

## <a name="pt-stored-task"></a> Задача

Строка [таблицы циклов][89] (или [простой таблицы][88]) — главный объект системы: товар, клиент, проект. Для витрины, поиска и отчетов ей нужны сводные данные из других таблиц: все характеристики товара, его цены по SKU, картинки, отзывы. Если такие поля посчитать обычным [кодом][27] с `select`, они будут пересчитываться **при каждом пересчете строки** — при любом изменении любого ее поля, при пересчете таблицы, при изменении кода поля. Каждый пересчет — снова все запросы к таблицам-источникам, и чем больше строк и полей, тем тяжелее.

Второй вопрос — объем: сводное поле [Данные][38] с JSON на десятки килобайт в каждой строке делает тяжелым открытие таблицы — эти данные читаются из базы и уходят в браузер для каждой строки страницы.

## <a name="pt-stored-solution"></a> Решение

+ Сводное поле считается кодом с настройкой [Исполнять код только при добавлении][186] (`codeOnlyInAdd`): значение рассчитывается при добавлении строки и дальше **хранится** — пересчет строки его не трогает.

+ Хранимое поле обновляется только тогда, когда изменились его источники: код действия таблицы-источника вызывает [reCalculate][289] с параметром `field` — он заново выполняет код «только при добавлении» указанных полей — и только для затронутых строк. Как собрать список этих строк — [Код действия таблицы: пересчет затронутых строк][712].

	```totum
	a1=: reCalculate(table: 'b2m___items'; field: 'features_data'; field: 'features_search'; field: 'features_list'; field: 'show_in_catalog'; where: 'id' = $uniq)
	```

+ Большим полям [Данные][38] (и [Текст][130]) включают [notLoaded][534]: при открытии таблицы вместо значения передается `**NOT LOADED**`. В простых таблицах и таблицах циклов значение поля в этом случае даже не читается из базы — запрос к таблице подставляет заглушку вместо колонки. Кодам значение доступно как обычно.

+ Технические сводные поля [видно ролям][178] только создателю, а [групповое изменение][163] выключено: массовое редактирование JSON-полей из интерфейса — тяжелая и почти всегда ошибочная операция.

## <a name="pt-stored-b2m"></a> Пример из B2M

Таблица циклов `b2m___items` (одна строка — один товар) хранит готовые данные для витрины. Все поля ниже — `codeOnlyInAdd`, обновляются кодом действия таблиц-источников:

| Поля `b2m___items` | Источник | Кто пересчитывает |
|---|---|---|
| `features_data`, `features_search`, `features_list`, `show_in_catalog` | `b2m___product_features` | код действия таблицы `b2m___product_features` |
| `catalog_prices`, `price_from`, `search_price`, `discount`, `max_price`, `min_price` | `b2m___sku` | код действия таблицы `b2m___sku` |
| `product_images`, `all_images` | `b2m___product_images` | код действия таблицы `b2m___product_images` |
| `files_data` | `b2m___product_documents` | код действия таблицы `b2m___product_documents` |
| `full_options` | `b2m___product_options` | код действия таблицы `b2m___product_options` |
| `reviews`, `questions`, `score`, `reviews_count` | `b2m___reviews` | код действия таблицы `b2m___reviews` |

Поле `features_data` — `codeOnlyInAdd`, `notLoaded`, видно только создателю, групповое изменение выключено. Его код один раз выбирает характеристики товара и собирает из них JSON для витрины (сокращенно; приемы внутри `listReplace` разобраны в [Нагрузка в listReplace][717]):

```totum
=: rowKeysRemove(row: $without_doubles; key: "double"; recursive: true)

without_doubles: listFilter(list: $double; key: "double" = false)

double: listReplace(list: $select_list; action: "double" = $double_check; action: "value" = $value; action: "shown_value" = $shown_value; key: "key"; value: "raw_data")

		~select_list: selectRowList(table: 'b2m___product_features'; field: 'feature' as "feature"; sfield: "feature" as "feature_title"; field: 'feature_value' as "value"; field: 'unit'; field: 'type'; field: 'show_in_catalog'; field: 'description'; where: 'product' = #id; where: 'sku' = $#lc; order: 'n' asc)
	double_check: …
	value: …
	shown_value: …
```

Хранимые поля строятся друг на друге: `features_search` — тоже `codeOnlyInAdd`, считается из уже готового `features_data` без запросов:

```totum
=: rowCreateByLists(keys: #features_data[[feature]]; values: #features_data[[value]])
```

Поэтому в `reCalculate` они перечислены вместе и в порядке зависимости — `features_data`, затем `features_search`, `features_list`, `show_in_catalog`.

Хранимое поле может запускать следующий шаг цепочки: у `features_search` есть [код действия][28] на изменение — когда пересчет изменил характеристики товара, он помечает категории каталога для фоновой перегенерации фильтров ([Тяжелые расчеты в фоне][714]).

## <a name="pt-stored-traps"></a> Ловушки

+ В `reCalculate` перечисляйте **все** хранимые поля, которые зависят от изменившегося источника, включая производные (`features_search` от `features_data`): поле, не указанное в `field`, останется со старым значением.

+ У поля «только при добавлении» нет разделения на расчетное и ручное значение: ручное изменение просто перезапишет значение и продержится до следующего `reCalculate` с этим полем.

+ Источник забыл вызвать пересчет — данные молча устарели. Каждой таблице-источнику — свой код действия таблицы; при удалении строк источника пересчет нужен тоже (см. ловушки в [Пересчет затронутых строк][712]).

+ `notLoaded` — только для [Текст][130] и [Данные][38]. Поле с `notLoaded` в таблице видно как заглушка: не делайте `notLoaded` поля, которые пользователь должен видеть в строке.
