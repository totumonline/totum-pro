# Тяжелые расчеты в фоне

## <a name="pt-bg-task"></a> Задача

Некоторые расчеты слишком тяжелы, чтобы выполнять их в действии пользователя: они перебирают много строк других таблиц, а запускают их много мелких изменений. В B2M так считаются данные фильтров категории каталога: для каждой характеристики категории собираются ее значения по всем активным товарам категории и подкатегорий и проверяется, что каждое значение действительно встречается. Повлиять на фильтры может изменение характеристики товара, его цены, бренда, маркера, категории.

Если считать фильтры прямо в действии, пользователь ждет после каждого изменения, а массовая правка (100 товаров) пересчитает одну и ту же категорию 100 раз.

## <a name="pt-bg-solution"></a> Решение: флаг-очередь и демон

1. **Флаг.** В таблице, где хранится тяжелый результат, — [чекбокс][126] «нужно пересчитать» (`update_filters_data`). Это и есть очередь: строки с `true` ждут пересчета.

2. **Изменения только ставят флаг.** Коды, которые влияют на результат, не считают его, а делают дешевый `setList` флага. Сколько бы изменений ни пришло, у строки один флаг — она пересчитается один раз:

	```totum
	set_update_list: setList(table: 'b2m___catalog'; field: 'update_filters_data' = true; where: 'id' = $add_ol_categories)
	```

3. **Демон разбирает очередь по одной строке.** В [Daemons][649] (`ttm__daemons`) код активации проверяет, есть ли работа, а код демона берет одну строку, снимает с нее флаг и на этом заканчивается. Через `pause` секунд демон снова проверяет код активации и берет следующую строку.

4. **Тяжелый расчет — на снятие флага.** [Код действия][28] поля-флага на изменение в `false` выполняет сам расчет — в B2M это [хранимые поля][711] с `codeOnlyInAdd`, которые пересчитываются через `reCalculate` с `field`.

5. **Запись демона не мешает пользователям** — параметр [exclude][682] в его `set` (см. ниже).

Тот же код действия срабатывает, если флаг снимет пользователь, — так получается кнопка «пересчитать сейчас», не дожидаясь демона.

## <a name="pt-bg-b2m"></a> Пример из B2M

**Постановка в очередь.** Флаг ставят:

+ код действия `features_search` в `b2m___items` — когда пересчет изменил характеристики товара (все категории товара, включая прежние);

+ коды действия полей `brand`, `markers`, `product_type`, `discount` в `b2m___items`;

+ `b2m___features` — при изменении участия характеристики в фильтрах (поле `category_recalc`): всем категориям, брендам и маркерам с этой характеристикой;

+ `b2m___catalog` — когда изменился состав подкатегорий.

Флаги ставятся так же в `b2m___brands` и `b2m___markers` — у бренда и маркера тоже есть свои страницы с фильтрами.

**Распространение вверх по дереву.** Код действия поля `update_filters_data` в `b2m___catalog` при установке флага ставит его и всем родительским категориям — их фильтры включают товары подкатегории:

```totum
ch2=: if(condition: $#nfv = true; then: $set_list)

	set_list: setList(table: $#ntn; field: $#nf = true; where: 'id' = $list_cut)
		list_cut: listCut(list: $id_upper_tree; cut: "last"; num: 1)
			id_upper_tree: #tree_path[tree_path][[id]]
```

**Демон** `update_catalog_filters`:

+ `activation_code` — генерация включена в настройках витрины:

	```totum
	=: if(condition: @b2m___global_settings.h_filters_autogen = true; then: true; else: false)
	```

+ `activation_interval` — 10 секунд, `pause` — 1 секунда.

+ `daemon_code` — одна строка за запуск: сначала категория (самая глубокая в дереве), если категорий в очереди нет — бренд, затем маркеры:

	```totum
	a1=: procVar(name: "is_it_daemon"; value: true)

	a2=: if(condition: $select_id_catalog != ""; then: $set_catalog; else: $check_brand)

		set_catalog: set(table: 'b2m___catalog'; field: 'update_filters_data' = false; where: 'id' = $select_id_catalog; exclude: "b2m___catalog")
			~select_id_catalog: select(table: 'b2m___catalog'; field: 'id'; where: 'update_filters_data' = true; order: 'tree_level' desc)

		check_brand: if(condition: $select_id_brand != ""; then: $set_brand; else: $set_marker)
			set_brand: set(table: 'b2m___brands'; field: 'update_filters_data' = false; where: 'id' = $select_id_brand; exclude: "b2m___brands")
				~select_id_brand: select(table: 'b2m___brands'; field: 'id'; where: 'update_filters_data' = true; order: 'brand_name' desc)

		set_marker: set(table: 'b2m___markers'; field: 'update_filters_data' = false; where: 'update_filters_data' = true; exclude: "b2m___markers")
	```

	`procVar` `is_it_daemon` сообщает кодам генерации, что они работают в процессе демона ([флаги между кодами][721]).

**Расчет.** Код действия поля `update_filters_data` в `b2m___catalog` при снятии флага пересчитывает хранимые данные фильтров и генерирует HTML фильтров для каждого активного интерфейса витрины (сокращенно):

```totum
ch1=: if(condition: $#nfv = false; then: $recalc)

	recalc: reCalculate(table: $#ntn; field: 'filters_data'; field: 'filter_list'; where: 'id' = #id)

ch4=: $gnrt

gnrt: listReplace(list: $registered_interfaces; action: $generate; value: "interface_name")
		registered_interfaces: selectList(table: 'b2m___registered_interfaces'; field: 'interface_name'; where: 'active' = true; order: 'interface_name' asc)
	generate: exec(code: @b2m___registered_templates.template_code.interface_key[$search_key]; var: "interface_name" = $#interface_name; var: "category_id" = #id)
		search_key: str`$#interface_name + "--" + "create--filter"`
```

**Для пользователя.** Форматирование флага показывает `Да` с подсветкой и кнопкой панели «Обновить фильтры», которая снимает флаг вручную. Таблица `b2m___features`, пока в очереди есть строки и включена автогенерация, выводит комментарий, что изменение параметров фильтров заблокировано до окончания генерации.

Второй демон системы, `clear_reserves`, — очередь по времени: код активации ищет резервы товара на складе с истекшим сроком, код демона за один запуск снимает один самый старый резерв (меняет тип движения и добавляет обратное движение по складу).

## <a name="pt-bg-exclude"></a> exclude и silent для записей в фоне

Демон пишет в таблицы, в которых одновременно работают люди. При обычной [проверке актуальности][104] его транзакция может конфликтовать с их изменениями и перезапускаться — а тяжелый расчет перезапустится вместе с ней.

+ [exclude][682] — для указанных таблиц до конца действия отключается проверка актуальности и перезапуск транзакции; код изменения таблицы записывается, пользователи видят уведомление. В B2M каждый `set` демона снимает флаг с `exclude` на свою таблицу: `exclude: "b2m___catalog"`.

+ [silent][682] — как `exclude`, но без записи кода изменения: нет уведомлений и автообновления у пользователей. Для таблиц, в которые постоянно пишут фоновые процессы и где уведомления не нужны: логи, очереди, журналы событий, — особенно когда параллельно пишут несколько демонов.

`exclude` и `silent` действуют на всю цепочку действия — достаточно указать их в первом изменении, с которого цепочка начинается.

## <a name="pt-bg-traps"></a> Ловушки

+ **Одна порция за запуск.** Демон, который разбирает всю очередь в одном запуске, превращается в одну огромную транзакцию: ошибка в любой строке откатывает всю работу, а таблицы долго заблокированы. Берите одну строку (или небольшую пачку) — `pause` вернет демона за следующей.

+ **Флаг снимается в той же транзакции, что и расчет.** Если расчет упал с ошибкой, транзакция откатится и флаг останется `true` — демон будет брать эту строку снова и снова. Следите за ошибками демона и не оставляйте в очереди строку, которая всегда падает.

+ Код активации выполняется каждые `activation_interval` секунд — он должен быть дешевым: один `select` по флагу или настройке.

+ Каждый демон — отдельный процесс на ядре процессора; на сервере с одним-двумя ядрами не запускайте несколько нагруженных демонов ([Daemons][649]). Демон с микро-интервалом и ошибкой в коде может положить слабый сервер — см. [Демоны: осторожно][737].

+ У процесса демона свой текущий каталог и свои процессные переменные — коды, которые работают с файлами или полагаются на `procVar` web-запроса, проверяйте именно в демоне (кнопка `do_it_now` в `ttm__daemons`).
