# Процессные переменные

[Процессная переменная][707] ([procVar][545]) живет, пока идет один процесс `php` — обработка одного запроса из браузера, одного вызова API, одного запуска крона или демона. Она доступна из любого кода любой таблицы этого процесса. На этом построены два паттерна: **посчитать один раз на весь процесс** и **флаги, которыми коды договариваются между собой**.

## <a name="pt-proc-once"></a> Один расчет на все строки

### <a name="pt-proc-once-task"></a> Задача

Код поля выполняется для каждой строки: форматирование — для каждой строки страницы, код — для каждой пересчитываемой строки. Если ему нужно значение, одинаковое для всех строк (список из другой таблицы, настройка), обычная строка кода сделает запрос в каждой строке. `~` здесь не поможет: [фиксация `~`](../../ARCHITECTURE.md#fix-lines) работает в пределах одного выполнения кода, а для следующей строки код выполняется заново.

### <a name="pt-proc-once-solution"></a> Решение

Значение кладется в процессную переменную с `default`:

```totum
~quick_list: procVar(name: "quick_list"; default: $sel_ql)
	sel_ql: selectList(table: 'b2m___header_quick'; field: 'teh_key'; where: 'type' = "product")
```

+ `default` выполняется, только если переменной еще нет: первая строка делает запрос и записывает результат, остальные строки этого процесса берут готовое значение без запроса.

+ `~` на строке с `procVar` — чтобы внутри одного выполнения кода, где строка используется несколько раз, не обращаться даже к переменной.

### <a name="pt-proc-once-b2m"></a> Пример из B2M

Форматирование поля `product_name` таблицы `b2m___items` подсвечивает товары, которые используются в элементах витрины (меню, баннеры, галереи, коллекции, блоки главной страницы), — по десятку списков из разных таблиц. Каждый список — процессная переменная, поэтому на страницу из 100 товаров приходится по одному запросу на список, а не по сто (сокращенно):

```totum
f1=: setFormat(condition: cond`$quick_list = #teh_key || $header_list = #teh_key || $banner_list = #teh_key || $interesting_list = #id`; …)

	~quick_list: procVar(name: "quick_list"; default: $sel_ql)
		sel_ql: selectList(table: 'b2m___header_quick'; field: 'teh_key'; where: 'type' = "product")
	~header_list: procVar(name: "header_list"; default: $sel_hl)
		sel_hl: selectList(table: 'b2m___header'; field: 'teh_key'; where: 'type' = "product")
	~banner_list: procVar(name: "banner_list"; default: $train_b)
		train_b: listTrain(list: $sel_b)
			sel_b: selectList(table: 'b2m___banners'; field: 'teh_key')
	~interesting_list: procVar(name: "interesting_list"; default: $sel_int)
		sel_int: selectList(table: 'b2m___interesting_items'; field: 'product')
```

Тот же прием — в форматировании `b2m___catalog`, `b2m___brands`, `b2m___pages` и в коде действия таблицы `b2m___pages`.

## <a name="pt-proc-flag"></a> Флаги между кодами

### <a name="pt-proc-flag-task"></a> Задача

Одно действие запускает цепочку кодов в разных полях и таблицах, и коды дальше по цепочке должны знать, что происходит: идет массовое изменение и не надо реагировать на каждую строку; строки удаляются вместе с владельцем; значение поставил код, а не пользователь.

### <a name="pt-proc-flag-solution"></a> Решение

Код, который начинает действие, ставит флаг `procVar(name: …; value: true)`, коды дальше по цепочке читают его с `default: false` и по нему пропускают или меняют свою работу.

### <a name="pt-proc-flag-b2m"></a> Примеры из B2M

+ **Не реагировать на изменения, которые делает сохранение.** Кнопка «Сохранить баннер» в цикле `b2m___banner` меняет его таблицы и ставит флаг цикла:

	```totum
	a4=: procVar(name: str`"banner-" + $#nci`; value: true)
	```

	Код действия таблицы `b2m___banner_additional_links` (таблица того же цикла) при любом изменении помечает баннер «требует перегенерации HTML», но не во время сохранения:

	```totum
	=: if(condition: $proc_var = false; condition: $sel != ""; then: $set)

	proc_var: procVar(name: str`"banner-" + $#nci`; default: false)

		sel: select(table: 'b2m___banner'; field: 'id')

		set: set(table: 'b2m___banner'; field: 'f_html_alert_banner' = true)
	```

	В имени флага — id цикла (`$#nci`): флаг одного баннера не влияет на другие.

+ **Удаление вместе с владельцем.** При удалении товара код действия поля `product_name` в `b2m___items` ставит флаг перед удалением его картинок:

	```totum
	dl10=: procVar(name: "delete_item"; value: true)

	dl11=: deleteList(table: 'b2m___product_images'; where: 'product' = #old.id; log: true)
	```

	Код удаления картинки в `b2m___product_images` по этому флагу не назначает следующую картинку основной и не перегенерирует OG-картинку товара — товар все равно удаляется.

+ **Один пересчет на владельца при удалении многих строк** — флаг хранит id последнего пересчитанного владельца, см. [удаленные строки][720].

+ **Ручное изменение или автоматическое.** Во временной таблице `b2m___set_price_levels` (цены SKU по уровням) поле `h_data` при открытии окна заполняет строки через `setListExtended` и ставит `procVar(name: "auto"; value: true)`. Коды действия полей `delta`, `final_sku_price`, `fixed` при `auto = true` не трогают фиксацию цены (`pin`, `clear`, признак `fixed`): она нужна, только когда цену меняет пользователь.

+ **Откуда запущен код.** Демон `update_catalog_filters` первой строкой ставит `procVar(name: "is_it_daemon"; value: true)`. Коды генерации HTML по нему выбирают путь к файлам: у процесса демона другой текущий каталог, чем у web-запроса.

## <a name="pt-proc-traps"></a> Ловушки

+ Переменная живет только в своем процессе. После закрытия окна с кнопкой «Закрыть после выполнения» таблица под ним обновляется уже в новом процессе — переменной там нет ([процессные переменные][707]).

+ Значение с `default` запоминается на весь процесс. Если тот же процесс дальше меняет данные, из которых оно посчитано, переменная останется старой — перезапишите ее через `value` или не кешируйте такие данные.

+ Имена переменных общие для всего процесса: давайте их по смыслу и добавляйте id (цикла, строки), если флаг относится к конкретному объекту.

+ Для значений, которые нужны разным процессам (блокировка параллельного запуска, счетчики), нужна [глобальная переменная][546], а не процессная.
