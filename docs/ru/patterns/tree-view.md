# Деревья: расчет, дети ветки, большие деревья

Таблица, показанная деревом ([tree-view][495], поле `tree` с [Тип таблицы-дерева][529]), — каталоги, структуры подразделений, справочники с вложенностью. Ниже — как в таком дереве считать значения, которые зависят от родителей и детей, и как не потерять производительность на большом дереве.

## <a name="pt-tree-calc-order"></a> Порядок расчета: сверху вниз или снизу вверх

Настройка [Порядок расчета в tree][579] (`treeViewCalc`) поля `tree` задает, в каком порядке пересчитываются строки разных уровней, когда в одном действии пересчитывается несколько строк. Работает для дерева и «по этой таблице», и «по другой таблице»; внутри уровня — обычный порядок (`id` или `n`):

+ `Сначала верхний уровень` (`roottoend`) — когда значение ребенка строится из значений родителя: путь, полный URL, хлебные крошки, наследуемые настройки.

+ `Сначала нижний уровень` (`endtoroot`) — когда значение родителя собирается из детей: количества, суммы, статусы «все дочерние готовы».

В B2M каталог `b2m___catalog` — дерево по этой же таблице с `Сначала верхний уровень`: полный URL и хлебные крошки категории (`tree_path`, `full_url`, `breadcrumbs`) собираются из URL ее родителей — родители должны быть посчитаны первыми.

## <a name="pt-tree-children"></a> Дети ветки — в техническом поле

Хороший подход — хранить у каждой ветки список **всех** ее потомков в техническом поле ([Кэш by design][729]). Он считается [selectTreeChildren][229] — дети, дети детей, без ограничения глубины:

```totum
=: listSort(list: $list; type: "number"; direction: "asc"; key: "value")

list: selectTreeChildren(table: $#ntn; id: #id; parent: 'tree')
```

Это `tree_children` в `b2m___catalog`. С ним оба направления по дереву — один запрос:

+ **Вся ветка вниз** — ветка и ее потомки: `listAdd(list: #tree_children; item: #id)`. Товары категории со всеми подкатегориями:

	```totum
	items_list: selectList(table: 'b2m___items'; field: 'id'; where: 'all_categories' = $list_add; where: 'active' = true)

		list_add: listAdd(list: #tree_children; item: #id)
	```

+ **Все предки вверх** — строки, в списке потомков которых есть эта ветка: `where: 'tree_children' = #id`. Искать родителей по цепочке `tree` → `tree` → … не нужно:

	```totum
	ch4=: reCalculate(table: $#ntn; where: 'tree_children' = #id)
	```

## <a name="pt-tree-move"></a> Перемещение, добавление, удаление: пересчитать и старых родителей

Когда ветка переезжает в другого родителя, добавляется или удаляется, меняются значения не только у **нового** родителя, но и у **старого** — и у всех их предков.

+ Старые значения — из `#old.поле` ([предыдущее значение][738]): `#old.tree`, `#old.all_categories`.

+ Список для пересчета — старые и новые значения вместе, без повторов, и все их предки через `tree_children`.

В B2M при смене категорий товара пересчитывается количество товаров и в новых, и в прежних категориях, и у всех их предков (код действия `all_categories` в `b2m___items`):

```totum
a2=: reCalculate(table: 'b2m___catalog'; field: 'product_count'; where: qrow`'id' = $uniq_plus || 'tree_children' = $uniq_plus`)

	~uniq_plus: listUniq(list: $plus)
		plus: listAdd(list: #all_categories; list: $null)

	~null: if(condition: $is_it_list = false; then: $#lc; else: #old.all_categories)
		is_it_list: listCheck(list: #old.all_categories)
```

**При удалении** значения удаляемой строки есть только в `#old.поле` — `#поле` уже пусто. В B2M удаление категории проверяет `#old.tree_children` (нельзя удалить ветку с подкатегориями) и ищет использование категории по `#old.id`, `#old.teh_key`:

```totum
dl01=: if(condition: #old.tree_children != $#lc; then: $error)
	error: errorException(text: "Нельзя удалить раздел с подразделами, сначала удалите подразделы или перенесите их в другую ветку!")
```

## <a name="pt-tree-big"></a> Большие деревья

+ **Фильтрация по ветке.** Большое дерево не показывают целиком — показывают ветку, выбранную в префильтре. Учтите: привязанный к колонке префильтр с деревом «по этой таблице» несовместим ([тип таблицы дерева][495]). Для такого дерева значение префильтра используют как переменную и передают выбранные ветки в параметр [roots][727] кода селекта `tree` ([selectRowListForTree][228]) — на верхнем уровне окажутся только они.

+ **Дерево и пагинация не связаны друг с другом.** Разбивка на страницы делит строки, а не ветки: на странице окажутся обрывки разных веток. Поэтому большое дерево либо выводят свернутым ([Загрузить все][531] без [Открыть все][530] или вовсе без загрузки всего — ветки подгружаются при раскрытии), либо ограничивают по веткам через `roots`.

В B2M каталог пока загружается и раскрывается целиком без пагинации — для текущего размера каталога этого достаточно; фильтрация больших деревьев по веткам еще не сделана.

## <a name="pt-tree-traps"></a> Ловушки

+ Список потомков `tree_children` устаревает при перемещении веток: у старых и новых предков он пересчитывается при пересчете их строк — пересчитывайте их (как `ch4` выше), а не только переехавшую ветку.

+ Значение, которое зависит от детей, при `Сначала верхний уровень` посчитается по старым данным детей — выбирайте порядок по тому, в какую сторону идут зависимости, а смешанные зависимости разносите по разным действиям.
