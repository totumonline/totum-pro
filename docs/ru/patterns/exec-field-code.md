# Вызов кода другого поля через exec

## <a name="pt-exec-task"></a> Задача

Одно и то же действие нужно запускать из разных мест: при изменении самого поля, при изменении других полей строки, по кнопке. Копировать код в каждое поле — значит потом править его в нескольких местах и рано или поздно забыть одно из них.

## <a name="pt-exec-solution"></a> Решение

Логика пишется один раз — в коде поля, к которому она относится по смыслу, а остальные поля вызывают ее функцией [exec][286] по `name` этого поля:

```totum
=: exec(code: "sitemap")
```

+ Если в `code` передан `name` поля текущей таблицы (строчные латинские буквы, цифры и `_`, не короче трех символов), выполняется код этого поля **того же типа**, из которого идет вызов: из [кода действия][28] — код действия, из [кода][27] — код, из [форматирования][39] — форматирование.

+ Вызванный код выполняется в контексте вызывающего: та же строка (`#field`, `#old.field`), та же таблица, тот же триггер действия — в коде действия срабатывают секции `=:`, `a…=:` и секции триггера вызывающего поля (`ch…=:` при изменении, `ad…=:` при добавлении, `dl…=:` при удалении, `cl…=:` при клике).

+ Параметры передаются через `var`, вызываемый код читает их через [var][285] с `default` — тогда он работает и при вызове через `exec`, и при срабатывании своего поля:

	```totum
	a1=: exec(code: "features_search"; var: "old_categories" = $minus)
	```

	```totum
	old_cat: var(name: "old_categories"; default: $#lc)
	```

## <a name="pt-exec-nfv"></a> $#nfv и $#nf в вызываемом коде

Вызванный код **не знает**, что он «код поля `sitemap`»: текущее поле для него — поле, из которого вызван `exec`. Поэтому в коде, который вызывают через `exec`, нельзя использовать:

+ `$#nfv` — значение текущего поля: это будет значение вызывающего поля (`lastmod`), а не `sitemap`;

+ `$#nf` — `name` текущего поля: это будет `lastmod`;

+ `$#onfv` — предыдущее значение текущего поля — по той же причине.

Поля в таком коде указывайте явно: `#sitemap` вместо `$#nfv`, `#old.sitemap` вместо `$#onfv`, `'sitemap'` вместо `$#nf` в `set` и `where`.

## <a name="pt-exec-b2m"></a> Пример из B2M

**Sitemap и редиректы.** Код действия поля `sitemap` таблицы `b2m___items` добавляет товар в карту сайта или удаляет из нее — все поля указаны явно:

```totum
a1=: if(condition: #sitemap = true; then: $set_sitemap)

	set_sitemap: extSitemap(host: $#nh; url: #full_url; lastmod: #lastmod; old: #old.full_url)

a2=: if(condition: #sitemap = false; then: $delete_sitemap)

	delete_sitemap: extSitemap(host: $#nh; url: #full_url; lastmod: #lastmod; old: #old.full_url; delete: true)
```

Его вызывают поля, от которых зависит запись в карте сайта:

+ `lastmod` — `=: exec(code: "sitemap")`;

+ `full_url` — `a8=: exec(code: "sitemap")` и `a9=: exec(code: "redirect_list")`.

Так же устроены `b2m___catalog`, `b2m___pages`, `b2m___brands` (`url_in_use` вызывает `sitemap` и `redirect_list`).

**Параметры вызова.** Код действия поля `features_search` помечает категории товара для перегенерации фильтров. Сам по себе он срабатывает, когда изменились характеристики, — и только если характеристика участвует в фильтрах. Другие поля вызывают его с параметрами:

```totum
=: if(condition: cond`$use_in_filter != "" || $force = true`; then: $set_update_list)

	use_in_filter: select(table: 'b2m___features'; field: 'id'; where: 'use_in_filter' != ""; where: 'feature_key' = $feature_keys)
		feature_keys: rowKeys(row: #features_search)

	set_update_list: setList(table: 'b2m___catalog'; field: 'update_filters_data' = true; where: 'id' = $add_ol_categories)
		add_ol_categories: listAdd(list: #all_categories; list: $old_cat)
			old_cat: var(name: "old_categories"; default: $#lc)

	force: var(name: "force"; default: false)
```

+ `active` (товар включили или выключили) — `a3=: exec(code: "features_search"; var: "force" = true)`: пометить категории, даже если характеристик в фильтрах нет;

+ `all_categories` (сменились категории товара) — `exec(code: "features_search"; var: "old_categories" = $minus)`: пометить и категории, из которых товар ушел;

+ `catalog_prices` — `a1=: exec(code: "features_search")`.

В коде `features_search` поле указано явно — `#features_search`, а не `$#nfv`: при вызове из `active` значение `$#nfv` было бы значением чекбокса.

Вызов возможен и из кнопки: кнопка `h_regen_og_teh` в карточке товара `b2m___item` — `=: exec(code: "h_og_image_raw")`, перегенерация OG-картинки выполняет код действия поля картинки. При вызове из кнопки `$#nfv` — значение кнопки (пусто), поэтому в коде поля картинки ее значение нужно брать как `#h_og_image_raw`.

## <a name="pt-exec-traps"></a> Ловушки

+ `$#nfv`, `$#nf`, `$#onfv` в вызываемом коде — главная ошибка паттерна: код работает при изменении своего поля и молча делает не то при вызове через `exec`.

+ Вызывается код того же типа: из кода действия нельзя выполнить код или форматирование другого поля этим способом.

+ Если у вызываемого поля нет кода нужного типа, выполнять будет нечего, — проверяйте `name` и тип кода. Строка, которая не совпала с `name` поля таблицы (опечатка, поле другой таблицы), будет выполнена как текст кода.

+ Секции с триггерами вызываемого кода работают по триггеру **вызывающего** поля: `ch1=:` вызываемого кода сработает только если вызов идет из действия на изменение. Логику, которую вызывают из разных триггеров, пишите в секциях `=:` и `a…=:`.

+ Переменные `var` вызова не должны пересекаться с именами строк и переменных вызываемого кода.
