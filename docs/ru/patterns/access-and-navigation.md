# Навигация и доступ

## <a name="pt-nav-sections"></a> Разделы дерева и таблицы по умолчанию

+ **Верхних разделов — немного.** Каждый верхний раздел — отдельная вкладка в шапке; без надобности их не умножайте: пять разделов по смыслу работы удобнее пятнадцати по таблицам. Остальное раскладывайте по папкам и [ярлыкам][710] внутри.

+ **Раздел открывает самую используемую таблицу.** У верхнего раздела заполните `Таблица по умолчанию` ([дерево][355]) — пользователь, перейдя в раздел, сразу попадает туда, где работает чаще всего.

	| Раздел B2M | Таблица по умолчанию |
	|---|---|
	| Витрина | Товары (`b2m___items`) |
	| Заказы | Заказы (`b2m___orders`) |
	| Доставки и Склад | Доставки (`b2m___shipping`) |
	| Технические | Настройки витрины (`b2m___global_settings`) |

+ **Стартовая таблица роли.** В таблице ролей в поле `Таблица редиректа` ([redirect_table_in_roles][723]) задается таблица, на которую пользователь роли попадает сразу после входа: менеджеру — заказы, складу — движения по складам.

+ **Дашборд на главной.** По клику на лого пользователь попадает на главную страницу. Для роли можно выбрать временные таблицы, которые показываются там вкладками ([Дашборды на главной][722], поле `Временные для главной`): сводка дня, задачи, ключевые цифры. В такой временной таблице через `tablehtml` [setTableFormat][317] можно вывести любой HTML (в PRO — и с JS): графики, плитки, ссылки на рабочие таблицы.

## <a name="pt-nav-tmp"></a> Временные таблицы

+ **Скрыть из дерева — для пользователей, не для создателя.** Временные таблицы открываются кнопками и окнами, в дереве пользователям они не нужны — поставьте им [Роли «скрыть в дереве»][121] (или скройте в роли — поле `Скрыть из дерева навигации`). Роль Создатель туда не добавляйте: создателю они нужны в дереве, чтобы не потерять их при разработке.

	В B2M временные таблицы собраны в папке `Технические > Временные таблицы`; скрытие из дерева для ролей пользователей еще предстоит настроить.

+ **Кнопки временной таблицы проверяют входные данные.** Временную таблицу открывают с параметрами (`linkToDataTable` с `params`, `linkToTable` с `filter`), но пользователь может открыть ее и напрямую — из дерева или по адресу — с пустыми параметрами. Кнопка, которая что-то пишет, должна проверять в [коде действия][28], что нужные параметры есть:

	```totum
	=: if(condition: cond`#h_item = "" || $control != "" || #f_sku = ""`; then: $err; else: $action)

		control: select(table: $#ntn; field: 'id'; where: 'control' = true)
	```

	Это кнопка «Добавить в заказ» временной таблицы `b2m___add_product`: без товара, без выбранного SKU или при строке, отмеченной контролем (`control`), она выдает ошибку, а не пишет в заказ пустую строку.

+ **Пустые параметры не должны открывать чужие данные.** Если код временной таблицы выбирает строки по параметру (`where: 'client' = #h_client`), с пустым параметром он выберет строки с пустым клиентом — или все строки, если условие собрано так, что пустое значение его выключает (`*ALL*`). Проверяйте параметр перед выборкой и не показывайте данные, если его нет.

## <a name="pt-nav-cycles"></a> Доступ к строкам таблицы циклов и внутрь цикла

Заблокированный префильтр, привязанный к колонке, ограничивает доступ к **строкам** таблицы — см. [задачи префильтра][706]. В таблице циклов это ограничивает строки самой таблицы циклов, но **не доступ внутрь цикла**: пользователь, у которого есть ссылка на цикл, откроет его таблицы.

Доступ внутрь циклов задается отдельно — настройкой таблицы [Тип доступа к циклам][116] вместе с владельцами цикла (`creator_id`) и настройками пользователей (`Начальник`, `Доступ к циклам пользователей`) — см. [Тип доступа к циклам][724]. В B2M у таблиц циклов (`b2m___items`, `b2m___orders`, `b2m___customers`, …) стоит «Доступ внутрь циклов на запись».

## <a name="pt-nav-prefilter-button"></a> Кнопка, которая ставит префильтры

Сложный отбор (по нескольким опциям, с вариантами «и» / «или») неудобно задавать полями префильтра. Его делают кнопкой в префильтре: она открывает окно подбора, а результат возвращается в таблицу через [linkToTable][305] со значениями префильтров.

В B2M так устроен поиск SKU по опциям в `b2m___sku`:

1. `fl_sku_search` — кнопка в префильтре (иконка `filter`, заблокирована, пока не выбран товар) открывает временную таблицу `b2m___sku_search` с опциями товара и текущим отбором:

	```totum
	a2=: linkToDataTable(table: 'b2m___sku_search'; title: str`"Поиск по SKU:" ++ #s.fl_product`; width: 940; height: "80vh"; data: $options; params: $params; topbuttons: false; bottombuttons: false)
	```

2. Кнопка «filter» окна снова открывает вкладку SKU товара и передает отбор переменной:

	```totum
	=: execButton(table: 'b2m___items'; field: 'tab_sku'; where: 'id' = #h_product; var: "target" = "top"; var: "filter_data" = $multi)
	```

3. Кнопка вкладки ставит его в префильтр `fl_search_field` (поле Данные, отбор по ключам — [поиск по ключам в поле Данные][702]):

	```totum
	=: linkToTable(table: 'b2m___sku'; filter: 'fl_product' = #id; filter: 'fl_tab' = true; filter: 'fl_search_field' = $data; target: $target)
	```

4. Пока отбор действует, таблица пишет об этом в `tablecomment`, а кнопка `fl_clear_search` («Сбросить фильтр SKU») подсвечена `##tomato` и открывает вкладку с пустым отбором.
