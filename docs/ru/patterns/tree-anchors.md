# Таблица с подтаблицами в дереве

## <a name="pt-tree-task"></a> Задача

Есть основная таблица и несколько вспомогательных, которые без нее не нужны: справочник городов и его регионы, движение по складам и сами склады, главная страница и ее блоки. В дереве пользователь должен видеть **одну точку входа** — основную таблицу, а вспомогательные — сразу под ней, а не россыпью в папке рядом.

Таблица в дереве не может быть родителем других таблиц: родителем может быть только ветка [дерева навигации][355]. Решение — [ярлык][355] на основную таблицу, а подтаблицы кладутся в ветку этого ярлыка.

## <a name="pt-tree-solution"></a> Решение

1. Основную таблицу кладут в техническую папку, куда пользователи не ходят ([положение в дереве][95] — например `Технические > Перемещенные таблицы`).

2. В той папке, где таблица должна быть видна, создают ветку дерева с типом **Ярлык**: `Таблица по умолчанию` — основная таблица, иконка — по смыслу. Переход по ярлыку открывает основную таблицу.

3. Подтаблицам в [положении в дереве][95] выбирают **ветку ярлыка**. В дереве они показываются под ярлыком — как вложенные в основную таблицу.

```
Доставки и Склад                      — раздел (папка)
├── Движение по складам               — ярлык → b2m___stock
│   ├── Склады                        — b2m___warehouses (положение в дереве: ярлык «Движение по складам»)
│   └── Поставки на склад             — b2m___goods_receipts
└── Города                            — ярлык → b2m___cities
    ├── Регионы                       — b2m___regions
    └── Подсказки                     — b2m___cities_suggestions

Технические > Перемещенные таблицы    — сами b2m___stock, b2m___cities, …
```

+ У ярлыка можно заполнить `Фильтры` — значения префильтров основной таблицы при переходе по ярлыку; такие префильтры блокируются на изменение и могут быть скрыты. Так из одной таблицы делают несколько точек входа: например, «Заказы новые» и «Заказы в работе».

+ Видимость ярлыка определяется видимостью основной таблицы для пользователя; `Роли` ярлыка могут ее переопределить.

## <a name="pt-tree-b2m"></a> Пример из B2M

| Ярлык (ветка дерева) | Открывает | Подтаблицы в ветке ярлыка |
|---|---|---|
| Доставки и Склад > Города | `b2m___cities` | `b2m___regions`, `b2m___cities_suggestions` |
| Доставки и Склад > Движение по складам | `b2m___stock` | `b2m___warehouses`, `b2m___goods_receipts` (таблица циклов поставок) |
| Витрина > Витрина > Главная страница | `b2m___main_page` | `b2m___main_page_hits`, `b2m___main_page_latest`, `b2m___main_page_discounts`, `b2m___interesting_items` |
| Витрина > Каталог | `b2m___catalog` | `b2m___custom_catalog` |
| Витрина > Данные товаров > Характеристики товаров | `b2m___product_features` | `b2m___features`, `b2m___features_group`, `b2m___features_uniq_values` |
| Витрина > Данные товаров > Опции товаров | `b2m___product_options` | `b2m___options`, `b2m___options_group`, `b2m___option_values` |
| Витрина > Данные товаров > Отзывы / Вопросы | `b2m___reviews` | `b2m___reviews_images` |

Основные таблицы (`b2m___cities`, `b2m___stock`, `b2m___main_page`, `b2m___catalog`) лежат в папке `Технические > Перемещенные таблицы`, таблицы данных товаров — в ее подпапке `Данные товаров`. Папка `Данные товаров` в разделе `Витрина` содержит только ярлыки — по одному на таблицу данных товаров.

## <a name="pt-tree-traps"></a> Ловушки

+ Ярлык — это ветка дерева, а не таблица: права на данные по-прежнему задаются ролями основной таблицы, ярлык только показывает вход.

+ Если подтаблице оставить положение в технической папке, она пропадет из-под ярлыка — положение в дереве подтаблицы должно быть именно веткой ярлыка.

+ Ярлыки на ярлыки дают вложенную структуру (в `Родитель` ярлыка можно выбрать другой ярлык) — пользуйтесь этим для глубоких справочников, но не стройте дерево глубже, чем нужно пользователю.
