# Порядок расчета и единицы пересчета

## <a name="table-seq"></a> Последовательность расчета полей

Поля рассчитываются в соответствии с [плейсментом][35] и параметром `sort` в [Составе таблиц][354], определяющими и их визуальный порядок отображения в таблице.

Плейсменты рассчитываются последовательно: Хедер → Префильтр → Строчная часть → Футер.

Поля внутри плейсмента рассчитываются слева-направо по возрастанию `sort`. Если `sort` одинаковый, то в соответствии с порядком `id` поля в [Составе таблиц][354].

Если согласно [коду][29], поле обращается к полю расчет которого еще не произведен, то вместо запрашиваемого значения вернется [пустота][5].

**Порядок расчета строк строчной части:**

+ Для таблиц со `строчной` единицей пересчета — строки рассчитываются в порядке возрастания id, за исключением случая, когда они выравнены по [полю сортировки][97] `n` — в этом случае они рассчитываются в порядке возрастания `n`.

+ Для таблиц с `табличной` единицей пересчета — строки рассчитываются в порядке возрастания их `id`, за исключением случая, когда они выравнены по [полю сортировки][97] `n` — в этом случае они рассчитываются в порядке возрастания `n`.


## <a name="table-recalc"></a> Единицы пересчета

Данные в полях таблиц обновляются в момент пересчета.

Пересчитываться может полностью вся таблица, либо некоторые выбранные строки.

Чем большее количество полей попадает в зону расчета — тем выше нагрузка на сервер и дольше время расчета.

Для задач расчета поля объединены в группы — `единицы пересчета`.

Если происходит изменение значения в поле, то запускается пересчет той `единицы пересчета` в которую это поле входит. Происходит последовательное вычисление значений всех полей входящих в `единицу пересчета`.

## Типы таблиц по единицам пересчета

### <a name="table-str"></a> Строчные

Единица пересчета = СТРОКА!:

+ [Простая таблица][88]

+ [Таблица циклов][89]

Эти типы таблиц годятся для хранения больших массивов данных. Нагрузка на сервер остается неизменной при росте количества строк.

![Строчные таблицы](https://totum.totum.online/fls/365_47_file.png)

К особенностям этих типов относится:

+ Отсутствие плейсмента [футер][35].

+ Автоматический пересчет [хедера][35] при:

	+ Открытии таблицы в web-интерфейсе.
	+ Пересчете любой из строк (один раз за действие).
	+ Вызове пересчета таблицы [recalculate][289] под условия которого не попадает ни одна строка.
	+ При пересчете цикла из web-интерфейса или функцией [recalculateCycle][304].



### <a name="table-full"></a> Таблица целиком

Единица пересчета = ВСЯ ТАБЛИЦА!:

+ [Расчетная в дереве][1]

+ [Расчетная в цикле][1]

+ [Временная][34]

Эти таблицы не годятся для хранения большого объема данных. Нагрузка на сервер при расчете растет вместе с ростом объема данных в таблице.

К особенностям этих типов относится:

+ У временных таблиц отсутствует [префильтр][48].

+ Пересчет всей таблицы при любом изменении.

+ Связанные с циклами:

	+ [Автоматическая взаимосвязь][379] таблиц внутри циклов.
	+ Версии для расчетных таблиц внутри циклов.
	
+ Наличие [футеров колонок][35].

+ Два режима [последовательности расчета][93] полей строчной части и футеров колонок.

### Режимы табличной единицы пересчета

#### <a name="table-full-str"></a> Строчный режим

![Строчный режим](https://totum.totum.online/fls/365_45_file.png)

В этом режиме поля [строчной части][35] рассчитываются построчно в порядке `id` строки, за исключением случая, когда они выровнены по полю сортировки `n` — в этом случае они рассчитываются в порядке возрастания `n`.

Поля внутри строк рассчитываются в порядке возрастания параметра `sort`.

Поля [футера][35] также рассчитываются в порядке `sort`, независимо от того, подключены они к колонкам или находятся в общем футере.


#### <a name="table-full-column"></a> Поколоночный пересчет

![Колоночный режим](https://totum.totum.online/fls/365_46_file.png)

Включается параметром [Поколоночный пересчет][93].

В этом режиме [строчная часть][35] таблицы рассчитывается поколоночно в порядке `sort` полей. Строки рассчитываются в порядке `id` или `n`.

[Футер колонок][35] рассчитывается в порядке `sort` колонок. Если к одному футеру колонки относится несколько полей, то они рассчитываются в порядке собственных `sort`.

Поля [общего футера][35] рассчитываются после футеров колонок в порядке собственных `sort`.
