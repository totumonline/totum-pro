# Пользовательские функции (spec)

PRO. Функции на языке Totum: код один раз записывается в таблицу `ttm__custom_functions` и вызывается из любых кодов как `spec<Имя>(…)` — так же, как встроенные [функции][75].

Не путать с [функциями на PHP][505] (`ext…`), которые подключаются файлом `CalculateExtensions.php` на сервере.

## <a name="user-functions-table"></a>Таблица Пользовательские функции

Располагается в `Системные таблицы` — `PRO Пользовательские функции` (`ttm__custom_functions`). Одна строка — одна функция:

| поле | name | что это |
|---|---|---|
| Name функции | `function_name` | имя без `spec`, уникальное: латинские буквы и цифры, первые два символа — буквы. С `_`, пробелом или кириллицей функцию не вызвать — разбор кода не распознает такое имя |
| Имя при поиске | `search_name` | рассчитывается: имя в нижнем регистре, по нему функция ищется при вызове |
| Шаблон автозаполнения | `template` | что подставляет редактор кода после имени, например `(system: ; user: ; model: "gpt-4o")` |
| Все параметры | `all_parameters` | список имен всех параметров, JSON: `["value","total","digits"]` |
| Обязательные параметры | `required` | список обязательных, JSON; пусто — обязательных нет |
| Множественные параметры | `multiple` | список параметров, которые можно указать несколько раз |
| Код функции | `code_totum` | код Totum, параметры в нем — `$#имя` |
| Описание | `description` | markdown: показывается в редакторе кода по клику на имя функции |

## <a name="user-functions-example"></a>Пример

Функция `percent` — процент от целого с округлением:

+ `function_name`: `percent`
+ `template`: `(value: ; total: )`
+ `all_parameters`: `["value","total","digits"]`
+ `required`: `["value","total"]`
+ `code_totum`:

```totum
=: if(condition: $#total = 0; then: 0; else: $rounded)

rounded: round(num: $p; dectimal: $digits)
p: $#value / $#total * 100
digits: if(condition: $#digits = ""; then: 0; else: $#digits)
```

Вызов:

```totum
=: specPercent(value: #done; total: #all)
```

`specPercent(value: 1; total: 3)` — `33`, `specPercent(value: 1; total: 3; digits: 2)` — `33.33`, `specPercent(value: 5; total: 0)` — `0`.

## <a name="user-functions-call"></a>Вызов

+ Приставка `spec` — строчными буквами, остальная часть имени — в любом регистре: `specPercent`, `specpercent` и `specPERCENT` — одна функция. `SpecPercent` — ошибка `Функция "SpecPercent" не найдена.`

+ Функция доступна во всех секциях кода: [код][27], [код действия][28], [код селекта][4], [форматирование][39]. Ее код выполняется по правилам той секции, из которой она вызвана: функции действий (`set`, `insert`, `linkTo…`) — только из кода действия, `setFormat` — только из форматирования. Форматы, заданные функцией, добавляются к форматам поля, из которого она вызвана.

+ Результат функции — результат ее кода.

+ Функции нет в таблице — ошибка `Функция "specИмя" не найдена.`

## <a name="user-functions-params"></a>Параметры

+ Значения параметров рассчитываются в вызывающем коде и передаются в код функции как переменные `$#имя`.

+ Передаются только параметры из `all_parameters`. Другие параметры вызова пропускаются **без ошибки** — опечатка в имени параметра означает, что параметр не передан.

+ Обязательный параметр не указан — ошибка `Параметр "value" является обязательным в функции "specPercent".`

+ Необязательный параметр не указан — `$#имя` равен `null`, множественный — пустому списку `[]`. Множественный параметр, указанный несколько раз (`item: 1; item: 2`), — список `["1","2"]`.

+ Имена параметров — строчные латинские буквы, цифры и `_`, не короче двух символов: `value`, `max_tokens`. Однобуквенное имя (`x: 5`) и имя с заглавными буквами (`maxTokens: 5`) разбор параметров не распознает — параметр не будет передан.

+ Не называйте параметры как служебные параметры встроенных функций: `condition`, `then`, `else` не рассчитываются (в функцию попадет текст кода), `where`, `filter`, `key` разбираются как условие `'поле' = значение`, `where`, `order`, `filter`, `condition`, `preview` всегда становятся списком, `order` — сортировкой.

### <a name="user-functions-defaults"></a>Значения по умолчанию: default не работает

**Особенность пользовательских функций** (так задумано): все параметры из `all_parameters` в коде функции **всегда существуют** как переменные — и переданные, и непереданные (со значением `null`, множественные — `[]`).
Поэтому `default` функции [`var`][285] для параметров функции **не срабатывает никогда**: `default` применяется только к неопределенной переменной, а параметр всегда определен.

```totum
// НЕ работает: при specPercent(value: 1; total: 3) $digits = null, а не 0
digits: var(name: "digits"; default: 0)
```

Значение по умолчанию задавайте проверкой на пустоту:

```totum
digits: if(condition: $#digits = ""; then: 0; else: $#digits)
```

Множественный параметр — проверкой количества: `if(condition: listCount(list: $#items) = 0; then: …; else: $#items)`.

## <a name="user-functions-context"></a>Контекст выполнения

+ Код функции выполняется в контексте вызывающего кода: та же таблица и строка — `#поле`, `#old.поле` и другие ссылки на поля относятся к строке, из которой вызвана функция, `$#ntn` — имя таблицы вызывающего кода.

+ Переменные вызывающего кода (`$#…`, `var(…)`) в функции не видны — все, что нужно функции, передавайте параметрами.

+ В [отладке][71] лог кода функции вложен в строку вызова, ошибка показывает путь `Функция "specИмя"`.

## <a name="user-functions-editor"></a>В редакторе кода

Для создателя редактор кода подсказывает пользовательские функции вместе со встроенными: имя, шаблон и параметры. Клик по имени `spec…` в коде показывает описание функции, кнопка редактирования открывает код функции (`code_totum`) в редакторе и сохраняет его в таблицу `ttm__custom_functions`.

## <a name="user-functions-check"></a>Изменение и проверка

+ Функция используется везде, где она вызвана: прежде чем изменить параметры или результат, найдите все вызовы `spec<Имя>` в кодах. Агент MCP (режим создателя): `search_codes {"q": "specPercent"}`.

+ Внешние действия внутри функции (`getFromScript`, `emailSend`…) не видны в коде места вызова: в схеме агента (`get_table_schema`, колонка `external calls`) вызывающее поле их не показывает. Их находит `search_codes {"external": true}` — в данных `ttm__custom_functions`. Отладка агента (`debug`) блокирует их и при вызове через функцию, в `where` указано вызывающее поле, мок из подсказки вызывающего поля работает.

+ Проверка без сохранения — агент MCP: `exec_code` с вызовом функции (транзакция откатывается). Новый код функции проверяется до сохранения в том же запуске: `a1=: set(table: 'ttm__custom_functions'; field: 'code_totum' = …; where: 'function_name' = "percent")`, затем `a2=:` с вызовом функции.
